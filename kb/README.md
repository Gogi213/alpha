# kb — база знаний проекта

Карточки Markdown в git (`kb/<тип>/<id>.md`) — единственный источник правды. `tools/kb.py` (один файл, только стандартный Python 3) строит из них sqlite/FTS5 (`kb/.kb.sqlite`, не в git), проверяет перелинковку и собирает сайт: http://5.231.25.224:8091/ (карточки, поиск, фильтры тип/статус/задача, обратные ссылки, граф). Перенос в другой репозиторий — [PORTING.md](PORTING.md).

## Карточка

```markdown
---
id: TK-625              # = имя файла; буквы, цифры, «.», «-», «_»
type: task              # decision | task | finding | protocol | runbook | rule | machine  (= каталог)
status: done            # open | running | done | dropped | superseded
title: "Короткий заголовок"
date: 2026-11-20
links: [P-42, docs/findings/отчёт.md]   # карточки по id, файлы репозитория по пути
supersedes: []          # id карточек, которые эта заменяет
---
Тело — Markdown. Ссылка на карточку в тексте: [[P-42]]; на файл: [[docs/findings/отчёт.md]].
```

Новая карточка из шаблона (`kb/_templates/<тип>.md`): `python tools/kb.py new task TK-630 "заголовок"`.

## Команды

| команда | что делает |
|---|---|
| `new <тип> <id> "<заголовок>"` | создаёт карточку из шаблона |
| `build` | пересобирает `kb/.kb.sqlite` (find / show / list делают это сами, если карточки новее) |
| `find "<запрос>"` | полнотекстовый поиск (префиксы, регистр, ё = е) |
| `show <id>` | карточка + ссылки из неё и на неё |
| `list [--type T] [--status S] [--link ID]` | список; `--link` — связанные с id в любую сторону |
| `check` | битые ссылки, сироты, дубли id, неверный front matter, `superseded` без замены; код 1 при ошибках |
| `site <каталог>` · `serve` | статический сайт без внешних зависимостей · локальный сервер (`--port 8095`) |
| `precommit [--changed]` · `install-hook` | `check` только если в коммит попал `kb/` · установка git-хука |

## Правила для тредов

1. **Результат = карточка.** Итог работы — карточка в `kb/` (`finding`, `decision`, `runbook`, `rule`…), а не новый файл-«свалка».
2. **Статус и «Дальше» — в карточке задачи** (`kb/task/TK-NNN.md`, разделы «Состояние» и «Дальше»); новые `handoff-vN` не заводим.
3. Каждая карточка ссылается минимум на одну другую; файлы `docs/**` — по пути, числа — с источником (`[[docs/findings/…]]`).
4. **`python tools/kb.py check` перед коммитом.** Хук `.claude/hooks/kb_check.py` запускает его сам при `git commit`, если правился `kb/`; красный — коммит не проходит.
5. Заменённая карточка — `status: superseded`, а заменяющая указывает её в `supersedes:`. Удалять карточки не нужно.

## Решения и протоколы (TK-632)

- Решения владельца — карточки `decision` в `kb/decision/`, **единственный реестр** (с 20.11.2026): **В-N** (бывший `.claude/decisions.md`, [[decisions-registry]]) и **S-N** (бывший `docs/plan/SETTLED.md`, [[settled-registry]]); сами файлы заморожены в `docs/archive/`, на старых путях — заглушки-указатели. В брифах и коде «SETTLED В-NNN» = карточка `S-NNN`, «В-NNN» = карточка `В-NNN` (кириллическая «В»); номера двух реестров пересекаются, id — нет. Найти: `python tools/kb.py find "<слова>"`, `python tools/kb.py show В-NNN`.
- Импортёр `tools/kb_import_decisions.py` — разовый (читает замороженные реестры из `docs/archive/`); поверх существующих карточек пишет только с `--force` и затирает их правки — не запускать.

### Как записать решение

1. Следующий номер: `python tools/kb.py list --type decision | awk '{print $1}' | grep '^В-' | sort -t- -k2 -n | tail -1` → +1 (сейчас **В-162**). Номер с кириллической «В», id = имя файла.
2. `python tools/kb.py new decision В-162 "В-162 — суть в одну строку"` → `kb/decision/В-162.md` из шаблона `kb/_templates/decision.md`. В шапке: `status: done`, `date:` — день решения, `links:` — минимум одна карточка (задача, протокол, соседнее решение; файлы — по пути).
3. Тело: «Слово владельца» — цитата дословно, по-русски, не пересказ; «Суть» — что решено; «Заменяет» — `—` или номера. Согласие, которого владелец не давал, не приписывать.
4. Заменяет полностью: у новой `supersedes: [В-M]`, у В-M `status: superseded`. Заменяет «в части …» — оговорка в «Заменяет», у старой карточки строка «Частично заменена В-N», статус не меняется.
5. `python tools/kb.py check` → коммит. Слова владельца в старой карточке правятся только при опечатке; смена решения — новая карточка.
- Протоколы — по карточке `P-NN` на каждый `docs/research/P-<NN>-*.md` ([[research-protocols]]); задачи — `TK-NNN`; машины и страницы — `machine` / `runbook`.

## Летопись (TK-646)

Выводы, журнал, реестр экспериментов и тексты протоколов — **не карточки и не md, а БД на srv** (`/data/chron/chron.sqlite`): `python tools/chron.py add` (новый вердикт / шаг), `chron.py psec add` (раздел протокола; `--prereg` — до счёта, неизменяем), `find` / `show` / `links` / `check`. Сайт — тот же :8091, раздел http://5.231.25.224:8091/chron/; карточки kb — связанный индекс летописи (`chron.py sync-kb`, делает `tools/kb_deploy.sh`), ссылки из записей на карточки (`TK-NNN`, `В-NNN`, `P-NN`…) проверяет `chron.py check`. Карточка задачи по-прежнему держит «Состояние» и «Дальше»; вывод — запись летописи со ссылкой на карточку. Порядок — [[docs/research/CHRONICLE.md]].
