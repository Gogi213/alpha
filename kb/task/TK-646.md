**Алгоритм:** варианты — (а) SQLite центральная на srv, запись по ssh; (б) один JSONL в git; (в) JSONL «файл на запись» в git + индекс; полнотекст — FTS5 unicode61 (префикс) против trigram; kb — в той же БД против связанного индекса. Замер — история: 21 из 23 слияний master, трогавших `JOURNAL.md` / `EXPERIMENTS.md` / `P-42`, дали конфликт; 8 параллельных веток: один JSONL — 7/8 конфликтов, файл на запись — 0/8, но запись не видна до слияния и неизменяемость держит только хук; SQLite на srv, 16 писателей × 50: 800 из 800 строк, 0,4 мс на запись; вызов с ПК по ssh ≈ 1,2 с. Поиск, 5 запросов (пробо, титров, n24, 13.28.1, заморож): trigram = подстрока 5/5, unicode61 — 2/5 (титров 38 из 51, n24 18 из 34), цена trigram 11,4 против 4,3 МБ и 1,9 против 1,1 мс. kb: карточки правятся после создания (443 правки на 428 новых), 0 из 7 слияний kb с конфликтом. Выбрано — (а) + trigram + kb связанным индексом (`kb_node`, `sync-kb`), потому что только центральная БД даёт ноль конфликтов и потерь и запись видна всем сразу, неизменяемость — триггерами БД, trigram — единственный, совпавший с подстрокой; карточки kb — изменяемые документы без конфликтов в git, переносить их в append-only БД незачем.

Отступления: (1) перенесённым записям вердикт в поле не размечен (кроме дословного «ОПИСАТЕЛЬНО» — 7), $ / сделки / Шарп — в тексте, не в полях: разметка = новые записи-исправления, вне задачи; (2) первый перенос на srv взял CRLF рабочей копии (autocrlf) — БД пересобрана с нуля (своих записей в ней не было), испорченная — `/data/chron/bad/`; (3) `kb-page` перезапускался 3 раза, ≈ 2 мин недоступности 8091 при первом запуске.
