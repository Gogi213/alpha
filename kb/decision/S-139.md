## Оглавление

Модель ролей и защита от перерасхода (2026-09-27 ~22:10 по `date`, владелец).

## Запись реестра

**В-139. Модель ролей и защита от перерасхода (2026-09-27 ~22:10 по `date`, владелец).** Роли под диспетчером шли на
пользовательской настройке по умолчанию `fable[1m]` / xhigh (пилот Судьи $6,8); владелец — «все роли модель опус 55; судья
xhigh; инженер high; исследователь high» → диспетчер задаёт `--model claude-opus-5-5 --effort …` явно. Защита (владелец:
«150 в сутки это не защита от дрейна; нужна защита от быстрого оверспенда и оверспенда несопоставимого с задачей»):
бюджет задачи `budget_usd` по размеру (S $3 / M $10 / L $25, ставит CEO; исчерпан → стоп, решение CEO, крупное —
владельцу); потолок запуска `--max-budget-usd` = min(остаток, $8); скорость ≤ $15 за скользящий час по всем ролям;
холостой ход (> 50 % бюджета без записи/смены статуса) → стоп; прежние: 2 роли одновременно, 6 запусков задачи в час,
40 мин на запуск, $150/сут. Суммы — оценка по ценам API (доля лимита подписки). Упоминания `@роль` в инструкциях CEO
будят роль сразу — писать их только когда роль нужна сейчас.

## Дополнение

**В-139, дополнение (2026-09-27 ~22:15, владелец).** «запрещено добивать задачи до их бюджетов раздувая токены». Бюджет —
стоп-линия, а не норма: роли его не видят (он только в state диспетчера), в промпте — «трать минимум, траты каждого
запуска записываются и сравниваются с результатом»; задача, закрытая на ≥ 80 % бюджета, — сигнал CEO «проверить
соразмерность»; CEO просматривает траты против результата.
