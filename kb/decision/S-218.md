## Оглавление

рантаймов ≤ 3, сколько нужно — по факту; каждый сверх одного оправдан необходимостью (поддержка дороже) (2026-10-10, владелец).

## Запись реестра

**В-218. Число рантаймов — минимально необходимое, не больше трёх (2026-10-10 ~06:20, владелец).**
«как закончишь ревьюшки приступай к планированию рефакторинга рантаймов. нужно чтобы было их <=3. По факту сам разберись
сколько необходимо. чем больше рантаймов тем больше саппорта на них». Порядок: план (TK-123) стартует после закрытия
последней дыры ревью (TK-137). Три рантайма В-214 — потолок, а не цель: каждый рантайм сверх одного оправдывается
измеренной необходимостью (разные требования, которые один рантайм не закрывает без потерь), иначе — слияние.
