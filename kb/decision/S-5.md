## Запись реестра

**Возражение.** Ни один HTTP-клиент не создаётся с таймаутом: `reqwest::Client::new()` в `rest.rs:175`, `probe.rs:318`, `clock.rs:604`, а у `reqwest` общего таймаута по умолчанию нет. В `clock.rs` таймауты выставлены на NTP-сокет, но не на HTTP для `serverTime`. Процесс, который по плану работает неделями без присмотра, вправе повиснуть на любом из трёх

**Ответ плана.** Таймаут на всех трёх — часть done-condition шага **0.7**, проверяется грепом по исходнику тем же приёмом, что граница модулей в 1.1

Оговорка, не ставшая отдельным пунктом | Греп границы модулей реализован **пофайлово** (`levels.rs:689`), а не по дереву, как обещал черновик 2 архитектуры. На `markout.rs`, `watch.rs` и `export.rs`, которых ещё нет, гарантия сама не распространится | Строка добавлена в раздел «Что это меняет в `PLAN.md`» архитектуры; каждый новый файл ядра обязан унести такой же тест, пока не написан тест по дереву
