Вынесено из `CLAUDE.md` 2026-09-12 (В-39, экономия контекста): здесь полный текст, в `CLAUDE.md` — сжатая версия и указатель сюда. Правит тот же таск, что меняет команду.

## Какие команды дают какой артефакт

| Команда | Артефакт |
|---|---|
| `lob pick --window-secs --h3-k [--top N]` | `instruments.csv` в корне (**только пул** — `--top` строк, по умолчанию десять, В-35/В-50, ранг по обороту) + `docs/plan/candidates.csv` (все кандидаты, причина по каждому). Оба несут колонку `depth_check` (`ok`/`below_floor`/`not_measured`): глубина — проверка, не критерий отбора (В-35). Замер глубины держит **по соединению на инструмент** одновременно: 50 инструментов — 50 соединений на окно (живой прогон 2026-09-13: пул 50 замерен, само `lob session` потом держит все 50 в **одном** соединении); `--top 0` — ошибка. Боевая заморозка пула требует `--window-secs 3600` (час), иначе оба CSV помечаются `# debug` и для отбора не годятся |
| `lob session --pool-instruments --root --minutes` (5..15) **или** `--pilot-minutes` (16..360, режим пилота §11; `session.json.pilot`) **или** `--always-on` (В-34: без дедлайна; остановка — файл `<root>/stop`, Ctrl+C или SIGTERM (`systemctl stop`/`restart`, перезагрузка; A8.2) — все три одним путём, `closed=true`; новые сутки UTC — новая часть с синтетическим снапшотом; `session.json` на старте / раз в час / на ротации / на остановке (`closed`), `samples` RSS/CPU, `reconnects`/`resyncs`/`frames_failed`/`bytes_written`/`connect_failed`/`subscribe_failed`); `debug = duration_s < 3600`; несколько сессий в сутки — части `-p2`, `-p3`… (`session.json.binlog_files`); **пул на ходу** (T34, R89): дописать строку в `<root>/instruments.csv` (формат `lob pick`) — на ближайшем тике (≤ `FRAME_LOSS_WINDOW_SECS` = 10 с) символ получает свой `<SYMBOL>-<день>.binlog` (часть — следующая свободная), своё соединение (`feed::DynamicPool::add`, живые сокеты не трогаются), строку stderr `session: добавлен …` и место в `session.json.instruments`/`binlog_files`; повтор строки — не дубликат; битая строка/файл — только stderr, повтор на следующем изменении `mtime`; **снятие и замена на ходу** (A8.1, 2026-09-17): строку убрали — на ближайшем тике символ снят с записи (`feed::DynamicPool::remove`: файлы **обоих** потоков сброшены и закрыты, его соединение остановлено; соседи по тому же сокету переезжают в новый сокет **с теми же индексами**, у них шов `gaps.csv`, как у переподключения), строка stderr `session: снят …` и событие в `session.json.pool_removals` (`symbol`, `ts_utc`); вернувшийся в файл символ — **новый** индекс и новая часть (`-pN`), история снятого остаётся в `instruments`/`binlog_files`, а `instruments` не дублирует имя; индексы не переиспользуются, `bytes_written` снятого из сводки не пропадают. Применяется только **дописанный** файл: разобрался и кончается переводом строки (пустой/оборванный — прежний состав, строка stderr), поэтому пул пиши атомарно (`cp <root>/instruments.csv.new && mv …`), а не переписывай по месту; файл, обрезанный ровно по границе строки, от целого неотличим — метки поколения пула нет | каталог сессии: `<SYMBOL>-<день UTC>.binlog` на инструмент, `gaps.csv`, `clock.csv`, `session.json` — это имя читают все остальные команды (`commands::lob::session_binlog_for`) |
| `lob record --symbol --root` | запись **одного** инструмента (legacy-путь, не пул) |
| `lob verify --symbol --root` | `<root>/verify-<SYMBOL>.status` — ровно `ok`/`fail`, маркер сверки сессии, который читают `profiles`/`watch` (без `ok` сутки не читаются, fail-closed); сверка по всем частям символа (`session_binlog_for`), строка stdout на часть с сутками, и в строке же — состав нарушений (`block`/`rpi`/`in_spread`/`adj1`/`far`/`stale20`/`stale100`). **Вердикт (В-56 + В-59):** целостность — ровно ноль (`gaps`, инварианты книги) **и ноль потерь целостности в `gaps.csv`** этого символа в том же каталоге (`write_failed`, `book_invariant`); **швы покрытия** (`sequence_gap` — переподключение, `parse_error`, `connect_failed`, `subscribe_failed` — A8.3: биржа отказала в подписке на топик) сутки не роняют, а считаются; `step_change` — не потеря (В-59, 2026-09-17: разрыв `u` в бинлоге не виден — поля `u` там нет, — поэтому его единственный след — журнал потерь; в строке вердикта печатается `gaps_csv=<n> seams=<n> losses=<n> step_changes=<n>`), тест 3 «цена ни разу не держалась» — **доля меньше 0.1 % сделок** (план §11; сравнение целочисленное `violations * 1000 < trades`, ровно 0.1 % — уже `fail`). До В-56 вердикт рубил на любом ненулевом счётчике, и 14 монет из 100 (сутки 09-15) выпадали из анализа молча; поимённые числа — `docs/findings/hft-underground-2026-09-16.md` §12e. Маркер пишет одна функция `commands::lob::verify::verify_and_mark` — ею же `lob pilot`. `verify.csv` — сайдкар записи (`bybit::verify_sidecar`), не эта команда |
| `lob archive --path <файл> [--level 19] [--out <файл>] [--delete-original]` | сутки целиком → контейнер `*.binlog.zst` (T46): один zstd-поток над заголовком v3 и телами кадров; **обязательная** сверка round-trip (читаются и исходник, и контейнер **с диска**) — оригинал не трогается, пока она не сошлась; удаление — только по флагу, только при маркере `verify-<SYMBOL>.status == ok` в каталоге оригинала и только если часть закрыта (A1/V8: `session.json` с `closed = false` → отказ, `unlink` открытого файла терял бы дописанное). Замер: 92.3 % от оригинала, `docs/findings/archive-compression-2026-09-15.md`; только для v3 (v2 — сперва `binlog-stats --rewrite-out`) |
| `lob binlog-stats --path <файл> [--reencode] [--rewrite-out <файл>]` | **только чтение** входа (T43/В-48, T44/В-49): версия формата из заголовка, записи, кадры, **группы-сообщения** (сколько записей на сообщение биржи), `ev` по типам, блочные сделки, `local_ts ≠ exch_ts`; для файла версии 2 — счётчики мёртвых полей `order_id`/`ival`/`fval` (ими доказано «0 % ненулевых» и на них стоит v3). `--reencode` — замер A/B формата на **тех же** записях: M1 байт/запись v2 против v3, M1b кадр-на-сообщение, M1i симуляция «уровень индексом», **M1e «`ev` таблицей на кадр» (−2.1…−4.7 %, отклонён порогом 5 %), M1z уровни zstd 3 и 6 (0.9–2.8 %, уровень 3 хуже уровня 1)**, M2 экстраполяция ×10, M3 нс/запись (кодирование+zstd и чтение), M4 round-trip и совпадение перекодировки v2 с файлом на диске; считается только по файлу версии 2 (иначе отказ). `--rewrite-out <файл>` — переписать v2-файл в v3 (тот же заголовок, те же границы кадров) — ворота M5c: `verify`/`levels` на v3 обязаны дать те же артефакты, что на v2 (сошлись побайтово). Пороги и числа — тикеты 43/44, `docs/findings/binlog-v3-2026-09-13.md` |
| `lob levels --h3-mode floor\|percentile [--h3-k <f64>]` (`--h3-k`: пол = `floor(k × median_trade_lots)` из `instruments.csv` на лету; только с `floor`) | `levels-<SYMBOL>.csv` — шесть признаков жизни уровня |

Тот же реплей, что `levels`/`markout`; смерти не менялись; дашборд/профили/шортлист касаний не читают (после предрегистрации) |

## Грабли

- `--h3-mode floor|percentile` обязателен, умолчания нет — у `levels`, `markout`,
  `watch`, `profiles`, `shortlist` (проверено `--help` каждой); `pilot` этот флаг
  не берёт — он гоняет `floor` и `percentile` сам, оба режима за один прогон.
  `floor` берёт `h3_lots` из `instruments.csv`, `percentile` требует часа прогрева
  (`--warmup-ms`, умолчание 3 600 000 — на 5-минутной записи даёт `levels=0`,
  это прогрев, не баг; для отладки `--warmup-ms 0`)

  правилам §2 (BTC/ETH, некрипта, < 30 суток) прошли хотя бы десять кандидатов, —

  реплей на инструмент) и берёт наименьшее `k`, при котором медианный инструмент

  2026-09-11: `k` не определим** — `eaten` на медианном < 5 % при всех `k`; G0 edge RED

  файле выглядел бы полными сутками. Порча (`Corrupt`, `MissingSnapshot`, `TruncatedHeader`) —

   (`cp target/release/alpha data/always-on/alpha-collector` — как локально, чтобы не держать
   `target/`).
2. **Файлы:** `<root>/instruments.csv` (боевой пул из `lob pick` или копией), сам `<root>`.
   Старт удаляет старый `<root>/stop`, если он остался с прошлой остановки.
3. **Запуск:** `./alpha-collector lob session --pool-instruments <root>/instruments.csv
   --root <root> --always-on`. Штатная остановка — файл `<root>/stop`, Ctrl+C из настоящей консоли
   или **SIGTERM** (`systemctl stop`/`restart`, перезагрузка машины) — A8.2, 2026-09-18: все три идут
   одним путём (на ближайшем тике сброс писателей, `session.json closed=true`). До бинарника с A8.2
   (задеплоен `3614321`) `systemctl stop` рвёт запись на границе кадра — данные целы, `closed` не
   выставляется; поэтому остановка — файлом `stop`.
4. **systemd**, `Restart=always`: рестарт **начинает новую часть** суток (файл всегда на границе
   кадра, потерь нет, но появляется лишний `<SYM>-<day>-pN.binlog`); `--minutes` рядом с
   `--always-on` — взаимоисключающие. **SIGTERM (A8.2):** `systemctl stop`/`restart` и `kill` по
   умолчанию закрывают запись штатно (`closed=true`) — тем же путём, что файл `stop`; на Windows
   сигнала нет (`cfg(unix)`), там Ctrl+C или файл `stop`.
5. **Проверка после первого старта:** `binlog-stats --path <root>/<SYM>-<day>.binlog` печатает
   «формат v3 (текущая)»; `lob verify --symbol <SYM> --root <root>` → `verify-<SYM>.status == ok`;
   `session.json.samples` обязан давать вменяемые CPU/RSS (Linux-ветка — `/proc/self/stat`,
   `CLK_TCK = 100` — факт ABI x86_64, единственное допущение о Linux).
6. **Диск — вручную (решение владельца 2026-09-17).** Сторожа свободного места и порогов нет:
   местом на диске управляет владелец, автоматики и предупреждений в коде не заводим. Опорные
   числа для решения: боевой пул 100 монет пишет **≈ 6.5 ГБ/сутки** (аудит
   `collector-audit-2026-09-17.md` §8), свободного места 38 ГБ (≈ 22.09).
   **Регламент закрытых суток:** (1) после UTC-полуночи `lob verify --symbol <SYM> --root <root>`
   по каждой монете — маркеры `verify-<SYM>.status` ложатся в боевой корень; (2) закрытые сутки →
   `lob archive --path <root>/<SYM>-<day>.binlog --level 19` (контейнер `<SYM>-<day>.binlog.zst`,
   замер — 92.3 % от оригинала); (3) только после `verify == ok` и сверки round-trip —
   `--delete-original`.
   **Открытую часть `lob archive` не трогает:** если `session.json` в каталоге имеет
   `closed = false`, команда отказывает (и архивировать, и удалять) для последней части символа
   этой сессии — `unlink` открытого файла потерял бы всё, что допишется после (A1, аудит V8). Это
   страховка от ошибки в ручном режиме, а не сторож.
   Резать файл по кадру нельзя — сутки читаются с первого байта и держат синтетический снапшот
   первым кадром.
7. **Присмотр:** `session.json.updated_utc` (не отстал больше часа), `reconnects`/`resyncs`
   (сеть), `frames_failed` (диск). Осторожно: `bytes_written` считает **только текущие части**
   файлов (`session.rs:660`), а не всю сессию, — объём берите с диска (`ls -l <root>/*.binlog`),
   а не из счётчика (на олвейс-оне 20260912T201737Z счётчик показал 827.3 МБ против 928.2 МБ на
   диске; тикет 43, `docs/findings/binlog-v3-2026-09-13.md`).
8. **Первый серверный день** закрывается тем же, чем локальный: `lob binlog-stats` на файл
   (версия, группы, байт/запись), `lob verify`, а дальше штатные `levels`/`markout`/`profiles`.
9. **`verify` закрытых суток — таймером (A2, 2026-09-17).** `alpha-verify.timer`
   (`tools/systemd/alpha-verify.timer`) дёргает `alpha-verify.service` → `/opt/alpha/tools/verify-day.sh`
   каждый день в **00:20 UTC** (ротация суток — в 00:00 UTC, кадр ложится на диск не позже 10 с;
   20 минут — запас, `Persistent=true` догоняет пропущенный пуск). Скрипт берёт пул
   `/opt/alpha/root/instruments.csv`, раскладывает **вчерашние** части в
   `/opt/alpha/verify/<день>/` hardlink'ами (места не занимают) и гоняет `lob verify` по каждой
   монете оттуда — иначе вердикт смешал бы все сутки, которые лежат в одном корне, ведь маркер
   один на символ. Маркеры `verify-<SYM>.status` копируются в боевой корень (там их ищут читатели),
   сводка — строка на часть, строка на символ и итог `ok/fail/missing` в `/opt/alpha/verify/<день>.log`.
   В рабочий каталог копируются и **строки `gaps.csv` этого дня** (V4, 2026-09-17): `verify` смотрит
   журнал потерь того каталога, который сверяет, а разрыв `u` в бинлоге не виден — поля `u` там нет.
   Без этого копирования потери целостности проходили бы `ok`; швы покрытия (переподключения) сутки
   не роняют (В-59) — в строке вердикта `gaps_csv=<n> seams=<n> losses=<n> step_changes=<n>`.
   Ручной прогон (догон суток, перепроверка): `sudo /opt/alpha/tools/verify-day.sh 2026-09-16`
   (аргумент — сутки `YYYY-MM-DD` по UTC; без аргумента — вчера). Сверяет **быстрый поток**
   (`root/*.binlog`); `deep/` (`.200`) не сверяется — у него свой файл и своя глубина (T45).
   Код возврата — 0 и при `fail`: `fail` это вердикт о данных, а не сбой службы; настоящий сбой
   виден строкой `verify: day=...` и отсутствием маркеров. Бинарник для сверки — `/opt/alpha/alpha-verify`
   (копия `~/alpha-build/target/release/alpha`), тот же, что чинит/архивирует руками по ранбуку; сам
   коллектор живёт своим бинарником `/opt/alpha/alpha-collector`.
