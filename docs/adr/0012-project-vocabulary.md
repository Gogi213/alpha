# Словарь проекта: таск ≠ задача, профиль ≠ испытание, сессия ≠ сутки-кластер, debug ≠ данные

*Источник: спека и манифест целиком; иллюстрация — манифест D03*

## Контекст

В документах проекта несколько пар терминов легко перепутать, и путаница уже
случалась на практике: таск 06 буквально писал «строится крест семи осей» —
формулировку тикета исполнителя, которую ревью впоследствии отличило от
решения плана (см. ADR 0004, D03).

## Решение

Проект различает четыре пары терминов и не позволяет им означать одно и то
же:

- **таск** — единица нарезки работы исполнителю; может содержать ошибку
  нарезки и не имеет полномочий менять решения плана. **Задача** —
  `BUSINESS-TASK.md`, постановка владельца, документ не редактируется.
- **профиль** — точка отчёта, сочетание корзин по семи осям. **Испытание** —
  единица счёта для DSR; не каждый профиль — испытание: непригодная пара
  (инструмент, корзина) не считается и не печатается вовсе.
- **сессия** — единица записи, 5–15 минут. **Сутки-кластер** — единица
  статистической кластеризации (`G`); сессия сутки не заменяет и не
  агрегируется в них по умолчанию.
- **`debug`** — пометка прогона короче полного окна (в первую очередь
  ≤ 5 минут против живой биржи), означающая, что результат не является
  данными ни для одного гейта, вердикта или предрегистрации.

## Почему

Рассмотрели и отвергли использование одного слова на обе роли в каждой
паре — отвергнуто по документированным инцидентам, а не из абстрактной
любви к терминологии:

- смешение «таска» с «решением» едва не привело к тому, что полный
  семиосевой крест вошёл в предрегистрацию как будто бы принятое решение,
  а не текст ошибочной нарезки (D03);
- смешение «профиля» с «испытанием» завысило бы поправку DSR (посчитав
  непригодную ячейку испытанием) или скрыло бы нулевой результат как
  несуществующий (В-18, В-23);
- смешение сессии с сутками сделало бы дисциплину кластеризации
  (`G_MIN` считается по суткам, не по сессиям) непроверяемой на глаз;
- не будь `debug` явной пометкой, пятиминутная отладочная разведка
  (`RECON-2026-09-11.md`) рисковала бы быть принятой за боевые данные, из
  которых уже сейчас пришлось бы делать выводы о выборе `H3`.

## Последствия

Каждый новый документ и тикет обязан использовать эти четыре пары строго в
указанном значении. Ревью обязано ловить их смешение как содержательную
ошибку (как это уже произошло с таском 06), а не как стилистическую
придирку — то есть словарь становится частью критерия приёмки для текста
тасков и отчётов, а не просто справочником для чтения.
