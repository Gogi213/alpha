# Один код на обе фазы: `Feed` + `on_event<MD, B: Bot<MD>>`

*Источник: спека, «Решение», §3; PLAN.md D-ПРОДУКТ*

## Контекст

Владелец хочет не «сигнал», а методику, которая, если подтвердится, «торгует
по ней без переписывания и без издержек во времени» — даже если плотности
живут секунды. На момент решения не было зафиксировано, останется ли фаза 1
(запись, разметка, бэктест) отдельным исследовательским кодом, а живая
торговля — будущей отдельной системой.

## Решение

Одна кодовая база обслуживает обе фазы. Стратегия — одна функция сигнатуры
`fn on_event<MD, B: Bot<MD>>`, без правок идущая и в `Backtest`, и в будущий
`LiveBot`. `Feed` — итератор (`next_event()`): реплей бинлога и живой сокет
взаимозаменяемы, без ветки `if live` где бы то ни было в коде стратегии.
Фаза 2 добавляет только коннектор поверх той же функции.

## Почему

Рассмотрели и отвергли раздельные кодовые базы — черновой бэктест-прототип на
фазу 1 и отдельный боевой движок, написанный только если методика
подтвердится. Отвергнуто прямым указанием владельца: переписывание после
подтверждения стоит времени именно тогда, когда система обязана быть «супер
быстрой сразу», а не после второго прохода.

Рассмотрели и отвергли частично общий код с условной веткой на источник
события (`if live { сокет } else { бинлог }`) внутри самой стратегии или
цикла обработки. Отвергнуто через границу модуля `feed/`: он обязан прятать,
откуда пришло событие, а не выставлять эту развилку наружу — иначе горячий
путь начинает ветвиться по признаку, не имеющему отношения к торговому
решению.

## Последствия

Единственный способ формально проверить, что фаза 2 получит тот же код —
тест `Bot<MD>` на `Backtest`, и это один из всего шести допустимых швов для
тестирования во всём проекте. Архитектурные ограничения горячего пути (A2–A6,
семь запретов) обязаны соблюдаться уже в фазе 1 — исследовательский код,
которым ещё никто не торгует, нельзя писать «как удобно для бэктеста»: любое
такое удобство, несовместимое с живым режимом, придётся либо сразу
отвергать, либо потом переписывать — то есть повторить единственную
отвергнутую альтернативу задним числом.
