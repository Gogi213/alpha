# D03 — структура испытаний: маргиналы плюс один крест, не полный крест

*Источник: манифест, раздел N, строка D03; `SETTLED.md` В-18, В-23; спека
раздел «Профиль»*

## Контекст

План предполагал (Decision 26/26а, `SETTLED.md` В-18, В-23), что число
испытаний для DSR — это маргиналы по каждой из семи осей плюс один
предрегистрированный крест инструмент × исход × расстояние, посчитанный
только по пригодным парам (инструмент, корзина). Полный крест по семи осям
даёт 5400 номинальных ячеек, а порог `n ≥ 100` на профиль требует выборки,
которой при такой сетке не будет (В-18); непригодную корзину (не помещающуюся
целиком в покрытие топ-50 инструмента) нельзя ни считать испытанием, ни
тихо занулять (В-23).

## Решение (что доказал код)

Таск 06 всё же построил полный семиосевой крест — 8129 испытаний вместо
предрегистрированных маргиналов плюс одного креста. Ревью (ось
«Предрегистрация») это поймало: формулировка таска 06 «строится крест семи
осей» была ошибкой нарезки задачи исполнителю, а не решением, отменяющим
В-18/В-23. Структура испытаний остаётся прежней: маргиналы по семи осям + один
предрегистрированный крест инструмент × исход × расстояние; число испытаний
для DSR — количество пригодных пар (инструмент, корзина) × исходы, плюс
маргиналы, плюс тесты на час суток.

## Почему

Рассмотрели и отвергли полный крест по семи осям дважды. Первый раз — в
В-18: 5400 ячеек при пороге `n ≥ 100` неисполнимы физически. Второй раз —
в D03: даже когда код уже построил такой крест и текст тикета описывал это
как факт, это не признано решением, потому что нарезка задачи не имеет
полномочий переопределять предрегистрированную структуру испытаний из
плана. Сам оркестратор сначала ошибочно записал D03 в пользу креста —
и в тот же час это снял, убедившись, что расхождение с В-18 ничем не
оправдано.

## Последствия

Число испытаний для DSR обязано считаться по пригодным парам
(инструмент, корзина), а не по номинальному полному кресту — если код
когда-либо снова «по пути» посчитает лишние (в том числе непригодные)
ячейки испытаниями, поправка на множественность раздуется и легитимные
профили перестанут проходить порог. Граница между «текстом таска» и
«решением плана» отныне обязана перепроверяться явно при каждом ревью, а не
приниматься на слово формулировки тикета.
