# Проверка Судьи: план T-31 — `bounce-grid --busy-skip off` + `busy-replay.py` (`.claude/roles/journal/T-31.md` §План) (2026-09-27)

**Итог: принято при условиях; главное — гейт пути фильтра (д).** Гейт (б) «фильтр — всё» доказывает только, что
реплей повторяет занятость движка без фильтра. Задача T-31 — фильтр **до** занятости, и её надо сверить с движком,
который фильтрует сам.

## Ответы

1. **(б) на главном варианте достаточно для логики занятости.** Перекрытий там много: август — 3 588 сигналов,
   523 исполнения, 2 657 «занято»; сентябрь — 564 / 145 / 367 и 167 / 49 / 96 (`forms.csv` `b5/titrc-u500r`, посчитал
   сам). Набор с большим числом перекрытий (`t-bid-age-45`: 29 134 / 2 578 / 23 621 в августе) — по желанию. Набор
   T-29 `$100k + 60 мин` для (б) слабее: сигналов меньше, перекрытий меньше. Но он нужен для (д).
2. **`forms.csv` при `off` с эталоном не сравнивать — согласен.** Его счётчики по смыслу другие. `forms.csv` при `on`
   покрыт гейтом (а).

## Условия

1. **(д) Путь фильтра = фильтр движка.** Прогон `off` на наборе главного варианта (надмножество), затем `busy-replay`
   с фильтром «возраст ≥ 60 мин и номинал ≥ $100k». Результат обязан совпасть побайтно (`rounds.csv` без шапки) с
   точным прогоном `b5/t29-a60u100k` (набор `age=3600,usd_min=100000`), август и сентябрь. Затем `portfolio-sim` — до
   цента. Это проверка того, ради чего T-31. Если бинарник новый — сначала (а), чтобы точный прогон 7bdf9a4 оставался
   эталоном.
2. **Сырое `off` нельзя подать вместо обычного прогона.** `rounds.csv`/`forms.csv` при `off` несут `# busy_skip=off`
   (по плану). `bounce-verdict` на таком каталоге отказывает. `portfolio-sim` без реплея отказывает или громко
   предупреждает: его «занята» — не правило движка. Выход `busy-replay` несёт свою метку (`# busy_replay=<фильтр,
   коммит>`).
3. **Переход через полночь.** Реплей считает занятость по символ-суткам. Если у движка при `on` позиция, перенесённая
   из суток D (В-94), держит монету в D+1, гейт (б) на полных месяцах это поймает. Отдельно проверить сутки с
   переносом в тесте (г).
4. **Цена.** При `off` считаются круги всех сигналов — в августе ≈ 7× больше, чем исполнений. Сначала одни сутки —
   время и пик памяти, потом месяц. `bounce-grid` ≤ 2 процессов (устав).
5. Тесты (г) — как в плане, плюс: фильтр, отбросивший сигнал, освобождает монету, и следующий сигнал получает круг,
   которого при `on` не было.
