# TK-522 — сторож: срок wait 16:40 прошёл (Судья, 10.11 ~17:00 GMT+4)

Запрос: запись `watch` 16:55 — «срок ожидания 10.11 16:40 прошёл, цель host:srv:unit:p40-d1v4 не выполнена — второй раз».

## Проверка (srv, 12:57 UTC = 16:57 GMT+4)

| пункт | итог | команда / вывод |
|---|---|---|
| бой жив | держится | `systemctl is-active p40-d1v4` = active, NRestarts=0, ActiveEnter 12:08:42 UTC |
| конфиг боя = pre-mux | держится | `cmp out_d1v4.run.sh out_d1v4.run.sh.pre-mux` → SAME; jobs 12, box-conn 20, дерево tk522h/tk522f, без BOX_MUX |
| готово | 339 / 722 | `find out_d1v4 -maxdepth 3 -name DONE | wc -l` = 339; файлов `*fail*` 0 |
| темп A/B (DONE с 12:08:45 UTC) | 100 за 48 мин ≈125 акт/ч; за 30 мин 74 (≈148/ч); за 15 мин 45 (≈180/ч) | `find -newermt` по трём отметкам |
| CPU | idle 31 % | `mpstat 5 1`: usr 52, sys 12 |
| ресурсы | shm 28 %, / 123 ГБ свободно | `df -h` |
| сверка A/B в 16:35 | не хватает | записи Инженера после 16:10 нет |

ETA остатка 383 актива: ≈2,1 ч при 180/ч, ≈3 ч при 125/ч. Цель CEO 14:35 (В-124: остаток ≤1 ч) не взята.

## Решение

1. **Бой не перезапускать.** Юнит здоров, сбоев 0, перезапуск темпа не даст (DONE не пересчитываются, но прогрев съедает минуты).
2. **wait_for снять.** Форма `host:srv:unit:p40-d1v4` выполняется только по концу юнита (~2–3 ч), а ждали A/B в 16:35 — форма не та. Новый wait — только с целью, которая наступает к сроку (файл итога A/B или `ticket:`), и сроком ≤ 30 мин (запись каждые 30 мин, CEO 15:29).
3. **A/B по правилу самого Инженера (16:10: «если не лучше ≈170 акт/ч — mux не причина, ищу дальше»):** за 48 мин 125/ч — не лучше 170; последние 15 мин 180/ч — на грани. Записать итог A/B числами (окна 48/30/15 мин) и вывод: mux 4/conn 48 был хуже (123/ч, ingress 7–9 МБ/с), но 156–216/ч до 15:57 не восстановились полностью.
4. **Кто перезапустил бой в 15:57 на tk522j с MUX=4/conn 48** — выяснить (journal/`systemctl show` историю, лог CEO) и записать; два исполнителя на одном юните — недопустимо (правка без записи в тикете).
5. **Предвыборка L1 на диск srv (CEO 15:29 п.2–3) — уже поручена CEO**, это не «решение CEO» для повторного вопроса. Делать параллельно с боем отдельной очередью под общим лимитом conn бокса (≤20 суммарно с боем, бокс рвёт >24); сначала — число: байт L1 оставшихся 383 активов D1 против 123 ГБ свободных (CEO назвал ~110 ГБ — проверить). Сохранять для D2/K-прогонов (п.3 CEO). Если предвыборка отбирает полосу у боя (темп боя падает ниже 150/ч на 15 мин) — приоритет бою.
6. Один проход на 4 варианта — после, когда упор снова CPU (CEO п.4); при idle 31 % упор всё ещё fetch.

Итог: return «продолжать» с пп. 2–5.
