# TK-353 — «реальная стена в полосе» для C3 (Судья, 22.10 ~19:45)

Вопрос Инженера (19:32): гейт пар on/off (calc 1022170733912, XRP×5 сут, 855 событий) — 0 контролей; `wall_in_band`
режет 174 539 из 177 583 кандидатов (порог = `detector_floor_usd` 10 000, ±1 тик, всё окно [τ', t']).
Решение по В-53, без владельца; внесено в `docs/research/G013-scope.json` → `assigned.C3.wall_in_band`.

| параметр | решение | на чём |
|---|---|---|
| порог «реальной стены» | **не пол детектора 10k, а определение стены своей популяции**: A_B — `usd_min` **И** сила/поток набора B1 (из конфигурации правила, тот же код фильтра, что у B1); S\* — rank q90 по монете. Возраст — не условие (стена любого возраста в полосе загрязняет). | R4.1 п.2 «≥ `usd_min`» + R2.2/стр. 323 «определение стены `usd_min`/сила»; стр. 338 — определение замораживается пакетом с B1. Пол 10k на XRP = почти любой уровень книги: условие пусто по построению, это ошибка чтения, а не свойство данных. |
| полоса | ±1 тик — без изменений | R4.1 п.2 дословно |
| окно | каждый кадр [τ', t'] — без изменений | R4.1 п.2 дословно; «хвост до t'» — новое число, не вводим |

| если доля контролей и после этого ≈ 0 | **не ослаблять** — печатать долю по монетам и режимам (R4.1 п.7, это и есть «отгон»); вопрос о пороге доли «A_B не определён» — Судье с числами 10 монет × неделя | R4.1 п.7, проверка G1 «доля ≠ 0 на ≈10 монетах» |
