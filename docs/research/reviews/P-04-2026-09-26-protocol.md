# Проверка Судьи: протокол П-04 «стоп на уровень снятой стены» (`docs/research/P-04-wall-level-stop.md`, 55ad276) — до владельца (2026-09-26)

**Итог: вернуть — шесть пунктов; три главных.** Первое: правило «отвергнут» путает «не доказано, что не хуже» с
«хуже». Второе: не проверено, достижимо ли «не хуже −$10» при шуме парной разницы — это урок порога 30. Третье:
польза по просадке меряется одной реализацией, а это стоит в отказах навыка. Вопрос, механизм, данные, семья m = 3 и
заморозка — годятся.

## Вернуть

1. **Правило «отвергнут» (§10).** Сейчас: «нижняя граница < −$X в любом месяце → отвергнут». При широком интервале
   это «не доказали», а не «хуже», и шум пометит режим «не повторять». Надо так:
   - **отвергнут** — верхняя граница двустороннего интервала (уровень 1 − 0,05/3) Δ$ < 0 в любом месяце (значимо хуже
     базы) или польза не выполнена в обоих месяцах (п. 3);
   - **не ясно** — нижняя граница < −$X, но значимого вреда нет.
2. **Достижимость до «ок» владельца (§8).** До утверждения X нужна оценка шума парной разницы Δ$ за месяц на
   близком аналоге: суточные пары E20/E21 (`gone50/90 be`, те же сигналы, прогоны есть на Steam Deck) или пересчёт
   выхода по свечам. Записать ожидаемую ширину односторонней границы на уровне 1 − 0,05/3 в каждом месяце. Если она
   ≳ X, «не хуже −$10» не пройдёт даже при Δ = 0 — владелец утверждает X, зная это (или берёт X по ширине).
3. **Польза по просадке — не точкой (вопрос б).** `dd_pct` одной реализации — «реализованная просадка как бюджет
   риска», это в отказах навыка. Добавить парный блочный бутстреп по суткам: одни и те же выборки блоков для базы и
   режима, просадка по дневному капиталу каждой выборки, распределение Δ просадки. Условие пользы — доля выборок с
   Δ < 0 не меньше заранее записанного порога (предлагаю 0,8) в каждом месяце. `dd_pct` с минутной переоценкой и
   худшие сутки — чтение рядом.
4. **Привязка суток (§6, §9).** «По суткам закрытия» переносит деньги: ранний выход закрывает сделку днём раньше, и
   ряд суточных разностей получает искусственную отрицательную автокорреляцию. Относить сделку к суткам **входа** в
   обоих прогонах. Сделка, вошедшая 31.08 и закрытая 01.09, — августовская.
5. **Сверка базы.** Форма `none` этого прогона обязана совпасть с главным вариантом (`b5/titrc-u500r`, `rounds.csv`
   без шапки) побайтно на всех 54 сутках — иначе стоп до чтения режимов. Это заодно проверка бинарника `46b964b` на
   данных П-04.
6. **Соседи (вопрос а).** W = 50 не подогнан: в E21 гоняли и 50, и 90, и 50 было хуже, так что отбора в его пользу нет.
   B = 0 — слова владельца. Для плато нужен сосед и снизу: добавить W = 30 (+3 формы в тот же прогон). B = 10 годится.

## Повторная сдача 7558bbb (27.09) — принято при четырёх условиях; до «ок» владельца — достижимость

Внесены п. 1 (по деньгам — асимметрично), 4 (сутки входа), 5 (сверка базы побайтно до чтения), 6 (сосед W = 30),
п. 3 по форме (парный бутстреп просадки).

1. **«Отвергнут» по просадке — тоже только значимым вредом.** Сейчас «польза (доля ≥ 0,8) не выполнена в обоих
   месяцах → отвергнут» снова путает «не доказали» с «хуже». Отвергнут по просадке: доля повторов с Δ(dd_pct) < 0
   ≤ 0,05 в любом месяце, то есть просадка режима значимо больше. Доля от 0,05 до 0,8 — «не ясно».
2. **Просадка зависит от пути — блоки ≥ 7 суток** (как KPI, `reviews/kpi-days-to-new-high-2026-09-27.md`), а не
   ⌈n^{1/3}⌉ = 4 / 3. Короткие блоки режут длинные спады, и доля выходит оптимистичной. Для Δ$ (сумма суток) блок
   ⌈n^{1/3}⌉ оставить.
3. **§8а — до «ок» владельца, обе величины.** Ширина Δ$ (для X) и достижимость доли 0,8 по просадке — на аналоге
   E20/E21 (`gone50/90 be`) с блоками 7 суток. Если у аналога доля далека от 0,8 при видимой разнице просадок,
   владельцу — «ждём „не ясно“».
4. **KPI.** H = 5 суток (число владельца, В-120 доп. 3), t ≤ 19.09 для сентября — не H = 7. Сейчас KPI «по факту
   счёта» без правила — это чтение после счёта. Либо правило как в П-07 (точка и устойчивость, «суждение»), либо явное
   решение владельца: П-04 судится по деньгам и просадке, KPI — описание.
