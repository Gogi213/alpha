# TK-274 · Г-03: развилка «wall_dead у двойника» — решение Судьи 17.10.2026

**Решение: вариант (б), в рамках текущего заказа (не «второй вариант новым заказом»).**

| пункт | да/нет | на чём проверено |
|---|---|---|
| Δ g03 (alsched 1017145040346) читается | нет | tk274-p15-g03-delta-2026-10-17.csv: сделок двойников / стен янв–сен 3 / 310 = 0,010 ∉ [0,5; 2] (П-15 §5 стр. 59) |
| причина — механика, не шум | да | .md сдачи: 2026-01-05 seed 1 — двойники 15/17 отмен wall_dead (idle ≈ RTT отмены); код backtest.rs:3362 (отмена по порогу В-66 на цене входа) |
| текущий счёт соответствует §5 | нет | П-15 §5 стр. 54: «базовые фильтры B1, требующие стену, к двойнику неприменимы и не заменяются выдуманными». Отмена входа по гибели стены (порог В-66) требует стену → к двойнику неприменима. Применение её к двойнику — расхождение реализации с замороженным построением, а не «другой вариант контроля» |

**Порядок:**
1. Флаг в режиме `--level-control` (умолч. выкл): у двойника правила, читающие стену на цене входа, выключены — отмена wall_dead (В-66) и любое другое правило B1 по размеру/жизни стены (перечислить в сдаче, с файл:строка). Вход/стоп/тейк/дедлайн/ttl/В-68/prob:3 — без изменений. Стены (paired) — без изменений.
2. Тест + гейт «выкл = прежний» байт в байт (как прежний гейт g, 41 md5) и «стены paired = прежний g03» байт в байт.
3. Пересчёт только двойников (random × 5 seed) — стенная часть g03 уже посчитана, не пересчитывать (В-213); alsched по очереди, калибровка не нужна (тот же профиль).
4. Δ тем же `tk274-g03-delta.py`; сопоставимость — по месяцам, как §5. Месяц вне [0,5; 2] — «не сопоставим», печатается «мощность» (сделки, сутки). Если вне во всех месяцах и в окне — Г-03 закрыть «не сопоставим» без метки «стена — причина».
5. В отчёт — различие наборов: «у двойника нет отмены по гибели стены (§5: правила стены неприменимы)».

Метка не сильнее замера: при 13 из 98 символов B1 с тиком ≤ 1 bps и 285 из 310 сделок в январе — вывод только о монетах с двойниками и о месяцах с сопоставимым числом сделок.
