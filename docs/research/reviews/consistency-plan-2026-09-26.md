## По пунктам

**У1 (файл варианта)** — условия в `variant-file-plan-2026-09-26.md`. Строка таблицы «сравнивать без строк `#`»
противоречит условию 1 оттуда: шапку сравнивать целиком, допуская только добавленную строку имени/хеша варианта.

**У2 (реестр имён) и У3 (общие константы) — гейт.** «Те же строки флагов» надо доказать, а не предположить. Опасность
не в значениях, а в подстановке: общий `_env.sh`, выставляющий переменную безусловно, перетрёт то, что вызывающий
передаёт через окружение (`ORDER`, `SETS`, `FORM_EXIT`, `DAY_JOBS`), а переименование набора сменит каталог выхода, по
имени которого читают `portfolio-sim`, дашборд и `fresh-days`. **Гейт:**
1. Заглушка вместо бинарника (`BIN=`), которая пишет полный `argv` в файл и создаёт пустые ожидаемые выходы. Прогнать
   каждый скрипт (`nightly-grid.sh` по стадиям, `oos-frozen.sh` с и без `SETS`/`FORM_EXIT`/`ORDER`, `recompute-carry.sh`,
   `crash-stress.sh`, `titrate*.sh`, `gate-g10.sh`) до и после правки — снимки `argv` совпадают строкой. Это ловит и
   перетирание переменных, и смену имён, без часов Steam Deck.
2. Один настоящий прогон главного варианта на одних сутках — шапка `forms.csv` совпадает байт в байт.
3. Реестр — в git вместе с `study/titration-sets-v1.txt` (сейчас он только на Steam Deck, а из него собран ряд
   `b5/titrc-u500r`). Определение по каждому используемому имени — строкой то же, что сейчас; старые имена остаются
   читаемыми для старых каталогов (синонимы, а не переименование).
4. Модель очереди «по назначению» (`risk-adverse` в ночной сетке, `prob:3` в OOS и гейте) — в `_env.sh` двумя явными
   именами, не одной переменной с умолчанием.

**У4 (метрики), У5 (строка сделки и `--epoch`), У6 (правила портфеля) — порядок «до / после».** Числа меняются по
замыслу, поэтому:
1. **Сначала ошибки, потом унификация.** Пять подозрений (T-20) проверяются и, если подтвердятся, исправляются
   **отдельными** коммитами с числами до/после — раньше У4. Иначе исправление ошибки спрячется в «изменилось по
   замыслу».
2. **Канонические определения — до чисел «после».** Какая формула долларов, какая просадка (от депозита по минутам /
   по закрытым сделкам / …), к какому дню относится сделка (вход / выход), что такое «месяц» — записать с
   обоснованием в документ до пересчёта, не выбирать после, глядя, какой вариант даёт лучшие числа. Каждая замена →
   строка «было / станет / почему».
3. **Снимок «до».** Перед правкой — все числа, которые видел владелец или на которые опирается вердикт: дашборд v14
   (все KPI по периодам и вариантам), таблицы отчётов П-02 (блок B — Δ$ через `portfolio-sim`), вердикты E-реестра,
   если они на затронутых скриптах. После — та же таблица с разницей и причиной по каждой строке (какая формула).
   На проверку мне до публикации.
4. **Вердикты, стоящие на затронутых числах**, перечислить: если число вердикта меняет сторону порога — вердикт
   пересматривается явно, не молча.
5. **Сначала закрыть 14.09** — иначе в разнице «до/после» смешаются смена формулы и добавленные сутки.
6. **У5:** аддитивные колонки Rust — за флагом или новым файлом, как предложено; старые имена колонок — читаются
   общим разборщиком (синонимы), чтобы старые каталоги не пересчитывать.

**П-01 — закрепить с зависимостями (новое, важно).** Экзамен П-01 считает деньги кодом `portfolio-sim.py` и
`exit-sim.py`, а заморожен только `fresh-days.py` и `nightly-grid.sh`. У4/У6/У7 поменяют эти модули — и измерение
экзамена сменится посреди экзамена. Условие: до любой правки этих модулей закрепить для П-01 копию зависимостей
(или md5 с проверкой перед ночным прогоном и отказом при расхождении) и записать это в П-01 §5 (как поправку до точки
чтения — она не читает исходов). Переход П-01 на новый модуль — только поправкой протокола до точки чтения.

**У7 (пересчёт выхода Python — грубый фильтр)** — да: решения и числа владельцу — только по `bounce-grid`; каждый отчёт,
где есть `exit-sim.py`, печатает свою сверку с `bounce-grid` на тех же сутках (совпадение причин выхода и разница $).

**Порядок.** Предложенный (У3, У2 → У1 → У4, У5 → У6, У7) — да, с вставками: закрепление П-01 — первым (без него
нельзя трогать `portfolio-sim`/`exit-sim`); T-20 (ошибки) — до У4; 14.09 — до снимка «до».
