## Что проверено сам

  выход по цене закрытия минуты `m + 1` с `t1 = m + 2 мин`.
- п.5: `titration-read.py:74` без `and signs[0]`, `exit-titration-read.py:85` — с ним. Подтверждаю.
- п.1, п.3, п.4 — принимаю по отчёту (строки и шапки названы, перепроверены автором).
- Отчёт верно отделяет задетое от незадетого: П-02 (деньги — `lot=usd:500x1`, `--btc-kill-bps 0`), П-01 (копия

Каждое исправление — отдельный коммит, в нём числа до/после и пометка в задетом отчёте (не молча). Порядок:

2. **п.4** (дашборд: средние из `acc`) — **до пересчёта 14.09**, на тех же 22 сутках сентября, чтобы разница «до/после»

   дашборда с пометкой, что изменилось.
3. **п.3** (`family-titrate`: комиссия по типу выхода) — до/после E31/E33 «тейк» и поправка строки

4. **п.1** (`ORDER`, Инженер; можно параллельно) — прежние ряды `b5/oos-frozen`, `b5/epoch-frozen` **не дописывать**
   на новом лоте: новый лот — новый каталог, старый закрыть с пометкой «лот пула — для денег не годится». Плюс список

5. **п.2** (минута BTC) — только после выкладки `bin/p01/` и первой ночи на копии байт в байт. Исправлять

## п.4 — таблица плиток «до/после» (f4373aa, `docs/findings/t20-p4-tiles-2026-09-26.csv`)

**Итог: принято, публиковать можно** при трёх условиях ниже.

- Проверил арифметику: август главного варианта — было 110,23 / 506 = $0,218 (kpi, все строки), стало
  106,04 / 503 = $0,211 (сделки счёта); сентябрь 103,46 / 152 = $0,681 — без изменений, как в таблице. Средние теперь
  из того же множества сделок, что «Сделок» и net (`taken_stats` в `portfolio-sim.py`, по сделкам после правила «одна
  позиция на монету», потолка, стопа дня и выключателя; `net` — с учётом переоценки выключателем).
- П-01 не задет: на Steam Deck `bin/portfolio-sim.py` пока прежний (md5 `82a484…e879`), ночь уже считает П-01 из
  `bin/p01/` со сверкой md5 (`nightly-grid.sh:451-458`). Новый `portfolio-sim.py` выкладывать в `bin/` можно — в
  `bin/p01/` нельзя.

**Условия к публикации:**
1. **Вторая причина — назвать конкретно.** «Ночь дозалила свечи» — это время файлов, а не причина. Показать, какие
   сделки сентября изменили внутрисделочную оценку (по сделке: вход, выход, минимум оценки до/после) и почему — например,
   перенос позиции на 24.09 или пропуск минут в свечах на момент v14. Числа свежих суток при этом не нужны: смотреть
   только сделки со входом ≤ 23.09. Входы, выходы, n и суммы не изменились — это уже показано.
2. **На странице — «сентябрь: 22 из 23 суток (14.09 не посчитано)»** в шапке периода, пока нет пересчёта 14.09.
3. **Новая версия с пометкой, что изменилось:** «средние, ожидание, профит-фактор, время в рынке — по сделкам счёта
   (T-20 п.4); просадка «+ потолок 3» сентября — <названная причина>».

**Условие 1 выполнено (26.09):** причина названа и доказана воспроизведением — на момент v14 минутные свечи кончались
23.09 17:15 UTC, сделки после этого `minute_curve` оценивал по цене входа (нет свечи → `px = entry`); с нынешними
свечами, обрезанными на 17:15, все прежние поля совпадают с v14 в 192 из 192 строк, обрезки на 24.09 00:00 и 17:27 —
не совпадают. Сделки: DRAMUSDT (+28,5 bps) и ATOMUSDT (стоп, −210,2 bps) — у второй просадка в v14 была занижена.
**Замечание в план У4/У6:** молчаливое `px = entry` при отсутствии свечи — источник тихой ошибки; метрика должна
считать и печатать число минут без свечи по сделке и отказывать (или помечать строку), а не подставлять цену входа.

## п.3 — комиссия пересчитанного выхода (402b5a9)

**Итог: принято.** `exit-sim.simulate`: из комиссии круга вычитается нога **исходного** выхода (мейкер, если исходный
выход — лимитный тейк, иначе тейкер) и добавляется нога **нового** (лимитный тейк — мейкер 1,26 bps, прочие — тейкер
3,15 bps; значения совпадают с `costs.rs::leg_fee_bps` — 1,4 / 3,5 bps с возвратом 10 %). Для рыночных выходов
пересчёт побайтно прежний. До/после сделаны правильно — старый и новый `exit-sim` на одних нынешних данных (свечи
дозалиты; сравнивать с таблицей 25.09 было бы смешением двух причин). Меняются только строки «тейк 1,75 %» (+$1…+$3 на
семейство); E33 K = 3 «август → сентябрь» +$41 → +$38 — у семейства 3 на подборе выбор сменился трейл → тейк, это
ещё одно свидетельство хрупкости подбора, вывод E33 «не держится» не меняется. П-01 не задет (`bin/p01/` — копия).
Замечание для У3/У4: константы комиссий теперь продублированы в Python — в общий модуль вместе с прочими.
