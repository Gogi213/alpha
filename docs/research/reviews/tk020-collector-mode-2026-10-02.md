# Судья — TK-020 шаг 4: коллектор пишет сутки → перенос на ящик, гейт плана (2026-10-02)

Проверено: `docs/findings/tk020-collector-mode-plan-2026-10-02.md`.

**Вердикт: план принят при условиях 1–4.** Его основа верна. Удаляется только то, что совпало по свежей sha256 самого
ящика. Удаление идёт по явному манифесту, не по маске. Текущие сутки не трогаются, коллектор не перезапускается. При
любом сбое локальная копия остаётся.

## Условия (до включения)

1. **Тревога должна дойти до людей.** Файл `ALERT-*` на коллекторе никто не читает. Нужно вывести `ALERT-<сутки>` и
   `ALERT-disk` коллектора туда, где команда смотрит, например в `tools/alpha-status.sh` / morning-status или
   `ceo-wake.log`. Иначе сбой незаметно копится, как с забором 30.09 (17 → 33 %).
2. **Сам догоняет.** Каждый прогон проходит по всем закрытым суткам, у которых остались локальные файлы, от старших
   к младшим, а не только по вчерашним. Если файл ещё открыт, через час — повтор. Ручной `sb-push-day.sh <сутки>`
   остаётся на крайний случай.
3. **Манифест и проверки охватывают `deep/`.** Число файлов «ящик ≥ локально» сверяется по `root/` и `root/deep/`
   отдельно. К сценариям теста на копии добавить два:
   - файл суток, которого нет в манифесте, после прогона цел;
   - на ящике не хватает одного файла (недокачка): ничего не удалено, ALERT.
4. **Заполнение ящика.** На 1 ТБ сейчас 578 ГБ, коллектор даёт ≈ 5–6 ГБ/сут, то есть ≈ 2 месяца до упора. Нужна
   тревога «ящик > 85 %» в том же месте, что и п. 1.

## Для владельца (решение не Судьи)

После переноса ящик становится **единственной копией** свежей записи: Steam Deck забор больше не делает, коллектор
стирает свою копию. От искажения при копировании защищает sha256. От потери самого ящика не защищает ничто. Варианты,
дешёвые по месту:
- снимки Storage Box (Hetzner, автоматически, место из квоты);
- на коллекторе держать одни сутки запаса: удалять D−2, а не D−1. Это отходит от буквы «сразу переносить», поэтому
  только с согласия владельца.

Прогон теста на копии (сценарии плана + п. 3) и его журнал — на проверку Судье перед первой боевой ночью.
