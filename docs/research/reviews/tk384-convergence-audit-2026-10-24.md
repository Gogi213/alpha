# TK-384 — аудит метода «схождение Gate к DEX» (TK-377/380/382), 24.10.2026

Судья. Прочитано: `tools/compute/tk380-bsc-lag3.py`, `tk380-evm-lag3.py` (копия BSC с таблицей сетей), `tk380-sol-lag3.py`,
`tk382-biggap.py`, отчёты `tk380-gate-dex-2026-10-23.md`, `tk382-big-gaps-2026-10-24.md`, `practitioners-dex-spread-2026-10-23.md`,
`tk380-participating-coins-2026-10-24.csv`. Своя проверка — одна (Д2, ниже), скрипт `/tmp/tk384chk.py` на calc.

**Вывод:** вывод «края нет» (TK-380 v3, TK-382) относится к **тяжеловесам** при **цене DEX = цена последнего свопа с комиссией пула**,
**входе на первом пересечении** и **закрытии ≤ 5 мин** (v3). Класс практиков (монеты без Binance/Bybit/OKX, отрывы 2–6,5 %, вход на
развороте, удержание 30+ мин) этим не проверен. «Метод проверен криво» — да: Д1, Д2, Д4 меняют вывод или его область.

## Спецификация чистого пересчёта (для Исследователя; протокол — по навыку alpha-research, до счёта)

1. **Монеты.** Фьюч Gate USDT, монеты **без** фьюча/спота на Binance/Bybit/OKX (список — по API инструментов трёх бирж на дату
   счёта, сохранить в `docs/findings/`). Тяжеловесы — отдельный класс как отрицательный контроль, не в одном агрегате. Исключить:
   пулы-обёртки (сеть пула ≠ родная сеть токена), токенизированные акции, тикеры с оборотом фьюча Gate 0. Порог ликвидности пула —
   не назначать, а показать результат по терцилям ликвидности.
2. **Пул.** Один пул на монету — с наибольшей ликвидностью в $ за окно; остальные пулы — только для сверки базиса.
3. **Цена DEX — середина пула после свопа**, не цена исполнения: v3 — `sqrtPriceX96` из события Swap; v2 — резервы из Sync;
   Solana — состояние пула после свопа (Whirlpool/CLMM `sqrt_price`, AMM — резервы). Если середины нет — цена исполнения,
   сдвинутая на ½ комиссии пула против направления свопа (комиссия — из пула), с пометкой. Возраст цены DEX на входе ≤ 60 с, результат
   — по слоям возраста.
4. **USD**: стейблы = 1 (проверить отклонение от 1 по своему пулу); нативные (WBNB/WETH/WSOL) — середина BBO фьюча Gate в ту же секунду.
5. **Отрыв**: log(середина BBO фьюча Gate / середина DEX); базис — скользящая медиана за предшествующие 24 ч (без заглядывания);
   рядом — сырой отрыв без вычета.
6. **Фильтр выбросов DEX** — не по соседним свопам ±10 %, а только явные ошибки (нулевые суммы, неверный маппинг); резкие ходы оставить.
7. **Формы входа** (каждая — отдельное испытание): (а) первое пересечение T (как было — для сопоставимости); (б) **разворот**: после
   пика |отрыва| вход, когда отрыв сократился на долю r от пика; (в) мейкер-лимит на Gate на стороне схождения.
   **Пороги T**: 1 / 2 / 3 / 5 %. **Выход**: сход до T/2 и до 0; **таймауты** 5 мин / 30 мин / 2 ч / 8 ч. Сетку записать до счёта, число
   испытаний — в отчёт.
8. **Издержки**: тейкер/мейкер Gate фьюч по тарифу, фактический спред BBO, фандинг за удержание.
9. **Разложение каждого эпизода**: ход ноги Gate и ноги DEX до выхода; доля «Gate пришёл к DEX» / «DEX пришёл к Gate» / «не сошлось».
10. **Справочно** — двуногий вариант (хедж на DEX с комиссией пула и газом).
11. **Отчёт**: **по каждой монете отдельно** (эпизоды, нетто, интервал), затем по классу; единица бутстрапа — монето-сутки; эфф. N;
    контроль — 5 случайных входов той же монеты, тот же знак и длительность (как TK-382); поправка на перебор сетки.
12. **Ввод/вывод**: статус депозита/вывода токена на Gate по сети пула (API Gate) на дату счёта — колонка в таблице монет.
13. **Окно**: 15–22.10 (8 сут.) — одно окно; вывод не сильнее одного окна, месяцы — при расширении данных.
