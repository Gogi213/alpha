## Н1 (вернуть): фандинг на реальных данных не применяется ни разу — минуты в разных эпохах

- Ставки: `read_funding` (`src/statarb/cli.rs:437`) даёт минуту `time_ms / 60000` — unix-минуты (BTCUSDT 1585152000000 → 26 419 200).
- Панели: `first_min` в `.sap` — 717 681 / 636 953 / 909 064 (AAVE/ADA/ALGO, `od` заголовка `/data/tk0479/panels-bybit-linear`), т.е. другая эпоха (≈ минуты от 2020-01-01).
- Следствие: выплата никогда не `≤ ft` → в D3 `r_mean` = NaN всегда → 0 сделок; начисление фандинга D2 тоже ноль.
  Прямое доказательство из лога гейта: digest funding-pp **равен** digest cross-binance (`86d72e803db9e086` kernel 240,
  `c9e56b48f82f504a` reference, `e862aa8126235b23` kernel 1440), хотя в хеш входит `funding_bps` (`cli.rs:201`) — фандинг ни
  в одной из 2,5 млн сделок не ненулевой.
- Объяснение отчёта «уровень ставки не перекрывает круг издержек» неверно: при базовой ставке 0,01 % (1 bps) и k=9, h=24 доход
  24 bps > круг перп↔перп 4·3,15 = 12,6 bps (β = 1) — сделки должны быть почти всё время.
