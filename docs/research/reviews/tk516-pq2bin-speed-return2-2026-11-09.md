## Почему «предел по Амдалу» не доказан

- В «неустранимые 40–45 %» включён **разбор строк** — это ровно то, что заказано ускорить (п.1–2 описания TK-516), а не неустранимая часть.
- По числам самой сдачи предел Амдала: bn/okx 1/0,20 ≈ 5×, gate/bybit 1/0,26 ≈ 3,8× — 2× **не исключён**.
- Шум мерки ±10 % (сдача) при выигрыше 1,02–1,08× на bn/okx/gate: эти три числа неотличимы от нуля. Прошлый прогон той же базы: bn 11,01 / 10,69 G (final5 / final10).

## Что сделать (один круг, ≤ 1 ч)

1. **Разбивка итогового бинаря по источнику** (perf report, self %, `cycles:u`), таблицей по корзинам: распаковка входа · сжим выхода · декод parquet/arrow · разбор чисел/строк · `Book` · `L1Enc` · прочее. Это и есть основание любого «предела».
2. **Бить в крупнейшую устранимую корзину каждого источника** с замером вариантов (В-170): на bn — гибрид `Book` (хеш для количеств + отдельный порядок только для лучшего уровня; в отчёте «по источнику не делался»), на gate — построчное чтение/разбор (read_line, 16 % по замеру 1).
3. **Уровень zstd выхода 2 — принять по умолчанию** (разрешено прежним вердиктом): по `zl.txt` суммарный размер 4 источников 26,27 → 27,48 МБ (+4,6 % ≤ 15 %), cycles −6…−16 %; гейт — равенство после распаковки (уже 0 расхождений) + ab несжатых.
4. Каждое число ускорения — медиана ≥ 3 прогонов (шум ±10 %).
5. Если после этого 2× нет — сдать с таблицей п.1; планка прежнего вердикта не меняется: «максимум при доказанном пределе» — если остаток вне распаковки входа и сжима выхода ≤ 15 % циклов. Без этого «≥2×» остаётся условием приёмки.

Подмена бинаря в юнитах `p40-l1-dl / p40-bg-dl / p40-box-conv` — только после приёмки.
