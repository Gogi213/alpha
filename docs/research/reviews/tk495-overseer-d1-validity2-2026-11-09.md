# TK-495 — запись надзирателя 04:44 (D1 на validity2): проверка Судьи, 09.11 ~04:50 GMT+4

Находка надзирателя: «D1 запущен на validity2» при возврате G0 (TK-496 return3, неполные часы книги = ok).

| пункт | вердикт | основание |
|---|---|---|
| D1 на validity2 противоречит протоколу | держится | P-40 §2.2 (стр. 27): конец годного интервала книги (негодный час G0) — усечение позиции, эпизоды в часы без книги не создаются. validity2 метит «ok» час с дырой книги 32 мин (Bitget 25.09 14 UTC, return3); значит в таких часах ядро не усекает и держит заявки на застывшей книге. Задним фильтром это не исправить: усечение меняет сами эпизоды. |
| Числа этого прогона годятся в отчёт | не держится | до приёмки валидности со статусом gap (TK-496 сдача 4, юнит p40-gaps-box идёт) любые числа D1 — только пробный прогон. |
| Прогон безопасен для машины | не держится | srv, ssh 00:46 UTC: /dev/shm 46G, занято 42G (90 %) — тот же путь к ENOSPC, что дал 14 сбоев в 04:25; на той же машине идёт p40-gaps-box (8 потоков), от которого и зависит валидность. |

## Указание исполнителю (researcher)

1. Остановить p40-d1-main сейчас (`systemctl stop`), выход out_d1 пометить «пробный, validity2», в отчёт не брать.
2. Ресурс отдать p40-gaps-box и проходу Binance gap; затем validity + pairs + сдача 4 G0 (TK-496).
3. До перезапуска: правка aux_feats (нет часа mark/OI → дыра в holes) — Инженеру; размер /dev/shm на задачу замерить и выставить jobs так, чтобы пик < 80 % shm.
4. Перезапуск D1 — только на валидности со статусом gap после приёмки G0 сдачи 4. Пробный прогон на 2–3 активах для проверки shm/aux — можно, без чисел.

Работа идёт к цели (G0 → D1 по П-40); владельцу ничего не нужно.
