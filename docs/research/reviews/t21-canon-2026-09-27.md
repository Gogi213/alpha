## Ответы на §4

1. **Просадка — две меры, разные имена, «просадкой» зовётся одна.** «Просадка счёта» (П1) — владельцу, главная:
   equity = депозит + реализованное + переоценка открытых по закрытию минуты; просадка = max по t (пик equity до t −
   equity t), в $ и в % **от депозита** (не от пика) — записать формулу в документ. «Откат по закрытиям» (П2) —
   справочно, этим именем. Эпизоды по закрытиям (П3′) — только внутри KPI «до перехая», словом «просадка» не называть.
2. **Шарп — по календарным суткам с нулями, × √365** — согласен (бот стоит и в нулевые дни). Рядом — число суток;
   Шарп месяца (23–31 точка) — описание, варианты по нему без интервала не сравнивать. DSR (T-26, Rust) — на тех же
   сутках; если в Rust иначе — строкой в список расхождений.
3. **Месяц сделки — месяц её сигнала (`t0` / `day_utc`), не `t1`.** Сделка 31.08 23:50 → 01.09 — августовская.
   Почему: (а) месяц — это разбиение данных для решения (В-115, перекрёстно авг ↔ сен): решение о входе принято на
   августовских данных, по `t1` ~12–13 сделок на границу переезжают в чужой месяц вместе с августовской информацией;
   (б) окно по `t1` несимметрично на концах — теряет сделки 23.09 → 24.09 и добавляет 31.08 → 01.09; по `t0` каждый
   сигнал считается ровно один раз и в своём месяце; (в) парная Δ по суткам уже берётся по суткам входа (H14).
   Время внутри месяца — по `t1`: точки кривой, дневной P&L, худшие сутки, календарь, Шарп — по дню выхода среди
   сделок месяца (хвост месяца может залезть на 1–2 сутки следующего — это нормально). Занятость, потолки и
   выключатель — одной непрерывной лентой по времени (как у бота), принадлежность месяцу — после. Блоки бутстрепа для
   вердиктов — по суткам сигнала. «Август + сентябрь одним счётом» — непрерывно по `t1`, вопроса нет.
   Строку §2 «месяц» переписать так; «день для денег = `t1`» оставить для оси времени.
