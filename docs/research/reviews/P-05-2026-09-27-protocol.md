# Проверка Судьи: протокол П-05 «возраст, размер и сила стены» (`docs/research/P-05-wall-age-size.md`, 8dfc261) — до чтения (2026-09-27)

**Итог: сетку считать можно — клетки и наборы не меняю. Правила чтения — вернуть, пять пунктов; до них числа
сетки не читаются как вердикт.**

**Для владельца (одним абзацем).** По деньгам на двух месяцах эта сетка «лучше / хуже» почти ничего не покажет.
Точный прогон твоей точки (60 мин / $100k) дал разницу с главным: август −$70 [−$438; +$185], сентябрь −$94 [−$193;
+$24]. Интервал в августе — около ±$300, а весь главный вариант зарабатывает ~$106 в месяц. Любой строгий фильтр
убирает большую часть сделок главного, и разница тонет в их шуме. Поэтому сетка — это описание: сделок, денег,
просадки по клеткам. Решение по ней — твоё суждение, а не вердикт статистики, и так это и надо подписать. Отдельно
про плечо (§3а): подбирать размер по **реализованной** просадке клетки с 27–69 сделками — самая опасная ошибка из
отказов навыка. Мелкая выборка случайно даёт малую просадку, множитель выходит большим, и плечо ставится на шум.
Уравнивать риск нужно по устойчивой мере с потолком множителя (ниже, п. 3).

## Вернуть (правила чтения)

1. **Достижимость (§8) — записать до чтения сетки.** По точному прогону H1 ширина 95 % интервала Δ$ — ≈ ±$310
   (август) и ±$110 (сентябрь). Для любой клетки, которая убирает большую часть сделок главного, ширина того же
   порядка. «Лучше» (нижняя > 0) требует Δ больше этой полуширины. «Не хуже −$10» недостижимо при любой Δ. Написать
   прямо: по деньгам ожидаем «не ясно» у H1, H2, H4 и у строгих клеток; сетка — описание, решение — владельца.
2. **Правило (§10) — как в П-04 и В-117.**
   - Только R2: §10 П-02 с порогом эфф. N снят владельцем.
   - **Подтверждено** — Δ > 0 в обоих месяцах (для H2/H4 — в обоих направлениях перекрёстной проверки), интервал после
     Холма не накрывает 0, держится без одних-двух суток и монеты, есть плато.
   - **Отвергнуто** — значимый вред: верхняя граница < 0 хотя бы в одном месяце или направлении. «Δ < 0 по точке»
     (сейчас у H2) — не опровержение.
   - **Не ясно** — иначе.
3. **Равный риск (§3а, H3).** Множитель k = просадка главного / просадка клетки — отношение двух реализаций, у клетки
   с десятками сделок — шум. Заменить: k = σ суточного результата главного / σ суточного результата клетки (по
   месяцу подбора, применяется к другому месяцу — перекрёстно, как в протоколе). Потолок k ≤ 3. Рядом — медиана
   просадки по блочному бутстрепу суток для обоих рядов при этом k. Прямой счёт размеров, точный прогон на $1000 /
   $2500 и запас до ликвидации оставить как есть — это правильно.
4. **Холм — по месяцу проверки, с пересечением.** Семья в каждом месяце проверки: H1, H2 (направление с этим месяцем
   проверки), H3 (то же), H4 (то же), точка «сила ≥ 50 %» — m = 5. Решение — max(p Холма) по двум месяцам < 0,05.
   «12 проверок» считает месяцы дважды.
5. **Охват до денег (§3б и строгие клетки).** По каждой клетке и месяцу — число сигналов/сделок без денег (кэш D20 и
   `t29-wall-filter.py`) — записать до чтения $. Клетки с < 10 сделками в месяце — «сделок нет», без Δ (для порогов
   силы 50–100 % так и ожидается по В-70). Условие перекрёстного отбора «≥ 30 сделок в месяце» оставить.

## Ответы на вопросы Исследователя (сообщение 27.09)

1. **≥ 30 сделок в месяце — нижняя граница клетки подбора: да.** Вместе с п. 5: клетки с < 10 сделками — «сделок нет»,
   без Δ; клетки с 10–29 — в таблице описанием, в подбор не идут.
2. **X = $10 — на этих данных бессмысленно.** Нижняя граница Δ у точки H1 — −$438 (август) и −$193 (сентябрь).
   «Не хуже −$10» не пройдёт ни одна строгая клетка при любой Δ. Владелец либо назначает X, зная эти ширины (≈ $300 /
   $110 в месяц), либо принимает, что «не хуже базы» здесь заранее «не ясно». Это надо написать в §8 до его «ок».
3. **Холм — да, так же, как В-117:** m в каждом месяце проверки (здесь 5), решение — max(p Холма) по двум месяцам.
4. В-117, Г-36: флаг 1 = 0 сделок → «не определена как фильтр» (19c6b5a) — верно, по моему условию охвата.
