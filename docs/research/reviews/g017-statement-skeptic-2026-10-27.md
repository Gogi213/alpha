## Правки к TK-421 / P-TK421 (дописать в протокол v2)

1. **Многомасштабно, без «основного T».** Событие = объединение по T ∈ {5,15,60,240}: окно минуты попадает, если z ≥ z\*_T
   хоть на одном T; перекрытые сливаются. В csv — `T_min` (наименьший T, на котором прошло) и `z_T` по всем четырём T.
   Выбор «основного T» убрать.
2. **База — V1 (только ход).** Оборот m, OI — столбцы признаков, не фильтр. V2 показывается как подмножество V1
   (доля событий с m ≥ m\*), не как другое определение. C2 переименовать в «класс: размах без объёма» (часть V1).
3. **Абсолютный ход рядом с z.** Добавить вариант V0: `ln(1+R_T) ≥ r*_T` (порог тем же K1 на абсолютном ходе) и
   таблицу пересечения V0∩V1 / только V0 / только V1 по биржам-месяцам — Судья выбирает базу по таблице.
4. **Пары памп↔дамп.** Столбцы `пара_id`, `тип_пары ∈ {памп, дамп, памп→дамп, дамп→памп}`: дамп, чей старт
   лежит в [t_peak пампа, t_end + длит. пампа] той же монеты, — вторая нога пары (длина окна — назначено этим
   протоколом). В эфф. N пара — один кластер.
5. **Рыночность.** Столбцы `доля_монет_рынка` = доля инструментов той же биржи-рынка с ходом того же знака ≥ z\*
   в ±T_min минут пика, и `ход_BTC_%` за [t_start, t_peak] (BTCUSDT той же биржи). Класс «рыночный» —
   по излому распределения доли (K1), не назначенный.
6. **Склейка бирж/рынков.** `монета_id` (база без котировки) и `кластер_id`: события одной монеты на любых
   биржах/рынках с перекрытием [t_start, t_end] — один кластер. Эфф. N — по кластерам, бутстреп — по монетам.
7. **Контроли C1 — по режиму.** Подбор: та же монета, длительность, час UTC ±1 ч **и** σ предыдущих 24 ч в той же
   квинтили монеты **и** `ход_BTC` окна в той же терции месяца. Если пар нет — пишется «не подобран», не ослаблять
   молча. Доля неподобранных — в отчёт.
8. **Фазы в формате окон.** Каждой строке — `t_pre_ms = t_start − длит.` (окно «до» той же длины). Окна для TK-422:
   pre [t_pre, t_start), leg [t_start, t_peak], post (t_peak, t_end]; у контроля — те же три доли длительности.
9. **Август неполный — не в критерий.** Критерии (1)–(2) приёмки определения: сентябрь (две половины) + август
   только после TK-423 (полный охват). Август-50/21 — справка с пометкой «отобранные монеты».
10. **Убрать из шага 1:** метку «прямая/ступень» по тертилям и V3; K2 — проверка совпадения с K1, не вторая сетка.
11. **Счёт стоимостей.** Число порогов после правок: 4 T × 2 знака × (V0, V1) по K1 = 16, K2 — проверка; записать.

## Правки к TK-422 (счётчики)

1. Признак считается **по фазе** (pre / leg / post — окна из правки TK-421 №8), имя столбца `<признак>_<фаза>`;
   ничто из leg/post не называется «до пампа».
2. **Покрытие:** на каждое окно и признак — `cov_<признак> ∈ {ok, нет_данных}` (сделки/стакан/OI есть не у всех).
   Без этого «общее» будет смещено к монетам с данными.
3. Сетка параметров каждого признака — **≤ 3 значения**, записаны в `pump-features-<дата>.md` до счёта шага 3
   (числа автора курса — одно из значений). Больше — только с обоснованием (каждое значение множит перебор).
4. Нужные для №4/№12 входы: таблица пар фьючерс↔спот (монета_id, биржа, инструменты) и ряд BTC — сделать
   частью инструмента. OI/фандинг Bybit (REST, как отдаёт биржа) — список пробела для Инженера; ликвидации Bybit —
   «истории нет», не подменять.
5. №9 (старший фрактал день/неделя): лукбэк ≥ 7 сут — без июльских свечей первые сутки августа = «нет истории».
6. Возраст листинга (дней от первой свечи/даты листинга) — добавить признаком.
7. Признак — описание (значение в окне), не сигнал: без «вершина/вход»; марк-аут — не здесь.

## Шаг 3 (не заведён) — что обязано быть в протоколе (CEO заводит, Судья утверждает)

- **Общее:** для каждого признака × фазы — доля/медиана в событиях против C1 (подобранных), эффект с
  бутстреп-интервалом по монетам; «общее» = эффект в одну сторону **в обоих месяцах** и на обеих биржах, после
  BH-поправки q (назначить в протоколе) по всем признак×параметр×фаза×знак. Август — открытие, сентябрь — проверка
  (или наоборот), записать до счёта.
- **Классификация:** на признаках pre+leg (+ форма, T_min, рыночность, пара, объём) без post; число классов — из
  данных (силуэт/gap), «один класс» допустим. **«Правильная» =** (а) устойчивость: классы, обученные на августе,
  назначенные сентябрю, совпадают с классами, обученными на сентябре (ARI; порог — в протоколе), и бутстреп-Jaccard
  по классам; (б) не артефакт определения: те же классы на V0 и V1 и при сдвиге z\* к краям интервала;
  (в) нулевая модель: та же процедура на C1 даёт заметно худшую структуру; (г) сопоставление с каталогом TK-414
  и таксономией notes-2 — кросс-таблица (описательно, не критерий).
- **Без подмены:** ни марк-аута, ни точности детектора; торгового вывода у шага нет (трек Б — по слову владельца).
