## 1. `18a9100b` — statarb, строгие линты 969 → 832

Дифф слияния `04ea09c1` против первого родителя совпадает с диффом коммита построчно (773 строки, разницы нет) — при слиянии
ничего не добавлено. Файлы: `src/statarb/{cli,kernel,panel,reference}.rs`.

На корректных входах поведение не меняется (проверено построчно):

- Арифметика: формулы `gross`, `fee`, `qty`, `fund`, средние фандинга, z/β — те же выражения, те же операнды.
- Порядок суммирования f64 сохранён: корзина `lx` — по компонентам `i = 0..k`; кольцо фандинга — от `ring_head` по кругу
  (`skip(head).chain(take(head))` = `(head + j) % fk`); суммы окна `Sums::rebuild` — `lo..=hi` подряд; ноги в P&L — Y, затем X по порядку.
- Разбиение `qty/pin[0..=k]` на `qty_y/pin_y` + `qty_x/pin_x[0..k]` — переименование индексов; кольцо `ring` через `push` вместо
  счётчика `ring_len` — те же значения на тех же местах.
- Индексация `x[t]` → `at(x, t)` (NaN за краем): за край не выходит — новый `PairInput::assert_aligned` в начале обоих `run_pair` и
  `z_series` проверяет ровно те длины, по которым старый код индексировал на каждой минуте `t < n` (`lx, oy, ox[i] ≥ ly`, `wx ≥ ox`).
  Падение просто переехало с индекса на assert.
- Приведения: `(i64) as usize` → `usize::try_from(..).ok()?` — разности там неотрицательны (`lo = max(first_min)`), ветка `None`
  недостижима; `u64 as usize` — на 64 битах без изменений; `as f64` под `#[allow(cast_precision_loss)]` — те же выражения.
- `read_series`: 24 байта заголовка читаются четырьмя `read_exact` вместо одного — тот же итог (магия проверяется после чтения
  всех 24 байт, как раньше); `chunks_exact(8)` → `as_chunks::<8>()` — те же 8-байтовые группы.

Изменения только на путях ошибок (паника → `None`/`Err`/NaN/пропуск), на корректных данных не срабатывают:

1. `DriftSink::z` (`cli.rs:152`): минута за краем вектора молча пропускается вместо паники. Вектор размера `ly.len()`
   (`cli.rs:221`), `t < n` — недостижимо.
2. `price_at` / `last_open`: нет конечного open до `t` → NaN вместо выхода за край; по комментарию недостижимо (позиция открыта
   по конечному open).
3. `convert_csv_stats` (`panel.rs:195`): минута раньше начала панели (неотсортированный CSV) → ошибка файла вместо
   `resize` на ~2^64 (паника/OOM). Улучшение, на отсортированных выгрузках не срабатывает.
4. Отравленные замки в `convert`/`bench`: поток выходит / не добавляет счётчики, но `thread::scope` всё равно поднимает панику
   упавшего потока; итог прежний — падение.
5. `file_name().unwrap()` → `unwrap_or_default()`: у файлов из `sorted(dir, ..)` имя всегда есть.

Замечаний, требующих правки, нет.
