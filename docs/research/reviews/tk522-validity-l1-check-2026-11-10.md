## Решения
1. `S_max` и допуск сверки mid — **из G0** (П-40 r3.2 стр. 89): значения взять из выходов G0 08.11 (на тех 2 394
   нога-сутках, где G0 есть), записать в отчёт числом с файлом:строкой; час с `age_p99_ms > S_max` — негоден
   (`stale`). Если G0 этих чисел не выдал — посчитать их по L1 тем же правилом r2 §2.3 на D1 до счёта эпизодов
   (исходы не читаются, стр. 89 «не касаются исходов»).
2. Сверка mid с mark: CHFT-ноги — mark из aux-копии (mark хранится, В-123), Bybit/Gate — публичные свечи 1 м;
   час вне допуска — `mark_dev`. HL — по mid (16.4), сверка с mark HL — та же.
3. Часы бирж: кросс-корреляция BTC/ETH 10–100 мс по L1 — одна таблица на биржу за D1 (не по часу), печать
   неопределённости; час не бракует.
4. Справка G0↔L1 — таблица совпадения вердикта часа, порога нет.
5. Bitget: после TK-521 (переконвертация с `P40_L1_CARRY=1`) — из L1; `--raw-ex bitget` из боевого скрипта убрать.
   До тех пор боевой запуск с Bitget невозможен — это и есть зависимость от TK-521, а не отдельное исключение.
6. Сделки Binance: L1 Binance без `.tr` — в TK-521 достроить сделки в L1 (или до удаления сырья сделок по В-123
   выгрузить `.tr.zst`); `--l1-trades-raw` в бою — только если на момент пуска parquet сделок всех Binance-ног D1
   на боксе есть (проверка числом файлов до пуска).
7. Сквозной тест: синтетическая пара с пустыми сутками посередине → эпизоды до и после, открытый эпизод у дыры
   с причиной `gap`.

## Вердикт
«blocked» верен только для боевого пуска (TK-521, слово CEO, p40-d1l1). Пункты 1–4 и 7 по силам Инженеру сейчас,
параллельно TK-521 — `return`. Пп. 5–6 — передать в TK-521 комментарием. Чисел владельцу нет.
