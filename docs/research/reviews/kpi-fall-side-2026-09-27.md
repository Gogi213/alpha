# Проверка Судьи: сторона падения KPI (`drawdown_stats`, cc691cf) и годность KPI для сравнения вариантов (2026-09-27)

**Итог: «до перехая» со скользящим стартом — годится (принято 1d2a3f4), но уточнения ещё не внесены, и для правила
П-07 его надо считать долей, а не p90. Сторона падения — вернуть: месяц по пику прячет самую глубокую просадку
сентября, «перелоу» зависит от придуманного порога, квантили — на 3–5 эпизодах.** Пересчёт —
`reviews/scripts/kpi-fall-check.py` (данные `data/kpi/*-closes.json`, код `kpi-newhigh.py` как есть).

## 1. «До перехая» (1916132) — как сравнивать

- Уточнения 1d2a3f4 (доля t с ожиданием > H, p90 по Каплану — Майеру, число t и доля цензуры) в коде нет: `rolling_kpi`
  подставляет время до 24.09 вместо незакрытого ожидания. Из-за этого вариант, не вернувшийся на пик к концу данных,
  выглядит лучше (в сентябре у части рядов цензура 17–43 %).
- **Правило владельца «p90 ≤ 5 дней в обоих месяцах» (В-120 доп. 3, В-122) считать так: доля часов t, с которых ждать
  перехая дольше 5 суток, ≤ 0,10**, только по t ≤ 24.09 − 5 сут = 19.09 00:00. Без цензуры это то же самое, что
  p90 ≤ 5, а с цензурой — единственный точный ответ. То есть H = 5 суток (порог владельца), не 7. В таблице — число t
  месяца в мере.
- **Блок — не эпизоды.** Эпизодов 3–5 в месяце, они разной длины, а спокойные дни между ними — часть KPI. Для «лучше
  базы» — парный круговой блочный бутстреп по суткам, блок ≥ 7 суток (из `kpi-days-to-new-high…`), честно с ожиданием
  «не ясно»: при 31 / 23 сутках это 4–5 / 3–4 блока. Для порогового правила П-07 бутстреп не нужен, нужна **устойчивость
  (R2 п.3):** «проходит» остаётся при исключении сделок любой одной монеты и любых одних суток. Выбор клетки из сетки —
  перекрёстно (август → сентябрь и обратно, В-116(2)), число клеток — в счётчик испытаний.

## 2. Сторона падения (cc691cf) — вернуть

1. **Месяц по пику.** Откат, начавшийся в августе, целиком идёт в август. Сентябрь не видит своей глубокой просадки:
   у главного варианта в сентябре максимальная глубина по эпизодам $45, а счёт по часам был ниже пика на **$94**; у Г-85 —
   **$60 против $138**. Считать по месяцу момента t, как «до перехая» (почасовая кривая под водой), или делить
   эпизод на границе месяца.
2. **Квантили на 3–5 эпизодах.** В месяце n = 3 (главный: август и сентябрь), 3–5 (Г-85). p90 спада на трёх эпизодах —
   это максимум. Печатать список эпизодов (пик → дно → возврат, глубина, перелоу), квантили не печатать.
3. **«Перелоу» зависит от порога.** `REBOUND_FRAC = 0,2` и `DD_MIN_USD = $10` — придуманные числа. Г-85 в августе:
   перелоу 8 / 6 / 3 при пороге отскока 0,1 / 0,2 / 0,3; главный — 11 / 9 / 8. Счёт идёт по закрытиям, так что у
   варианта с частыми сделками больше поводов для «отскок-и-ниже» при том же пути. Порог — решение владельца (В-##) до
   любого правила; в таблице — рядом чувствительность.
4. **Незакрытый откат — цензура.** В сентябре один открытый у обоих: его спад и глубина — «≥», дно может стать ниже;
   медиана восстановления без него оптимистична — писать «(без 1 незакрытого)».

## 3. Мера спада для сравнения (предложение, решение владельца)

Если владельцу нужно одно число «сколько падаем», без порогов эпизода: **по часам месяца — доля часов под водой глубже
$D и RMS просадки («язва»)**. Одно число на месяц; парный бутстреп по суткам работает на них так же, как на «до перехая».
Для справки:

| | главный авг / сен | Г-85 авг / сен |
|---|---|---|
| доля часов под водой > $0 | 0,78 / 0,78 | 0,67 / 0,84 |
| > $25 | 0,51 / 0,40 | 0,45 / 0,45 |
| язва (RMS), $ | 37,7 / 26,8 | 59,6 / 42,3 |
| макс. просадка по часам, $ | 98 / 94 | 149 / 138 |

Эпизоды и перелоу остаются справочными (для П-07 это и так решено владельцем, В-122 доп.).
