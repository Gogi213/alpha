# П-40 D1: решения Судьи по находкам критика 10.11 (TK-523)

Основание: В-53 (методика и числа до счёта — Судья), В-110 (описание, без валидации), В-115 (только L1 + сделки),
П-40 r3.2 (master @8dc30b54). Сверено сам: `P40_NOTRADE` не задан → `skip` (`tools/p40core/rs/src/main.rs:85–90`,
ветка `tk522-orch-l1all`), K1/K2 включаются только `P40_SHIFT_B_MS` / `P40_K2` (там же `:655`). Остальные факты —
из записи критика в TK-523; решения ниже от них не зависят по знаку (меняют, ЧТО печатается, а не правило §4.1).

**Итог:** прогоны d1c, d1l1, d1hl — **в отчёт не идут** (три разные книги, несравнимы, п. 3). D1 считается заново
одним прогоном по правилам ниже. Это не меняет правило §4.1 (θ, N, вход/выход), только источник ног, исполнение
ног без сделок, полноту и сводки. Текст §16 ниже вставляется в P-40 дословно (Исследователь, TK-522/TK-514).

## Текст для П-40 §16 «Поправки до счёта D1 (Судья, 10.11, TK-523)»

**16.1 Одна книга.** Все ноги всех пар — из L1 бокса одним конвертером (r3.2 §1). Сырьё в D1 не читается.
Прогоны d1c / d1l1 / d1hl отброшены целиком. Сдвиг L1 против полной книги (G-L1b) печатается справкой на DOGE и
ещё 2 активах с ≥ 200 эпизодов (по L1 против полной книги, пока сырьё есть), порога нет (В-115).

**16.2 Ноги без сделок (Bybit ob200, Gate) — две границы, не одно число.**
- верхняя граница: `P40_NOTRADE=drain` — убыль объёма на уровне заявки считается сделкой (отмены засчитываются
  исполнением → оптимистично);
- нижняя граница: `through` — исполнение только при проходе цены сквозь уровень заявки (покупка: лучший bid ниже
  цены заявки; продажа: лучший ask выше), уход уровня «вверх» из L1 (бит2 при лучшей цене на нашей стороне)
  исполнением не считается. Режим `through` ядро добавляет (TK-522), тест: искусственная книга, 3 случая.
- `skip` в D1 не применяется (он молча выкидывает 78 % пар).
- **Главное `ȳ` и Холм — только по парам, где обе ноги со сделками** (Binance, OKX, Bitget между собой).
  Пары с ногой Bybit/Gate — отдельный блок «нога без сделок»: `ȳ` при `through` и при `drain` двумя строками
  с интервалами, в Холм не входят; признак «нога Bybit» (§4.2 п. 7) считается на этом блоке справкой.

**16.3 Исполнение мейкером на двух ногах — находка описания (В-110).** Правило не меняется и не подбирается.
Отчёт первой таблицей печатает (на всё и по парам бирж): доли исходов (обе / одна+страховка / нет / сошлось не
вышел / усечён); вероятность второй ноги при исполненной первой; время до исполнения каждой ноги (квантили 50/90);
**разложение `ȳ` = Σ доля исхода × средний `net_bps` исхода** с вкладом каждого исхода в bps. `ȳ` «обе исполнены»
печатается только с его `n`; при `n` < 200 — без интервала, пометка «мало». Формулировка: «вход мейкером на обеих
ногах исполнился в X % взводов; `ȳ` на X % определяется исходом …». Справкой — `T_life` = 10 и 300 с (§8, уже
заморожено), K2 (та же механика без взвода).

**16.4 Hyperliquid.** Снимки ≈ 5,4 с — очередь мейкера не считается. Пары с HL: только описание по mid (§4.2
п. 2–4: расхождение, схождение, путь/МПУ по mid), без `net_bps`, без `ȳ`, вне Холма и срезов. Кластер — актив
по базовому символу, общий для всех бирж (не `1000+база`): правка в assemble/p40stats с тестом «один актив на двух
парах бирж = один кластер».

**16.5 Валидность — на всю вселенную, по умолчанию «негодно».** `validity` покрывает каждую (биржа, контракт, час)
плана; час без строки — негоден. Gate 29.09 вечер – 08.10 полдень (только часовые снимки) — негоден по построению.
Перед счётом — проверка покрытия: 100 % (нога, час) плана имеют строку, иначе счёт не запускается. Усечение на
границе негодного — §2.2.

**16.6 Куски.** Пара считается **за 14 суток D1 одним проходом** (уровень `L` = 6 ч прогревается один раз —
17.09 00:00–06:00, эти часы без эпизодов, печатается). Если ресурсы не дают одного прохода — нахлёст: кусок читает
предыдущие 6 ч для уровня, эпизоды взводятся только внутри своего куска, открытая позиция досчитывается по данным
следующего куска до закрытия/усечения. Гейт: на 2 активах кусками = целиком байт в байт таблицы эпизодов.

**16.7 Фандинг в `net_bps`.** Фактические начисления по меткам расчёта каждой биржи между входом и выходом ноги:
`−сторона · ставка · номинал`, в `net_bps` и отдельной колонкой; `ȳ` без фандинга — справкой. Источники: Binance,
OKX, Bitget, HL — mark+funding CHFT (бокс, хранится по В-123); Bybit — публичный `/v5/market/funding/history`;
Gate — публичный `/api/v4/futures/usdt/funding_rate`; только 17.09–22.10 (В-109). Перед счётом — покрытие: каждая
(нога, метка расчёта) в плане имеет ставку; дыра — докачать, счёт с дырой не запускается. Уровень `P̄_L`: выбор
`ln(mark/index)` или медианы фиксируется на пару до счёта по покрытию index (< 100 % годных часов → медиана на весь
период), не переключается во времени.

**16.8 K1/K2 — обязательны в D1.** Тот же прогон: настоящий + `P40_K2=1` + K1 `P40_SHIFT_B_MS=+60000` и `−60000`
(входят в разности §4.3). ±1 с, ±10 с, ±1 ч — справкой, можно после. Отчёт без K2 и K1 ±60 с не принимается.

**16.9 Полнота.** В план входят все пары вселенной В-113 по всем биржам, включая Bitget (1731 пара) — выпадение
биржи или пары молча запрещено. Пара, упавшая по любой причине (shm, ENOSPC, нет L1), — перезапуск; отчёт строится
при 0 упавших пар, иначе печатается список упавших с причиной и доля пар/эпизодов по активам — счёт не завершён.
Смещение к мелким активам (падают крупные) проверяется таблицей «план / посчитано» по терцилям оборота.

**16.10 Код статистики до счёта (TK-522, с тестами).** `assemble.py` — колонки r3.2 (`l1_notional`, `bookimb1`
вместо `depth_slip`, `bookimb`); `p40stats.py` — `n_d` = число различных суток, не `max(day)+1` при `YYYYMMDD`;
`t_conv` — цензура на усечении/конце данных, «сошлось за `H`» при `H` = 600 с (не 60 с).

**16.11 Сырьё.** TK-521 удаляет сырьё CHFT только после `.ok` L1 этого контракта-суток (В-123); D1 сырьё не читает
(16.1), конфликта нет. Сдвиг G-L1b (16.1) снять до удаления сырья DOGE и двух выбранных активов.

## Что не меняется
§4.1 правило, θ = 12,6, N = 1 000, `L_ms` = 500, `T_life` = 60 с, комиссии, Холм/BH, схема интервала §6.1,
формулировка §4.5. Новых испытаний в Холм не добавлено (блок «нога без сделок» и HL — вне Холма), `m` ≤ 16 прежнее.
