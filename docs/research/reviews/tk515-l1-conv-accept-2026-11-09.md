## Своя сверка G-L1b (по строкам fills, 50 эпизодов × 2 ноги)

- Время исполнения и `imm` — **0 расхождений** из 100 ног. Все 50 «расходящихся» строк fills отличаются только `front0` (очередь впереди при постановке): полная книга знает размер уровня вне L1, L1-файл — последний видимый.
- 4 ноги (строки 23, 25, 32, 36) в L1-прогоне не поставлены (`front0 = -1`, без исполнения и в полной книге): в окне жизни заявки (500 мс) у L1-файла нет события. Во всех 4 в полной книге цена этой ноги уходила из L1 — отношу к тому же классу «очередь при уходе цены из L1»; исход (не исполнена) одинаков.
- exits: 2 расхождения — только `exit_ms` страховки (+0,6 с / +25 мс), `pnl_bps` равен.

## Замечания (вывод не меняют)

1. `l1_gate_b.sh`: проверка 7 признаков печатает список различий, но всегда `sys.exit(0)` — непустой список гейт не уронит. Сейчас список пуст (проверено), при следующей правке — сделать `sys.exit(1 if bad else 0)`.
2. Направление смещения: при цене вне L1 очередь L1-файла может быть сильно меньше полной (строка 21: 957 против 794 952) — смещение к исполнению в плюс возможно на неликвидных контрактах; на DOGE исходы равны. В-115 решил достаточность L1 — печать, не порог.
3. Постановка заявки на цену вне L1 с последним видимым размером — добавлено Инженером сверх §2.3 (отчёт §1 это называет), тест `l1_placed_while_price_outside_l1…` есть.
4. Сравнение вариантов (хеш, zstd-уровень) не мерили; уровень zstd по §2.4 выбирается на пробе TK-514.

Хвост: нет. Слияние `tk515-l1` → `tk500-p40core` — по гейту, вне заказа (ветка П-40, слияние в `master` по В-217 позже).
