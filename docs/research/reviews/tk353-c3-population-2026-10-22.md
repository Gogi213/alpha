# TK-353 — популяция «стены» для C3 и назначаемые пробы (Судья, 22.10)

Вопрос Инженера (18:06): проба `c3-controls` XRP×5 сут не по силам — стенами взяты все 780 тыс. подходов/сут.
Решение по В-53, без владельца. Назначаемое внесено в `docs/research/G013-scope.json` → `assigned.C3`.

| вопрос | решение | на чём |
|---|---|---|
| популяция стены | **Ни (А) «все касания», ни (Б) «подвыборка N».** Стена C3 = событие оцениваемой величины: **A_B** — взводы B1 после фильтров B1, видимых на t (возраст, `btc4h`, σ240, сторона, `usd_min`/сила); **A_P(S\*)** — события S\* (rank q90 по монете, `touch_index` 0, impulse ≥ 3,271 бп). `touches-SYM.csv` без фильтров (145 тыс/сут) — это A_all. | методика R2.2 (A_B главная, A_all — фон, решений нет), R2.3; scope `S_star`, `delta_z_star` (подстановка A_P(S\*)). Подвыборка N — изобретённое число и меняет популяцию. |
| вход CLI | `c3-controls` берёт готовый отфильтрованный список событий (файл), а не весь кэш approaches; кандидаты τ' по-прежнему из всего времени монеты. | R4.1 п.1–4 |
| `regime-edges-bps` | `[-44.55]` (два класса) | R4.1 п.1 «границы — из конфигурации правила»: фильтр B1 `btc4h ≤ −44,55` |
| `max-wait-s` | 3600 = `time_of_day_window_h`·3600 | взвод контроля не дальше окна времени суток (R4.1 п.1, п.4) |
| `stride-s` | 60 | минутная сетка режима; перекрытия окон соседних τ' снимает «без возвращения» |
| ускорения (1) пред-отсев по ln σ0, (2) индекс интервалов `used` | Разрешены как точные. Гейт: на малом срезе выбранные пары `c3-*.csv` байт в байт до/после ускорения; разбивка счётчиков отказов может отличаться — печатать обе. | A9/«ускорение — только байт в байт» |
