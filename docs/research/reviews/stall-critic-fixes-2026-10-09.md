## Чего не хватает (класс «неизвестно = живо» и «ничего не происходит N часов»)

**П-1 (БЛОКЕР, нового нет в отчёте): сторож жизни смотрит ход работы, а не живость ждущего.** Для тикета в `waiting` с
`host:`-целью: если цель не выполнена И у тикета нет ни одного задания alsched в `running/queued` (имена заданий несут
номер тикета; адаптер `lifewatch.py`/`RPV_JOB_STATE_CMD` уже есть для `job:`) дольше 15 мин — будить исполнителя тикета
с причиной («ждёшь X, работающих заданий 0, последние: rc …»). Поймал бы оба: TK-114 — задания tier1 кончились 05:58,
работающих 0 → будит ~06:15 (даже при кривой форме, т.е. страхует К1.1); TK-115 — последнее задание 10:24, 264/275,
работающих 0, ждущий юнит «жив» → будит ~10:40. Проверка: воспроизвести на копии состояния обоих тикетов — тревога ≤ 3 циклов.

## Минимальный набор

1. **БЛОКЕР** К1.1 (+проверка формы в стороже той же функцией).
2. **БЛОКЕР** К2.1+К2.2: rc≠0 → будить исполнителя с причиной из systemd.
3. **БЛОКЕР** П-1: «ждёт, а работающих заданий нет» → будить исполнителя.
4. **ПОТОМ** К2.5 (`--mem` по пику пилота), К2.3 (автоповтор OOM).
