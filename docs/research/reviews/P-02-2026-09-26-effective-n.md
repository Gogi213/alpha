# Проверка Судьи: правка `effective_n` (aed6288, `docs/findings/effective-n-fix-2026-09-26.txt`) (2026-09-26)

**Итог: вернуть.** Правило «оценка > n → не определено» (это было моё предложение) на независимых данных даёт
«не определено» в 63–80 % случаев при любой длине ряда. Чем сильнее положительная зависимость, тем «не определено»
реже, то есть вердикт становится доступнее для более зависимых рядов. Это обратное тому, что нужно. Заменить потолком:
`factor < 1` → `n`, иначе `n / factor` (≤ n). Вердикты П-02 не меняются ни при одном из двух правил.

## Что проверено

- Код: `effective_n.py:96` (`factor < 1` → `None`), вызывающие `p02-wall/wall2/wave3-analyze`, порт
  `p02-h10-fix-analyze.py`, тест `tools/compute/tests/test_effective_n.py`; `tools/compute/tests` — 39/0 (сам).
  «До» воспроизводит опубликованные JSON — принимаю по отчёту (таблица «до → после» на 45 оценок).
- Сам: моделирование AR(1), 4000 повторов на точку, `reviews/scripts/effective-n-sim.py`. Длина ряда 23 (сентябрь П-02),
  40, 100, 290 (диапазон точки чтения П-01). При n = 23 окно лагов — 5.

## Почему правило не годится

| AR(1) φ | n | истинное эфф. N | «не определено» (aed6288) | доля ≥ 30 (aed6288) | доля ≥ 30 (потолок n) |
|---|---|---|---|---|---|
| 0 (независимы) | 23 | 23 | 78 % | 0 % | 0 % |
| 0 | 40 | 40 | 80 % | 10 % | 90 % |
| 0 | 100 | 100 | 73 % | 27 % | 100 % |
| 0 | 290 | 290 | 63 % | 37 % | 100 % |
| +0,2 | 290 | 193 | 30 % | 70 % | 100 % |
| +0,5 | 290 | 97 | 4 % | 96 % | 100 % |
| −0,3 | 290 | 539 | 98 % | 2 % | 100 % |

Причина: выборочные автокорреляции короткого ряда смещены вниз (≈ −1/n на лаг), поэтому сумма часто отрицательна и
у независимого ряда. «Не определено» в таких случаях — шум оценки, а не свойство данных. С потолком n независимый
ряд из 290 суток проходит порог 30 всегда, как и должен.

## Что сделать (вернуть)

1. `effective_n_from_autocorr`: `factor < 1` (в т. ч. ≤ 0) → `float(n)`; иначе `max(1, n / factor)`. Больше n не
   бывает никогда. Докстринг: «нет признаков положительной зависимости → n».
2. Тест: на белом шуме n = 23 значение всегда ≤ n и в большинстве случаев = n; антиперсистентный ряд → n; AR(1)
   φ = 0,5, n = 290 → медиана < n; белый шум n = 40 (фиксированный seed, 2000 рядов) → доля ≥ 30 не меньше 85 %.
   На aed6288 последний тест должен падать.
3. Вызывающие: обработку `None` можно оставить, она безвредна; порт H10 — то же правило, что в навыке.
4. Отчёты: вместо «не определено» — число с пометкой «= n (потолок)». Таблица до/после — заново. Мои
   `reviews/scripts/p02-stage{2,3}-analyze.py` при потолке менять не нужно (на входе снова число).
5. П-02: при потолке эфф. N сентября ≤ 23 < 30 → «не ясно» у всех, как и сейчас. В августе потолок даёт 31 только
   у соседей и контролей (`g08_neighbor` 34,3, `g08_strat_side_bid` 87,3, `g08_strat_size_lo` 31,0, `g46_mismatch300`
   43,3 → 31) и у пары (было 31 в опубликованном блоке B). У основных вариантов август < 30 (Г-28 9,8, Г-08 12,7, Г-07
   10,5, Г-36 22,3, H10 28,1, H7 14,8). Вердикты не меняются — это подтвердить в новой таблице.

## Не блокирует — в навык (правит Исследователь, принимает Судья)

Даже с потолком оценка на коротком ряде **завышена при положительной зависимости**: φ = 0,5, n = 40 — медиана 29,6 при
истинных 13,3, порог 30 проходит в 50 % случаев. Значит, порог «≥ 30 эфф. N» при n < 100 нестрог. В
`references/07-effective-sample.md` записать это смещение, а для решений у порога при n < 100 добавить вторую
проверку: интервал блочным бутстрепом по суткам. К точке чтения П-01 это важно; сейчас П-02 не задевает.
