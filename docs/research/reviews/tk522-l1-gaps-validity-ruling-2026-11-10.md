## 2. Validity покрывает 8 % плана — счёт не запускается (16.5 в силе)

«strict только по ногам со строками» — **отказ**: это либо молча считает годными 92 % плана без проверки, либо
молча выкидывает их — оба нарушают 16.5. Решение:
- `validity` строится **на весь план D1** (Binance, OKX, Bitget, Bybit, Gate; HL — по mid, 16.4) теми же
  правилами G0 (r2 §2.3), **по L1** — той же книге, что считается (16.1), не по сырью;
- критерии r2 §2.3, которые на L1 посчитать нечем (непрерывность `update_id`, если её нет в формате L1), —
  колонка «неприменимо» с причиной, печатается долей; час не бракуется по неприменимому критерию (В-115);
  кроссированная книга, возраст лучших цен `S_max`, сверка mid с mark (CHFT; Bybit/Gate — публичные свечи 1 м),
  часы бирж — применимы и считаются;
- дыры класса 3 выше — строки «негодно, `404`»; гейт покрытия 100 % (нога, час) — как в 16.5, до счёта;
- прежние строки G0 08.11 (2 394 нога-суток) — сверка «G0 против L1-validity» справкой по совпадению вердикта часа,
  порога нет.
