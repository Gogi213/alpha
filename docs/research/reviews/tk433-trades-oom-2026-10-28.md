# TK-433 v10 — задание К4–К8 (tk433-trades.py) упало oom-kill: решение Судьи (28.10 ~03:25)

**Факт.** Сторож 03:20: `tk0s-tk433-trd-1028001645106` — oom-kill (выше MemoryMax), `trd.done` не будет.

**Причина (по коду `tools/compute/tk433-trades.py`, коммит d4af4849).** `load_lin`/`load_spot` читают ВСЕ сделки
инструмента за месяц в список кортежей Python (~150–200 байт на сделку) и только потом `np.array`; для спота ещё раз
грузится весь линейный фьючерс (`L`). Ликвидные инструменты TK-417 — десятки–сотни млн сделок → память юнита кончается.
Метод (окна [p−60, p], [p+1, p+60], признаки К4–К8) не виноват — виновата загрузка.

**Решение: перезапустить после правки загрузки, метод не менять.**
1. До чтения файла собрать по инструменту множество нужных минут (пик ±60 по всем строкам этого инструмента, с
   контролями) и при чтении строк оставлять только сделки из этих минут (`int(t//60) in need`); остальное не хранить.
2. Для `L` (фьючерс к споту) — тот же фильтр по минутам строк спота; не грузить второй раз весь месяц.
3. Сразу в массив numpy по дням (или `array('d')`), без списка кортежей.
4. Гейт: на 2–3 малых инструментах выход до/после правки — байт в байт (тот же csv), затем боевой прогон alsched 15 ядер
   (по инструментам параллельно, если память позволит), новый `wait_for` на `trd.done`.
