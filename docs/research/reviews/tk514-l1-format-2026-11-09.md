## 2. Назначение: формат L1 (до счёта)

1. **Где L1 считается.** L1 — состояние книги в конце пакета `(event_type, final_update_id, event_time)` по правилам ядра (`book.rs`): внутри серии снимка не публикуется, `bid ≥ ask` не публикуется. Запись — только при изменении `(bid, bq, ask, aq)`. Время — `event_time` (как ядро, отчёт TK-500 §5 допущение 4).
2. **Файл** — тот же 33-байтный `.bin` ядра (`event_time i64, final_update_id i64, price f64, qty f64, flags u8`), чтобы ядро читало его без нового читателя. Смена L1 пишется строками одного пакета (одно `event_time`, один `final_update_id`): новая лучшая цена с размером; старая лучшая цена, ушедшая из L1, — строкой с qty = 0 и **новым флагом бит2 = «уровень вышел из L1, не удалён»** (если уровень действительно удалён в сырье — бит2 = 0). В начале каждого часа — снимок (бит0) из двух строк, как сейчас (часы независимы).
3. **Почему бит2 обязателен.** `fills.rs:110-117`: на каждой строке по цене заявки зовутся `on_depth(prev, qty)`, а в режиме `drain` (биржи без сделок) убыль = сделка → `on_trade` → **исполнение**. Без бита2 уход нашей цены из L1 читался бы как снятие всей очереди впереди (prob:3) или как сделка (drain) — ложные исполнения, смещение в плюс. Правило ядра для строки с бит2: заявку по этой цене не трогать (ни `on_depth`, ни `on_trade`), очередь заморожена; при возврате цены в L1 видимый размер `q1` против последнего видимого `q0`: `q1 < q0` — `on_depth(q0, q1)` (без `on_trade`, и в drain — тоже без исполнения), `q1 ≥ q0` — без изменения. Пересечение лучшей цены (`on_cross`) работает как сейчас — L1 его видит.
4. **Хранение** — по `(биржа, контракт, сутки)`: `<ЧЧ>.l1.bin` 24 файла, сжатые zstd (уровень — замером на пробе, не выше времени конвертации); сделки — существующий `trades` 25 Б (`pq2bin trades`), без изменений.
5. **Признаки, которым нужна глубина** (`feats.rs`): `depth_slip` (VWAP 1000 USDT вглубь) и `bookimb` (top-5) на L1 не считаются. Замена — `l1_notional` = min по ногам номинала USDT на стороне нашей заявки (ask дорогой, bid дешёвой) и `bookimb1` = (bq − aq)/(bq + aq) по ногам с тем же знаком `dir`, что сейчас. Это правка протокола П-40 §3.5 / §3 п. 7 (число контрастов прежнее, 16) — пишет Исследователь, отклонение от r3 записать до счёта D1/D2. **Одна система:** счёт D1/D2 по всем парам — на L1, и для уже скачанных полных книг (L1 из них тем же конвертером), чтобы пары были сравнимы.
