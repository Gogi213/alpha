## Что исправить (v2)

1. **C1 подобран по σ 24 ч — это и есть «спокойно до»/дормантность**, которую владелец велел искать как общее; `range_bps_pre`,
   `amd_*_range_vs_base` и т.п. против такого C1 дадут ≈0 по построению. Решение Судьи: основной C1 для шага 3 = та же монета,
   длительность, час UTC ±1 ч, терция `ход_BTC`; квинтиль σ24ч пишется столбцом контроля. Вторичное чтение «сверх режима
   волатильности» — подвыборка контролей той же квинтили σ (тот же файл), справка. Признаки, совпадающие с условиями подбора
   (`btc_ret_bps_leg`, час), — список «подобрано, не тестируется», вне M.
2. **Тавтология ноги.** Событие = ход цены ≥ порога, у контроля хода нет: ценовые признаки фазы `leg` (`ret_bps_leg`,
   `range_bps_leg`, `leg_*`, `sw_*_swept_n`/`_top_over_bps`, `htf_*_over_bps_leg`, `amd_*_break`, `smt_*_swept_leg`…) отличаются
   по определению. Записать до счёта поимённый список «по определению»: вне M и вне таблицы «общее» (в классификации — можно,
   это форма). Не-ценовые признаки ноги (оборот, сделки, OI, фандинг, базис, корреляции) — тестируются.
3. **p-значение — перестановкой внутри подобранной четвёрки** (событие ↔ 3 контроля, та же процедура, что MDE §7), не долей
   бутстреп-δ ≤ 0 (перцентильный бутстреп при десятках кластеров антиконсервативен, BH на нём не держится). Бутстреп по монетам —
   только интервал.
4. **Нулевая модель и разрезы — дописать правила:** (а) признаки, не определённые у контроля (`T_min`, `a_T*`, `тип_пары`,
   `доля_монет_рынка`), — нулевая на C1 и сравнение с ней идут на общем подмножестве признаков; полный набор — описательно;
   (б) C1 подвыборкой до N событий того же знака, 200 прогонов; (в) §6 п.2 переписать однозначно: «в каждой части каждого
   разреза доля бутстреп-δ того же знака ≥ 90 %»; часть разреза с числом кластеров ниже назначенного протоколом минимума →
   «не проверяемо», ячейка не «общее»; (г) события на краях интервала z\*/a\*_T для п.8.2 — кто считает (код TK-421) и когда.

## Ответы на §11
1. q\*=0,10, δ Клиффа (парный), разрезы (а)(б)(в) — да (с п.3).
2. Порог ARI/Jaccard из нулевой + 0,75 справочно, k ≤ 6, отсев `нет_данных` > 20 % — подтверждаю (отсев считать по пулу; доля по
   биржам — в отчёт).
3. Контроли C1/C2 даёт TK-421 (P-TK421 v6 §6: «B2b — … контроли C1/C2»), в формате окон `tk422-probe-windows` с фазами
   pre/leg/post в долях длительности, C1 по п.1. Если B2b их не сдаёт — хвост TK-421, не работа шага 3.
4. Один проход Судья+владелец достаточен; «спорно» — вне основного счёта, чувствительность «с ними» — справкой.
