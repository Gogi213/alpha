# П-09. Г-55 как правило выхода: съедание стены после входа, «рынок» и «местный» раздельно

Статус: **Судья — принято при условиях 1–4 (`035f674`, `reviews/P-09-2026-09-28-protocol.md`), вписаны 28.09 ~04:55;

как фильтр входа почти не действует (проба 04.08: съедания за 60 с до взвода нет у 96/96), по смыслу — форма выхода.
Код — Инженер, `docs/findings/tk014-design-2026-09-28.md` (форма `weat<X>s<W>{m|l|a}<Y>` на оси `--exit-form`).
Всё, что здесь не сказано, — как П-08 (`P-08-new-code-7.md`: данные §4, метрика §6, правило §10 с В-146, §12 п. 14–15).

## 1. Вопрос и решение

Улучшает ли KPI (В-120) базы выход из позиции, когда после входа стену едят сделками, — отдельно при съедании «рынком»
(BTC падает) и «местным продавцом» (BTC стоит)? Август/сентябрь — развитие (Г-55 выбрана на них, TK-011), июль —
проверка. «Да» на июле → январь–июнь (правило чтения — до их чисел). «Нет» → «края нет» для этого режима на этой базе.

## 2. Механизм и направление (до счёта)

Стена, на которую опирается лонг, съедается сделками — пробой вероятнее отскока; выйти по рынку раньше стопа pct2.
- **(m) «рынок»:** съедание при падающем BTC — внешний драйвер; стену сносит волна.
- **(l) «местный продавец»:** съедание при стоящем BTC — продавец монеты, он не уйдёт с BTC (механизм Г-55, П-08 §2).
- **(a) оба** — выход при любом BTC: сравнение, не третья гипотеза.

Направление каждой клетки одно: выход лучше удержания (доля часов ожидания ниже). Вторичный прогноз механизма —
(l) полезнее (m) (при (m) BTC может отскочить и увести монету с собой) — только описание, вердикт не меняет.

**Приор против (условие Судьи 2):** E19 (23.09, `exit-titration-2026-09-23.md` п. 4) — выход `eat20` (форма F7: сделки
по цене стены **с входа** ≥ 20 % размера стены **на входе**, сделки обеих сторон — Судья `97eade9`, поправка к условию 2)
вредит везде: +27,2 → +1,6 bps на историю. `weat` отличается: только продажи в стену (сторона сделки по всем битам
маски), доля — от наибольшего видимого размера в скользящем окне 60 с, а не накопленное с входа от размера на входе;
плюс разделение по BTC. Ближайший прежний замер — против направления (a).

## 4. Клетки (значения назначены до счёта)

Клетка = база + `--exit-form weat<X>s<W>{m|l|a}<Y>`, всё остальное как у базы.

| параметр | значение | откуда (не по исходу) |
|---|---|---|
| **W** | **60 с** | окно ленты TK-012 / Г-55 П-08 §7 («прямо сейчас»); меньше минуты BTC не видно (минутный ряд) |
| **X** основная | **50 %** наибольшего видимого размера стены в окне | «съели половину» — `eat50`, решение владельца 21.09 (В-80) |
| **X** сосед | **20 %** | `eat20`, тот же В-80 |
| **Y** | **5 bps** | П-08 §7 Г-55: «шум минуты BTC, не ход» |

Имена: `p09-<база>-<режим><X>`, 2 базы × 3 режима × 2 X = **12 клеток**:
`p09-b-m50` `weat50s60m5`, `p09-b-l50` `weat50s60l5`, `p09-b-a50` `weat50s60a5`, `p09-b-m20`, `p09-b-l20`, `p09-b-a20`
(`weat20s60…5`) — на B1; `p09-m-…` — те же шесть на M.

**BTC:** `--btc-minutes epochs/e-jul/study/regime/ref-BTCUSDT-1m.csv --btc-minutes epochs/e-aug/study/regime/ref-BTCUSDT-1m.csv`
(на деке; проверено 28.09: 01.07–23.09 — 122 400 минут без пропусков в `e-crash`, `e-jul` и начало `e-aug` с ним
совпадают по `close`; `e-aug` идёт до 24.09 — хвост дедлайна 23.09 покрыт; Судья: 30.06–24.09 без пропусков). Ход BTC — последняя закрытая минута против
`k = ceil(W/60) = 1` минутой раньше (дизайн TK-014): запаздывание до 60 с — свойство данных, в отчёте.

**Достижимость (условие Судьи 1, до счёта, без исхода):** доля минут BTC close→close ≤ −5 bps — июль 9,7 %, август
8,9 %, сентябрь 10,7 % (≤ −10 bps — 2,2–2,4 %). Режим (m) редкий: ожидаемо 10–30 % выходов (a); (l) почти совпадает
с (a) — почти одна находка (вложенность, прецедент H9р/H14). Клетки `m` могут оказаться «не определены» по охвату
(§8.1); Холм m = 6 остаётся — он строже.

## 5. Метрика

Как П-08 §6: главная — доля часов с ожиданием перехая > 5 сут (июль 744 ч; август — все t; сентябрь — t ≤ 19.09);
рядом — наибольшее ожидание, $ за месяц, парная Δ$ к своей базе по суткам (бутстреп, блок ⌈n^{1/3}⌉, 20 000).
**Охват** — доля сделок базы, закрытых этим выходом (`exit_reason` = `wall_eat_btc` / `wall_eat_local`), по месяцам;
третьи — стопы, худшие сутки, $ сделок с выходом против тех же сделок у базы (по ключу сигнала).

## 6. Счётчик испытаний

- **Семья (Холм, по месяцу отдельно, по базе отдельно):** m = 6 на базу.
- **Сквозной (контекст):** П-08 165 + П-07 H13 (выходы `gone*`, 24) + поиск выхода 25.09 E27–E34 (~60) + E19 `wall`

   доливаются в незапущенные сутки П-08 (как слияние TK-009), уже посчитанные сутки — отдельным вызовом только с П-09.
2. **Ворота до чтения:** (а) без флага — байт в байт `bin/alpha-a5d4e3a` на 03.08 (гейт Инженера); (б) базы в этом
   прогоне = прежние `p07b-base` / `titrc-u500r` на 03.08, кроме строки `#`; (в) согласованность режимов по ключу
   сигнала до `busy-replay` (условие Судьи 4): время выхода `a` = min(выход `m`, выход `l`) с тем же `exit_reason`;

   у всех клеток = базе. Это единственная проверка логики нового кода на данных. Красное — стоп, запись, не читать.
3. **Авг/сен** — по клетке и месяцу §5; Холм m = 6 по Δ$; устойчивость (без одних суток, без монеты с наибольшим вкладом).
4. **Июль** — печать: только статусы ворот и путь; числа июля — только у клеток, прошедших §8.1, и у баз;
   остальные — в файл, запечатано (грабли TK-004).
5. **Отчёт** `docs/findings/p09-<дата>.md` + `.json`, по месяцам отдельно; KPI-колонка у каждой клетки. Рядом с (m)
   против (l) — доля выходов, где класс по последней закрытой минуте совпадает с классом по минуте, содержащей выход
   (заглядывание — только описание, в правило не идёт; условие Судьи 3).

## 8. Правило вердикта (П-08 §10 с В-146)

1. **Отбор на июль:** итог $ клетки за август ≥ 0 **и** за сентябрь ≥ 0 — и только это (В-146); идут все такие клетки.
   **Охват (H9р, условие Судьи 1):** < 10 выходов `wall_eat_*` в месяце — клетка в этом месяце «не определена»
   (p = 1 в Холме, m не уменьшать); отбор на июль по В-146 это не блокирует.
2. **Июль (клетка против своей базы, парно по суткам):** С1 доля ≤ доля базы − 0,10; С2 то же без любых одних суток;
   С3 верхняя граница 95 % Δ$ ≥ 0. Все три — «подтверждено на июле» → январь–июнь. С1 нет и в августе или сентябре доля
   клетки > доли базы − 0,10 — «стоп». Иначе — «не ясно» → январь–июнь как описание. Холм на июле — m = число
   прочитанных клеток; П-07 §10 (≤ 0,10 абсолютно) — рядом, не блокирует.
3. «Лучший режим/порог» не называется (максимум шума); (m) против (l) — описание по §2, парно по суткам.
4. Январь–июнь — правило чтения записывается до их чисел.

## 9. Что нужно от кода (TK-014, Инженер)

Форма `weat<X>s<W>{m|l|a}<Y>` и `--btc-minutes` по дизайну; `rounds.csv` `exit_reason` раздельно; без формы — байт в байт;
в `rounds.csv` — ключ сигнала и время выхода, достаточные для ворот §7 п. 2(в). **Живой бот** берёт то же определение
хода BTC (последняя закрытая минута) — иначе это другое, не проверенное правило (условие Судьи 3).
