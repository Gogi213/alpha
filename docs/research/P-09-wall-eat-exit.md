# П-09. Г-55 как правило выхода: съедание стены после входа, «рынок» и «местный» раздельно

Статус: **черновик 28.09 ~04:40 (GMT+4)** — ждёт Судью (@judge) и «ок» владельца; значения X/W/Y — здесь, до счёта.

## 1. Вопрос и решение

Улучшает ли KPI (В-120) базы выход из позиции, когда после входа стену едят сделками, — отдельно при съедании «рынком»
(BTC падает) и «местным продавцом» (BTC стоит)? Август/сентябрь — развитие (Г-55 выбрана на них, TK-011), июль —
проверка. «Да» на июле → январь–июнь (правило чтения — до их чисел). «Нет» → «края нет» для этого режима на этой базе.

## 2. Механизм и направление (до счёта)

Стена, на которую опирается лонг, съедается сделками — пробой вероятнее отскока; выйти по рынку раньше стопа pct2.
- **(m) «рынок»:** съедание при падающем BTC — внешний драйвер; стену сносит волна.
- **(l) «местный продавец»:** съедание при стоящем BTC — продавец монеты, он не уйдёт с BTC (механизм Г-55, П-08 §2).
- **(a) оба** — выход при любом BTC: сравнение, не третья гипотеза.

Направление каждой клетки одно: выход лучше удержания (доля часов ожидания ниже). Вторичный прогноз механизма —
(l) полезнее (m) (при (m) BTC может отскочить и увести монету с собой) — только описание, вердикт не меняет.

## 4. Клетки (значения назначены до счёта)

Клетка = база + `--exit-form weat<X>s<W>{m|l|a}<Y>`, всё остальное как у базы.

| параметр | значение | откуда (не по исходу) |

| **W** | **60 с** | окно ленты TK-012 / Г-55 П-08 §7 («прямо сейчас»); меньше минуты BTC не видно (минутный ряд) |

## 5. Метрика

Как П-08 §6: главная — доля часов с ожиданием перехая > 5 сут (июль 744 ч; август — все t; сентябрь — t ≤ 19.09);
рядом — наибольшее ожидание, $ за месяц, парная Δ$ к своей базе по суткам (бутстреп, блок ⌈n^{1/3}⌉, 20 000).
**Охват** — доля сделок базы, закрытых этим выходом (`exit_reason` = `wall_eat_btc` / `wall_eat_local`), по месяцам;
третьи — стопы, худшие сутки, $ сделок с выходом против тех же сделок у базы (по ключу сигнала).

## 8. Правило вердикта (П-08 §10 с В-146)

1. **Отбор на июль:** итог $ клетки за август ≥ 0 **и** за сентябрь ≥ 0 — и только это (В-146); идут все такие клетки.
   Охват < 1 % сделок базы в месяце — пометка «почти не действует» (клетка ≈ база), отбор не блокирует.
2. **Июль (клетка против своей базы, парно по суткам):** С1 доля ≤ доля базы − 0,10; С2 то же без любых одних суток;
   С3 верхняя граница 95 % Δ$ ≥ 0. Все три — «подтверждено на июле» → январь–июнь. С1 нет и в августе или сентябре доля
   клетки > доли базы − 0,10 — «стоп». Иначе — «не ясно» → январь–июнь как описание. Холм на июле — m = число
   прочитанных клеток; П-07 §10 (≤ 0,10 абсолютно) — рядом, не блокирует.
3. «Лучший режим/порог» не называется (максимум шума); (m) против (l) — описание по §2, парно по суткам.
4. Январь–июнь — правило чтения записывается до их чисел.
