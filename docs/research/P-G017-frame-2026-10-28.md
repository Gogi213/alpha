# P-G017 — общая рамка методики для всех гипотез G-017 (пампы/дампы, трек А) — Судья, 28.10

Статус: **действует с 28.10.** Задача — TK-437 (владелец 28.10: «можно пересмотреть алгоритмы? ускорить кратно»; за ночь
~15 возвратов протоколов TK-421/TK-433). Рамка собрана только из уже утверждённого: v9b
(`P-TK433-pump-v9b-2026-10-28.md`), правки контроля (`reviews/tk433-controls-sf-2026-10-28.md`,
`reviews/tk434-control-choice-2026-10-28.md`), v10 (`reviews/tk433-protocol-v10-2026-10-28.md`), v11
(`P-TK433-v11-window-vol-2026-10-28.md`), код `tools/compute/tk433-analyze.py`. Новых чисел рамка не вводит.

**Как работает:** новая гипотеза/вариант = строка в реестре `docs/research/g017-hypotheses.csv` + дельта-заявка (§9) в
тикете. Заявка в рамке → считается сразу, без протокола и без ожидания Судьи; Судья сверяет заявку с рамкой при приёмке
результата. Возврат — только за выход за рамку (§10) или расхождение счёта с заявкой.

## 1. События — только цена (признак никогда не фильтр)

Разрешённые определения (любое из них, вариант называется в заявке):

| id | определение | параметры (только эти) |
|---|---|---|
| EV-Z | нога зигзага по close 1 м, порог разворота θ = a*_T рынка (`b1-thresh-2026-09.json`), длительность старт→пик ≥ 90 мин (число владельца), верхней границы нет | T ∈ {5, 15, 60}; 240 — чувствительность |
| EV-W | окно [t, t+D] с ходом ≥ X_D; X_D = квантиль |хода| всех окон длины D всех монет Bybit+Gate месяца (шаг 1 мин); пересекающиеся окна монеты и знака склеиваются | D ∈ {1,5; 3; 6; 12; 24} ч; X = q99 (q98, q99,5 — чувствительность) |

Знак — вверх (памп) и вниз (дамп) отдельно, всегда оба. Нога/окно короче 90 мин — не событие G-017.

## 2. Исключения и склейки (одни для всех; в csv остаются с причиной, ступень воронки)

E1 токены с плечом (по имени) · E2 ребалансы TK-431 и артефакты бирж (`tk421-art.py`, Gate 30.09 08:00) · E3 пересечение с
рыночным периодом L4 v8 своего знака · E4 фитиль (для EV-Z: ход без лучшего 10-мин блока < θ; для EV-W: возврат ≥ 50 % за
≤ 15 мин после пика, порог TK-421). Склейки: пара вверх→вниз (обе ≥ 90 мин, дамп стартует в пике); одна монета на
рынках/биржах (`coin()` из `tk421-b2b.py`) с пересечением окон — один кластер, представитель — рынок с наибольшим
оборотом, остальные — столбцами.

## 3. Контроли

- **Главный:** до 5 окон той же монеты/рынка, той же длины, того же часа UTC, в пределах месяца (±30 сут), не
  пересекающих события любого варианта; доля минут со свечой ≥ как у события; детерминированно (md5, seed 433) —
  `cmd_windows` в `tk433-features.py`. Норма признака у контроля — та же формула, что у события.
- **Обязательная проверка знака:** ближайшие окна той же монеты до старта, любой час (месяц + предыдущий), признаки
  оборота/волатильности делённые на суточный профиль монеты (TK-434); ±7 сут тот же час — чувствительность.
- События без контроля в r не входят; отдельная строка: N по рынку/знаку, медианы длительности и |хода| «с контролем»
  против «без»; вывод — «на N из M событий».

## 4. Метрика

**r = log(признак события / медиана признака его контролей)** для положительных величин (оборот, волатильность, меры
ATR/RV/…); **r = признак − медиана контролей** для разностных/долей (покупки, базис, спот↔фьюч, OI-изменение, фандинг) —
как `rval` в `tk433-analyze.py`. Нормировка к собственной норме монеты — медиана той же меры за 7 сут до старта без
минут других событий; < 3 сут истории — отдельная строка воронки. Волатильность внутри события — за вычетом среднего хода
(иначе тавтология с отбором по ходу). Положение — «до» (окно кончается в t_start), «внутри», «после» (для конца); окна
до/после — 60 мин (назначено Судьёй, v10) либо окно меры из заявки.

Нуль — «контроль против остальных контролей своего события» (только при ≥ 2 контролях; N нуля — в отчёте). Доля событий
«с повышенным» = доля r выше q95 нуля, с интервалом.

## 5. Интервал и поправка

- Бутстреп по монетам (кластер-события), B = 4000, seed 433; p = 2·min(доля ≤ 0, доля ≥ 0) + 1/B (как код).
- Строка оценивается при N ≥ 8 событий и ≥ 5 монет (код); иначе «нет данных», но в семействе остаётся.
- **Семейство = вся заявка:** все её строки × варианты событий × D × положение × знак, число пишется в заявке до счёта.
  Холм внутри семейства (интервал на уровне 0,05/k шага). Холм консервативен при коррелированных мерах — принимаем.
- **Расширение семейства:** новая заявка — новое семейство; реестр ведёт накопленное число испытаний G-017, оно — в
  каждом отчёте владельцу. Защита от перебора между заявками — подтверждение на другом месяце (§6), не общий Холм.

## 6. Месяцы и правило вердикта

- Вердикт — сентябрь 2026. **Подтверждение — другой месяц** (август; январь–июль — после приёмки TK-428): тот же знак
  медианы r, p < 0,05, один тест на строку (не семейство).
- По строке: **подтверждено** — нижняя граница интервала (Холм) > 0 **и** знак совпал в проверке контроля (§3) **и** знак +
  p < 0,05 на месяце подтверждения; **оспорено** — верхняя ≤ 0 при тех же двух проверках; иначе **не различимо**; один
  месяц без подтверждения — «подтверждено на сентябре, не проверено» (не вывод для владельца).
- Выбор «лучшей» меры/варианта — только на сентябре по p-Холм, затем |r|; на месяце подтверждения выбранное проверяется
  одним тестом. Выбор по r на месяце подтверждения запрещён.

## 7. Числа и сетки

Разрешены только: числа владельца (90 мин, 1,5 ч, ТФ ≤ 5 м); квантили распределения самих данных (q98/q99/q99,5, q95
нуля); пороги из существующих артефактов (`b1-thresh`, TK-421, TK-431, L4 v8); сетки шагом ×2 (D; титрование ×1/8…×8 —
описательно, вне семейства); окна 60 мин. Любое другое число — выход за рамку.

## 8. Сдача (одна форма для всех)

`docs/findings/pump-<H-id>-<дата>.csv` — события (монета, рынок, знак, t_start/t_peak/t_end, ход, длительность, кластер,
причина исключения, признаки, r) и `pump-<H-id>-r-<дата>.csv` — таблица r (N, монет, медиана r, lo/hi, p, k шага, вердикт,
N нуля, доля выше q95 нуля, знак проверки контроля, знак/p месяца подтверждения); `pump-<H-id>-<дата>.md` — воронка,
таблица, накопленное число испытаний G-017, вывод не сильнее замера. Код — `tools/compute/`, счёт — alsched NX=15.

## 9. Дельта-заявка (в лог тикета до счёта, коммитом раньше любых файлов исходов)

```
H-id: H-0NN (строка добавлена в g017-hypotheses.csv)
вопрос: <одна фраза; чьё слово>
события: EV-Z T∈{…} | EV-W D∈{…}
признаки/меры: <id, формула, окно, положение; источник данных + валидация>
вид r: log | разность
семейство: <строк> × <вариантов> × <положений> × 2 знака = K
месяц подтверждения: август | <месяц>
числа: <каждое — со ссылкой на §7>
вне рамки: нет | <что — тогда протокол>
```

Судья при приёмке результата сверяет: заявка закоммичена раньше исходов; всё в §1–§8; счёт = заявке. Расхождение — return.

## 10. Выход за рамку — нужен протокол (P-TK…) с утверждением Судьи

Новое определение события (не EV-Z/EV-W) или событие по не-ценовому признаку; признак как фильтр/условие отбора; другая
метрика вместо r; другой контроль или отказ от проверки знака; изобретённое число (§7); новый источник данных без
валидации; выбор варианта после исходов; торговый вывод (вход/выход/стратегия, трек Б) — навык `alpha-research` целиком.
