# П-01. Держится ли главный вариант и кандидаты выхода на новых сутках

**Статус:** черновик — ждёт утверждения владельцем (переписан из предрегистрации E35, 25.09)
**Реестр:** `docs/plan/EXPERIMENTS.md`, П-01 (= E35) · **Журнал:** `docs/research/JOURNAL.md`

## 1. Вопрос и решение
- Вопрос: зарабатывает ли главный вариант В-104 на сутках, которых не было ни в подборе, ни в чтении;
  улучшают ли его выходы Г-24/25/26.
- «Да» (главный) → готовить живой бот на главном варианте (B2: стратегия в `lob/`), малым размером.
- «Нет» → главный вариант не запускать; вернуться к поиску входа (очередь В-101).
- «Не ясно» → продолжать копить сутки до следующей точки чтения (§8), ничего не меняя.
- Кандидат выхода «да» → включить в главный вариант новым протоколом проверки; «нет» → в архив.

## 2. Механизм
Лонг от старой крупной бид-стены в просадке BTC: продавцы в панике доходят до стены, крупный покупатель
держит уровень, отскок. На другой стороне — вынужденные продажи (ликвидации, стопы) в падении рынка.
Механизм правдоподобен, но не измерен напрямую (поток сделок перед входом не замерен).

## 3. Гипотеза и опровержение
- H1: главный вариант даёт $ > 0 в месяц на позиции $500 / счёте $2500 вне выборки.
- Опровергает: $ ≤ 0 за месяц проверки при числе суток не меньше точки чтения (§8).

## 6. Метрика
- Главная: $ за календарный месяц, бэктест главного варианта (для кандидатов — Δ $ к базе пересчёта по свечам).
- Вспомогательные: сделок, стопов, худшие сутки, просадка счёта.

## 7. Бюджет испытаний
4 варианта (главный + 3 кандидата), больше не добавляется. Поиск, из которого они вышли (~60 вариантов
выхода E27–E34), учитывается поправкой для кандидатов.

## 8. Размер выборки и точка чтения
- Наблюдение — сутки. **Замер 25.09** (поиск, счёт дашборда `data/titration-dashboard/data-merged.json` →
  `account.<месяц>.btc4h_trail.daily_usd`; сверка метода: сумма суток = `net_usd` в обоих месяцах):
  август — среднее +$3,7/сут, σ $31/сут (29 суток), 95 % интервал месяца [−$214; +$441], P(месяц ≤ 0) ≈ 0,26;
  сентябрь — +$4,9/сут, σ $16/сут (21 сутки), [−$40; +$235], P ≈ 0,08 (бутстреп по суткам, 20 000).
  Суток до t = 2 при таком среднем: ≈ 40 (как сентябрь) … ≈ 290 (как август). Средние взяты с поиска и скорее
  завышены — на проверке суток понадобится больше.
- Точка чтения: <по замеру; предварительно — конец октября (первый полный месяц проверки)>.
  Прежнее правило E35 «≥ 100 сделок» заменяется до чтения: сделки не наблюдения.
- Досрочная остановка (только в худшую сторону): <по замеру σ, например убыток хуже −2σ месяца>.

## 9. План анализа
Бутстреп по суткам для $ месяца; для кандидатов — парная разница по суткам с базой пересчёта;
эффективное N (`effective_n.py`); кандидаты — DSR с учётом ~60 испытаний поиска; месяцы отдельно
(сентябрь 24–30.09 — неполный, читается вместе с октябрём только дополнительным столбцом).

## 10. Правило вердикта
<заполнить после §8 числами>: главный — подтверждён, если $ месяца > 0 и нижняя граница интервала
не хуже <…>; опровергнут, если $ ≤ 0; иначе не ясно. Кандидат — подтверждён, если Δ > 0 и
интервал Δ не накрывает 0 после поправки; иначе нет.
