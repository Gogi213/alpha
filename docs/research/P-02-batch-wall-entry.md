# П-02. Пакет: сила/подлинность стены и место входа-выхода (10 первостепенных гипотез)

**Статус:** черновик — ждёт утверждения владельцем
**Реестр:** `docs/plan/EXPERIMENTS.md`, П-02 (строка не добавлена — по правилу задания протокол не редактирует
реестр/коммитит до утверждения) · **Журнал:** `docs/research/JOURNAL.md`

Пакет собран по решению владельца 25.09: несколько гипотез кодируются одной партией, считаются
последовательно, каждая — против своей базы, с общей поправкой на число гипотез (не по одной с
перечитыванием). Источник состава — `docs/research/hypothesis-pool-2026-09-25.md`, раздел «Все
первостепенные (10)»: **Г-28, Г-33, Г-07, Г-08, Г-46, Г-36** (класс «стена») и **Г-85, Г-88, Г-86,
Г-105** (классы «вход»/«выход»). **Г-59 выведен из пакета** (следующая партия — экспорт ленты по
нему уже частично делает эту работу). **Г-01 — не 11-я гипотеза, а инфраструктура измерения**:
таблица событий подхода «устояла/пробили» нужна, чтобы вообще была база для проверки блока «стена»
(Г-28/33/07/08/46/36 — все признаки на подходе, не отдельные сделки главного варианта).

## 1. Вопрос и решение

Вопрос: какие из 10 первостепенных гипотез меняют результат — (блок A) исход подхода к стене
«устояла/пробила», (блок B) $ за месяц варианта — против того, что принято сейчас, и в какую сторону.

- Блок A, гипотеза «да» (эффект в предсказанную сторону, после поправки Холма интервал не
  накрывает 0, ≥ 30 эффективных наблюдений) → признак идёт в фильтр входа следующим протоколом
  (полная проверка `bounce-grid`/`bounce-verdict` на варианте), в `HYPOTHESES.md` статус `поиск+`.
- «нет» → в «Не повторять» банка гипотез, статус `поиск−`.
- «не ясно» (мало суток/событий, инфраструктура не готова к чтению) → не вердикт, а находка:
  доснять данные (approaches по всей записи, экспорт ленты) и продолжить тем же протоколом, не новым.
- Блок B, гипотеза «да» (Δ$/месяц > 0, интервал по суткам в паре не накрывает 0 после поправки) →
  новая форма входа/стопа заменяет текущую базу в следующей проверке главного варианта (П-01 линия).
- «нет» → форма не меняется, гипотеза — в «Не повторять» с явной оговоркой «наша форма проверена
  против их формы, разницы нет/хуже».

## 2. Механизм (по гипотезе, кратко — полные формулировки и источники в пуле)

| Г## | механизм |
|---|---|
| Г-28 | агрессору нужно снести несколько плотностей подряд (завал), а не одну — эффективная сила = стек + фронтран |
| Г-33 | заявка, которую без конца переставляют и никогда не исполняют, стоит не для сделки — декоративна, реакции цены не даёт |
| Г-07 | пустой стакан позади уровня — пробой проваливается дальше, стопы некому ловить; заваленный — гасится |
| Г-08 | на «красивых» уровнях (круглые числа, стопы) стену держит больше участников одновременно |
| Г-46 | крупный игрок лимитками против тейкерского потока — расхождение цена/CVD выдаёт его присутствие |
| Г-36 | скрытый (айсберг) участник докладывает заявку по мере исполнения — видимый размер занижен |
| Г-85 | фронтран первым принимает удар продавца — дешевле и раньше проверка сценария, чем вход вглубь стены |
| Г-88 | «закол» (свип за уровень и возврат) вычищает часть продавцов — входить нужно после возврата, не во время свипа |
| Г-86 | огромный завал редко проедается одним рыночным импульсом — на разъедании/ноже рыночный вход надёжнее лимитного |
| Г-105 | стоп внутри/за стеной ловит тот же сквиз, что её снесёт — практики ставят перед стеной, мы — за |

## 3. Гипотеза и опровержение

**Блок A** (H1–H6, метрика — доля `bounced` / markout `m_1h` на подходах, В-44 определение исхода):

- H1 (Г-28) `stack_levels + frontrun_lots` (сумма или совместный бакет) на подходе разделяет исход:
  верхний терциль эффективной силы даёт долю `bounced` выше нижнего на ≥ 5 п.п. Опровергает: разница
  ≤ 0 или интервал накрывает 0 после Холма.
- H2 (Г-33) подходы к уровню с длинной цепочкой `repriced`-замен без роста `traded_lots` (декоративные)
  реже кончаются `bounced`, чем без цепочки. Опровергает: разница ≤ 0 / не значимо.
- H3 (Г-07) высокая глубина того же борта позади уровня (вне текущего окна `DISTANCE_MAX_BPS`, за
  уровнем от середины) увеличивает долю `bounced`. Опровергает: разница ≤ 0 / не значимо, либо
  выборка `.200` (только 15–24.09) недостаточна (< 30 эффективных суток) — тогда «не ясно», не «нет».
- H4 (Г-08) `round_zeros ≥ 2` даёт долю `bounced` выше, чем `round_zeros ≤ 1`, на величину, не
  объяснимую одним размером/возрастом (контроль по этим осям). Опровергает: разница ≤ 0 / не значимо.
- H5 (Г-46) расхождение знака тейкерского потока (CVD за окно до подхода) и направления цены
  предсказывает `bounced` сильнее, чем базовая ось `flow_1h_lots`. Опровергает: не лучше базовой
  оси / не значимо.
- H6 (Г-36) уровни с быстрым (≤ несколько кадров) восстановлением после частичного сноса и
  суммарным `traded_lots` за жизнь много больше пикового видимого размера — по ним доля `bounced`
  на СЛЕДУЮЩЕМ подходе выше, чем у уровней без такого паттерна. Опровергает: разница ≤ 0 / не значимо.

**Блок B** (H7–H10, метрика — Δ$/месяц варианта против базы, парно по суткам):

- H7 (Г-85) вход только по фронтрану (`single@fr`, без ступеней вглубь) даёт Δ$/месяц ≥ 0 против
  текущей лестницы `ladder3x2..20w2`, интервал не накрывает 0 в минус. Опровергает: Δ < 0 значимо.
- H8 (Г-88) исключение входа на подходах со свежей «пружинкой» (`repeat_count > 0` в коротком окне
  перед взводом) даёт Δ$/месяц > 0 против базы без фильтра. Опровергает: Δ ≤ 0 / не значимо.
- H9 (Г-86) рыночный вход при `eaten_min` выше порога (сильное разъедание) даёт Δ$/месяц > 0 против
  лимитного входа на тех же событиях. Опровергает: Δ ≤ 0 / хуже из-за проскальзывания.
- H10 (Г-105) стоп `before` (перед стеной, `P+1`) даёт Δ$/месяц ≥ 0 против текущего `behind` (`P−1`)
  на главном варианте. Опровергает: Δ < 0 значимо (как в частичном замере B2 17.09, где все три формы
  были отрицательны на другой, ещё не главной, форме входа — `bounce-b2-stops-2026-09-17.md:33-40`).

## 7. Бюджет испытаний

По одному основному варианту на гипотезу (10), соседи — только для проверки плато, не для выбора
лучшего:

- Г-28: 1 основной (терцильный бакет суммы) + 2 соседних (другой сплит — квартили, другая сумма —
  максимум вместо суммы) = 3.
- Г-33: 1 основной (цепочка ≥ 2 без роста `traded_lots`) + 1 сосед (порог цепочки ≥ 3) = 2.
- Г-07: 1 основной (глубина за уровнем на `.200`, окно 15–21.09) + 1 сосед (тот же порог на `.50`,
  вся история, как более грубый прокси) = 2.
- Г-08: 1 основной (`round_zeros ≥ 2` против ≤ 1) + 1 сосед (порог ≥ 3) = 2.
- Г-46: 1 основной (знак CVD 60с против направления цены) + 1 сосед (окно 300с) = 2.
- Г-36: 1 основной (айсберг-паттерн да/нет) = 1 (соседей нет — бинарный признак).
- Г-85: 1 основной (`single@fr` против базы) = 1.
- Г-88: 1 основной (гейт по `repeat_count` в окне 5 мин) + 1 сосед (окно 10 мин) = 2.
- Г-86: 1 основной (`eaten_min` порог из P-90 «огромный завал» — калибровать по квантилям
  `eaten-threshold.py`, не изобретать) = 1.
- Г-105: 1 основной (`stop-form before` против `behind`) + 1 сосед (`stop-form at`) = 2.

**Итого 18 вариантов** (10 основных + 8 соседей для плато) — учитывается в поправке и в счётчике
испытаний журнала целиком, не по одной гипотезе.

## 8. Размер выборки и точка чтения

- Блок A: наблюдение — **сутки** (не событие подхода: подходы одной монеты в одном окне BTC-просадки
  коррелированы так же, как сделки главного варианта). Кластеризация бутстрепа — по суткам. Нужно
  подготовить кэш подходов на полных `e-aug`+`e-archive`/`root` (см. §4) прежде, чем считать
  эффективное N (`scripts/effective_n.py`) — до этого объём выборки неизвестен, а не мал.
- Блок B: то же, что П-01 §8 — по замеру 25.09 август σ ≈ $31/сут (29 суток), сентябрь σ ≈ $16/сут
  (21 сутки); для парной разницы по формам ожидать меньшую дисперсию (общая часть сделок), но без
  отдельного замера различимость не считать — первая точка чтения делает этот замер, вторая — вердикт.
- Точка чтения: после (а) достройки кэша подходов на обе эпохи, (б) кода T1–T2 (для H3/H5/H6),
  (в) первого прогона — считать эффективное N и объявить точку чтения числом (как П-01 §8), не датой
  заранее. Раньше — только проверка исправности (прогон прошёл, файлы на месте, K1 ok).
- Досрочная остановка: не применимо (это не живая проверка, а разовый бэктест на сожжённых данных —
  досрочно останавливать нечего, весь массив читается один раз).

## 9. План анализа

- Блок A: доля `bounced` и markout по бакетам — бутстреп по суткам (кластер), p-значение на разницу
  бакетов; поправка Холма по p-значениям **внутри блока A (6 гипотез = 6 p-значений)**, отдельно от
  блока B. Контрольные оси (возраст, размер, сторона) — как ковариаты/страты, не как отдельные
  гипотезы (иначе двойной счёт).
- Блок B: парная разница Δ$ по суткам (форма против базы на тех же сделках/сигналах), бутстреп по
  суткам, интервал; поправка Холма **внутри блока B (4 гипотезы = 4 p-значения)**.
- Эффективное N — `scripts/effective_n.py` для обоих блоков; месяцы отдельно, «август + сентябрь» —
  только дополнительным столбцом.
- DSR/PBO (`scripts/selection_bias.py`) — учитывать 18 испытаний пакета плюс сослаться на близкий
  предыдущий поиск (E27–E34, ~60 вариантов выхода) как контекст в отчёте, не складывать напрямую в
  один счётчик (разные семьи гипотез), но упомянуть как оговорку при итоговом вердикте.

## 10. Правило вердикта

Дословно по гипотезе (числа в §3); общая форма: **подтверждено**, если направленный эффект (H1,
таблица §3) присутствует и после поправки Холма (по блоку) интервал не накрывает 0 при ≥ 30
эффективных наблюдениях; **опровергнуто**, если эффект ≤ 0 либо противоположного знака значимо;
**не ясно** — иначе (в т.ч. если кэш/эффективное N до точки чтения меньше 30 — это ограничение
данных, а не отрицательный результат, оформлять отдельно от «опровергнуто»).

## 11. Цена

- Кэш подходов на обе эпохи (August + Sept, ~76 монет × ~53 суток) — по аналогии с `approach-scan.sh`
  на 4 сутках (не измерено оценочно тут; сама история по касаниям на всём пуле — ориентир из
  `backtest-speed-2026-09-18.md`: 10 монет × 2 суток ≈ 488 с сплошным реплеем) — оценка часов не
  делается изобретением, до первого прогона на паре суток пометить как «не замерено».
- Новый код (T1 лента, T2 глубина за уровнем, T4 рыночный вход) — время сборки/тестов на VPS, не на
  Steam Deck (В-контроль одной сборки, `~/.claude/hooks/alpha_one_build.py`); часы счёта после кода —
  не измерены до первого прогона гейта.
- Место на диске — экспорт ленты по всему пулу и истории может быть заметным (сделки чаще снапшотов
  книги); оценить объём на одних сутках одной монеты перед полным прогоном, не считать заранее числом.

- **Что делает:** join `approaches-<SYM>.csv` (из T0) + `touches-<SYM>.csv` (исход по `touch_start_ms`)

### T4 — рыночный вход (Rust; открывает Г-86)

- **Что меняется:** новый вариант входа (например `EntryForm::Market` или отдельный флаг типа

  лучшей цене (уже есть модель издержек тейкера, `costs::TAKER_FEE_BPS`) вместо очереди/лимитки —
  проще существующих моделей очереди (`prob:<n>`), не сложнее.
- **Плюс:** ключ `eaten_min=` рядом с существующим `eaten=<%>` (сейчас только «не больше», нужен

- **Флаг/форма (умолчание = старое поведение):** новое значение `--entry-form`, старые формы и байты
