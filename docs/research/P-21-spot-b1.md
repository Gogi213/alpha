## 1. Вопрос
Даёт ли B1 (лонг по стене на bid, как на фьючерсе) на споте Bybit положительный итог после комиссий спота — и как он соотносится с фьючерсом на общих монетах и сутках. Не «лучший вариант»: перенос готовой базы + силой стены В-67 в связке с `usd_min`.

## 2. Где осталась «сила» (проверено по коду 19.10) и что это
- **B1 силы не содержит:** набор `age=2700,side=bid,btc4h_max=-44.55`, пол — общий флаг `--h3-mode notional --h3-usd 10000` (`tools/compute/day-cells.sh:27`). Сила у фьючерса — только ось 6б П-18 (титровка, не база).
- **«Сила» = В-67 (владелец 19.10 03:35):** `S = size_at_touch / flow_1h_lots × 100 %` — доля объёма плотности в часовом обороте монеты; ключ набора `flow=` (`sets.rs:352`, `min_flow_pct`), пороги П-05 §3б S ∈ {8,1; 15,9; 25; 30,7; 50; 75; 100} %. **Не** «×соседи» (`H3Mode::Strength`, Г-28) — её в протоколе нет. Для спота `flow_1h_lots` — оборот **спота** (сделки спота из бинлога TK-312).
- **Слово владельца 19.10 03:45:** силу титруем **в совокупе с мин. объёмом** → решётка S × `usd_min` (ключ `usd_min=`, `sets.rs:365`), оба фильтра «И». Оба — ключи набора → один проход, один `--cells`; `--h3-mode` — общий флаг, на всех клетках один (`notional`, пол `--h3-usd` = нижний край решётки, см. §3).
- Абсолютные $ фьючерса на спот не переносятся вслепую: пол `usd_min` на споте — по распределению стен спота (§4).

## 3. Клетки (один `--cells`, один проход по суткам)
Общее, как B1: approach, `prob:3`, задержка В-68, 500 $/сделку, лонг, `age=2700`, BTC-фильтр `btc4h_max=-44.55` (BTCUSDT спот — Q-2 Судьи), дедлайн 14 400, ttl 1 800, стоп pct2, тейк tr1x1, σ240.
- **Ряд S0 (перенос как есть):** набор B1 + `usd_min=10000` (B1 дословно; `--h3-usd` общий = 0 → пол задаёт только набор). Ожидаем мало сигналов — измерение, не вывод.
- **Решётка G = S × U:** S ∈ {нет; 25; 50; 100} % (подмножество шкалы П-05 §3б; 100 % — число В-66/В-67; 25/50 — середина шкалы), U ∈ {нет; u1; u2; u3} — три `usd_min` спота, = квантили номинала стен спота, на которых фьючерсные 30k/100k/300k стоят в распределении фьючерса (§4). 4×4 − (нет,нет) = **15 клеток**; (нет,нет) — это B1 без пола, в G не входит (контроль «пол вообще нужен ли»). Полная решётка 7×… и сетка по квантилям S — **вторая партия**, только если G дала сигнал (F1→F2, П-14), решение Судьи по размеру.
- Режимы исполнения free и B2, как П-18.
- **Три прохода по `--h3-mode` не нужны:** сила здесь — ключ набора `flow=`, не режим H3 (правка Судьи п.1 учтена: S1/S2 «strength×соседи» сняты).

## 4. Пол `usd_min` спота (назначаемое → через измеримое)

## 5. Издержки спота (Q-1 решено Судьёй)
- (а) комиссии фьючерса как есть (`costs.rs`) — **диагностика «механика стены на споте»**, не испытание.
- (б) публичный спот non-VIP 10/10 bps, без возврата, пометка «публичный» — **главный ряд вердикта**. Нога за ногой по модели B1: вход maker (10 bps), выход по форме — тейк лимитом maker (10 bps), стоп/дедлайн тейкером (10 bps); комиссия по типу ноги. Тариф владельца придёт → пересчёт только издержек по готовым сделкам (сделки с типом ноги выхода в выходе), без нового прохода.

## 6. Что отличается от фьючерса и как это учтено
1. **Нет шорта без маржи.** Тестируется только лонг-сторона B1 (bid), как у фьючерса B1. Шорт/маржинальный спот — вне протокола (Q-3: нужен ли отдельный ряд «маржинальный спот» — решение владельца/Судьи; по умолчанию нет).
2. **Фильтр BTC (Q-2, Судья):** BTCUSDT **спот**; контрольный проход с фьючерсным BTC не нужен (базис ≪ порога 44,55 bps).
3. **Глубина 200 вместо 500:** стена за пределами ±200 уровней невидима; сила В-67 от глубины не зависит (оборот, не соседи); потерю стен за пределами 200 уровней оценить в отчёте долей касаний с невидимой стеной.
4. **Шаг цены/лота по суткам** — как было на бирже (В-172), из бинлога TK-312.
5. **Пул:** 194 монеты спота (TK-305). Общий пул со фьючерсом = пересечение символов, **v171c без TRUMP/TRX/BCH (В-105)**; брак по `verdict.csv` и по `verify-<SYM>.status == ok` (K1). Окно — 01.01–30.09 (В-211), октябрь — пометкой; сутки спота = сутки, где есть оба рынка.
6. Режимы исполнения: free и B2, как П-18.

## 8. Шум и правила вердикта (до счёта)
- **Главная метрика: Σ$ по месяцу при издержках (б)**, ряд S0 и клетки G. SR, markout (bps), доля исполненных входов, разбивка по монетам — описательные.
- Интервалы: bootstrap по суткам, эфф. N = сутки с ≥ 1 сделкой; < 30 сделок/месяц → «совместимо с», не «объясняется».
- N_test = 16 клеток (S0 + 15 G) на (б) → Холм по 16; (а) — диагностика, не испытание.
- «Перенос удался» (на (б), для клетки): Σ$ > 0 в ≥ 6 из 9 месяцев **и** нижний край 90 % интервала месячного SR > 0 в агрегате, после Холма. «Механика переносится» (на (а)): знак и порядок Σ$ как у фьючерса B1 на общих сутках. Иначе — «не переносится», причина по таблице §7. Порог 6/9 — назначение протокола.
