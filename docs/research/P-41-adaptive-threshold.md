## 1. Постановка

Разрыв пары `d_t` — как в П-40 §3 (`d⁽¹⁾`: `ln(mid_A/mid_B)` минус уровень `P̄_L`; запасной `d⁽²⁾`). Эпизод: вход при `|d| ≥ θ`, выход при `dir·d ≤ q·d_вход`, `q ∈ {0; ¼; ½}` (П-40: ½).

**Снимаемый разрыв по построению** = `(1−q)·|d_вход|` (bps номинала ноги). **Пол издержек** эпизода:

`Φ = C_fee + s_вх + s_вых + m`

- `C_fee` — комиссия круга Bybit (В-88): **8,82** bps (вход мейкером 2×1,26 + выход тейкером 2×3,15) — ведущая; **5,04** (всё мейкером) — верхняя оценка, **12,6** (всё тейкером) — нижняя; печатаются все три;
- `s_вх`, `s_вых` — спред входа и ожидаемый спред выхода; вход мейкером по своей стороне спред не платит (0), выход тейкером платит половину спреда каждой ноги (`s_вых = (spr_A + spr_B)/2`, спред — текущий L1 и скользящая медиана спреда ноги за `W_s` — выбирается меньшая «ожидаемая» из двух только если обе известны; в протоколе — **текущий**, медиана справкой);
- `m` — минимальная маржа.

**Правило пола:** вход только при `(1−q)·|d| ≥ Φ`, т.е. `θ_t ≥ Φ_t/(1−q)`. Контроль достижимости: доля эпизодов с `(1−q)·|d_вход| < Φ` обязана быть **0** (проверка кода, не результат).

**Допущение Д-1 (на утверждение владельцу):** «условно 20» читается как **полный пол** `Φ = 20 bps` (издержки + маржа вместе; при `C_fee` = 8,82 маржа ≈ 11,2). Второе чтение — маржа 20 сверх издержек (пол ≈ 29) — в сетке справкой: `Φ ∈ {15, 20, 29, 40}`.

## 2. Адаптация к диапазону пары: кандидаты порога входа

Порог `θ_t = max(Φ_t/(1−q), S_t)`, где `S_t` — масштаб «нормального» разрыва пары на момент `t`, считается **только по прошлому** (окно до `t − 1 с`, без заглядывания).

| № | `S_t` | параметры сетки |
|---|---|---|
| A0 | нет (чистый пол) | `Φ` |
| A1 | фиксированный `θ` П-40 = 12,6 (контроль, как в `p40-d1-naive`), с полом после | — |
| A2 | скользящий квантиль `|d|` за окно `W` | `W ∈ {1, 6, 24} ч`, `p ∈ {0,90; 0,95; 0,99}` |
| A3 | робастный масштаб: `med(d) + k·1,4826·MAD(d)` за окно `W` | `W` как в A2, `k ∈ {3; 5}` |
| A4 | EWMA-квантиль (стохастическая аппроксимация, без хранения окна) | полураспад `{1; 6} ч`, `p` как в A2 |
| A5 | режим: A3 или A2 раздельно по классу (крипта / TradFi: открыт-закрыт рынок акций) и по терцилю 5-мин волатильности более подвижной ноги | лучшая настройка `W,k` из A3 |

Выход: `q ∈ {0; ¼; ½}` (печатаются все; П-40 — ½). Усечения — П-40 §2.2. Стопов и таймаутов нет.

## 3. Выбросы: мусор против настоящего всплеска

Флаги данных-мусора (на входе и при обновлении `S_t`), **значения порогов — из измерения, не назначаются**: берутся из распределений G0/D1 (см. ниже), печатаются таблицей чувствительности.

1. спред любой ноги ≥ `X_s` — сетка `{30; 50; 100}` bps (по `p40-d1-naive-masked`: окно времени не влияет, порог спреда влияет: +10,8/+11,2/+11,5);
2. первые `10 с` часа UTC — **только флаг справкой**, т.к. по масочному разбору причина — широкий спред, не время;
3. возраст лучшей цены ноги `> S_max` (G0);
4. одиночная котировка: нога не обновлялась `> u` последних секунд при движении другой ноги (признак «устаревшая цена, не разрыв»).

**Правило:** флагованный тик (а) **не входит** в окно/квантиль `S_t` (норма не сдвигается по мусору), (б) **не открывает эпизод**. Оценки `S_t` робастны сами по себе (медиана/MAD/квантиль); отсечка винзоризацией на `p99` окна — опция. Настоящий всплеск (спред нормальный, обе ноги свежие) — **торгуется**, но печатается отдельно: доля, выигрыш, МПУ.

Проверка правила мусора (нет разметки «правды», поэтому только косвенно): доля эпизодов под флагом; `ȳ` и МПУ у отсечённых против оставленных; дрейф `S_t` с отсечкой и без; число эпизодов, где отсечка меняет решение «входить / нет».

## 4. Догоняющая нога и исполнение (критика №2)

Разрыв закрывает нога, которая **отстала**. По П-40: лидер/догоняющий за 10 с (нога, чей mid двигался раньше). Правило говорит: **на какой ноге и какой стороной стоять**:

- догоняющая (устаревшая) нога: сторона, в которую она должна пойти (продаём, если она «дорога» против лидера; покупаем, если «дешева»);
- лидер: хеджирующая сторона.

Исполнения, считаются **в одном прогоне** (все — мейкер-вход по правилу 08.11, без тейкера на входе):

- **E1 (потолок, как наивный П-40):** обе ноги мейкером по устаревшей цене t0; исполнение — по лучшей цене без очереди (В-125), ликвидность ≥ 100 $. Верхняя оценка.
- **E2 (реальнее):** заявка на догоняющей ноге ставится на лучшей цене **на момент `t0 + L`** (книга уже сдвинулась), на лидере — тоже на лучшей цене `t0 + L`; исполняется только если цена подошла (сделка/пересечение), `L ∈ {0; 500 мс; 2 с}` (кривая задержки). Нет исполнения = 0 (ITT).
- **E3 (справкой, не главное):** тейкер на догоняющей ноге (вход — «клюнуть устаревшую цену») + мейкер на лидере: **правило 08.11 запрещает тейкер на входах**, поэтому E3 — только оценка величины «что теряем, не беря», без вывода.

Печатается: на каждый кандидат и `E1/E2/E3` — доля исполнения, снимаемый разрыв, результат после комиссии, доля эпизодов, где лидер определён неверно (разрыв закрыла не отстающая нога).

**Что нужно от ядра (TK-522):** L1 `qty` на t0/t_end, bid/ask на t0, t_end, t_peak, `H=600`. До них E2 и 100 $-фильтр не считаются.

## 5. Метрики и сравнение

Единица — актив × сутки (кластеры для интервалов, схема П-40 §6.1); интервал 90 %.

На кандидата × `{Φ, q, E}`:
1. сделок/сутки, пар-сутки, активов;
2. снятый разрыв `(1−q)|d|` (bps) и **доля эпизодов с ожидаемым разрывом `< Φ` — обязана быть 0**;
3. результат после комиссии `ȳ` (три `C_fee`; ведущая 8,82), по ITT;
4. **bps/сутки/пару** (сумма `net` по паре за сутки) — главная величина сравнения;
5. устойчивость: доля суток с `ȳ > 0`, худшие сутки, без 3 лучших активов и суток;
6. хвосты: МПУ, `p1`/`p5` `net`;
7. контроли П-40 (K1 — сдвиг ноги B, K2 — случайный вход) на выбранных кандидатах — **доработка K1/K2 по итогам возврата Судьи по `p40-d1-prelim` не закрыта (K1 вывод был заменён парами актив×сутки)**; здесь K1 как нуль, K2 справкой.

**Одна таблица** — кандидаты × `{q, E}` × метрики; таблицы по классам (крипта / акции / ETF / прочее) и по парам бирж — справкой.

## 7. Алгоритм счёта (В-170)

Узкое место: ядро П-40 считает эпизоды при фиксированном `θ`; адаптивный `θ_t` в ядре нет. Варианты: (1) **Python-перебор по сетке разрывов `d` на 1 с** из кэша L1 `/data/p40l1c` — быстро для **сравнения кандидатов** (скорость и качество замеряются на 1–2 суток × 20 активов); (2) правка ядра: `θ_t` как функция от окна — тикет Инженеру, через неё E2 с очередью; (3) стохастическая аппроксимация квантиля без окна (A4) — O(1) на тик. Выбор — по замеру; в отчёте строка «Алгоритм: варианты; замер; выбран потому что».
