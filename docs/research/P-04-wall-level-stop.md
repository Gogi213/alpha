# П-04. Стоп на уровень снятой стены: не хуже ли главного варианта по деньгам и снижает ли просадку

**Статус:** черновик 26.09 (T-24) → Судье → владельцу через `CEO`; до «ок» владельца счёт не запускается.
**Реестр:** `docs/plan/EXPERIMENTS.md`, П-04 · **Журнал:** `docs/research/JOURNAL.md` · **Гипотеза:** Г-141 в пуле.

## 1. Вопрос и решение
- Вопрос: если стену, от которой вошли, сняли, — переносить стоп на цену этой стены (с буфером), а не держать 2 % до
  конца. Владелец 26.09: «не безубыток а стоп на то место где была плотность прогнать»; три режима «уже ниже на
  снятии» — «прогнать, не выбирать».
- Изменение **против просадки**, не ради прибыли → правило «не хуже базы» (В-116(1)) + польза по просадке (§10).
- «Да» (режим принят) → форма выхода главного варианта меняется на этот режим (новое решение В-##, дашборд — новой
  версией). «Нет» → остаётся стоп 2 % (В-104); идея в пуле «не повторять» в этой форме. «Не ясно» → остаётся В-104,
  в журнал — что не хватило.

## 2. Механизм
Вход — от стены, которую держит покупатель. Снятие стены (без сделок) — покупатель ушёл, причина сделки исчезла; цена
стены — последнее место, где защита была. Стоп на этой цене выходит раньше 2 %, если цена после снятия вернулась ниже
уровня, и не трогает сделку, если цена выше (трейл 1/1 и 4 ч продолжают работать). Отличие от уже проверенного:
выход при снятии и безубыток после снятия (E19–E21, Г-104 / N-03 — «не повторять») хуже «ничего не делать»; здесь цель
стопа — уровень стены, а не вход и не немедленный выход. Риск: стену снимают перед отскоком (ложное снятие) — тогда
стоп на её цене выбьет сделку, которая бы отработала.

## 3. Гипотеза и опровержение
- H1 (для каждого из трёх режимов): по сравнению с главным вариантом на тех же сделках режим не хуже базы по деньгам
  (без значимого вреда, §10) **и** просадка счёта меньше по правилу доли парного бутстрепа (§10) — в августе и в
  сентябре, каждый отдельно.
- Опровергает (**отвергнут**, §10, правка Судьи повторной сдачи `693d0ae` п.1): по деньгам — верхняя граница
  двустороннего интервала разницы значимо ниже нуля в любом месяце (режим значимо хуже базы). По просадке —
  **тоже только значимым вредом**: доля повторов парного блочного бутстрепа с Δ(dd_pct) < 0 (просадка режима меньше
  базы) ≤ 0,05 в любом месяце (просадка режима значимо больше базы). Доля от 0,05 до 0,8 — **не ясно**, не отказ:
  «польза не доказана» — не то же самое, что «хуже». Нижняя граница одностороннего интервала денег < −$X без
  значимого вреда — тоже **не ясно**, а не опровержение (см. §10).

## 6. Метрика
- Главная: Δ$ = (режим − база) по суткам **входа сделки** (не закрытия — Судья 26.09 `a96fb2a` п.4: по суткам закрытия
  ранний выход переносит деньги на день раньше и вносит искусственную отрицательную автокорреляцию), сумма за месяц,
  на тех же сигналах; отдельно август и сентябрь.
- Польза (условие §10): парный блочный бутстреп по суткам просадки счёта (`dd_pct`, минутная переоценка,
  `portfolio-sim`) — доля повторов с Δ(dd_pct) < 0 (просадка режима меньше базы). **Блоки — отдельно от Δ$ (правка
  Судьи, повторная сдача `693d0ae` п.2): просадка зависит от пути, блок ≥ 7 суток** (как KPI, короткие блоки режут
  длинные спады и завышают долю в пользу режима), **Δ$ (сумма по суткам) — блок ⌈n^{1/3}⌉**, как в §9 п.2 — выборки
  блоков для просадки и для денег не одни и те же. Худшие сутки ($) — справочно рядом (Судья 26.09 `a96fb2a` п.3:
  точка `dd_pct` одной реализации — отказ навыка).
- Вспомогательные (не для вердикта): число снятий, доля «уже ниже на снятии», причины выхода, стопы, $ по обвалу.

## 10. Правило вердикта (для каждого режима, W = 50, B = 0; правка Судьи 26.09 `a96fb2a` п.1–3,6)
- **Не хуже по деньгам (без значимого вреда):** верхняя граница двустороннего интервала блочного бутстрепа Δ$ за
  месяц на уровне 1 − 0,05 / 3 (поправка на три режима) ≥ 0 — в августе **и** в сентябре (режим значимо не хуже
  базы). Рядом — нижняя граница одностороннего интервала на том же уровне: если она < **−$X**, но верхняя граница
  ≥ 0, условие «не хуже −$X» не выполнено, но это **не ясно**, а не отказ. **X = $10 в месяц** (≈ 10 % месячного
  результата базы $106 / $111) — **предложение, утверждает владелец до счёта**, после оценки достижимости (§8а;
  В-116(1): X до счёта).
- **Польза:** доля повторов парного блочного бутстрепа (блок ≥ 7 суток, §6/§9) с Δ(dd_pct) < 0 (просадка режима
  меньше базы) — не менее **0,8** — в августе **и** в сентябре, каждый отдельно; худшие сутки — справочно рядом.
- **Устойчивость:** оба условия держатся без суток с наибольшим влиянием, без двух таких суток и без монеты с
  наибольшим влиянием; соседи (W = 90/B = 0; W = 50/B = 10; W = 30/B = 0) — верхняя граница интервала по точке
  не < 0 (значимо не хуже базы) в обоих месяцах.
- **Принят** — верхняя граница Δ$ ≥ 0 в обоих месяцах (не отвергнут по деньгам) **и** доля Δ(dd_pct) < 0 ≥ 0,8 в
  обоих месяцах (польза по просадке выполнена) **и** устойчивость держится.
- **Отвергнут** — по деньгам: верхняя граница интервала Δ$ значимо < 0 в любом месяце (режим значимо хуже базы).
  **По просадке (правка Судьи, повторная сдача `693d0ae` п.1 — заменяет прежнее «польза ≥ 0,8 не выполнена в обоих
  месяцах»): доля повторов с Δ(dd_pct) < 0 ≤ 0,05 в любом месяце** (просадка режима значимо больше базы, не просто
  «польза не доказана»).
- **Не ясно** — иначе: нижняя граница денег < −$X без значимого вреда (верхняя граница ≥ 0); **или доля
  Δ(dd_pct) < 0 в диапазоне (0,05; 0,8) в любом месяце** — польза по просадке не доказана, но и вреда нет.
- Если приняты несколько режимов — выбор между ними не по максимуму денег (это шум), а по правилу: режим с меньшей
  просадкой (по медиане бутстрепа) в обоих месяцах; при разном порядке по месяцам **или** если разница просадок в
  пределах шума (доля повторов 0,4–0,6) — берём самый простой режим (порядок простоты — по выбору владельца), иначе
  решает владелец (ответ Судьи 26.09 `a96fb2a` на вопрос в).
- **KPI (правка Судьи, повторная сдача `693d0ae` п.4 — заменяет H = 7 и «по факту счёта без правила»).** Мера —
  доля часов t с ожиданием перехая > H суток, **H = 5** (число владельца, В-120 доп. 3); сентябрь — t ≤ 19.09 00:00
  UTC (не «24.09 − 7 суток»), август — все t. Правило чтения — как в П-07 (`reviews/P-07-2026-09-27-protocol.md`,
  «Третья сдача»): точка и устойчивость (доля ≤ 0,10 в обоих месяцах и без суток/монеты — «проходит»; доля > 0,10 в
  любом месяце и без исключений тоже > 0,10 — «не проходит»; иначе — «на границе»), без бутстреп-порога; колонка в
  таблице режимов — дополнительный критерий отбора, деньги и просадка остаются главным правилом §10 (не блокируется
  KPI). **Открытый вопрос владельцу (не блокирует счёт):** либо это правило, либо явная альтернатива — «П-04 судится
  по деньгам и просадке, KPI печатается только как описание (число без правила прохода/провала)»; до ответа читаем
  KPI по правилу П-07 выше.
