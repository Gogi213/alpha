# P-26 — G-016: чистый пересчёт «схождение Gate-фьюча к DEX» (TK-386)

Статус: **договор до счёта** (24.10.2026 ~15:40 GMT+4). Основание: слово владельца 24.10 «криво проверил схождение к декс» (G-016); аудит Судьи
`docs/research/reviews/tk384-convergence-audit-2026-10-24.md` (Д1–Д10), «Спецификация чистого пересчёта» п.1–13 — берётся дословно, ниже только заморозка
сетки и порядок. Окно одно: 15.10 00:00 – 22.10 23:59:59 UTC (8 сут.); вывод не сильнее одного окна (п.13).

## 1. Вопрос и правило вердикта (заморожено)
Даёт ли вход по Gate-фьючу в сторону DEX **нетто > 0** (после тейкера/мейкера Gate, спреда BBO, фандинга) на монетах класса практиков
(без Binance/Bybit/OKX), измеримо отличимо от 5 случайных входов той же монеты (тот же знак и длительность)?
- «Край есть» для формы F: нижняя граница 95 % интервала (бутстрап по монето-суткам) нетто класса > 0 **и** > контроль, после поправки Бонферрони на число
  испытаний сетки, **и** ≥ 2 монет по отдельности с нетто > 0 и ≥ 30 эпизодов. Иначе — «края нет / не доказан»; N эфф. < 30 — «не хватает данных».
- Тяжеловесы — отрицательный контроль: ожидание «края нет» (TK-380 v3); если и на них край — признак ошибки счёта, а не открытие.

## 2. Данные и подготовка (шаги по порядку)
1. **Монеты (п.1, Д1).** Инструменты Binance/Bybit/OKX (спот+фьюч) по API на дату счёта → `docs/findings/tk386-exchange-listings-2026-10-24.csv`.
   Класс практиков = фьюч Gate есть, на трёх биржах нет; исключить пулы-обёртки (сеть пула ≠ родная сеть токена), токенизированные акции,
   оборот фьюча Gate 0. Тяжеловесы = на биржах есть. Терцили ликвидности пула — показать, порог не назначать.
2. **Пул (п.2, Д3).** Один пул на монету — наибольшая ликвидность в $ за окно (по `swaps` TK-380); остальные — сверка базиса.
3. **Середина пула (п.3, Д2).** v3 — `sqrtPriceX96` из data Swap (3-е слово) — уже в сырых `/data/tk0380/sqd/<сеть>/part-*.jsonl`; v2 — резервы из Sync:
   выгрузка SQD **докачивается** (`tools/compute/tk386-sqd-sync.py`, юнит `tk386-sync`, `/data/tk0380/sqd-sync/`, bsc/base/ethereum). Нет середины
   (v4, Solana до проверки состояния пула) — цена исполнения со сдвигом на ½ комиссии против направления свопа, помета `mid=exec`; результат по пометам отдельно.
   Возраст цены DEX на входе ≤ 60 с; слои возраста 0–10 / 10–60 с.
4. **USD (п.4):** стейблы = 1 с проверкой отклонения по своему пулу; нативные — середина BBO фьюча Gate той же секунды.
5. **Отрыв (п.5, Д5):** `log(mid BBO Gate / mid DEX)`; базис — скользящая медиана за предыдущие 24 ч (без заглядывания; первые сутки окна — без базиса,
   в счёт не идут, т.е. рабочее окно 16–22.10 — 7 сут. для медианы; оговорить в отчёте); рядом сырой отрыв.
6. **Выбросы (п.6, Д7):** только нулевые суммы / неверный маппинг; резкие ходы остаются.
7. **Ввод/вывод (п.12):** статус депозита/вывода токена на Gate по сети пула — API Gate, колонка в таблице монет.

## 3. Сетка (п.7, заморожена до счёта; число испытаний = 3 формы × 4 T × 2 выхода × 4 таймаута = **96** на класс)
- Формы входа: (а) первое пересечение T; (б) разворот: вход, когда |отрыв| сократился на долю r=0,25 от пика (одно r; r назначается решением, не подбирается —
  фиксируется здесь); (в) мейкер-лимит Gate на стороне схождения (исполнение — по правилу очереди: сделка Gate через лимит; без допущения о позиции в очереди — верхняя оценка, пометить).
- T: 1 / 2 / 3 / 5 %. Выход: |отрыв| ≤ T/2 или ≤ 0. Таймаут: 5 мин / 30 мин / 2 ч / 8 ч (выход тейкером по BBO).
- Издержки (п.8): тейкер/мейкер Gate фьюч по тарифу (из API аккаунта-стандарта Gate на дату), фактический спред BBO входа/выхода, фандинг Gate за удержание.
- Разложение (п.9, Д6): ход ноги Gate и ноги DEX до выхода; доли «Gate→DEX» / «DEX→Gate» / «не сошлось».
- Справочно (п.10): двуногий вариант — хедж на DEX с комиссией пула и газом (не входит в вердикт).
- Контроль (п.11, Д10): 5 случайных входов той же монеты, тот же знак и длительность.
