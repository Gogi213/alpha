## 1. Что извлекается (строка таблицы = сделка-цепочка; `docs/findings/sancho-trades-<дата>.csv`)

| поле | источник | правило |
|---|---|---|
| trade_id, post_ids (все звенья), root_post_id, файлы картинок | выгрузка | дословно |
| t_post (GMT+4, мс), t_post_utc | `title` поста | дословно, зона из выгрузки |
| coin, symbol_binance | текст (`$BTC`, `#BNB`, слово) / заголовок картинки | иначе «не извлечено» |
| chart_exchange, chart_tf, chart_market (перп/спот) | заголовок картинки | не виден → «не извлечено» |
| dir (long/short) | текст/зона на картинке (красная/зелёная) | оба источника расходятся → «не извлечено» |
| entry, stop, tp1…tpk, доли фиксации (Fix %) | подписи цен на шкале картинки | только число, **напечатанное** на шкале/метке; по пикселям цену не вычислять; нет подписи → «не извлечено» |
| t_pub_img (время публикации картинки, с зоной) | шапка картинки | переводится в GMT+4; расхождение с t_post > 1 ч — флаг |
| t_entry_claim | свеча входа на картинке (ось времени) | грубо (ось ТФ); не извлечено, если не читается |
| claim_outcome: класс (стоп / цель k / частичная+БУ / открыта / не названо), заявленное R | текст звеньев, `UPD:` | дословная цитата в отдельном столбце; не названо → «не названо» |
| class_post: **план** (до входа) / **отчёт** (после входа) / **итог** | текст | по словам («ожидаю», «зафиксировано», «закрыта»); неясно → «не извлечено» |
| size_claim, risk_claim (% депозита) | текст | дословная цитата |
| status_extract: ok / partial / none + причина | — | ни одного домысла: пропуск = «не извлечено» |

Картинки читает Исследователь глазами (Read по файлу); каждая прочитанная картинка — строка с файлом; вторая независимая сверка на выборке (п. 5). Посты с одной ссылкой TradingView и без файла картинки (≈95 из 141): **в выгрузке данных нет → «не извлечено: нет картинки»**. Загрузка снимков по ссылкам — новый внешний источник без валидации (§10 рамки): **вопрос Судье (Q-1)**; до ответа не делается.

## 2. Проверка по минуткам (по каждой сделке со status_extract ≠ none)

2.1 Данные: Binance UM 1 м свечи; нет монеты/дыра (ICP 22–26.09.2022, PUMP 10.07.2025) → «нельзя проверить: данные».
2.2 Базис: график не Binance-перп (спот или другая биржа) → проверка идёт, но сдвиг цены уровней относительно минуток — отдельный столбец; вердикты помечаются «база ≠».
2.3 Допуск касания: **ε = 0** и **ε₁ = медиана (H−L) 1-минуток этой монеты за сутки поста, в bps** (измеряемое, §7 рамки: квантиль самих данных). Расстояния — только в bps. Вердикт по ε = 0 и ε₁; **если они расходятся — «зависит от допуска», не подтверждено/оспорено.**
2.4 Достижим ли вход: для класса «план» — первая минута t ≥ t_post, где [L, H] накрывает entry (±ε); не достигнут до **конца цепочки** (последний пост) → «вход недостижим»; для класса «отчёт/итог» вход был до поста: проверка «цена накрывала entry в окне [t_pub_img−ТФ, t_post]» (по картинке), иначе «нельзя проверить».
2.5 Порядок событий после входа: по минуткам первая минута касания стопа vs tp1…tpk; **минута, где касаются и стоп, и цель — «неразрешимо внутри минуты»** (порядок внутри 1 м неизвестен; не решается догадкой). Результат: класс (стоп / tp k / ни то ни другое к концу цепочки), время.
2.6 Заявленный исход против свечей: **совпало** — класс заявленного = класс по свечам (и «ни то ни другое» ↔ «открыта»); **не совпало** — иначе (например, заявлена цель k, а цена её не достигала при ε₁; заявлен стоп, но он не касался); **нельзя проверить** — нет entry/stop/target, нет данных, неразрешимо внутри минуты, класс «не названо».
2.7 Реализованное R по заявленным уровням: R = ±расстояние(bps)/расстояние до стопа(bps) по доле фиксации; без «Fix %» — только классы целей. Чистое R = R − (комиссии + фандинг) в R: **комиссия Binance USDⓈ-M — реальные тарифы из официальной страницы/архива изменений Binance на дату сделки (источник и дата доступа в отчёте; не извлечено → строка без чистого R)**; **фандинг — реальная история `fundingRate` Binance за время удержания** (источник: data.binance.vision `fundingRate` — **новый источник, нужна валидация** — вопрос Судье Q-2); без них — только валовое R, с пометкой.
2.8 Заявленное R (`+2.22R`) против пересчёта: совпало, если пересчёт по ε = 0 и ε₁ даёт одинаковый класс исхода **и** расхождение R ≤ шага округления заявления (число знаков в самом заявлении, не изобретённый порог); иначе не совпало/нельзя.

## 3. Заявления про депозит (87 постов)

Сначала разбор текста на типы (таблица в отчёте): (а) доходность периода «+N % от депозита», (б) риск на сделку «X % от депозита», (в) призыв/реклама без числа, (г) прочее. Числа — дословными цитатами.
- (а) пересчёт возможен **только** если все сделки периода есть в таблице и **заявлен риск на сделку**: период-R = Σ R_сделок × risk%; сравнивается с заявленным процентом. Интервал пересчёта = [нижняя, верхняя] граница по неразрешимым/неизвлечённым сделкам (худшее/лучшее чтение). Подтверждено: заявленное внутри интервала И все сделки периода извлечены и проверены; оспорено: заявленное вне интервала даже при лучшем чтении; иначе — нельзя проверить (чаще всего: канал не публиковал все сделки периода — выживший).
- (б)–(г): проверяемы только как «показатель совпал со stop-расстояниями сделок» (риск = |entry−stop|·размер) — если размер дан; иначе нельзя проверить.
Никаких «ожидаемых» чисел; без доходности как цели (В-61 слои 1–2 идут в TK-451).

## 4. Правило вердикта по заявлению (строка итоговой таблицы отчёта)

Строка = заявление канала (сделка с заявленным исходом / заявление про депозит). Столбцы: заявление (цитата, пост) → что показали минутки (класс/время/R, по ε = 0 и ε₁) → вердикт:
**подтверждено** — «совпало» при обоих допусках, данные полные; **оспорено** — «не совпало» при обоих допусках либо вход недостижим при обоих; **нельзя проверить** — всё остальное (с причиной из закрытого списка: нет картинки / нет цены / нет данных / неразрешимо в минуте / зависит от допуска / не названо). Сводка — по числам: извлечено / проверено / подтверждено / оспорено / нельзя, доли с интервалом Уилсона (95 %); разбивка по годам (месяц — по N ≥ 8). Все по «одним и тем же правилам», выбора правил после просмотра исходов нет; число испытаний = число строк (описательно, без поправки на семейство — нет гипотезы о превышении нуля).

## 5. Самопроверка извлечения (до счёта по минуткам)

Из 46 постов с картинкой случайная выборка md5-порядком (seed 454) 10 сделок читается **вторым проходом** (отдельный разбор той же картинки после паузы без просмотра первой строки); совпадение полей по числам — в отчёте; расхождение любого напечатанного числа → правится в первую очередь, повторная сверка. Зона времени: на каждой картинке t_pub_img сверяется с t_post (флаг > 1 ч).

## 6. Счёт и код

`tools/sancho_posts_parse.py` (готов) → `tools/sancho_trades_check.py` (проверка по минуткам; читает `sancho-trades-<дата>.csv`, zcat минуток через calc). Счёт на calc через alsched NX=15 (объём малый: ≤141 сделок × диапазон дней — запуск одним проходом; параллельность не нужна, калибровка не требуется — оценка < 15 мин).
Алгоритм: варианты — загрузка минуток целиком в память по монете / бинарный поиск окна по `t_open_ms` + линейный проход; замер — до счёта (окно ≤ цепочка, сутки–недели); выбран — окно по бинарному поиску: потому что минимум чтения, результат тот же. (Замер — в отчёте.)

## 8. Правки Судьи (`docs/research/reviews/tk454-protocol-2026-10-30.md`, 30.10) — вписаны до извлечения; протокол УТВЕРЖДЁН

- **Q-1 да:** снимки `tradingview.com/x/<id>` — источник при валидации: на сделках с файлом и ссылкой сравнить напечатанные числа (цены шкалы, инструмент/ТФ/биржа, время публикации). Хоть одно расхождение — источник не валиден, проверка только по файлам. Загруженное — `data/` (gitignored), sha256 в таблице; не открылась — «не извлечено: снимок недоступен».
- **Q-2 да:** фандинг — data.binance.vision `futures/um/monthly/fundingRate` (сверка `.CHECKSUM`) + выборочная сверка с REST `/fapi/v1/fundingRate`. Комиссии — официальная страница тарифов/объявления с датой; уровень VIP неизвестен → чистое R интервалом [maker, taker] базового уровня на дату; источник и дата доступа в отчёте; тариф не найден — строка без чистого R.
- **Q-3:** риск на сделку — только дословная цитата из той же цепочки или поста о периоде; иначе «нельзя проверить: риск не назван». «Типичный» риск из других постов не подставлять.
- **П1 (к §2.5):** начало поиска «стоп или цель»: «план» — минута касания входа (§2.4); «отчёт/итог» — минута первого накрытия entry в окне §2.4; не найдено — «нельзя проверить: нет минуты входа».
- **П2 (к §2.4):** цепочка из одного поста (конец цепочки = t_post) без заявленного исхода — не мерить «вход достижим» с горизонтом 0; пометка «не названо» (§2.6), в сводке отдельной строкой.
- **П3 (к §2.1):** монеты с множителем (`1000PEPE…`, `1000SHIB…`) — уровни с графика без множителя пересчитывать только по напечатанному на картинке инструменту; масштаб не совпал — «база ≠», без домысла.
- **П4 (к §2.2):** «база ≠» в сводке §4 — отдельная строка, не смешивать с базой Binance-перп.
- Замечание: §5 при расхождении на втором проходе выборку 10 расширить до всех 46.
