## Определение (порог из распределения, число не назначается)
Для инструмента i, окна T минут (T ∈ {5, 15, 60, 240, 1440} — сетка масштаба, назначена коммитом протокола; 1440 по возврату Судьи 27.10: пампы малых монет идут часами–сутки):
- Ход: `R_T = max_{t1<t2, t2−t1≤T} (high[t2] / low[t1] − 1)` (памп), `D_T` симметрично (дамп, по low/high); порядок минут внутри окна (low раньше high); все сдвиги по минуте.
- **V0 (абсолют, заказ владельца «ход X % за T»):** `a = ln(1+R_T)`, событие при `a ≥ a*_T`.
- **V1 (база, нормированный ход):** `z = a / σ_T,i`, `σ_T,i` = MAD×1,4826 логдоходностей T-окон монеты за месяц; событие при `z ≥ z*_T`. Нормировка прячет пампы шумных монет — поэтому V0 считается наравне.
- **Таблица V0∩V1 / только V0 / только V1** по биржам-рынкам-месяцам (число событий, кластеров, монет). **Базу (V0 или V1) выбирает Судья по этой таблице**; до выбора csv содержит оба флага (`в_V0`, `в_V1`).
- **Оборот** `m = Σquote_v окна / медиана Σquote_v по T-окнам монеты за месяц` и OI — **столбцы признаков, не фильтр**. «V2» — не другое определение, а подмножество базы: доля событий с `m ≥ m*` (m* из K1 ниже). Нет излома по m — «оборот не разделяет», m* нет.
- **Многомасштабность, без «основного T»:** событие = объединение по T из сетки: минута попадает, если мера ≥ порога хотя бы на одном T; перекрытые окна одной монеты сливаются. В csv: `T_min` (наименьший T, на котором прошло) и значения a и z по всем пяти T. «Основной T» не выбирается; правила (1)–(2) приёмки проверяются на каждом T отдельно, показываются все.
- **Порог x\*_T (x = a для V0, z для V1) — для каждого T, знака, биржи-рынка; месяцы отдельно:**
  - Сетка (общая): S(x) — эмпирическая функция выживания пулом по монетам; 200 значений x на равных шагах log S от S=0,1 до точки, где в хвосте < 30 кластеров монета-день (нижняя граница хвоста назначена, согласована с правилом (3)). Кластер монета-день: окна одной монеты и суток — один.
  - **K1 «излом»** (определяет порог): без сглаживания; вторая разность log S с шагом 3 точки сетки; x\* — аргумент максимума по модулю; интервал — бутстреп по монетам (с возвращением, B = 1000, процентильный 95 %).
  - **K2 «хвост»** (только проверка совпадения с K1, не вторая сетка порогов): на тех же точках u подгон обобщённого Парето превышений x−u (МП), ξ(u) с асимптотическим 95 %; u\* — наименьшее u, где ξ(u') при всех u' ≥ u лежит в интервале ξ(u); интервал u\* — тот же бутстреп.
- **Оборот m\*:** K1 (та же сетка/шаг/бутстреп) на распределении log m среди окон с x ≥ x\*_T.
- z разных T как одну шкалу не сравнивать.

## Границы события (формально, параметры только из определения)
- Пик: минута максимума high (памп) / минимума low (дамп) внутри объединённого события (пик = экстремум объединения).
- Старт: от пика назад до минуты, где встречный ход (от текущего экстремума) достиг порога x\*_{T_min} (для V1 — z\*·σ) или прошло T_min минут без нового экстремума; старт = минута этого экстремума.
- Конец: от пика вперёд до первого из: (а) откат на порог x\*_{T_min} от пика («откат»), (б) T_min минут без нового экстремума («плато»). Тип конца пишется.
- Ход % = экстр.пик / экстр.старт − 1; длительность = t_end − t_start; оборот× = Σquote_v[t_start,t_end] / (медиана монеты за то же число минут).
- `t_pre_ms = t_start − длительность` (окно «до» той же длины). **Фазы для шага 3 (TK-422):** pre [t_pre, t_start), leg [t_start, t_peak], post (t_peak, t_end]; у контроля — те же три доли длительности.
- Граница апостериорная (описание/поиск, не онлайн-вход).

## Класс «размах без объёма»
Бывший C2: событие базы с `m < m*` (если m* найден) — часть базы, не отдельный набор. Метки «прямая/ступень» по тертилям и V3 из шага 1 убраны. Каскад (несколько монет биржи в ±T_min мин) — флаг; тип конца (откат/плато) — как есть. Сценарии уточняет шаг 3.

## Пары памп↔дамп
`пара_id`, `тип_пары ∈ {памп, дамп, памп→дамп, дамп→памп}`: дамп, чей старт лежит в [t_peak пампа, t_end + длит. пампа] той же монеты, — вторая нога пары (длина окна назначена этим протоколом); симметрично дамп→памп. В эфф. N пара — один кластер.

## Рыночность
`доля_монет_рынка` = доля инструментов той же биржи-рынка с ходом того же знака ≥ порога базы в ±T_min минут пика; `ход_BTC_%` = ход BTCUSDT той же биржи за [t_start, t_peak]. Класс «рыночный» — по излому (K1) распределения доли, не назначенный.

## Склейка бирж/рынков и кластеры
`монета_id` — база без котировки (BTCUSDT → BTC) через Bybit linear/spot и Gate futures/spot. `кластер_id` — связная компонента событий одной монеты на любых биржах/рынках с перекрытием [t_start, t_end]. `id_рынка` — компонента по [t_start−T_min, t_end+T_min], `первый`, `лаг_мин` (t_start − t_start первого). Эфф. N — по `кластер_id` (пара = один кластер); бутстреп — по `монета_id`.

## Контрольные окна
- **C1 (по режиму):** на событие — 3 окна (назначено) той же монеты и длительности, без перекрытия с любым событием ±длительность, подобранные по: час UTC (±1 ч) **и** σ предыдущих 24 ч в той же квинтили монеты (квинтили по монете-месяцу) **и** `ход_BTC` окна в той же терции месяца. Нет пар — `не_подобран`, критерии молча не ослабляются; доля неподобранных (по бирже-рынку-месяцу) — в отчёт. Зерно = хеш(инструмент, месяц). Оба знака.
- **C2 (трудный):** окна монеты с x в верхнем дециле окон ниже x\*_T (ближайшие промахи), без перекрытия с событиями; знак — как у пары. C2b совпадает с классом «размах без объёма» — отдельно не строится.
- Формат (согласуется с тикетом счётчиков): csv `биржа,рынок,монета,монета_id,id,кластер_id,id_рынка,пара_id,тип_пары,вид(event|ctl_c1|ctl_c2),знак,парный_id,t_pre_ms,t_start_ms,t_peak_ms,t_end_ms,ход_%,длит_мин,оборот×,m_ge_mstar,T_min,a_T5..a_T1440,z_T5..z_T1440,в_V0,в_V1,класс,доля_монет_рынка,ход_BTC_%,первый,лаг_мин,месяц,подбор(ok|не_подобран)`; время UTC, мс начала минуты; разрешение 1 мин, уточнение по сделкам — шаг 3.

## v4 (27.10 ~22:10) — определение от явления; заменяет роль V0/V1 как «определения пампа»
Основание: владелец 27.10 («ты путаешь памп с повышенной волатильностью, тысячи событий — так в мире пампов не бывает»); CEO: пересобрать от явления (дормантность → многократный ход → всплеск оборота → не рынок → распределение), литература — sources/pump-dump-owner-notes-2 §5, Kamps & Kleinberg 2018 (EWMA-волатильность + двойное объёмное условие), Karbalaii 2025. **Разделы выше (V0/V1, K1/K2, границы, пары, рыночность, контроли) остаются как механика; V0/V1 — только ступень L0 воронки. Шаг A (tk421-moves, ходы по T на инструмент) переиспользуется как есть.** Определение «памп/дамп» = все ступени ниже вместе.

**Воронка (по бирже-рынку, месяцы отдельно; на каждой ступени пишется число событий / кластеров монета-день / монет):**
- **L0 размах** — объединение V0/V1 по T (v3). Широкий слой (десятки тысяч; это и есть «волатильность», не памп).
- **L1 дормантность до старта:** окно «до» = 1440 мин перед t_start (верхний T сетки, не новое число). Условия, оба относительно СОБСТВЕННОЙ нормы монеты за месяц (норма — медиана, не назначаемый порог): оборот окна «до» ≤ медианы суточного оборота монеты; σ минутных логдоходностей «до» ≤ медианы σ суток монеты. Дополнительно (описательно, не фильтр): доля «плоских» минут (h=l; у Gate — минут без сделок). Подсказка литературы «дормантные низколиквидные» → показываем и срез по возрасту листинга/медиане оборота.
- **L2 кратность хода:** `κ = ход_% / медиана суточного размаха монеты (high/low−1 по суткам месяца)`; порог κ\* — K1 (излом log S) по κ среди L1-событий. Это «многократный ход» в единицах самой монеты, а не абсолютный %. Абсолютный ход (V0) остаётся столбцом.
- **L3 всплеск оборота:** `m` окна [t_start, t_peak] к медиане монеты (как в v3); m\* — K1 по log m среди L2. Если K1 не находит излом — «оборот не разделяет», ступень не применяется и это пишется (но тогда отчёт показывает воронку с L3 и без).
- **L4 не рынок:** `доля_монет_рынка` и `ход_BTC_%` из v3; событие исключается, если доля выше излома (K1) её распределения или ход BTC той же биржи за [t_start, t_peak] ≥ x\*-порога V0 для BTC (то есть рыночное движение по тому же правилу, что для монет).
- **L5 распределение (метка, не фильтр):** `откат_%` = (peak − low за [t_peak, t_peak+длит.])/(peak−start) и тип пары памп→дамп (v3). Фильтром не делаем: медленное распределение не должно выбрасывать памп; показываем воронку с L5 и без.
- **Итог = L0∩L1∩L2∩L3∩L4.** Все пороги — K1/«норма монеты»; ни одно число не назначено. Испытаний K1: 20 (v3) + κ (5 T × 2 знака = 10) + m (v3, 10) — **40 порогов**, Судья подтверждает.

**Проверка-отказ (до приёмки):**
1. Масштаб: ориентир владельца/CEO — десятки событий в месяц на обе биржи, не тысячи. Это не порог и не критерий подгонки; если итог L0..L4 даёт > сотен кластеров монета-день или ≈ L0 (воронка почти не сужает) — определение отвергается как «волатильность», пишется в отчёт без подкрутки порогов.
2. Ручной просмотр: выборка 30 итоговых событий (случайных по зерну хеша, 15+15 по биржам) + 10 самых «близких промахов» (последние отсеянные на L1/L2/L3) — таблица (инструмент, t, ход, κ, m, дормантность, доля рынка) + мини-график 1 м (close/объём, окно ±длит.) в `docs/findings/pump-events-sample-<дата>.md`. Смотрит Судья/CEO; примеры владельца, когда даст, — отдельный тест: попали ли они в итог и на какой ступени выпали.
3. Правило (3) v3 «≥ 30 кластеров на биржу-рынок» при масштабе «десятки в месяц» может не выполниться: тогда шаг 3 берёт Bybit+Gate пулом, месяцы вместе (авг+сен), с оговоркой о мощности; порог не снижается.
4. Правила (1)–(2) v3 (K1↔K2, половины сентября) считаются для порогов κ\* и m\* так же.

**Контроли:** C1/C2 как в v3, но подбор C1 дополнительно по L1 (тоже дормантные до старта монеты-дни) — иначе сравнение «спокойное до + памп» с «любое окно» вернёт саму дормантность. C2 — окна, прошедшие L0..L(k−1) и не прошедшие ступень k (ближайшие промахи по последней ступени).

**Что не меняется:** данные, формат csv (+ колонки `κ`, `оборот_до×`, `σ_до_отн`, `L_прошёл` = номер последней пройденной ступени, `откат_%`), исполнение alsched 15 ядер, август не в критерии (TK-427).

## v5 (27.10 ~22:20) — правки по возврату v4 (reviews/tk421-protocol-v4-return); заменяет в v4 пункты ниже, остальное v4 в силе
1. **L0 = V0 (абсолютный ход) обязательно** (~~объединение V0∪V1~~). V1 (ход в σ монеты) — только столбец/срез. Итог = V0 ∩ L1 ∩ L2 ∩ L3 ∩ L4. В отчёте одной строкой: сколько событий «только V1» отсеяно этим (V1 \ V0).
2. **L2 без излома κ:** если K1 не находит излом log κ на данном T/знаке/бирже — ступень L2 на этом T не проходит никто («пампа по этому T нет»); это записывается строкой воронки с числом 0. Формулировка «ступень не применяется» — отменена. То же правило для L3 вместо «оборот не разделяет → не применяется» (~~v4 L3~~): нет излома m — на этом T/знаке никто не проходит; воронка «с L3» и «без L3» показывается как диагностика, итог — «с L3».
3. **Масштаб — число до счёта (слово владельца «десятки в месяц на обе биржи»):** определение отвергается, если итог L0..L4 даёт > 99 кластеров монета-день за сентябрь на Bybit+Gate вместе, по каждому знаку (памп / дамп) отдельно.
