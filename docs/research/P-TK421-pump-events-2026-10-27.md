# TK-421 протокол: определение «памп/дамп», полный список событий авг+сен 2026, контрольные окна (до счёта, 27.10)

Статус: **черновик на утверждение Судьи** — до утверждения счёта нет. Основание: G-017 (владелец 27.10: «брать все пампы и дампы / выделять общее по сценариям»), аудит TK-414/TK-420 (21 736 эпизодов θ 10,48 % — все размахи, не пампы). Шаг 1 из 3: определить и собрать; признаки — шаг 3 (TK-422 считает счётчики).

## Вопрос
Есть ли в распределении ходов монет естественный излом («обычный размах» → «памп/дамп»), по которому порог выбирается из данных, а не назначается; и какой набор событий он даёт на Bybit и Gate за август и сентябрь.

## Данные (только как отдаёт биржа, В-172)

- Август: на calc полно только 50 Bybit linear (сделки `/data/tk420/tr/bybit/bybit-linear`, свечи из них) и 21 Gate fut. **Пробелы августа (список для Инженера через CEO, качать не здесь):** (1) Bybit linear+spot все инструменты — `/v5/market/kline` 01–31.08 (`tk411-bybit-kline.py`, окно параметром); (2) Gate futures_usdt+spot — месячные архивы сделок 202608 → свечи (`tk411-gate-dl.sh`/`gate-candles.py`, `--kind net`, ~7 ГБ gz); (3) закрытые в августе Bybit linear — из `public.bybit.com/trading` (как 35 в TK-411). До закрытия пробелов август считается на том, что есть (Bybit 50 + Gate 21), с пометкой «неполный охват»; полный август — отдельный проход той же программой.
- OI/фандинг/mark — только описательно (Gate сентябрь, TK-415), в определение не входят.

## Определение (кандидаты; порог из распределения, число не назначается)
Для инструмента i, окна T минут (T ∈ {5, 15, 60, 240} — сетка масштаба, назначена коммитом этого протокола; выбор T — из данных, ниже):
- Ход: `R_T = max_{t1<t2, t2−t1≤T} (high[t2] / low[t1] − 1)` (памп) и `D_T` симметрично (дамп); внутримесячный порядок минут (low раньше high).
- Норма монеты: `σ_T,i` = робастный масштаб (MAD×1,4826) логдоходности T-окон монеты за месяц; `z = ln(1+R_T)/σ_T,i`. «Своя норма» — чтобы шумные монеты не забивали выборку.
- Оборот: `m = Σquote_v окна / медиана Σquote_v по T-окнам монеты за месяц`.
- **Выбор порога z\* (две независимые процедуры, сравниваются):**
  - K1 «излом»: пулом по монетам эмпирическая функция выживания S(z); z\* — точка наибольшего изменения наклона log S(z) (макс. вторая разность на сетке квантилей); устойчивость — бутстреп по монетам (интервал z\*).
  - K2 «хвост»: порог u графика стабильности формы обобщённого Парето (наименьшее u, выше которого оценка формы ξ остаётся в своём интервале); тот же бутстреп.
- **Оборот:** `m\*` — тем же K1 на распределении log m среди окон с z ≥ z\* (двугорбость = «обычный большой размах» vs «с объёмом»). Если излома нет (унимодально) — оборот в определение не входит, в отчёт пишется «оборот не разделяет».
- **Выбор T:** T, при котором z\* (K1) и число событий на монето-месяц устойчивы к бутстрепу лучше всего (наименьший относит. интервал z\*); все T считаются и показываются, основной — выбирает Судья по таблице.
- **Варианты определения (сравниваются в отчёте):** V1 = только ход (z ≥ z\*); V2 = ход + оборот (z ≥ z\*, m ≥ m\*); V3 = V2 + OI (описательно, только Gate сент.).

## Границы события (формально, параметры только из определения)
- Пик: минута максимума high (памп) / минимума low (дамп) внутри окна, давшего z ≥ z\*; слияние перекрытых окон одной монеты в одно событие (пик = экстремум объединения).
- Старт: идём от пика назад до минуты, где встречный ход (от текущего экстремума) достиг z\*·σ_T или прошло T минут без нового экстремума; старт = минута этого экстремума.
- Конец: идём от пика вперёд до первого из: (а) откат на z\*·σ_T от пика («откат»), (б) T минут без нового экстремума («плато»). Тип конца пишется.
- Ход % события = (экстр.пик / экстр.старт − 1); длительность = t_end − t_start; оборот× = Σquote_v[t_start,t_end] / (медиана монеты за то же число минут).
- Граница — апостериорная (для описания/поиска, не для онлайн-входа; предсказание — не цель шага).

## Сценарий-черновик (метка, не вердикт)
По форме ноги: прямая (≥ 70 % хода в ≤ 1/3 длительности — доли выводятся из распределения форм, не назначаются: метка по тертилям внутри выборки), ступень/пила (≥ 2 откатов < z\*), каскад (несколько монет одной биржи в ±T мин), конец: откат/плато. Метка черновая — сценарии уточняет шаг 3.

## Контрольные окна
- C1 (общий): на каждое событие — 3 окна (назначено: 3 на событие) той же монеты, той же длительности, без перекрытия с любым событием ±длительность, подобранные по часу UTC (±1 ч) события; генератор с зерном = хеш(инструмент, месяц).
- C2 (трудный): окна с z в верхнем дециле, не прошедшие оборот (m < m\*) — «крупный размах без объёма»; нужен для отличия памп/просто движение.
- Знак: контроль наследует знак события только в C2; C1 — оба знака.
- Формат (согласован с TK-422, окно для счётчиков признаков): csv `биржа,рынок,монета,id,вид(event|ctl_c1|ctl_c2),знак,парный_id,t_start_ms,t_peak_ms,t_end_ms,ход_%,длит_мин,оборот×,сценарий,месяц`; время — UTC, мс начала минуты.

## Статистика и число испытаний
- Месяцы отдельно (авг, сен), биржи отдельно (Bybit linear/spot, Gate futures/spot); пулом — только справка.
- Испытания определения: 4 T × 2 процедуры (K1, K2) × 2 знака = 16 порогов; 3 варианта V1–V3. Это выбор из данных, не гипотеза о прибыли; торгового вывода шага нет.
- Эфф. N: событие считается по монете-дню (независимость: события одной монеты в одни сутки — один кластер); интервалы — бутстреп по монетам.

## Правило приёмки определения (заранее)
Определение пригодно, если: (1) излом K1 найден и z\*(K1) входит в интервал K2 (или наоборот) в обе месяца и на обеих биржах — иначе «два режима» и определение на каждую биржу отдельно; (2) z\* первой и второй половин сентября совпадают в пределах бутстреп-интервалов; (3) число событий V2 на монето-месяц не вырождено (медиана по монетам ≥ 1 на монетах с ≥ 1 событием, и ≥ 30 событий на биржу-месяц, иначе шаг 3 без мощности — пишется как оговорка). Если (1) не выполнено — отчёт «излома нет», пороги не берутся.
