## Что лежит в БД

| таблица | строка | неизменяемость |
|---|---|---|
| `entry` | запись: время GMT+4, задача TK, проект П-NN / G-NNN, вид, гипотеза, вердикт (работает / не работает / не ясно / описательно), $ на ставку 500 $, сделок, Шарп, «найдено на этих данных», текст | всегда (триггеры): исправление — новая запись `--corrects L-N` |
| `protocol`, `psec` | протокол и его разделы (§): заголовок, номер, вид (правила / ворота / α / правило вердикта / данные…), α, «до счёта» и когда записан | раздел «до счёта» — неизменяем; поправка — новый раздел `--amends` |
| `metric` | число записи (TK-647): запись × сторона (long / short / both) × клетка × вселенная × окно — сделок, Σ $ на ставку 500 $, $ / сделку, Шарп (годовой по дневному), вердикт, «найдено на этих данных», «из текста», источник: файл в git + коммит + место (путь JSON / строка) | всегда (триггеры); повтор той же строки (`h`) не пишется |
| `psec_flag`, `psec_num` | исправление флага «до счёта» / номера раздела (строка `psec` неизменяема); вид `psec_cur` читает последнее | только добавляются |
| `link` | типизированная ссылка src → dst: запись, раздел, протокол, задача, решение В / S, карточка kb, коммит, файл (заморозка, отчёт) | только добавляются |
| `kb_node` | карточки kb (решения, задачи, протоколы…) — связанный индекс; сами карточки — md в git (`kb/`) | заменяется `sync-kb` |
| `doc`, `chunk` | снимки перенесённых md: файл восстанавливается байт в байт (`export-md`) | — |

Узлы: `L-N` — запись, `PS-N` — раздел протокола, `P-42 §13.28` — раздел по номеру, `P-42-level-breakout` — протокол, `TK-646`, `G-022`, `В-167`, `S-225`, id карточки kb, коммит (SHA), путь файла. Ссылки видны в обе стороны: `chron.py links <узел>` и блоки «Ссылки» / «Обратные ссылки» на сайте.

## Команды (`python tools/chron.py …`)

С ПК и из любого worktree команда сама идёт на srv по ssh (`-i ~/.ssh/id_rsa`, `UserKnownHostsFile` — кириллица в HOME; переменные `CHRON_SSH_KEY`, `CHRON_KNOWN_HOSTS`, `CHRON_HOST`); на srv — `python3 /data/chron/chron.py …` прямо с БД. Коммиты и файлы в ссылках проверяются по git там, где запущена команда.

| команда | что делает |
|---|---|
| `add --title "…" --kind verdict --task TK-NNN --project П-NN --verdict "не работает" --usd -120 --trades 431 --sharpe -0.8 [--same-data] --body-file отчёт.txt --link "P-42 §13.37" --link 76ffc4d14 --link docs/findings/x.md [--corrects L-N]` | новая запись; битая ссылка — отказ, ничего не пишется. Виды: verdict, prereg, amend, freeze, result, step, measure, experiment, correction, note |
| `find "<слова>" [--project П-42] [--verdict …] [--kind …] [--since ГГГГ-ММ-ДД] [--until …] [--sections]` | поиск по подстроке (FTS5 trigram, регистр и ё = е) + фильтры; `--sections` — и по разделам протоколов |
| `list [фильтры]` · `show <узел>` · `links <узел>` | список · запись / раздел / протокол / задача с текстом и ссылками · ссылки в обе стороны |
| `psec add P-42 --heading "13.38 … — записано ДД.ММ.ГГГГ ДО счёта" --body-file текст.md [--prereg] [--amends "P-42 §13.28"] [--after PS-N]` | новый раздел протокола; `--prereg` — записан до счёта, сразу неизменяем |
| `psec edit PS-N --body-file …` · `psec lock PS-N` | правка черновика (до пометки) · пометить «до счёта» |
| `psec flag PS-N --prereg 0\|1 [--at ГГГГ-ММ-ДД] --reason "…"` | исправить флаг «до счёта» неизменяемого раздела: строка `psec_flag` только добавляется, везде читается последняя |
| `psec num PS-N --num "8а" --reason "…"` | исправить номер раздела: строка `psec_num`, везде читается последняя |
| `add … --metric "side=long; cell=L_n24; uni=h775; win=01.07–13.11; trades=181; usd=294.31; sharpe=5.11; verdict=не ясно; same_data=1; src=docs/research/freeze/x.json[@коммит][#место]"` | числа записи (повторяемо): `src` обязателен, файл и коммит проверяются по git; не JSON / CSV — только с `text=1` («из текста») |
| `metrics [--entry L-N] [--project П-42] [--side short] [--uni h775] [--win …] [--cell подстрока] [--verdict …] [--min-trades 100] [--sort=-sharpe] [--coverage]` | числа по фильтрам; сортировка usd / sharpe / trades / mean / date / entry (`-` — по убыванию); `--coverage` — сколько записей и полей с числами |
| `metrics-import [--entry L-N] [--dry-run]` | числа записей из файлов результатов в git (`tools/chron_metrics.py`): JSON / CSV, иначе таблицы отчёта md «из текста»; повтор не дублирует |
| `protocol list` · `protocol new P-43-тема "П-43. Заголовок"` · `protocol show P-42` | протоколы · новый · протокол целиком (Markdown) |
| `check` | целостность (CI): битые ссылки (записи, разделы, протоколы, карточки kb, коммиты, файлы), триггеры, FTS, снимки md; код 1 при ошибке |
| `import-md [пути] [--read-from путь=файл]` | перенос md (повторный — только новое: совпавшие строки не дублируются, изменённый раздел — поправкой) |
| `export-md <путь>` · `sync-kb` · `stats` · `fields [--ids]` | восстановить перенесённый md · обновить узлы kb · счётчики · поля перенесённых записей: заполнено и почему пусто |
| `backup` · `serve` | (srv) снимок + JSONL в `/data/chron/backup` и Storage Box `box:chron/` (юнит `chron-backup.timer`, 04:20 UTC) · сайт :8091 (юнит `kb-page`) |

## Правила для тредов

1. **Новый вердикт, предрегистрация, поправка, заморозка — `chron.py add`, не строка в md.** `JOURNAL.md`, `EXPERIMENTS.md` и `P-*.md` не дописывать — это заглушки.
2. **Новый раздел протокола — `chron.py psec add`;** записанный до счёта — с `--prereg` (или `psec lock` до первого счёта). Изменить раздел «до счёта» нельзя — только поправка `--amends`.
3. Числа в записи — с меткой: `--same-data`, если найдено отбором на тех же данных; деньги — $ на ставку 500 $, Шарп — годовой по дневному. Числа по сторонам / клеткам / вселенным / окнам — `--metric` с источником (файл результатов), не текстом.
4. Ссылки — на всё, на что опирается вывод: раздел протокола, коммит, файл заморозки, отчёт, решение, карточка задачи. `chron.py check` перед слиянием.
5. Ошибка в записи — новая запись `--kind correction --corrects L-N`; старая остаётся, на сайте помечена «исправлена».
