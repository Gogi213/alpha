## 1. Что ломается при v3 (почему v4)
1. **Прибыли в правиле нет.** `Params` (`src/statarb/kernel.rs:57`) знает `entry_z/exit_z/stop_z/max_hold`; `entry_z` назначается «безубыточной точкой» ×m (П-32 §6.3) — один множитель на все пары, без учёта скорости возврата и стоимости удержания: z = 2 при полураспаде 3 суток не окупает круг 12,6 bps + фандинг за время ожидаемого возврата, а вход происходит. В v4 это отсекает правило §3 M1 (издержки удержания `F·τ` и ошибка прогноза на горизонте `τ` растут с медленностью возврата); если медленная пара всё же проходит правило — это видно по руке a0 (§5) и в отчёте, а не принимается на веру.
2. **Слепой `max_hold`.** Не отличает медленный возврат от разрыва связи; в разрыве держит до `max_hold`; стоп по z — не сигнал разрыва, а просто далёкое z (бывает и обычным большим расхождением; владелец В-91: «разрыв связи надо сразу прописать стоп»); стоп `2×entry_z` или выключен — хвостовые убытки от разрывов определяют результат вида и в отчёте отдельно не видны.
3. **β по скользящей OLS** лагает на дрейфе связи и смещает z (ложные входы после сдвига β); внутри позиции β заморожен.
4. **Вердикт v3 непропорционально жёсткий:** пять барьеров подряд — знак плюс в *каждом* из пяти годов, ≥ 2/3 месяцев, Холм m = 19, плацебо, без топ-2 суток. Арифметика: если у истинно положительной клетки вероятность плюса в году 0,8, то «все пять годов плюс» — 0,8⁵ = 0,33 (при 0,9 — 0,59): барьер отсекает половину и более реальных эффектов; сам П-32 §8 заранее ждёт «не ясно». «Опровергнуто» при ≥ 2 годах без плюса — приговор по шуму, не по различимому эффекту.
5. **Подгонка в этапе 2:** 72 клетки на прошедшую клетку, выбор по сумме bps вперёд — пять свободных ручек, выбираемых по шуму (число испытаний ≤ 21 + 72·k).
6. **Скорость (В-90):** этап 2 — до 72 × 10 мин × k на вариант; сетка v4 исчезает (параметры выводятся из подогнанной модели).
7. **Ядро v3 не умеет** ничего из §3 (список — §9).

## 2. Расхождение и кто его определяет (явно)
- **Объект.** Для пары/корзины (Y; X с весами w) спред в логарифмах закрытий `s_t = ln Y_t − β_t · Σ w_i ln X_{i,t} − α_t`. Для C1 (один контракт на двух биржах) β = 1 фиксировано, спред — базис.
- **Модель.** `s_t` — процесс Орнштейна–Уленбека (ОУ) с параметрами `(κ, μ, σ_eq)`: `E[s_{t+τ} | s_t] = μ + (s_t − μ)·e^{−κτ}`, равновесное σ_eq, полураспад `ln2/κ`. Параметры оцениваются **онлайн только по данным ≤ t**: (а) `(α_t, β_t)` — фильтр Калмана (§3, M1); (б) `(κ, μ, σ_eq)` — экспоненциально взвешенная регрессия AR(1) спреда `s_{t+1} = a + φ s_t + ε`: `κ = −ln φ / Δt`, `μ = a/(1−φ)`, `σ_eq = σ_ε/√(1−φ²)`; коэффициент забывания — измеряется на формировании (§4.1), не назначается.
- **Расхождение** = `s_t − μ_t` в единицах `σ_eq`, **но входом не является**: вход определяет *модель издержек и возврата* (§3, M1): «расхождение торгуемо», только когда ожидаемая чистая прибыль положительна. Определяет расхождение **модель**, а не человек: пороги — выход модели, а не уровни, назначенные руками.
- **Расхождение не торгуется,** если сработал **стоп по разрыву связи** (M3, §3), полураспад вне допустимой области, измеренной на формировании (минимум — несколько минут исполнения, максимум — окно формирования/2), или ширина связи выпала из формирования.
- Допущение (проверяемое, не верится на слово): `s_t` стационарен на горизонте удержания. Проверяет детектор M3 и контроли П-32 §9 (плацебо-пары, сдвиг партнёра).

## 3. Набор методов (современный; каждый — переключатель, выбор по замеру §5)
| код | метод | замена в v3 | суть | источник |
|---|---|---|---|---|
| **M1** | β/α динамические (Калман) + правило входа/выхода по ожидаемой прибыли | OLS + z | Состояние `θ_t = (α_t, β_t)` — случайное блуждание, шум состояния `Q = δ/(1−δ)·P`, δ — измеряется (§4.1); шум наблюдения `R` — EW-оценка инновации. Спред — остаток фильтра по прошлому. **Единицы и сторона.** Всё в логарифмах закрытий; `ď = d/σ_eq`, `d = |s_t − μ_t|`, расхождение берётся по модулю, сторона входа — знак `s_t − μ_t` (расхождение вверх → короткий спред, вниз → длинный; ниже формулы для верхней стороны, нижняя — зеркально). `C = round_trip_cost_bps(p, β, wsum)/10⁴` (ядро, ставки `costs.rs`), `c̃ = C/σ_eq`. **Уровень выхода — по другую сторону среднего** (как у Бертрама 2010, максимум ожидаемой доходности на единицу времени при симметрии): вход сверху, выход при `s = μ − b·σ_eq`, где `b = b*(c̃)` — единственный корень `2·erfi(b/√2) = (2b − c̃)·√(2/π)·e^{b²/2}` (условие максимума отношения `(2b − c̃)/erfi(b/√2)`; `b*` зависит **только от `c̃`**, κ масштабирует лишь время ⇒ одна 1-мерная таблица, счёт один раз в `bench`, на минуту интерполяция; при малых `c̃` `b* ≈ (3c̃/2)^{1/3}`). Уровень входа Бертрама `a* = b*` в правиле не используется (вход определяет `G`; в отчёт `a*` — справкой). Стратегия «вход при фактическом `d ≥ b*`, выход в `−b*`» **не оптимальна по Бертраму** (оптимум — вход ровно в `b*`), это прагматичный вариант: оптимальность `b*` не заявляется, ценность проверяет замер a0↔a2 (§5).
**Время удержания — ожидаемое время первого достижения** уровня выхода (не условное среднее). Для ОУ в единицах `σ_eq` (`dZ = −κZ dt + √(2κ) dW`, скорость возврата κ из §2): `E[T_{x→y}] = (K(x) − K(y))/κ` при `x > y`, `K(z) = √(2π)·∫₀^z e^{u²/2}Φ(−u) du` (Φ — стандартная нормальная функция распределения; 1-мерная таблица, счёт один раз; сверка с независимым численным интегралом и Монте-Карло ОУ, 3 точки, отклонение ≤ 5 % — проверено при правке v4.2). Проверка: `E[T_{b→−b}] = (π/κ)·erfi(b/√2)` — формула Бертрама. Итак `τ(d) = (K(ď) − K(−b*))/κ` — конечное при любом `ď` и `c̃`.
**Правило входа — одно.** `F` — стоимость удержания в долях номинала на единицу времени (§4.4(ii): фандинг обеих ног по ставкам, известным в `t`, для выбранного направления). Ожидаемая чистая прибыль круга `G(d) = d + b*σ_eq − C − F·τ(d)` (ход спреда от `s` до `μ − b*σ_eq`). **Вход, когда** `ď ≥ b*`, `τ(d) ≤ τ_max` (граница полураспада §2) **и** `G(d) − k_m·RMSE_cal(τ(d)) > 0`, где `RMSE_cal(τ)` — измеренная на формировании ошибка прогноза `s_{t+τ} − μ` моделью §2 на горизонте `τ` (§4.4(i)), `k_m ∈ {1, 2}`. Время входит двояко: через `F·τ` и через рост `RMSE_cal(τ)`; κ — через `τ`.
**Предельные проверки (записаны до счёта; тест ядра и `reference.rs` на каждую).** (1) `c̃ → 0`: `b* → 0` (как `c̃^{1/3}`), выход в `μ`, `τ(d) = K(ď)/κ` конечно, `G → d − F·τ` — правило входит при малой `F`, бесконечного времени нет. (2) `F = 0`: `G = d + b*σ_eq − C`, вход при `d + b*σ_eq − C − k_m·RMSE_cal > 0` и `d ≥ b*σ_eq` (без члена `k_m` — `d ≥ max(b*σ_eq, C − b*σ_eq)`); κ входит только через `τ_max` и `RMSE_cal` (в точной ОУ-модели `RMSE_cal` от κ не зависит: оговорка §1.1 в силе). (3) `κ → ∞`: `τ → 0`, `G → d + b*σ_eq − C`, `RMSE_cal → σ_eq`; вход при `d > C − b*σ_eq + k_m·σ_eq`. (4) `κ → 0`: `τ ∝ 1/κ → ∞`, при `F > 0` `G → −∞`, при любом `F` блокирует `τ_max` (пара вне допустимой области, §2). (5) `ď → b*`: `G = (2b* − c̃)σ_eq − F·(π/κ)·erfi(b*/√2)` — положительна, если `F` не слишком велика; на этом краю правило эквивалентно оптимуму Бертрама при `k_m = 0`; при `k_m > 0` вход при `G > k_m·RMSE_cal(τ)`. (6) `ď → ∞`: `K(z) = ln z + 0,636… + o(1)` (замер: `K(2)−ln 2 = 0,732`, `K(8)−ln 8 = 0,643`, `K(32)−ln 32 = 0,636`), поэтому `τ ≈ (ln ď + 0,636 − K(−b*))/κ` растёт **логарифмически**, `F·τ` — как `ln ď`, а `d` — линейно ⇒ `G → +∞`, `RMSE_cal ≤ σ_eq` ограничена, `τ_max` практически не срабатывает. **M1 сам глубокие расхождения не отсекает — наоборот, берёт любое.** Верхняя граница входа — отдельное правило ниже. **Верхняя граница входа (одна, всегда включена):** вход только при `d ≤ d_hi = min(d_q, d_stop)`, где `d_q` — квантиль 0,99 распределения `|s−μ|` пары на её формировании (измерено, то же, что фильтр §4.2) и `d_stop` — уровень стопа, если стоп включён (клетка «выкл» — `d_stop = ∞`). Расхождение выше `d_q` — вне распределения формирования, это зона M3 (признак (г)): пара в неё не входит. Без допущенного M3 защита от входа в уже порванную пару — только `d_q` и стоп. Численно `K` считать через `erfcx` (`e^{u²/2}Φ(−u) = erfcx(u/√2)/2`), иначе переполнение при `u ≳ 38`. **Тейк-профит** — уровень `μ − b*σ_eq` (с этой стороны среднего), исполнение open `t+1`; **стоп** — уровень избыточного расхождения (клетка: выкл / максимум отклонения пары на формировании) или стоп по разрыву M3. **Время** — страховка `max_hold = ρ_tail · τ(d)`, где `ρ_tail` — квантиль 0,95 отношения «наблюдённое время достижения / `τ(d)`» по эпизодам формирования пары (§4.4(iii)), а не квантиль модели. В отчётах расхождение и `G` дублируются в bps (`·10⁴`). | Bertram (2010), Elliott–van der Hoek–Malcolm (2005, ОУ в пространстве состояний), Leung–Li (2015, издержки), Kalman |

## 4. Что измеряется на формировании (только по прошлому, 90 суток до месяца)
1. **Параметры фильтров** (δ Калмана, забывание AR(1), число факторов `k_f`, пороги `h`, RMSE_cal): каждый выбирается из конечной сетки по **ошибке одношагового предсказания спреда на второй половине окна формирования** (первая половина — обучение). Никаких торговых результатов на этом шаге. Сетка (δ, забывание) — степени 2 от длины окна формирования; в счётчике испытаний сетка не множится (параметры «измерены»), но число рассмотренных значений пишется в `P-33-params-<дата>.csv`.
2. **Отбор пар (A1/A2/B1):** как v3 — Энгл–Грейнджер на двух половинах + Холм, **плюс «модельный» фильтр прибыли**: пара допускается, только если на формировании найдётся расхождение `d` из распределения |s−μ| пары (квантиль 0,99), для которого выполняется правило входа §3 M1 (`b* ≤ ď`, `d ≤ d_hi`, `τ(d) ≤ τ_max`, `G(d) − k_m·RMSE_cal(τ(d)) > 0`; иначе пара не дойдёт до входа никогда — экономия счёта). Это отбор по прошлому, не по торговому месяцу.
3. **Разрешение формирования** (1 мин / 5 мин / 15 мин для EG и полураспада): совпадение выбранных пар и время — замером на С0 (§5), выбирается самое грубое, при котором доля общих выбранных пар с 1-мин ≥ порога 0,8 (решение Судьи, 03.11, записано до замера).
4. **Калибровка горизонта и удержания.** (i) `RMSE_cal(τ)`: на второй половине формирования для сетки горизонтов `τ` (степени 2 минут до границы полураспада) — среднеквадратичная ошибка прогноза `s_{t+τ}−μ` моделью §2 по прошлому; в правило входа берётся ближайший горизонт сверху к `τ(d)` из §3 (ожидаемое время первого достижения). (ii) `F`: стоимость удержания на единицу времени — по направлению сделки, фандинг ног по ставкам, известным в `t` (для видов без фандинга — 0; ставки — из тех же данных, что у ядра `Rule::Funding`); измеряется, не назначается. (iii) `ρ_tail`: по эпизодам формирования пары (вход, когда `d` в первый раз вышло на `ď ≥ b*`) — наблюдённое время достижения `μ − b*σ_eq` (или конец окна, цензура) к `τ(d)` по модели; `ρ_tail` — квантиль 0,95 (цензурированные эпизоды считаются «не достигли»); при < 20 эпизодов у пары — по пулу пар формирования той же биржи. Пишется в `P-33-params`.
5. **Стоп по разрыву: выбор признака и меры (на формировании, до торговых месяцев).** (i) Доля пар, у которых связь рвётся **внутри** торгового месяца: пары отобраны на первой половине формирования, проверены на второй; метка «разрыв» — спред не вернулся к уровню выхода `μ − b*σ_eq` за `ρ_tail·τ(d)` (§4.4(iii)) и остался вне полосы `b*σ_eq` не короче того же срока (метка по прошлому, торговых результатов нет). (ii) Для каждого признака §3 M3: задержка срабатывания относительно **начала** помеченного разрыва и относительно момента, когда сработал бы **старый стоп по z** (`2×entry_z`); доля ложных срабатываний на парах без разрыва. (iii) **Нулевой признак** — случайные срабатывания (в случайные минуты пары-месяца) с той же частотой, что у проверяемого признака, против тех же меток разрыва; считается доля помеченных разрывов, пойманных признаком раньше старого стопа по z, и та же доля у нуля (по парам, 90 %-интервал блочного бутстрепа разности). Допускается признак, у которого нижняя граница разности «признак − нуль» > 0 при доле ложных срабатываний на парах без разрыва ≤ 1 − q порога (порог — квантиль выше, по конструкции). **Победитель** — среди допущенных наименьшая медианная задержка относительно начала разрыва; ничья — дешевле по стоимости шага; правило записано до счёта. Если допущенных нет — M3 в a3/a4 не включается, а отчёт С0 называет это пределом (слово владельца о стопе по разрыву сохраняется; решение — CEO/владельцу, не подгонка признака под результат). Результаты — в `P-33-params-<дата>.csv` и отчёт С0 (§5).
6. Всё, что измеряется, пишется в `docs/research/P-33-params-<дата>.csv` до первого месяца разведки.

## 9. Что нужно ядру (отдельный список Инженеру; тикет после приёмки v4)
1. **Калман β/α:** состояние 2, `Q = δ/(1−δ)·P`, адаптивное `R`; на выходе `β_t, α_t`, инновация `e_t`, её дисперсия `S_t`. O(1) на минуту, без аллокаций. В `PairInput` — режим `BetaMode::Kalman { delta }`.
2. **ОУ-оценка (EW-AR(1)):** 6 экспоненциальных сумм, `(κ, μ, σ_eq)` пересчитываются раз в `refresh_ou` минут (лог — нечасто), между пересчётами константы. Признак «ОУ допустим» (`φ ∈ (0,1)`, полураспад в диапазоне).
3. **Две 1-мерные таблицы (один раз при старте, в `bench`):** `b*(c̃)` — корень `2·erfi(b/√2) = (2b − c̃)·√(2/π)·e^{b²/2}`; `K(z) = √(2π)·∫₀^z e^{u²/2}Φ(−u)du` для `E[T_{x→y}] = (K(x) − K(y))/κ`. Интерполяция на минуту. Сверка обеих таблиц с независимым расчётом (python, `scipy`) в тесте; проверка `E[T_{b→−b}] = (π/κ)·erfi(b/√2)` и шести предельных проверок §3 M1, включая (6): `K(z) − ln z → 0,636…` при `z = 8, 32, 128` (допуск 0,01), `dG/dď → σ_eq` при `ď → ∞` (при `F/(κ·ď) < σ_eq`, т.е. `ď > F/(κ·σ_eq)`, `G` растёт; при меньших `ď` и `F/κ > 8σ_eq` может убывать — тест берёт `κ, F` с `F/(8κ) < σ_eq`); и граница входа: при `d > d_hi` вход не открывается, при `d ≤ d_hi` — по `G`.
4. **Правило `Rule::Ou`:** вход по §3 M1: `ď ≥ b*(c̃)`, `d ≤ d_hi = min(d_q, d_stop)` (всегда включена), `τ(d) = (K(ď) − K(−b*))/κ ≤ τ_max`, `G(d) − k_m·RMSE_cal(τ(d)) > 0`, `G(d) = d + b*σ_eq − C − F·τ(d)`; тейк — уровень `μ − b*σ_eq` противоположной стороны; стоп-уровень; страховочное время `ρ_tail·τ(d)`. Параметры в `Params`: `k_m`, `F`, `τ_max`, `rmse_cal` (из `P-33-params`, на пару-месяц, по сетке горизонтов), `d_q` (q0,99 `|s−μ|` формирования, из `P-33-params`, на пару-месяц), `ρ_tail`, `stop_kind` (`d_stop` берётся из него). Источник времени удержания — таблица `K` (не условное среднее).
5. **Причина выхода в `Trade`:** сейчас `Trade` (`src/statarb/kernel.rs:115-128`) причины выхода не несёт. Ввести `ExitReason { Take, StopZ, Time, Break, EndOfData }` (v3: `exit_z` → `Take`, `stop_z` → `StopZ`, `max_hold` → `Time`) и счётчики по причине (число, сумма чистых bps, доля); в хеш/дайджест v3 поле не входит — «байт в байт» на a0 сохраняется. Без поля строка отчёта «потери от разрывов: число, доля, bps» (слово владельца, CEO 03:09) не собирается. Чистые bps по месяцам подтверждения `bench`/`drift`/гейт TK-482 **не печатают** (нетронутость §7).
5а. **Выход «разрыв» (M3, слово владельца В-91):** `ExitReason::Break` (см. п. 5); признак — выбранный по §4.5 (кандидаты: CUSUM инноваций, дрейф β, уход κ, хвост остатка, скользящий тест; состояние на пару, O(1)); сработал в минуту `t` → закрытие по open `t+1` и **пара выключена до следующего формирования** (флаг на пару-месяц); стоп по z остаётся отдельным выходом `StopZ`. Счётчики: выходы и потери по причине. Тесты: синтетический разрыв β / полураспада, сверка с reference.
6. **Вход-фильтры и выходные признаки для M4:** ядро отдаёт на каждый вход вектор признаков (z, полураспад, `σ_eq/C`, волатильность спреда…) вместе со сделкой; ридж — снаружи (Python) для разведки, в ядро — после приёмки.

Алгоритм: варианты — β: скользящая OLS / Калман (EW-фильтр) / регрессия в пространстве состояний с переключением режимов (Markov-switching); вход: z-порог ×m / ожидаемая прибыль по ОУ + таблица Бертрама / численное решение уравнения Гамильтона–Якоби–Беллмана на решётке на каждом шаге / обучаемая политика (RL); нейтрализация: BTC / PCA-факторы по Марченко–Пастуру / Йохансен; разрыв связи: `max_hold` / CUSUM инноваций / ADF-перетест на каждой минуте; предиктор: ridge / GBDT / нейросеть; замер — **не выполнен (счёта нет)**, назначен W1 (срез С0 парными разностями + микробенч ядра у Инженера); выбран для включения в замер — Калман, ОУ+Бертрам-таблица, PCA по Марченко–Пастуру, CUSUM, ridge — потому что: дают O(1) на минуту (таблица вместо HJB на каждом шаге; ADF перетест O(W) на минуту отсеян, Markov-switching и RL — не воспроизводимы в «байт в байт» и дороже на порядки), каждый — переключатель с парным сравнением, а не пакет.
