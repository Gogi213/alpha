## 1. Что именно торгуем (источники)

Видео и xlsx — метод анализа: **вход, стоп, цель и риск на сделку автор не задаёт** (P-TK454 §1: в канале стоп/цели —
нарисованные боксы позиции конкретных сделок, правила в них нет). Поэтому две формы, не смешиваемые и помеченные источником:

| форма | что это | источник правил |
|---|---|---|
| **A «горизонт»** | сигнал → сделка по ожидаемой стороне, выход по закрытию бара t0+N, без стопа и цели | прямой перевод заявлений автора (61–92 % «@10» = состояние через N баров, слой 1–2): N=10 — прочтение, автором не подтверждено |
| **B «стоп и цель»** | сигнал → вход → стоп/цель/дедлайн | правила не автора: стоп «за экстремум свипа» (структурный, чисел нет), цель — титруется; все числа сетки ×2 (рамка §7) |

Число «2R / 1,8R» — число курса bp (bp12-05), здесь не берётся; r=2 входит в сетку цели как элемент ×2-сетки, помечено «сетка».
Сторона — «ожидаемая» как в слое 2: свип хая → шорт, свип лоя → лонг; A1/A4 пробой — продолжение за уровень. События: A5, A6, A7, A8 (формы A и B), A1, A4 (только форма A: продолжение).
A2/A3 — вне (в слое 2 без строк семейства). Ветка слоя 2 (A5 подтв., A6–A8 не различимо) здесь **не отбирает** события:
все шесть идут (решение «что в слой 3» не по исходам).

## 2. Вход, стоп, цель — оси

Момент решения = закрытие бара подтверждения t0 (как слой 2: для A5 t0 = t, для A6/A7/A8 — бар, где выполнено последнее
условие). Всё в правилах — по данным ≤ t0; цены и стоп-уровни фиксируются на t0; исход смотрит минуты после.

**Вход (E):**
- **E0 «по рынку»** (якорь): вход по open первой минуты после t0 (тейкер).
- **E1 «ретест уровня»**: лимит (мейкер) на цене уровня L; исполнен, если за окно W баров ТФ после t0 минута пересекла L
  **строго насквозь** (для шорта high > L, для лонга low < L; касание без прохода = не исполнено); не исполнен к t0+W или
  раньше достигнут стоп-уровень → заявка снята, **сделки нет** (доля неисполненных пишется). W ∈ {4, 10, 32} баров (×2 + якорь @10).
  Только форма B, события A5–A8 (у A1/A4 уровень уже пройден).
- Вход по краю имбаланса не берём (определения края автор не дал, у bp — отдельный слой B2).

**Стоп (S), только форма B:** S1 «за экстремум свипа» — за хай/лой бара свипа (якорь; чисел нет; для A6–A8 экстремум
бара свипа); S2 «ATR»: m·ATR14 в bps, m ∈ {1/2, 1, 2}, ATR14 на баре t−1 (известно). Расстояние в bps = |вход − стоп|/вход·10⁴.
Не торгуем, если стоп по ожидаемой стороне ближе, чем разброс минутной свечи входа [П: если стоп внутри первой минуты —
исход «неразрешимо» (TK-454 §2.5), считается отдельно, в вердикт не идёт].

**Цель (T), только форма B:** T-S «структурная» (якорь) — ближайший противоположный подтверждённый свинг порядка k=2, **известный
на t0**; нет такого → сделки нет (доля пишется). T-R «в долях риска»: r ∈ {1/2, 1, 2} × расстояние до стопа.

**Дедлайн/горизонт N** ∈ {4, 10, 32} баров ТФ от t0 (якорь 10; N=10 — «@10» автора, не подтверждено). Форма A: выход по
close_{t0+N} (тейкер). Форма B: стоп/цель/дедлайн (по закрытию бара дедлайна).

**Порядок внутри минуты:** стоп и цель в одной минуте → **стоп первым** (консервативно; доля таких минут пишется; чувствительность
«цель первой» — описательно). Стоп исполняется по худшему из уровня стопа и open минуты (гэп); цель-лимит — только при проходе
насквозь (строго). Однократные заявки; пирамидинга нет.

**Перекрытие:** на (монета, ТФ, событие, сторона) в каждый момент не больше одной открытой сделки; сигнал во время открытой
— пропуск (счётчик). Тем же правилом считаются контроли.

## 3. Издержки (измеряемое — измеряется)

- **Комиссии:** базовый уровень Binance USDⓈ-M (без VIP и без скидки BNB) по **датированной** таблице тарифов (официальная
  страница/объявления об изменении, дата доступа и источник — в отчёте). Реальные фазы выхода: вход E0 — тейкер; E1 — мейкер;
  цель-лимит — мейкер; стоп и дедлайн — тейкер. Уровень VIP неизвестен → чистое ожидание дано **интервалом** [все ноги мейкер;
  фактическая смесь по правилам формы; все ноги тейкер]. Года без датированного тарифа — «издержки не оценены», только gross.
- **Фандинг:** по факту, data.binance.vision `futures/um/monthly/fundingRate` (сверка `.CHECKSUM`; выборочно REST
  `/fapi/v1/fundingRate`): сделка, открытая в момент метки 00/08/16 UTC, платит/получает ставку × знак позиции; в bps.
- **Проскальзывание:** по минутным свечам не измеряется (глубины и спреда нет) → **«не оценено»**, число не выдумывается.
  Вместо него в таблице — **безубыточное проскальзывание** (bps на ногу, при котором ожидание = 0) — измеренная величина.
- Метрика строки: **ожидание на сделку, bps** (gross → − комиссии [интервал] → − фандинг), доля выигрышей (net > 0), число
  сделок, эффективное N (кластеры), сокращение «E1 не исполнено / T-S нет / неразрешимо / перекрытие».

медиана по C1/C2, как в слое 2). Δ и ожидание — с доверительным интервалом (§5).

## 6. Правило вердикта (записано до счёта)

Два независимых условия по строке семейства; обе величины с интервалом по Холму:
- **(D) против контролей** — как слой 2: «подтверждено» — нижняя граница Δ > 0, знак Δ одинаков в каждом году с N ≥ 8 и ≥ 5
  монет, и знак совпал против C1 и C2; «оспорено» — верхняя граница Δ ≤ 0 при тех же проверках; иначе «не различимо».
- **(P) после издержек** — нижняя граница ожидания net **при худшем конце интервала издержек** (все ноги тейкер) > 0 → «положительно
  после издержек»; верхняя граница net **при лучшем конце** (все мейкер) ≤ 0 → «отрицательно после издержек»; иначе «не различимо».

Вердикт строки: **держится** = (D) подтверждено **и** (P) положительно; **оспорено** = (D) оспорено **или** (P) отрицательно;
иначе **не различимо**. (D) подтверждено при (P) не различимо или отрицательно — читается как «преимущество над контролем есть,
издержки его не покрывают / не оценены»; это не «держится». Года без датированного тарифа в (P) не входят — вердикт помечается
«без издержек за …». Ничего про «стоит/не стоит» не пишется.
