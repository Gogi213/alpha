# П-29 · TK-401 — отклик Gate на своп DEX по событиям (замена метода TK-392; протокол до счёта, черновик Исследователя 25.10 23:00)

Основание: стоп CEO 22:37 — TK-392 строил сетку 1 с (последний своп секунды + ffill без предела) = запрещённый посекундный агрегат (владелец 25.10). Вердикт TK-392 и дополнения TK-401 (EVM 67, Solana) недействительны (TK-403). Разбор свопов Sol (swaps3) — сырьё, остаётся.

## 1. Вопрос
После крупного хода цены исполнения DEX (событие = конкретный своп) — как быстро и какую долю хода повторяет середина Gate (фьюч, спот) на горизонтах h, и есть ли у отклика исполнимый край. Тот же вопрос, что TK-392; меняется только способ измерения.

## 2. Данные (только событийные)
- DEX: свопы (EVM v2/v3/v4 — блок/слой sqd7; Solana — swaps3 дедуп). Время события = время блока/слота (разрешение источника: секунда, Solana blockTime — секунда; суб-секундного лага по DEX измерить нельзя — пишем в отчёте, не скрываем). Цена = цена исполнения свопа (дельты), своп без цены/квоты не USD/ноги — вне.
- Gate фьюч: книга gev2 (`/data/tk0402/gev2/<COIN>/<час>.npy`, мс) — середина (bid+ask)/2 после каждого изменения лучшего уровня; Gate спот и фьюч: сделки в мс — вспомогательный ряд. Дыры gev2 (15, 16, 19–21.10) — события в дырах вне.
- Никаких сеток по времени: значение Gate на t = последнее событие книги/сделки ≤ t.

## 3. Событие
Для монеты, свопа i в t_i с ценой p_i: ход за окно W = ln p_i − ln p_j, где j — последний своп с t_j ≤ t_i − W (не ffill; если свопа в [t_i − 2W, t_i − W] нет — события нет). Событие: |ход| ≥ X, первое пересечение знака; следующее той же ячейки (монета,X,W,знак) не раньше t_i + W. Ячейки (X, W) — как TK-392: X ∈ {0,5; 1; 2; 5} %, W ∈ {10; 60; 300} с (заморожены прежние, новых чисел нет).

## 4. Отклик
Горизонты h — те же 39 (1 с … 14 400 с) от t_i. G(t_i + h) — по §2, **годится только при возрасте последнего события Gate ≤ A** (A = 1, 5, 30 с, как TK-402; A = ∞ — только справочно). Исходное G(t_i) — по тому же правилу, иначе событие не считается. Отклик = s·ln(G(t_i+h)/G(t_i)) (s — знак события); доля = отклик / |ход DEX|. Ход DEX после = s·ln(p(t_i+h)/p_i), p — последний своп ≤ t_i+h (без предела не используется: только как справочная колонка с возрастом).
Контроль: те же ячейки, моменты — случайные t той же монеты-суток без события, число = числу событий, правило возраста то же.

## 5. Метрики и правило
Как TK-392: n, медиана и среднее отклика, доля догона, интервалы (блочный бутстрап по часам), Холм по ячейкам (монеты × X × W × h × A), месяцев нет — окно 15–22.10, 8 суток по дням отдельно. Исполнимость (край) — не здесь: только измерение отклика; торговый вывод по краю — после принятия кривых и издержек отдельным протоколом.

## 6. Проба (до всего)
1 монета, сначала EVM с gev2 и ≥ 100 событий (X = 0,5 %, W = 60 с). Сверка: число событий, доля отброшенных по возрасту A, сравнение кривой с прежней (TK-392) — ожидается отличие, показать его величину. Только после принятия пробы Судьёй — все монеты (дельта к уже принятым нет, т.к. прежнее недействительно: весь пул EVM 67+ и Sol после swaps3).

## 7. Что не делаем
Посекундных сеток, ffill без предела возраста, медиан секунды, «последний своп секунды» (чувствительность swaps3 med/last из прежнего плана — отпадает, агрегат по секунде не нужен).

## 8. Вопросы Судье
Q-1: A ∈ {1,5,30} с и A = ∞ справочно — достаточно? Q-2: правило «нет свопа в [t−2W, t−W] → нет события» не вводит ли смещение к ликвидным пулам. Q-3: возраст Gate-цены на t_i по книге (мс) — устраивает ли для спота (только сделки).

## 9. Правки Судьи R1–R7 (reviews/tk401-p29-protocol-2026-10-25.md) — внесены 25.10, обязательны; §4–§5 читать с ними (при расхождении главнее §9)
- **R1 (A):** для книги gev2 A = живость потока монеты: последняя запись gev2 (изменение лучшего уровня или его объёма — глубже уровней в gev2 нет, оговорка) ≤ A и час не дыра (нет файла / .n < 100). Главное A = 5 с; 1, 30, ∞ — чувствительность. Метки gev2 квантованы 0,1 с → разрешение h = 1 с.
- **R2:** правило окна [t−2W; t−W] принято; по монете пишется число свопов без опорного j. **Контроль** — случайные свопы той же монеты без события, с тем же правилом окна, |ход| < X, s = знак их хода за W (0 — вне), n = числу событий (после проверки живости), сид [401,W,X,знак,A,рынок].
- **R3:** спот = последняя сделка ≤ t, возраст ≤ A на обоих концах (t_i и t_i+h); ряд вспомогательный, отскок bid/ask — оговорка. Главный ряд — середина книги фьюча. Доля событий, отброшенных по A, — по монете и рынку (counts: drop_hole, drop_age).
- **R4:** главная метрика = excess (отклик события − отклик контроля) на h = 60 с, фьюч, A = 5 с. Тест — кластерный по монетам: t среднего excess, df = монет − 1, без пола p. Семейство Холма = X(4)×W(3)×знак(2)×h(≤900 с: 28 из 39)×рынок(2) = 1344 при главном A; монеты в семейство не входят; A ≠ 5 с — вне семейства. α = 0,05. Доля догона = Σn·excess/Σn·|ход DEX|, CI — бутстрап по монетам 1000; «догоняет» = нижняя граница CI > 0,5. Сутки — все 8 по отдельности с индексами.
- **R5:** колонка pre_bp = s·ln(G(t_i)/G(t_i−W)) с тем же правилом A (кто ведёт). Время события DEX — секунда блока (суб-секундный лаг не измерить; Solana blockTime — оценка).
- **R6:** кроме «не раньше t_i+W» — эфф. N по монето-суткам (counts.coin_days) рядом с n.
- **R7:** приёмка пробы — 1 монета EVM с часами gev2 вне дыр, ≥100 событий при X=0,5 %, W=60 с: n событий/контроля; отброшено по окну R2, по A, по дырам; кривая против TK-392; 3 события руками (`*-manual.txt`). Только после принятия — весь пул.
- Колонка «ход DEX после» (справочная, §4) в скрипте не считается: на цене отклика не нужна, цену DEX по последнему свопу без предела возраста вводить не будем.
