# P-TK473 — Holdout 2026: отбор конфигов на ≤ 2025, проверка на закрытом 2026 (G-019) — Исследователь, 31.10, записано ДО открытия 2026

Слово владельца 31.10 (дословно): «Что за 434 конфига? Там есть плюс или что?» → «Последний это какой» → «Возьми весь 2026». Закрыть 2026-01-01…2026-09-15 (данные кончаются 15.09): в отборе не участвует, в этом протоколе 2026 не открывался (ни одно число по 2026 не смотрелось до записи).

## 1. Данные (без пересчёта ядра, В-213)
Суточные сводки готовых `d2b-out*` (calc, `/data/tk0461/d2b-out{,-bp,-bp3,-s}`), 21 288 конфигов (источник × ТФ × вход × сторона × стоп × тейк × БУ × ОТ), 84 монеты, издержки по тарифу В-63 как в TK-461 (net `b`, bps, фандинг по факту). Контроль C-X — строки `ev=C-X` тех же файлов (тот же выход). Конфиг = ключ `src,tf,ev,dir,stop,take,par,be_r,ot,otp`.

## 2. Разделение (до счёта)
- **Открытие (О):** монеты чётного md5(символ) × сутки ≤ 2023-12-31 (как P-TK461 §8).
- **Проверка отбора (П):** всё остальное ≤ 2025-12-31 = нечётные × ≤ 2023 + все монеты × 2024–2025.
- **Holdout (H):** все монеты × 2026-01-01…2026-09-15. Не участвует ни в отборе, ни в выборе порогов.

## 3. Правило отбора (только О и П; пороги назначены здесь, не подбирались)
Конфиг-победитель, если одновременно:
1. на О: монет с n ≥ 5 сделок ≥ 10; доля монет в плюсе (net > 0) ≥ 0,60; сводный net на сделку > 0;
2. на П: те же три условия (монет с n ≥ 5 ≥ 10, доля ≥ 0,60, сводный net > 0);
3. на П: нижняя граница 95 % интервала сводного net (бутстрап по суткам, B = 2000, seed 473) > 0 после Холма по K_О, где K_О = число конфигов, прошедших п.1 (одностороннее).
K объявлена: 21 288 конфигов в сетке; накопленное число испытаний 377 + K_TK461 + 1 (+ эта семья). Конфиги делят сделки — не независимые испытания.

## 4. Счёт на H (один раз, после фиксации §3)
Для победителей: сделок; net на сделку (bps, после комиссий); интервал (кластер по суткам, 95 %, B = 2000); монет в плюсе (n ≥ 5); net по месяцам 2026; по стороне (лонг/шорт); Δ против C-X на H (тот же интервал, Холм по числу победителей W, односторонний Δ > 0); Q-3 (худший конец издержек) — через ядро `--legs` (TK-471), только если W ≤ 60, иначе не считается и пишется «не считан» (заявка через alsched, NX по замеру).
База сравнения: доля конфигов с net(H) > 0 среди **не**отобранных конфигов с n(H) ≥ 30 (что даёт «просто конфиг из сетки»), и среднее net победителей против среднего net C-X на H.

## 5. Правило вердикта (записано до исходов)
- **«Удержал плюс»** — победитель с net(H) > 0 и нижней границей интервала > 0 (Холм по W). Это строгая мера.
- **«Знак удержан»** — net(H) > 0 без требования границы (описательно).
- Вердикт верхней строкой: число победителей W, сколько «удержали плюс», сколько «знак удержан», против базы. Если доля «знак удержан» среди победителей не выше доли в базе (бутстрап по конфигам не нужен: разность долей с интервалом Ньюкомба) — отбор не перенёсся: «не различимо». Победители делят сделки: доли — мера, не независимые испытания.
- Порог W = 0 → «отбор на ≤ 2025 победителей не дал».
