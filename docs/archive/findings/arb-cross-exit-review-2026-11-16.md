## 1. Арифметика — независимый пересчёт

- Код `cross_indep.py`: ряд пары по объединённым моментам книг, Sell/Buy, центр (медиана середин закрытия минутных баров [m−60, m−1], ≥ 30 баров), правила входа/выхода/перевзвода и переворота — заново по описанию отчёта, по одному событию за шаг; комиссия 4 × 3,15 bps; размер ≤ 100 $ и ≤ вершины; исключение круга, пересекающего пропуск сбора ± 2 мин, — как в отчёте.
- Выборка: EVAA, SOPH, SHELL, TAC, IDOL, STRK, BAT, NIGHT — все их пары без BingX (18), от верха списка по $/сут (EVAA binance–bybit 107 $/сут, θ = 0,2 %, «через центр θ») до пар с 3–17 кругами. Настройки: θ 0,2 % — «через центр θ», «θ/2», «переворот», «к центру», «через центр θ» при L = 50; θ 0,1 % — «θ/2», «переворот».
- Итог: 126 из 126 совпали точно (`/data/arb-review/indep.log`). Комиссии: 12,6 = 4 × 3,5 × 0,9; 10,71 = 1,26 + 3 × 3,15 — по тарифу владельца (п. 12 приказов).
- Замечание к модели «переворота» (не к арифметике): на перевороте заявка на каждой ноге — старый размер + новый, а объём проверяется только на 1× вершины. Влияние не считалось.

## 2. Загрязнение дырами сбора

Что проверено. `pair_series` (`core.py`) переносит последнюю книгу ноги вперёд без ограничения по времени, поэтому символ, не подписанный в запуске сборщика (аудит `docs/findings/collect-gap-audit-2026-11-16.md`, ветка `bb/g-022-collect-gap-v1-thr_3rgkrr82s2` @ 1c1b0a45: пул фиксируется при старте; Bybit 9,78 % торговых минут без книги), даёт «замёрзшую» ногу на часы. Пропуски сбора в отчёте искались только по 8 самым активным символам биржи (`gaps_scan.py`) и нашли один (Binance 13.11 21:49, 52 с); ни отсутствие символа в подписке, ни обрыв Binance 15.11 18:12:18–18:14:20 (8 шардов) этим поиском не видны и из счёта не исключались.

Как мерили (`cross_review.py`, все 639 монет, все пары без BingX, L = 0, тот же код выходов). Пометки круга [вход, выход] (незакрытый — до конца окна):
- «аудит» — пересекает участок тишины книги ≥ 5 мин любой ноги из `stretches-book.csv` аудита (сверка с REST-минутками; ± 1–2 мин на точность минуты);
- «Binance 18:12» — нога Binance и круг пересекает 18:12:18–18:16:20 UTC;
- «возраст > 60 с» — у одной из ног нет ни одной сырой записи книги > 60 с в момент входа или выхода.

## 3. Исполнимость L = 0

- Время в модели — E биржи; лаг приёма srv — медиана 58–132 мс (отчёт, «Данные окна»). Значит, вход и выход «по ценам сигнала» (L = 0) раньше, чем бот вообще видит сигнал; L = 50 мс от E тоже раньше медианы приёма у Binance/Bybit/OKX (110–130 мс). L = 0 — только верхняя граница; так отчёт и пишет.
- Раздельные задержки (тот же код, `sim_split` в `cross_review.py`; «вход / выход», мс; $/сут без BingX):

  Плюс L = 0 съедается задержкой с обеих сторон примерно поровну: и вход, и выход идут по выбросу, живущему < 50 мс. Одна мгновенная нога из двух оставила бы 60–510 $/сут, но мгновенной ноги у бота нет.
- Мейкер на выходе (лимитка «мейкер-нога», вход тейкером): при L = 50 минус во всех ячейках (отчёт, обзор L = 50). Мейкер на входе (мейкер + хедж): минус при θ ≤ 0,5 %, а плюс при θ ≥ 0,75 % — от BingX (§4). Исполнимого варианта в отчёте нет.

Сделки BingX по ценам, которых нет в снимке книги (≈ 2,6 снимка/с), «исполняют» лимитку — та же причина, по которой отчёт выносит BingX-хедж из рейтинга. - Под позицию нужны обе ноги (маржа на двух биржах) — капитал ≥ 2 × пик. Выход «через центр θ» и «переворот» занимают в 8–10 раз больше пикового номинала, чем «к центру», при $/сут в 1,2–1,8 раза больше; при θ = 0,3 % «через центр θ» ниже «к центру» и по $/сут (775 против 1071).
- «Занятый номинал» отчёта включает незакрытые (хвост `dead.json` [t1 − 10 мс, t1] лежит после t1 отчёта = 20:00 UTC и незакрытые не снимает); мой средний номинал больше (20 896 против 19 900 $) из-за окна на 1,5 ч длиннее.
- Рейтинг «медиана круга > 0 в каждых сутках» и плацебо 0 для выходов «через центр» и «переворот» при L = 0 — механическое следствие правила: выход срабатывает, только когда исполнимая цена уже на θ_exit за центром, поэтому 99 % кругов в плюсе по построению. Это не довод о крае. Δ к «к центру» «3 из 3 суток» — три наблюдения (вероятность 3/3 по одному знаку при отсутствии разницы — 1/8). Интервал по суткам не считается.
- Концентрация: 39–42 % $/сут — 10 пар из ~700 (EVAA binance–bybit одна — 9 % у «через центр θ»).
- Удержание до 4,8 ч (p95) и незакрытые 3–19 % входов: при одном окне 61,8 ч хвост не измерен; незакрытые по цене конца окна — ±2 % от итога при θ ≤ 0,2 %.

## Отступления и ограничения проверки

- Окно проверки `cross_review.py` / `cross_review_mk.py` — до 15.11 21:30 UTC (по `/data/arb-cross/window.json`), а `cross.pkl` — до 20:00 UTC (61,77 ч); пересчёт §1 шёл на окне `cross.pkl`. $/сут §2–5 отличаются от отчёта на ≤ 1 % (мейкер + хедж — на ≤ 5 %); доли и знаки от этого не зависят.
- Первый проход `cross_review.py` снимал незакрытые хвостом `dead.json` (на моём окне он попадает до t1); исправлено, числа выше — со второго прохода.
- BingX-пары тейкер-тейкер, мейкер + хедж кроме θ 0,75 / 1 %, фандинг — не проверялись (остановка по слову координатора).
