## Метод приёмки

Счётчик «не подписано (REST)» по построению пуст (проверка, п. 1) — по нему не принимаем. Принимаем по независимым числам:

1. **Символы с данными против REST-состава.** `symbols.with_data_1m` (health) против `pool.rest_eligible` (health, опрос коллектора) и против независимого состава `univ.py` (свой разбор REST биржи: торгуемые бессрочные USDT-контракты с оборотом за сутки ≥ 300 тыс. $).
2. **Сверка с REST по записям (collect-gap, `tools/collect_gap/`).** За первый час после выкладки: матрица записей окна (`aggregate.py --only <запуск>`) против REST-минуток (`klines.py`) по независимому составу — доля торговых символ-минут без записи книги (`b`) / сделок (`t`), символы без единой записи книги. «До» — тот же скрипт на часе перед выкладкой (старый процесс), окно 00:12–01:12 UTC (04:12–05:12 GMT+4).
3. **Счётчики потерь** (`totals.sink_blocks_dropped`, `sink_errors`, `rx_clamped`, `ring.full_events_total`, `lost_1h_s` на странице `:8088`), **лаг прихода** p50 / p99 по окнам 60 с (`lag_in_ms`) «до» (30 мин перед выкладкой) и «после» (с 90-й секунды), шарды с одной или без линий.

Запись health раз в 30 с по всем биржам — юнит `poolfix-watch` (`/data/perf/poolfix-deploy/watch-<биржа>.jsonl`, `tools/collect_gap/watch.py`); сводка «до / после» — `accept.py`. Накат — `/data/perf/rollout.sh` (то же, что `tools/collector-perf/rollout.sh`, отличается только строкой комментария), откат — `/data/perf/rollback.sh <юнит>` (возвращает `<бинарь>.prev-<md5>` и прежние аргументы из `/data/perf/rollout-<юнит>.env`).

### Отклонения

1. **Приёмка по бирже — через 12–14 мин (Bybit, OKX, BingX, Gate) и через 60 мин (Binance), а не по часу на каждую.** Следующая биржа выкладывалась после приёмки по живым счётчикам и 10-минутной сверке с REST; часовые сверки шли по таймерам параллельно со следующими выкладками и закрыты после (таблица выше). Откат ни одной биржи по часу не потребовался.
2. **Накат `rollout.sh`: проверка «health свежий» дала «OK» на последней записи старого процесса** (`T_STOP` — целые секунды), у Bybit и Gate нового health ещё не было ≈ 13 с; приёмка велась по своим счётчикам, не по «OK» наката. Правка скрипта — доработка.
3. **Показатель дыр уточнён по итогам первого часа** (см. «Часовые сверки»): дыры «до первой записи» у символов, пересёкших порог внутри окна, не считаются срывом; независимый момент пересечения порога не проверялся.
4. **Свои инструменты:** `aggregate.py` падал `IndexError` на неполной последней строке живого файла (запись `m`) — правка в `tools/collect_gap/aggregate.py`; часовые задачи OKX и BingX упали из-за этого и из-за перезаписи `postcheck.sh` во время работы (код 127), перезапущены `rerun.sh` (REST-минутки не перекачивались). Результаты на диске: `/data/perf/poolfix-deploy/{before,after10,after60}/<биржа>/`.
5. **Сбросы Bybit / BingX и остановки хоста на :00** — причина не найдена (разделы выше); в очередь доработок по указанию координатора.
