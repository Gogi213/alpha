# TK-020 шаг 4: коллектор пишет сутки → перенос на ящик (план для гейта Судьи, 02.10)

Владелец 02.10: «сделать чтобы коллектор писал один день и сразу переносить его в сторедж бокс». Сейчас (T-37):
коллектор пишет `root/<SYM>-<сутки>[-pN].binlog` и `root/deep/…` по суткам UTC; таймер `alpha-sb-push` 00:10 UTC копирует
вчерашние сутки на ящик и сверяет sha256 (VERDICT OK 27–30.09), но локальную копию не удаляет — чистит её только
`prune-pulled.sh` после забора Steam Deck; забор 30.09 не прошёл (диск деки 99 %) → коллектор копит (17 → 33 %).

## Что меняется

1. `tools/sb-push-day.sh` (тот же таймер 00:10 UTC, тот же журнал `sync/sb/push-<сутки>.log`, `done.txt`, манифест на ящике)
   получает шаг **«перенос»** после сверки — только при всех условиях:
   - сутки закрыты: `<сутки>` < сегодня UTC, и ни один файл суток не открыт процессом коллектора (`fuser`/`/proc/<pid>/fd`);
     иначе — пропуск удаления, тревога;
   - VERDICT OK: на каждый локальный файл суток строка `ok` с той же суммой в `done.txt`, `MISMATCH` = 0, число файлов
     ящика (`ls` по маске суток) ≥ локального;
   - сумма ящика — свежая (`sha256sum` самого ящика в этом прогоне, как сейчас), не из манифеста.
   Тогда удаляются ровно файлы из манифеста `collector-<сутки>.sha256` (явный список, не маска) и их жёсткие ссылки
   `verify/<сутки>/<имя>`; итог — строка `MOVED <сутки> файлов N, байт B` в журнал.
2. **Тревога при сбое:** любой не-OK (rsync код ≠ 0, MISMATCH, открытый файл, нехватка файлов на ящике) → файл
   `sync/sb/ALERT-<сутки>` + запись в журнал; локальная копия остаётся; следующий прогон (ручной `sb-push-day.sh <сутки>`)
   догоняет. Сторож диска коллектора: > 70 % → `ALERT-disk`.
3. **Кадры при переключении суток не теряются:** коллектор не останавливается и не перезапускается — меняется только
   скрипт заливки (атомарно `cat > .new && mv`). Переключение файла на новые сутки делает сам коллектор в 00:00 UTC, как
   сейчас; заливка начинается в 00:10 и не трогает текущие сутки (проверка «< сегодня» и «не открыт»).
4. **Забор Steam Deck** (`alpha-pull` + `prune-pulled.sh`): после включения переноса не нужен — дека читает ящик
   (`~/sb`, sshfs ro) или берёт сутки с ящика. Предлагаю выключить `alpha-pull.timer` на деке тем же шагом (решение CEO:
   кто из счёта читает `~/alpha/root/` напрямую).
5. Швы `gaps.csv` (условие (б) T-37) — без изменений.

## Проверка до включения (гейт)

- Прогон на копии: `ALPHA_BASE=/tmp/tk020-test` с тремя сутками-образцами (≈ 10 файлов из 29.09, уже лежащих на ящике
  под `alpha/tk020-test/`), сценарии: OK → файлы удалены; подменённый байт на ящике → MISMATCH, ничего не удалено, ALERT;
  открытый файл (`exec 3<file`) → не удалён, ALERT; день = сегодня → стоп.
- Первая боевая ночь — 30.09 (уже на ящике, VERDICT OK) ручным запуском, затем таймер.
