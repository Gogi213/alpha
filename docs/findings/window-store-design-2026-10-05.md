# Хранилище окон ALWIN01 — дизайн (TK-050, 05.10 14:20)

Цель: круги читают с диска и декодируют не всю ленту монето-суток, а только объединение окон подходов D20; книга на начале
окна — готовым снимком. Основа — ALPREP01 (колонки + zstd, `lob prep-events`, `--prep-dir`, гейт d15 diff 0).

## Что берёт круг сейчас (код)
- Окно сигнала: `SignalWindow {t0_ns, start, DepthSnapshot}` (`src/lob/backtest.rs` ~3715): снимок книги после строк
  `[0..m)` (`m` — первая строка с `local_ts > t0` ИЛИ `exch_ts > t0`) + срез строк с `m` (`with_backtest_over_window`).
- Срез, который круг реально может прочесть: `[lower(t0), lower(t0 + horizon_span_ns(plan)))` — `window_row_spans`
  (`shared_driver.rs:87`); горизонт = вход-ожидание (`entry_ttl` ≤ 1 800 с) + дедлайн/выход по плану клетки.
- Счёт охвата уже есть: `ALPHA_PATH_STATS` печатает `windows / sum_rows / union_rows` на символ-сутки (`drive.rs:519`).

## Ключ хранилища монето-суток
`(символ, сутки, версия касаний D20, H_max, версия формата ALWIN01, tick/lot)`. В ключе НЕТ клеток, фильтров сигналов, σ.
- «Подходы D20» = множество `t0` ВСЕХ подходов к стене (до фильтров клеток); окна клеток — подмножество.
- `H_max` = максимум `horizon_span_ns` по всей сетке клеток (из набора ячеек/`--set`); округлить вверх до целых секунд.
  Клетка с большим горизонтом, чем `H_max` хранилища, — отказ (не тихий обход).

## Что лежит на монето-сутки
1. `windows`: объединённые интервалы строк `[a_i, b_i)` — слияние `[lower(t0), lower(t0+H_max))` по всем `t0` D20
   (пересекающиеся и смежные склеены). Строки — `CompactEvent` колонками + zstd (формат ALPREP01, куски по ~1 М).
2. `snapshots`: для КАЖДОГО подхода (не для склеенного интервала) `DepthSnapshot` на `m(t0)`: `t0_ns, start_row`
   (абсолютный номер строки суток), bids/asks `(tick,qty)`, best/low/high тики, timestamp. Хранить разностью к
   предыдущему снимку внутри интервала нельзя без проверки — v1: полные снимки колонками (tick дельтой, qty f64) + zstd.
   Ожидаемый размер снимка ≈ 16 Б × уровней (`levels_total`), число снимков = число подходов; оценка — замер (2).
3. Индекс: массив `(t0_ns, start_row, интервал_idx, смещение_в_интервале)` — поиск окна по `t0` двоичным; `row`→локальная
   строка = `start_row − a_i + смещение`.
4. Шапка: ключ, число строк суток, `H_max`, md5 колонок, число подходов, число интервалов.
Carry/D+1: окно у конца суток читает хвост D+1 только внутри `[t0, t0+H_max)` — хвост хранится в том же файле суток D
(второй сегмент `next_day_head`), чтобы круг не открывал два файла; пересечение «ничего после полуночи» кладёт 0 строк.

## Чтение (`bounce-grid --window-store <dir>`)
Вместо `open_replay_feed` + `SignalWindows::build`: загрузить интервалы и снимки; для сигнала клетки `window_at(t0)` берёт
снимок, срез `rest` = строки из интервала от `start_row`. `with_backtest_over_window` без правок. Сигнал, чьего `t0` нет в
индексе (D20 изменился) — отказ с названием ключа.

## Сверка при подготовке (бит в бит)
Подготовка строит и то и другое от полной ленты ТЕМ ЖЕ кодом (`SignalWindows::build` на `t0` D20), затем перечитывает файл и
сравнивает: (а) для каждого окна снимок == `SignalWindows::first_mismatch` None; (б) срез строк побайтно == срез ленты;
(в) гейт на данных: круги по хранилищу vs. круги по ленте — diff 0 на atom/d01/d15 (benchrun stand).

## Что инвалидирует
Версия касаний D20 (любая смена `t0`/фильтров ДО клеток), `H_max` меньше горизонта клетки, tick/lot, версия ALWIN01,
перезапись бинлога суток (md5 бинлога в шапке), смена правила снимка `m` (local/exch).

## Что неизвестно до замера (2) — число TK-049
- `union_rows` на сутки с горизонтом `H_max` (d01: 6,9 % ленты; d15 не гонялся; PATH_STATS считает по сетке 241 клетки —
  ближе к потенциалу, чем ATTEMPT_ROWS) → доля байт волны (читать придётся ≈ доля строк × коэфф. колонок 0,78 к бинлогу).
- Число подходов D20 на сутки и средний размер снимка → вес `snapshots` относительно интервалов.
- Размер выигрыша берётся только из этих чисел; прототип `lob prep-windows` + `--window-store` после них.

## Оценка байт и цены подготовки (15:20, по числам TK-049 и ALPREP)
- QUICK5: активных 147/435 суток, бинлог 3,41 ГБ; окна D20 = 48–64 % строк активных → ALWIN ≈ 1,3–1,7 ГБ (×0,78 колонки+zstd);
  снимков 238–407 на волну (единицы МБ).
- Подготовка = полный проход ленты активных суток + SignalWindows::build + zstd: ЦП ALPREP на 6 суток 16 301 с ⇒ порядка
  160 тыс. ЦП-с на янв+фев (волна янв+фев на b7 — 12 189 ЦП-с): окупается только при многократном использовании хранилища.
- Решение «строить / нет» — по двум числам: волна b10 (.abin) и читатель-вперёд (TK-048); без них — не строить.
