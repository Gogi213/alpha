## Форма выхода (ось `--exit-form`, как `eat<X>`/`gone<W>`)

`weat<X>s<W>{m|l|a}<Y>`, например `weat30s60m10`:

- `X` — % в (0, 100]: исполнено по цене стены **после входа** за окно `W` с ≥ X % наибольшего видимого
  размера стены на её цене в том же окне;
- `W` — целые секунды в [1, 3600]; окно — `[max(вход, t − W), t]`, точность — секунда (как Г-55 TK-012:
  секунда события `exch_ts`, корзины по секундам, кольцо на `W` корзин, память — при постановке плана,
  на событии аллокаций нет);
- режим: `m` — «рынок» (выход, только если BTC за окно ≤ −Y bps), `l` — «местный» (только если BTC > −Y
  bps), `a` — оба (выход при любом BTC; причина в `rounds.csv` всё равно раздельная);
- `Y` — bps ≥ 0.

Порядок в `decide_exit` — на месте `eat<X>` (после тейка и `eaten_half`, до `gone`); с `eat<X>`/`gone<W>`
в одной форме не сочетается (одна форма выхода на ось, как сейчас).

## BTC

BTC в пуле коллектора нет — источник минутные свечи `ref-BTCUSDT-1m.csv` (`minute_ms,open,high,low,close,volume`,
тот же, что у `regime.py`). Флаг `--btc-minutes <файл>` (повторяемый; ряды сливаются по `minute_ms`),
обязателен при любой форме `weat*`, без неё — отказ. Ход BTC в момент `t` без заглядывания вперёд:
`close` последней **закрытой** минуты (начало ≤ `t` − 60 с) против `close` на `k = ceil(W/60)` минут
раньше, в bps. При `W = 60` это ход последней закрытой минуты (запаздывание до 60 с — свойство
минутного ряда; секундного BTC у нас нет). Пропуск минуты — берётся ближайшая более ранняя закрытая;
ряд, не покрывающий сутки прогона (с часом до и дедлайном после), — отказ до счёта.
Ход считается только когда порог съедания уже пройден (редко) — двоичный поиск по отсортированному
`Vec`, без `BTreeMap`/`HashMap` на пути события.
