### П.5 Стандарт вместо своего (да/нет и почему)

| Что своё | Стандарт | Решение |
|---|---|---|
| pid-замок + останов по pid-файлу + запуск через WMI/`systemd-run` (start.py ~450 строк, `_pid_alive*` ×3 в dispatch.py) | systemd user-unit (Linux, уже есть `unit_name/stop_unit`), Планировщик Windows | **Да, частично:** на Linux юнит — единственный владелец процесса (останов `systemctl stop` без pid-файла). На Windows WMI-старт нужен ради «вне job, переживает закрытие Claude»; замена Планировщиком — то же самое с задачей при входе, **не делать до КТ-4**. Лечит #6/#11 по источнику |
| `state.json` диспетчера, `ci-state.json`, `job-state.json`, состояние сторожа, `downtime` внутри `state.json` — 4–5 JSON с «tmp+replace» и повторами под PermissionError Windows (ticket.py:312, pulsedata.py:70) | sqlite (одна БД; шина `bus.py` уже на sqlite) | **Нет сейчас.** У каждого файла один писатель (диспетчер / ci_watch / watch), гонок нет; sqlite = перенос ~10 мест записи и миграция состояния при живых тикетах ради нулевого выигрыша. **Вместо этого — одна функция `atomic_write`** в `paths_state.py` вместо 10 копий приёма (−40 строк, 25 мин). Понадобится общий писатель — класть в БД шины, а не заводить вторую |
| Тикеты — markdown с шапкой и логом, правят люди и git | sqlite / трекер | **Нет:** читаемость и история git — суть; `ticket_lock` и `compact_log` работают |
| Очередь запусков (диспетчер: тик 15 с по каталогу тикетов + `MAX_PARALLEL`, `ROLE_PARALLEL`, часовой лимит) | готовая очередь (celery/rq/systemd-timer) | **Нет:** правил выбора (ревью, ход, часовые лимиты, одинаковый статус) в готовой очереди нет — писать поверх. Шина с ack (bus.py, sqlite) — для событий, не для выбора работы |
