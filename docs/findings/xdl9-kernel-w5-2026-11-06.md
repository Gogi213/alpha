## 2. Что изменено в ядре

По решениям CEO D5(ii), D3 и аудитам №1–2 (находки по ядру и выводам `run`). Без новых флагов вывод побайтно прежний (G16).

1. **Запрет входа до `from_min` задания** (D5(ii), аудит M3-04). Флаг `statarb run --no-entry-before-from` (по умолчанию выкл.) → `Params::entry_from = Some(from_day·1440)` на задании. Вход не исполняется раньше `from_min`; **сигнал по закрытию минуты `from_min − 1` допустим** (исполнение ровно на `from_min` — как у видов z при `min_obs = window`, где первый сигнал на `t = window − 1`). Минуты, где сигнал был, а вход запрещён, — `Counters::warmup_blocked` (единица — минута, не событие). Стоимость: проверка стоит только в ветках сигнала входа.

Причина — скорость, §5: любая правка цикла `multi.rs` меняла выбор LLVM; цикл оставлен побайтно как в `4ef45cc8`. Для F8 это не помеха: запрет нужен правилу funding (D2), а на видах z при `min_obs = window` он тождествен (G17 а).
