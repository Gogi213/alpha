## Отступления

1. **K1 не проверялся отдельно.** Использован кэш `touches-<SYM>.csv` (D20) как есть, без повторной
   сверки `verify-<SYM>.status == ok` по каждому дню/символу в этом счёте — протокол §4 требует эту
   сверку для сеток `bounce-grid`, здесь её не переделывали (кэш уже был подтверждён исполнимым T0
   25.09). Если часть суток окажется без `verify: ok`, числа блока A придётся пересчитать без них —
   не сделано за пределами бюджета этой партии.
2. **Метод ковариатного контроля для H4 не был явно заморожен протоколом** («Заморожено перед счётом»
   фиксирует только пороги `round_zeros`, не метод контроля) — терцильные страты возраста/размера
   (пороги — по августу, тем же приёмом, что и Г-28) выбраны исполнителем как разумная реализация
   требования §3 «контроль по этим осям», не как то, что владелец видел заранее.
3. **Эффективное N** посчитан через `effective_n_from_autocorr` (генерическая функция навыка, рассчитана
   на ряд доходностей) применительно к дневному ряду «доля `bounced` верх минус низ» — это перенос
   метода по духу правила («эффективное число, поправленное на автокорреляцию по суткам»), а не
   буквально то, для чего скрипт написан; сам факт низкого eff N (9,8–23 против 23–31 календарных
   суток) отражает реальную сильную корреляцию дневного эффекта день ко дню (эффект почти всегда
   одного знака), а не единичный сбой оценки.
4. **Холм посчитан частично** — только по 2 p-значениям (H1, H4) из 6 в блоке A; H2/Г-33, H3/Г-07,
   H5/Г-46, H6/Г-36 считают параллельно другие исполнители. Итоговая Холм-поправка блока A (все 6)
   не готова — здесь она не меняет вывод (p ≈ 0 у обеих гипотез до поправки), но формально это
   промежуточный, не финальный расчёт.
5. **p-значения указаны как `<0,0002`**, где ни один из 5000 бутстреп-повторов не пересёк 0 (разрешение
   метода — 1/5000); точное значение меньше, не измерено точнее без увеличения числа повторов.

6. (26.09, проверка Судьи) **Эфф. N больше числа суток — «не определено».** `effective_n_from_autocorr` на коротком
   ряде с положительной автокорреляцией выдаёт оценку больше числа суток (сентябрь основного и max — 39,1 / 39,0
   при 23; Г-08 сосед ≥3 — 34,3 при 31 и 31,9 при 23); такие значения в таблице — «не опр.¹», вердикт по ним не
   выносится. Правило то же, что во второй и третьей очереди (поправлены там же).
7. (26.09) **Выборка сентября шире, чем во второй и третьей очереди:** блок A читал кэш D20 как есть, поэтому в
   него вошли 4 монеты с отказом К1 на 16–19.09 (`FFUSDT`, `POWERUSDT`, `SKHYNIXUSDT`, `VVVUSDT`, ≈ 480 касаний в
   сутки, ≈ 1,9 тыс. на 6,7 млн — 0,03 %), которые вторая и третья очереди не содержат; и, как они, — монеты вне
   пула 76 (0,28 % касаний сентября). Не пересчитывалось: на знак и величину эффектов такая доля не влияет; записано.

¹ не опр. — оценка эфф. N больше числа суток (отступление 6).

## Вердикт

Правило §10 применено буквально, по каждой гипотезе и месяцу отдельно (месяцы — не смешивать):

- **Г-28 (H1) — обновлено 26.09 по проверке Судьи.** Сентябрь: эфф. N **не определено** (оценка 39,1 /
  39,0 при 23 сутках — больше числа суток, сбой `effective_n_from_autocorr` на коротком ряде; соседние
  сутки коррелируют +0,52, настоящее эфф. N ниже 23) → **не ясно**; август: эфф. N 7,9–9,8 < 30 → **не
  ясно**. Обратный знак устойчив в обоих месяцах (−7,71 / −11,57 п.п.). Прежний вывод «опровергнуто»
  (на эфф. N 39,1 ≥ 30) снят. Не «не повторять», а **кандидат обратной гипотезы** («сильная по сумме
  стена отскакивает реже») — новым протоколом, проверка только на сутках после его регистрации.
- **Г-08 (H4).** Оба месяца: эфф. N основного варианта (12,7 / 23,0) < 30 → **не ясно** по правилу
  (ограничение данных, не отрицательный результат). Точечный эффект положительный, устойчивый по обоим
  месяцам и во всех 8 контрольных стратах (требование «не объяснимо размером/возрастом одним» —
  выполнено: эффект нигде не исчезает), сосед `≥3` — тем же знаком (эфф. N не определено: 34,3 / 31,9
  при 31 / 23 сутках). Формальный вердикт остаётся «не ясно» — правило эффективного N в протоколе строгое и не
  делает исключения для «убедительно выглядящих» страт. Практический вывод: **гипотеза не опровергнута,
  но и не подтверждена по правилу; кандидат на до-снятие** (больше независимых суток — например с
  фоновых свежих суток П-01 после их наработки — подняло бы eff N выше 30).

## Смысл (толкование)

Помечено как толкование, не часть вердикта. **Чтение Судьи (26.09, вне счётчика):** признак почти целиком
`frontrun_lots` (у 87 % касаний фронтран ≥ 10 × `stack_levels`); обратный знак — не состав монет: внутри монеты
−10,97 / −14,54 п.п., все сутки обоих месяцев в минусе. Правдоподобное объяснение обратного знака у Г-28: сумма
`stack_levels + frontrun_lots` может быть не мерой «здоровой» глубины книги, а симптомом уже идущего
крупного агрессивного прохода — `frontrun_lots` считает объём, снесённый непосредственно перед уровнем
тем же импульсом, так что высокое значение может означать «здесь уже едет большой снос», а не «здесь
стоит большая защита». Это согласуется с находкой аудита 25.09 (`loss-days-2026-09-25.md`): «волатильное
предсказывает стопы, не деньги» — размерные оси стены сами по себе могут быть прокси волатильности
момента, а не силы. Для Г-08 рост эффекта с возрастом уровня (низкий возраст ≈ +1,6…1,9 п.п., высокий
≈ +8,8…9,6 п.п.) правдоподобно связан с отбором: «красивый» уровень, доживший до преклонного возраста,
уже прошёл естественный отбор на прочность, а свежий круглый уровень ещё не успел себя показать —
для `HYPOTHESES.md`, если Г-08 пойдёт дальше, стоит рассмотреть эту интеракцию с возрастом отдельно, не
только основной эффект.
