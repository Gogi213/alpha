- Клетки — `/data/tk064/r1/cells/<мес>/<клетка>.csv` (пороги по предыдущим месяцам до исходов, 33d6ce9f; охват 7b2a76c1). Месяцы фев…окт (янв — калибровка), 244 суток.

- На каждую клетку и месяц — `busy-replay.py --keep` (правило движка «позиция занята» на оставленных сигналах), затем `portfolio-sim` (депозит 2500, позиция 500; без потолка и B2 = 3; closes-out). База — B1 (все сигналы, тот же busy-replay). Скрипты: `tools/compute/p12-r1-psim.py`, `tools/compute/p12-r1-analyze.py`; сырьё `/data/tk063r1/` (psim-cap{0,3}-<мес>.txt/json, closes-cap*-<мес>.json). Заявки alsched 1008154720127…729272, все rc=0.
- Сверка: B1 за март −241 $ = B1 R2 (запись Судьи 17:34); остальные месяцы и итог Судье пересчитать на сервере (`psim-cap0-<мес>.txt`).
- Метод анализа — как R2 (`p12-r2-analyze.py`): Δ$ к B1 по суткам, блоки ceil(n^(1/3)) = 7 суток общие для клеток, T = Δ̄/se, step-down WY внутри семьи (семья = префикс имени), p семьи = минимум; Холм α/2/(39−k) по 39 семьям пакета. Месяц клетки определён при ≥10 сделок и ≥10 суток со сделкой. Семьи R2 — их p из `p12-r2-kpi-free-2026-10-08.csv`; семьи вне счёта (e112, e116, e106, e133, e65, g95) — p = 1.
- §6(2) равная экспозиция: фильтр R1 только убирает сделки, нотионал не растёт — нормировка не нужна. §8 «≥10 срабатываний механики» для фильтров = определённость месяца (≥10 сделок).
