# П-42: трейл лимиткой (движок v22, ключ `tl`) — TK-603, 18.11.2026

Слова владельца (18.11, дословно): «трейлы только лимитками. стоп понятное дело рыночный как и безубыток. нам нужно выйти из позиции любой ценой при стопе и безубытке».

Описательно: вердиктов, отбора и выбора клеток нет. Деньги — `net_nf = gross − fees` (без фандинга; фандинг при смене правила не изменился: |Δ| < 0,0001 $ во всех 12 парах), комиссия — по тарифу владельца (мейкер 1,4 / тейкер 3,5 бп, возврат 10 %). Сделки — модель «по ленте», 566 монет, Binance USDT-перпы, движок v22 (`tl = 0` ≡ v21).

## 1. Правило (записано до кода; уточнено один раз по первому прогону — см. п. 1.2)

Ключ варианта `tl` (по умолчанию `0`). `tl = 0` — прежнее поведение v21, сделки побайтово те же (раздел 3). Только `breakout tick`; минутный счёт ключ отвергает. Все цены — в длинной раме движка (шорт — зеркало: «≥» для продажи ⇔ «≤» для откупа).

Остаётся рыночным, как в v21 (тейкер по цене сделки, проскальзывание `slip`): `HardStop`, `BreakEven`, `TimeExit`, `Return`, `Forced`. Тейки — мейкер, как были.

**Трейл при `tl ≥ 1`:**

1. **Срабатывание** — как в v21: трейл взведён, цена сделки `p ≤ L`, где `L` — уровень трейла, и трейл главнее остальных стопов (прежний вид выхода `Trail`).
2. **Приказ.** Вместо рыночного выхода выставляется лимитный приказ на весь остаток по цене `L` (заморожена на срабатывании; трейл дальше не двигается). Мейкер, без проскальзывания. Приказ доходит с задержкой выхода `latx` (в базах 4 мс): `due = мс срабатывания + latx`; до `due` позиция живёт как в v21 в окне задержки (сделки только исполняют тейки). С `due` оставшиеся тейки сняты (остаток уходит одним приказом).
3. **Исполнение.** Первой сделкой потока со временем `≥ due` и ценой `p ≥ L` (в рамe; «дошла или прошла»; сделка срабатывания приказ не исполняет). Цена исполнения — **ровно `L`**, не цена сделки; комиссия мейкер; вид выхода `Trail`. Если такой сделки нет — приказ стоит, позиция открыта.
4. **Пока приказ стоит**, на каждой следующей сделке по порядку: (а) если ждёт рыночный выход (см. (в)) и сделка не раньше его срока — выход тейкером по цене сделки; (б) исполнение приказа по п. 3; (в) стоп (жёсткий `S`, NATR-стоп `sn`, безубыток `bm`) как в v21, но **без трейла**: `p ≤ max(стоп, NATR-стоп)` → **рыночный** выход (`HardStop` / `BreakEven`), приказ снят; с `latx` рыночный выход идёт на первой сделке `≥ срабатывание + latx`, и пока он не исполнился, стоящий приказ ещё может исполниться (п. 3); (г) выходы по времени и возврату (`tt`, `rf`) — как в v21, рыночные.
5. **Конец потока** при стоящем приказе: `Forced` тейкером по последней сделке (как в v21).

**1.1 Значения ключа.**
- `tl = 1` — буква приказа (п. 1–5): приказ исполняется по `L` первой сделкой `≥ due` с `p ≥ L`, **в том числе когда к приходу приказа цена уже вернулась выше `L`**.
- `tl = 2` — то же, но если к приходу приказа (цена последней сделки до `due`) цена уже **строго за** `L` (лонг: `> L`), приказ маркетабелен и исполняется как рыночный выход v21: на первой сделке `≥ due`, тейкер, по цене сделки, с проскальзыванием. Стоящие приказы (цена к приходу была `≤ L`) исполняются как при `tl = 1`.

**1.2 Почему два значения.** Первый прогон (бинарь `a1521114`: `tl = 1` и «строго насквозь» как `tl = 2`) показал: (а) «строго насквозь» совпало с «дошла» **во всех 12 клетках** — цена трейла `L` не лежит на сетке цен, сделка ровно по `L` не встречается, поэтому режима «строго» в итоге нет; (б) при `tl = 1` в окне задержки 4 мс цена иногда уже вернулась за `L` (чаще на одиночных выбросах ленты) — приказ исполнялся по `L`, а не по сделке: например шорт `SPORTFUNUSDT`: прежний выход на 0,9672 от цены входа, по приказу — 0,9871 (−2 % на сделке). Реальная биржа исполнила бы такой приказ как маркетабельный по рынку, а не по `L`. `tl = 2` — это поведение; `tl = 1` оставлен как буквальное правило задания. **Решение координатора:** правило — `tl = 2` (В-172), `tl = 1` — только описательная колонка (обе колонки ниже).

**Допущения (модель, не измерено).** (1) Исполнение стоящего приказа по `L` на первой сделке `≥ L` — приказ впереди очереди: верно для сделки строго выше `L` (весь стакан до неё выбран), а `L` не округлена до шага цены (как и цены тейков в v21): реальный приказ стоит на шаге цены чуть дальше. (2) Маркетабельный приказ (`tl = 2`) исполняется по цене ближайшей сделки с проскальзыванием — как выход v21, цена стакана неизвестна. (3) Позиция без выхода платит фандинг и держит монету «занятой» — считается движком; набор сделок при этом не менялся ни в одной из 12 пар.

Δ на сделку с трейлом из п. 4 (лонг, 60 суток: +0,076 $ на 112 сделках) усредняет эти лоты (+0,165 $ на лот, 85 лотов) с лотами, где выход не изменился (рынок на приходе) или приказ не исполнен (−5,55 $).

## 5. Что решает координатор

1. **Решено координатором:** правило — `tl = 2` (В-172: приказ, пришедший при цене уже за ним, — рынок как в v21); `tl = 1` (буква задания: приказ по `L` даже при цене уже за ним) — только описательная колонка. Цифры выше — для обоих.
2. Неисполненные приказы (4–8 лонг-сделок на окно закрываются безубытком по рынку): приказ снимается стопом/безубытком по п. 4 — «любой ценой» исполняется. Другая реакция (например, переставить приказ ближе к цене через N секунд) — отдельный ключ, здесь не делалась.
3. `tl` в минутном движке не поддерживается; бинарь с `tl` — только `breakout tick`; в `master` ветка не слита.
