# П-42: трейл лимиткой (движок v22, ключ `tl`) — TK-603, 18.11.2026

Статус: правило записано до кода (этот раздел), числа — ниже, раздел «Чувствительность». Описательно: вердиктов и выбора клеток нет.

## 1. Правило (записано до кода)

Ключ варианта `tl` (по умолчанию `0`). `tl=0` — прежнее поведение v21, сделки побайтово те же (ворота — раздел 3). Только `breakout tick`; минутный счёт ключ отвергает.

Все цены — в длинной раме движка (шорт — зеркало: «≥» для продажи ⇔ «≤» для откупа). Ступени тейков, стоп, безубыток, время/возврат от уровня — без изменений.

1. **Срабатывание трейла** — как в v21: трейл взведён, цена сделки `p ≤ L`, где `L` — уровень трейла на этой сделке, и трейл главнее остальных стопов (`L > max(стоп, NATR-стоп)`), то есть прежний вид выхода `Trail`. При `tl = 0` на этой сделке выход тейкером по `p` с проскальзыванием.
2. **При `tl ≥ 1`** вместо рыночного выхода выставляется **лимитный приказ на весь остаток** по цене `L` (заморожена на срабатывании; трейл дальше не двигается), мейкер, **без проскальзывания**. Приказ выставляется с задержкой выхода `latx` (как рыночный выход: `due = мс срабатывания + latx`); до `due` позиция живёт как в v21 в окне задержки (сделки только исполняют тейки). С `due` оставшиеся тейки отменены (остаток уходит одним приказом).
3. **Исполнение приказа.** Только по сделке потока со временем `≥ due`, которая идёт в сторону приказа: `tl = 1` — цена `p ≥ L` (в рамe, «дошла или прошла»); `tl = 2` — `p > L` (строго насквозь, как у тейков; консервативно по очереди в стакане на цене `L`). Цена исполнения — **ровно `L`**, не цена сделки; комиссия — мейкер (1,4 бп, возврат 10 %), проскальзывания нет. Время выхода — время этой сделки, вид выхода — `Trail`. Сделка срабатывания приказ не исполняет (приказ позже неё). Если сделок `≥ L` нет — приказ стоит, позиция открыта.
4. **Пока приказ стоит**, на каждой следующей сделке (в порядке): (а) если ждёт рыночный выход (см. (б)) и сделка не раньше его срока — выход тейкером по цене сделки; (б) приказ исполняется по п. 3; (в) стоп (жёсткий стоп `S`, NATR-стоп `sn`, безубыток `bm`) проверяется как в v21, но **без трейла**: `p ≤ max(стоп_базовый, NATR-стоп)` — **рыночный** выход, тейкер, цена сделки с проскальзыванием `slip`, вид `HardStop` / `BreakEven` как в v21; приказ снимается. С задержкой `latx` рыночный выход идёт на первой сделке `≥ срабатывание + latx`, и пока он не исполнился, стоящий приказ ещё может быть исполнен (п. 3); (г) выходы по времени и возврату (`tt`, `rf`) считаются как в v21 — рыночные, `TimeExit` / `Return`.
5. **Конец потока** (данные кончились) при стоящем приказе: `Forced` тейкером по последней сделке, как в v21.
6. Остаётся рыночным по-прежнему: `HardStop`, `BreakEven`, `TimeExit`, `Return`, `Forced`. Тейки — мейкер, как были.

Следствия, которые считаются честно, а не «по построению»: позиция может остаться открытой дольше (фандинг на остаток, монета «занята» дольше, пауза портфеля по стопам считается по новому моменту выхода), приказ может не исполниться и закрыться стопом хуже, чем закрыл бы прежний трейл по первой же сделке.

Допущения (в моде́ли, не измерены): очередь на цене `L` не учитывается при `tl = 1` (оптимистично; `tl = 2` — другая крайность, нужен проход насквозь); приказ ставится по `L` независимо от того, где цена к моменту `due` (если цена уже `≥ L`, исполнение по `L`, не по лучшей цене — осторожнее реального).
