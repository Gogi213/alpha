# Storage Box: подключение, замер чтения, план переноса холодного (T-06, 2026-09-27)

Владелец 27.09 оформил Hetzner Storage Box BX11 (1 ТБ, Falkenstein). Вход — только по ключу:
`ssh -p 23 -i ~/.ssh/id_storagebox u677479@u677479.your-storagebox.de` (ключи Steam Deck и VPS; пароль владельца не
используется). Оболочка ящика ограничена (без труб), но есть `sha256sum`, `mkdir -p`, `df`, сервер rsync — суммы
считаются **на стороне ящика** с его диска.

## 2. Замер (27.09, Steam Deck ↔ ящик, домашний канал)

| что | объём | время | скорость |

Потребитель (`lob touches` по бинлогу с `~/sb` против локального) не мерился: на деке шла сетка Исследователя,
память на пределе. При 5–8 МБ/с чтение, а не счёт, задаёт время: сутки пула — 7–13 мин только на чтение, против
секунд с диска деки.

**Кэш VFS не стоит того.** Повтор через кэш ядра не ускорился: 3,7 ГБ не удерживаются при занятой сетками памяти.
Дисковый кэш rclone съел бы тот самый диск деки, который мы освобождаем. Вывод: **ящик — холодный архив**. Рабочие
месяцы (август, сентябрь) лежат на деке; с ящика — разовое чтение (`deep/` для Г-07, обвал) или возврат каталога
на деку перед серией прогонов.

## 4. План

1. **Копия единственных копий — идёт.** `deep/` и `root/` → ящик, сверка sha256 на обеих сторонах. После `VERDICT
   OK` данные на деке больше не единственная копия. С деки при этом ничего не удаляется.
2. **Ночной перенос — автоматом, после «да» владельца на план.** Таймер после забора (01:15 UTC): новые сутки `root/`
   и `deep/` → ящик со сверкой (~6,5 ГБ, ~16 мин). Правило удаления на деке одно: файл удаляется, только если его
   сумма на ящике совпала с манифестом.
3. **Освободить место (нужно «да» владельца — это единственные копии, В-106):**
   - `deep/` удалить с деки после сверки, затем удалять его каждую ночь после переноса. Вычисления его не читают;
     Г-07 «полная» читает через `~/sb` (~5 мин на сутки). **+26 ГБ сразу, и рост падает с ~7 до ~4 ГБ за ночь.**
   - `epochs/e-crash` удалить с деки (копия сверена). **+7,5 ГБ.**
   - Итог: ~50 ГБ свободно, рост ~4 ГБ за ночь → ~12 ночей запаса.
4. **Предложение CEO.** Сейчас T-30 август не качает (CEO: «не дублировать»). Можно отдать 01.08–15.09 в T-30 (VPS качает архив Bybit, ~1 ч) — тогда на ящике
   лежат все месяцы, и августовский и сентябрьский архивы на деке становятся дублями. Их убираем, когда месяц
   перестанет быть рабочим.
5. **Ещё через ~12 ночей** — то же правило для старых суток `root/` (старше N суток, после того как П-01 их учёл).
   N и момент — решение владельца.
