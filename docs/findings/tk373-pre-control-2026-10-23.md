# TK-373 / P-25: контроль «ход Bybit до события» для L (дисбаланс потока DEX) и F (расхождение цены пула и середины Bybit) — 23.10.2026

**Итог.** Канал «арбитражёры гонят DEX вслед за Bybit, Bybit продолжает» (моментум) в L не виден: наклон Snet на предходе **отрицательный** (−0,02…−0,18 бп на бп предхода), а там, где Bybit за 10/60/300 с до события ещё не пошёл по стороне события, Snet остаётся положительным. Размер прежний — 0,3–3,3 бп, ниже издержек. Для F — частично: у F024/25/27/28 на h=5 наклон слабо положительный (+0,02…+0,03), но значение при нулевом предходе остаётся +3,8…+12,8 бп; F026 (разрыв держится ≥10 с) на h=300–900 тоже держится в страте «Bybit не пошёл» (+5,7 ± 2,1 / +12,2 ± 6,2 бп), CI широкий. «DEX ведёт Bybit» по-прежнему писать нельзя без разведения по причине (направление не доказано одним предходом), но возражение «это просто моментум Bybit» этим контролем не подтверждено.

**Метод.** Движок `tools/compute/tk373-run.py` (импортирует `tk369-run2.py`: те же события L048–L055 и F024–F029, середина стакана, Snet v=1 = маркаут с вычетом сдвигов ±3600, окно счёта 16–21.10). К каждому событию — предход pre_W = s·(mid(t0) − mid(t0−W))/mid(t0−W), t0 = ts+1, W ∈ {10, 60, 300} с, бп. Агрегация `tools/compute/tk373-agg.py`: Snet по страте pre ≤ 0, по квинтилям pre, регрессия Snet = a + b·pre; SE устойчивая, кластеры — монето-сутки. Это контроль, а не поиск: BH не применялся, порог §6 не пересматривался. Таблица — `tk373-pre-control-2026-10-23.csv`, строки — `…-top.txt`. Счёт на calc: `/data/tk0369/run/out3`, юнит `tk373-run`, ≈ 7 мин.

**Охват.** 77 монет (в v2 агрегации было 76 — Q не успела; поэтому n чуть больше: L054 h=60 n=13 708 против 13 488, Snet +1,12 против +0,99). Месяцы отдельно не считаются: неделя 16–21.10 (6 суток), одна секунда блока.
