## Определение KPI (фиксируется)

- Кривая счёта — по закрытиям сделок (реализованный PnL), каждый период с нуля: август (с закрытиями 01.09, В-94),
  сентябрь 01–23, «август + сентябрь» одним счётом.
- Новый максимум — закрытие, после которого счёт строго выше всех прежних значений (старт периода = максимум 0).
- Период до перехая — время от максимума до следующего максимума, часы; собираются **все** периоды. Незакрытый хвост
  (от последнего максимума до конца периода) — отдельно; в «самый долгий с хвостом» входит.
- Распределение: число новых максимумов, медиана, p75, p90 по счёту периодов, самый долгий, хвост; плюс p90,
  **взвешенный временем** — длина периода, в котором проходит 90 % времени месяца (хвост входит).
- Рейтинг: 1) плюс в обоих месяцах и сделок ≥ 30 (август) / ≥ 10 (сентябрь) — прошли 95 из 285; 2) p90 по времени по
  худшему месяцу; 3) самый долгий с хвостом. **Отступление от постановки CEO:** счётный p90 и медиана вырождаются —
  у вариантов с сотнями сделок большинство перехаев случается на соседних закрытиях (медиана 0 ч), а ожидания по
  200+ ч остаются; поэтому порядок по взвешенному временем p90, счётные — колонкой.
- Прочее: R² линейной регрессии дневной кривой на номер дня; доля плюсовых 7-дневных блоков; просадка по закрытиям /
  прибыль; «эпизоды» — группы сделок с разрывом между закрытиями ≥ 4 ч (приближение эпизодов просадки BTC).
- Смесь «среднее» — закрытия двух вариантов на половине позиции, без занятости монеты; «одним счётом» — точный
  прогон `portfolio-sim` на объединённых сигналах (`набор1+набор2`, занятость монеты учтена, позиция $500).

Счёт: `tools/compute/kpi-newhigh.py` → `data/kpi/kpi-2026-09-27.json` (все 285 рядов, все периоды).

## Поправка 27.09: KPI, устойчивый к старту (CEO, копия Судье)

Прежнее определение отсчитывает от начала месяца с максимумом 0 — чувствительно к случайному старту (потолок 5: 18,9 дня
только потому, что вытеснены ранние плюсы 01–08.08). Новое основное — **скользящий старт по непрерывному счёту «август +
сентябрь»** (без обнуления 01.09): для каждого часа t — время до первого закрытия выше максимума, достигнутого к t;
распределение по всем t месяца (медиана, p90, максимум), незакрытые к 24.09 00:00 — цензура (доля печатается). Рядом —
«со старта»: до первого закрытия выше значения счёта в t (бот запущен в t). Прежнее «от начала месяца» — справочно.
Рейтинг — по p90 «от максимума» худшего месяца; `data/kpi/kpi-roll-2026-09-27.json`.

- Главный: p90 13,7 дня в августе (максимум 16,8 — пик 22.08 перекрыт только в сентябре), 5,1 в сентябре; 73-е место.
- Первое место — П-05 45 мин · $25k: p90 6,0 / 2,9, максимум 9,1 / 4,6 дня, +$87 / +$69 (на проверке у Судьи).
- p90 ≤ 5 в обоих месяцах — нет ни у кого (лучший август 6,0). У вариантов с цензурой в сентябре 17–43 % оценка занижена.
- Немонотонность потолков уходит: без потолка 13,7, одновременно 3 — 13,8, 5 и 8 — 16,3 (`data/t32/grid-summary.md`).

## Правило П-07 (принято Судьёй `3d3a5f6`, 27.09) — доля часов вместо p90; H = 5, не 7 (эта мера заменяет раздел выше)

Судья, третья сдача П-07: «p90 ≤ 5 суток» читать как «доля часов t с ожиданием перехая дольше 5 суток ≤ 0,10», только по
t с полным горизонтом (сентябрь — t ≤ 19.09 00:00 UTC; август — все t, так как ожидание продолжается в сентябрь, данных до

максимум) — справочно, не главный показатель. `tools/compute/kpi-newhigh.py`: `rolling_kpi(h_days=5)` теперь по умолчанию;
добавлены `stability_by_day`/`stability_by_symbol` (худший случай без сделок одних суток / одной монеты),
`verdict_kpi` («проходит» — доля ≤ 0,10 в обоих месяцах и остаётся ≤ 0,10 под обоими исключениями; «не проходит» — > 0,10
хотя бы в одном месяце и остаётся > 0,10; иначе «на границе» — суждение по точке на двух месяцах, не статистика),
`bootstrap_share_le` (блочный бутстреп 7 сут — справочная колонка «доля выборок ≤ 0,10», без порога, Судья:
