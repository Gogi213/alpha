## 2. Три рантайма

### ГОРЯЧИЙ — живой бот
- **Состав:** `lob::strategy::on_event<MD, B>` + `LiveBot` (hftbacktest), `feed/live`, `bybit/*`, коллектор `lob session`. Тот же `on_event` исполняется в `Backtest` — A1.
- **Вход/выход:** события биржи → ордера. Конфиг стратегии — файл с хешем.
- **Граница:** только запреты горячего пути (CLAUDE.md «Правила, которые ловят ревью»). Исследовательские формы живут за флагами и в горячем пути не компилируются в исполняемую ветку, если флаг выключен (**условие вливания R2**: выкл. = байт в байт прежнее поведение + ≤ +1 % ЦП).
- **Кто вызывает:** systemd на боевой машине; тёплый рантайм вызывает ту же функцию через `Backtest` — другого кода стратегии нет.
- **Что меняется при переезде:** ничего в поведении. Только сборка из ствола и тег релиза.

### ТЁПЛЫЙ — прогонщик исследования
- **Состав:** один бинарник `lob bounce-grid` из ствола (все формы R1/R2 под флагами), оркестровка TK-048 как **одна** параметризованная обёртка `warm-run` вместо 154 `tk048-*` скриптов, планировщик `alsched`, Летопись (`guard.py plan/step/equiv`).
- **Вход:** `cells`-файл (список конфигов), период, `build-id` (хеш бинарника из манифеста), версия холодных данных.
- **Выход:** `/data/runs/<run-id>/` (CSV по клеткам + `run.json` c хешами входов) и запись шагов в Летопись; результат читается агрегатором, а не из россыпи папок.
- **Граница:** не готовит данные (берёт готовые из холодного), не пишет в холодное. Один проход по суткам на все клетки (`--cells`, В-136). Пачка клеток копится в один проход: 1 клетка ≈ 93 % стены 241 клетки (TK-121), поэтому отдельный проход на 1 конфиг — запрещён обёрткой (предупреждение при < N клеток).
- **Кто вызывает:** Исследователь/Инженер через `alsched submit --cls prod`; никто не запускает голый бинарник или свой скрипт-пересчётчик.
- **Опорные цифры:** волна 01–15.01, 241 кл = 211,8 с; 2 891 кл = 625,9 с; пул 275 суток, 242 кл = 4 878 с (TK-040).

### ХОЛОДНЫЙ — подготовка данных
- **Состав:** импорт архива/коллектора, `lob verify` (K1), эпохи, подходы/касания `.abin`, признаки, перенос carry; кэш **один раз под хешем**: ключ = `sha(версия формата, эпоха данных, сутки, параметры подготовки, build-id подготовителя)`.
- **Вход/выход:** сырой binlog → подготовленные форматы в `/data/cold/<ключ>/` (+ `/dev/shm` как горячая копия по требованию тёплого).
- **Граница:** не знает про формы и стратегии; ничего не пересчитывает при том же ключе — отсутствие ключа = считать, наличие = ссылка (В-213). Удаления — только по плану с «да».
- **Кто вызывает:** тёплый рантайм через `cold ensure <ключ>`; плановый крон для новых суток.
