## Определения (ядро `/root/p40core/rs/src/main.rs`)

- Расхождение: d = 10⁴·(ln(mid_A/mid_B) − уровень), уровень — медиана x за 6 ч (L_S=21600, :13), отставание 60 с (GAP_S, :14); эпизод открывается, когда |d| ≥ θ при спокойствии ≥ 60 с (W_MS, :15; условие :338).
- Вход (`Ep::new`, :247–250): мейкерская сторона лучших цен в t0 — продажа на аске дорогой ноги, покупка на бид дешёвой.
- Схождение: `dir·d ≤ 0` (main.rs:286) — **по середине (mid) относительно уровня**, не по равенству цен ног; выход по закрывающей стороне лучших цен (шорт — аск, лонг — бид; :264), т. е. спред на выходе платится. Результат = `pnl_end_bps` из `<base>.path.csv`, bps номинала ноги, сумма двух ног.
- Комиссия, тариф Bybit (В-88, В-125). Выход ядра идёт по цене тейкера (откуп шорта по аску, продажа лонга по биду, main.rs `Ep::step`), вход — по мейкерской стороне. Согласованные строки: **(i) вход мейкером, выход тейкером = 2×1,26 + 2×3,15 = 8,82** — считается сейчас; **(ii) вход и выход мейкером = 5,04** — нужны bid/ask на t_end (досчёт), до него 5,04 — верхняя оценка; «всё тейкером 12,6» — нужна противоположная сторона на t0 (досчёт), строка убрана.
- «Не сошёлся» — до конца данных; результата на H=600 с в выходе ядра нет (см. «Нужно досчитать»).

## Нужно досчитать (запись Инженеру TK-522)

1. Размер L1 (bid/ask qty × price × множитель контракта) обеих ног в t0 и в t_end → правило «≥ 100 $» на входе и выходе; доля отсечённых.
2. pnl на H=600 с (закрывающая сторона на t0+600 с) для не сошедшихся к H; на конец данных — для 28 несошедшихся.
3. Цены обеих ног в t_peak → настоящий потолок «вход на максимуме» вместо приближения по d.
4. (возврат Судьи) bid/ask обеих ног на t_end → вариант «выход мейкером», полуспреды на t_end; противоположная сторона (bid/ask) на t0 → вариант «вход тейкером»; медиана спреда ноги за сутки → доля эпизодов со спредом на t0 > 2× обычного.

Пока 1–4 нет, результат — без 100 $-фильтра и без H-отсечки.
