## 3. Находки

### Важно

1. **`merge_rule.py:176–187` — сбой GitHub после успешного слияния теряет все послеслияние.** `gh(PUT …/merge)` прошёл (PR влит), следом
   `gh(GET …/pulls/{n}).get("merged")` (строка 178) стоит вне `try`. Исключение (5xx, сеть) поднимается из `merge_once`, его ловит только
   цикл `ci_watch.py:224` (`print` в stderr); `_save(st)` (строка 207) не выполняется. PR уже не в `state=open`, следующий проход его не
   увидит ⇒ не будет: записи «влит» в тикет, `_drop_accepted` (в шапке `accepted` остаётся навсегда), и — для PR самого плагина —
   `R.tag_release` + `R.spawn_auto` (**выпуск без тега, автовыпуск не стартует, откат невозможен**). Тикет проснётся по `merged:`, но
   владелец видит «влит» без записи. Доказательство: код выше; в `test_merge_rule.py` нет теста «GET после PUT падает».
   Правка: обернуть проверку в `try`, при сбое — `_gh_error`-путь с повтором; состояние `{"merged_unverified": sha}` и повторный заход.
2. **`merge_rule.py:136–138` — `PATCH` базы PR (цепочка) без `try`.** Любая ошибка `gh` на PATCH обрывает весь проход: остальные PR не
   обработаны, `st` не сохранён (счётчики ошибок `errs` других PR теряются, ERR_LIMIT не наберётся). Остальные вызовы `gh` в цикле
   обёрнуты в `_gh_error`, этот — нет.
3. **`routes.py:48–56` + `check()` — «доказательство» `done` это только `Path.exists()`.** `--path .` или `--path /` проходит;
   роль может сдать `done` без артефакта (`proof` попадает в лог как «результат: .»). Обещание «шаг не закрыт без названного артефакта
   на диске» (CLAUDE.md alpha) держится на честности роли. Правка: путь внутри проекта, файл (или непустой каталог), не `.`/корень.
4. **Срезы части А из сводки 08.10 не выполнены, сложность выросла** (раздел 2). Для «закрываем разработку» — это не блокер, но
   `dispatch.py` 2 699 строк / сумма 878 остаётся самым рисковым файлом и именно он менялся при каждом выпуске — любая следующая
   правка идёт в `tick`/`_finish_role_part`/`_reconcile` (CC 42–43) без возможности понять эффект целиком.

## 3а. Дополнение после возврата Судьи (прочитано: ci_watch.py целиком, dispatch `_finish_role_part`/`_block_ticket`/`tick`/`main`/`_reconcile`, `ticket.parse_wait_for`, `plan.py`, `ask.py`)

**Важно**
14. **`merge_rule.py:20,176` + `ci_watch.py:47` — находка 1 шире (замечание Судьи принято).** `gh_api` ставит `timeout=60`; `hide.run` по таймауту бросает `TimeoutExpired`, текст содержит «timed out» ⇒ `_TRANSIENT` считает сбой временным, `_gh_error` молчит до ERR_LIMIT=3. Если GitHub успел слить PUT, а ответ не вернулся (таймаут/5xx после слияния), PR уже не `open` — `merge_once` его больше не увидит: ни записи «влит», ни `_drop_accepted`, ни `tag_release`/`spawn_auto`, **владельцу — ничего** (в отличие от пути «тег не поставлен», где владельца будят). Для PR плагина — тихая потеря выпуска. Правка: перед повтором PUT и при любом сбое PUT/GET после него спрашивать `pulls/{n}.merged`; если `merged` — идти по пути послеслияния; в `st` держать `{"pending_merge": sha}`.

Отладочный признак — только stderr. Правка: `try/except` вокруг тела цикла с `notify_parse_error`-подобной записью (≈ 6 строк) + тест «битый тикет не мешает соседям».
