# TK-244 — метрики и вкладка «Прогоны»: определения, источники весов (15.10)

Статус: определения и код (`tools/launch/metrics.py`, `runs.py`, `GET /api/runs`) готовы; таблица сверки «страница / независимый пересчёт» (≥ 10 хешей) — после снимка Летописи с метриками (шаг 3).

## Определения (одни и те же на «Прогонах» и в «Летописи»; подпись страницы цитирует их)

| метрика | определение | откуда |
|---|---|---|
| счёт | **cap 0** (без потолка позиций), $ из closes `[мс, $, монета]`, с нуля, **без депозита** | `pnl_usd` Летописи = Σ$ cap 0 (`load_f1.py`), сито TK-237 тоже cap 0; cap 3 (B2) в метрики не входит |
| PnL $ | Σ$ закрытий хеша за показанные месяцы | = сумма Летописи по этим месяцам |
| Шарп | mean / std (ddof = 1) суточного $ по календарным суткам UTC всех месяцев хеша, сутки без сделок = 0; **не годовой** | сито `tools/compute/tk237-sieve.py` (`sr`) |
| Винрейт | доля закрытий с $ > 0 | задача TK-244 |
| Перехай, дн | по каждому месяцу с нуля (старт = максимум 0, новый максимум — строго выше): самый долгий период «максимум → новый максимум»; по хешу — худший месяц; **незакрытый хвост** (последний максимум → конец месяца) — отдельным полем; цель ≤ 5 дн считается с хвостом | В-120 и доп. 1–3 (`docs/plan/SETTLED.md:611–621`), `kpi-newhigh.periods_to_high` |
| прочерк | нет сделок / нет месяцев / σ = 0 → `None`, не «0» | задача TK-244 |

Закрытия после конца месяца (В-94) остаются в своём месяце и продолжают ряд суток — сумма не расходится с Летописью.
Метрики прогона — за месяцы этого прогона (оверлей), «лучший вариант» — хеш с максимальным Шарпом среди посчитанных; без Шарпа в выбор не входит.

## Веса этапов общего %

Не придуманы: проход F1 П-14 (TK-231, 501 хеш × 251 суток): счёт ≈ 11,5 ч (11–12 ч), psim ≈ 50 мин (`TK-231.md`, строки про 251/251 и «psim cap0/3 ≈ 50 мин») ⇒ `W_DAYS = 690/740 = 0,932`, `W_PSIM = 0,068` (в макете 93/7 — то же). ## Источники состояния прогона (без обходов /data)

`<run>/run.json`, `days.txt` (всего суток), `out/run-<мес>-<сутки>/{claim,done}`, `psim/closes-p14f1-cap{0,3}-<мес>.json`, `psim/psim-p14f1.done`, `overlay.jsonl`, `result.json`, `postload.log`; запросы — `<request_dir>/L-*.json` (= «в очереди»); очередь, ядра, чужие задания — `alsched ps`. «В Летописи» = все хеш×месяц оверлея прогона есть в каноне (`master.have_hashes()`; по `run_id` не судим — его задаёт CEO при переносе), иначе «ждёт Летопись».
