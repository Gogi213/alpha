## Вердикт

Правило: клетка идёт кандидатом вперёд, только если проходит g1 (Холм) и g2–g4 (§13.30 п. 5); «слабая» (z ≥ 1,64, g2–g4) — только в `HYPOTHESES.md`. Результат: **0 из 36 правил защиты, 0 из 5 E(k), 0 из 26 клеток стопа** (лучшие: L `s` = 3 z +1,09, p 0,137, g2 ✗; E(15) p_Холм 0,615; Б(5 мин, 50 бп) p_Холм 1,0); «слабых» (z ≥ 1,64) нет. **Края нет** на этих данных среди перечисленных рычагов: защита до касания, вход после шага, уровень и тип стопа. Лонг-база вперёд идёт только описательно (§13.28 п. 7). Мощность вперёд для любой защиты хвоста: ожидаемо 1–2 сделки типа «стоп» в неделю (37 за 136 сут.), за 4–5 месяцев решить нельзя — поэтому новые рычаги на стопы вперёд не заводятся. Что осталось не проверенным: конструкции, не требующие касания (мейкер на уровне — TK-616 `L_mk2`, исключает хвост по построению, но у него вперёд α по §13.28 п. 7 только через решение координатора).

- Единственная конструкция, которая этот хвост исключает по определению, — мейкер на уровне (TK-616, `L_mk2`): заполняется только при касании. Остальное (стоп до касания, контрольная точка) на этих данных края не даёт.
- Ужесточение жёсткого стопа хвост не убирает: суммарный убыток по стопам почти постоянен, возвраты и выигрыши переводятся в стопы; стоп 5 % у L — 10 % маржи на сделку при плече 2, но укорочение его на этих данных не окупается (L `s` = 3 незначимо, S хуже базы при любом `s`).
