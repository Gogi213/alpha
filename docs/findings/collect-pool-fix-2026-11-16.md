## 1. Что изменено

- **`src/collector/livepool.rs`** — состав и гистерезис (`PoolState`: вход при обороте ≥ порога, выход, когда оборот ниже порога держится `--pool-hold-s`, по умолчанию 86 400 с; ответ REST короче половины пула считается сбоем и пропускается), раскладка по шардам (`Layout`: символ докладывается в шард своего вида с местом — наименее загруженный по числу потоков, иначе открывается новый шард; шард не опустошается: последний символ шарда не снимается), файл пула запуска (`PoolFile`), счётчики для health (`LivePool`).
- **`session.rs`, `shard.rs`** — живой набор потоков шарда (`StreamSet`, версия): сессия на тике сверяет версию и досылает разницу SUBSCRIBE / UNSUBSCRIBE на своём соединении (событие `pool_delta`); новая сессия (замена, переподключение) подписывается на актуальный набор, а не на начальный план.
- **Адаптеры пяти бирж** — `unsubscribe_messages`, `load_turnover` (оборот всех торгуемых контрактов + метаданные контракта для OKX, BingX, Gate), `shard_cap`, `pool_free_kinds` (Binance `mark` — один поток на все символы, от пула не зависит).
- **`runner.rs`** — поток `pool-refresh` (REST раз в `--pool-refresh-s`, по умолчанию 300, первый опрос через 60 с), применение операций в основном цикле; при `--pool-file` пересмотр по умолчанию выключен (копии для сравнения идут на том же наборе) и включается явным числом; при `--only-shards` выключен всегда.
- **`budget.rs`, `shard.rs`** — резерв мест (`set_urgent_reserve`: по 2 на шард, не больше трети лимита, только в окнах ≥ 60 с — Binance 54 из 280, Bybit 36 из 200) берут только шарды без соединения; потолки на шард (`Cap`): замен пути (не возрастной пересменки) — 4 за 5 мин, отбракованных путей покрытого шарда — 6 за 5 мин (шарду без соединения потолок не мешает: холодная проба идёт первой). События: `replace_capped`, `path_reject_capped`.
- **`shard.rs`** — порог паузы данных шарда по его истории (`GapThreshold`, `gap_seed`): история — хвост `stats-<шард>.jsonl` прежних запусков; порог пишется в событие `gap` (`thr_ms`) и в `stats-*.jsonl` (`gap_thr_ms`). Множитель 2, p95 и предел базы 10 с — назначаемое (Судье). Остановки приёма Binance и Gate (≈ 1,7 % окон) на p95 не влияют.
- **Страница здоровья** — `tools/collector_health/v3.py`, `page.html`, `serve.py`: строка «не подписано (REST)» (число, оборот, возраст опроса); строка биржи красная при `not_subscribed` > 0. Два теста страницы (`test_http_api_and_page`, `test_entrance_switch_in_hour_is_warn_and_passes_through`) красные и на основе cfce94f6 — не от этой правки.
- **`ladder.rs`** — 22 срабатывания линта `indexing_slicing` сняты: основа cfce94f6 давала 854 при бюджете 836 (бюджет красный на `all` ещё до правок).
- Документы: `docs/collector-ws-format.md` (файл пула запуска, порог паузы), `docs/COMMANDS.md`.

## 3. Топ-10: ёмкость и полнота (`tools/turbo/top10_ladder.sh` = `steps.sh` + `restpass.sh`)

**Почему топ-10 исключали.** Правило пришло из пула исследовательского бота (SETTLED В-35 / D-ПУЛ: «десять старших по обороту среди прошедших исключения»), в Python-коллекторе G-022 оно перенесено как «≥ 300 тыс. $/сутки без топ-10» (`docs/findings/tk527-binance-ws-2026-11-11.md`, п. 2 портирования Bybit). Оговорок про ёмкость нет ни в коде, ни в отчётах.

**Метод — как лестницы G-022:** окна 3 мин, по 3 окна на ступень, каждое окно — свежий процесс новой сборки с флагами боя (Binance: `--never-slow --lazy --reactor --worker-inline --reactor-window-us 5000 --rx-stamp kernel --no-pong-only-degrade`; Bybit: `--reactor --worker-inline --reactor-window-us 10000 --rx-stamp kernel`), REST-сверка — после лестницы. Ступени: `10` — ровно прежний исключённый топ-10 (по обороту на момент запуска), `full` — весь пул вместе с топ-10 (Binance 522 символа, 27 шардов, 54 соединения; Bybit 393 символа, 15 шардов). **Отличие от лестниц 12–13.11:** боевой процесс той же биржи работал рядом (п. 13 приказов: боевой + копии ≤ 80 % лимита; бюджет копии ≤ 140 за 5 мин), его нагрузка — в тех же окнах (`prodwatch.py`, `prodwin.py`); окна Bybit шли с `ALPHA_COLLECT_CAPTURE=1` (сверка по сырому захвату) — ЦП Bybit с захватом, то есть верхняя граница. Флаг `--mark-free` для Bybit (дельты `tickers` только при изменении; критерий «запись mark каждую секунду» — Binance, первый прогон Bybit по нему упал не по данным).

## 5. Порог паузы шарда (просьба координатора по `health-red-slots-2026-11-16.md` §B)

Прежний порог 3 с (`GAP_TIMEOUT_MS`) для всех шардов красил столбик Bybit на разреженном trade03 (p50 наибольшего разрыва за 10 с — 1,1 с, p99 — 3,4 с) без потери данных. Теперь порог шарда = `max(3 с, 2 × p95 наибольших разрывов его 10-с окон за сутки)`, база не выше 10 с (порог ≤ 20 с); у шарда без истории (< 60 окон) — 3 с. Тесты: пороги (оживлённый шард — 3 с, thin-шард с хвостом 3,4 с — 6,8 с, редкие остановки не влияют, база с потолком, забывание за сутки), засев из `stats-*.jsonl` (битые строки пропускаются), живой шард: источник молчит 4,5 с — без истории одна пауза (`thr_ms` 3000), с историей trade03 — ни одной. **Не проверено на боевых данных**: сверка пауз trade03 за 15.11 по архиву биржи (файл на 00:03 UTC не выложен — открыто в отчёте health-red).

## 8. Открыто

- **Нагрузка на соединение.** Раскладка нового символа выбирает шард по числу потоков, не по нагрузке; на Binance 20 самых оборотистых символов на одном соединении биржа сбрасывает (раздел 2). Боевой пул по алфавиту это не вызывает (ступень `full` чистая), но новый «горячий» символ мог бы лечь на уже тяжёлый шард. Решение — через раскладку «по обороту вперемешку» или потолок нагрузки на шард; не делалось без замера, что это нужно.
- Шард без потоков биржа закрывает: поэтому последний символ шарда не снимается (`remove_symbol` → `None`, счётчик `pool.remove_blocked` в health).
