## 13. `on_event` построчно (путь по фазам; `strategy.rs:2779`, `1893`, `2096`, `2221`, `2386`, `988`)
Прочитано: `on_event` → `sweep_orphans` → ветки `Holding / ExitPending / ExitCancelPending / EntryPending / CancelPending / Idle`; подробно
`on_holding`, `decide_exit` (≈200 стр.), `submit_exit`, `on_entry_pending`, `cancel_resting/cancel_open`, `entry_cancel_reason` (начало), `sweep_orphans`.
`on_exit_pending`, `on_exit_cancel_pending`, `on_cancel_pending`, `on_idle` — только заголовки; **не читаны**.
- **Запрет 1 (аллокации):** в прочитанных функциях нет `vec!/Vec/Box/String/collect/clone/push/format!`; `sweep_orphans` ходит по `self.orphans.batches[k]`
  массивом (`b` — копия `Copy`-структуры), чтение заявок через `bot.orders(..).get(&id)` — поиск в карте крейта без владения. Нарушений нет (проверено чтением и
  `grep` по диапазону 1400–2790: единственное совпадение — комментарий на 2213). Не доказано автотестом (О2).
- **Запрет 5 (REST/async):** нет. **Запрет 2 (часы):** время только `bot.current_timestamp()` → параметр `now`. Соблюдено.
- **Запрет 6 (`f64`)** в `decide_exit`: стоп/тейк/вход сравниваются как `f64` (`bid <= gone.stop_px`, `bid >= take_px`, `still_at_level` допуском в тик, 133–137);
  стоп/тейк сдвигаются на **целое число тиков** (`level_shift`, комментарий F4), но `entry_px + shift` — сложение `f64`; ошибки округления на границе возможны
  только если цены уровня не кратны тику — в тестах не нашёл проверки кратности (**гипотеза**, проверить Инженеру).
- **Запрет 7 (Hash в событии):** `bot.orders(self.asset_no).get(&id)` в `sweep_orphans`, `cancel_open` — поиск в `HashMap` внутри крейта `hftbacktest` на каждом
  событии при активной заявке; наш код хеш-карту не создаёт, запрет на «структуру, которую мы держим», поэтому формально ок, но это O(1) с хешированием на горячем пути.
- **Новое (дизайн, A9 «одна стратегия в Backtest и LiveBot»):** `strategy.rs` зовёт диагностику бэктеста **из решающего кода**:
  `crate::lob::backtest::fast_depth::set_watch_tick` (`strategy.rs:1330`, в `observe_wall` — на каждом событии с активным кругом) и `note_order_dist`
  (`strategy.rs:2170`, в `submit_exit` для лимитных выходов). Обе — глобальная статистика TK-049 (`BAND_STATS_ON` + `AtomicU64`/`thread_local`), по умолчанию выключена, но
  стоит `load(Relaxed)` на горячем пути и **живая стратегия тянет модуль бэктеста** (`strategy.rs:33` импортирует `entry_price, entry_side, executed_*,
  exit_price, round_half_away, ENTRY_TTL_NS, HOLD_NS` из `lob::backtest`). Для LiveBot эти функции должны жить в нейтральном модуле, диагностика — выноситься
  за трейт/`cfg`. **важно (Г, дизайн).**
- **Сложность `decide_exit`:** одна цепочка из ~13 `else if` приоритета выходов (стоп → жёсткий выход → съедание → трейл → тейк → … → дедлайн), плюс разбор ≈19 полей плана.
  Порядок приоритетов — продуктовое правило, оно спрятано в ветвлении; пары «выход — причина» хорошо лягут в таблицу приоритетов (Г: не менять поведение, только структура,
  с гейтом «байт в байт»). **важно.**
