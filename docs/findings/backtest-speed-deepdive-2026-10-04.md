```
D = B / (v_sdb + v_sda)      диск, читатели ≤ 4 на диск
C = 22 705 · k · f / 15      ЦП; f — доля оставшейся ЦП-работы (1,0 = эталон)
```

### 4.1 Граф зависимостей («A → B»: польза B видна или возможна только после A)

```
Д1 (sda до конца) ─┐
Р1 (читатель+ворота)├─► ЦП определяет стену ─► любой ЦП-шаг (Ц*, Ч*) виден в стене

Д1 ─► Р1 ×2 (читатель на каждый диск; без него sda не разгружает sdb)
```

### 4.3 Точки перелома узкого места

1. **Диск → ЦП.** На одном диске при f = 1 D ≈ C (1 750–1 967 против 1 771–2 119 с): диск и ЦП равны. Д1 + Р1 + Р2 переводят стену на ЦП. Значит Д1 и Р1 — до любой ЦП-правки: иначе её не видно (с одним диском после шага 6 стена 2 096 / 1 780 против 1 570 / 940 с).
2. **ЦП → диск (только оптимистично).** f* = (D − T)/(C₀(1+ε)) ≈ **0,48** (опт., D = 875 с). Дальше шаги пакета шагов круга и PGO в стене не видны (опт.: 939 → 905 → 905 с). В консервативной колонке перелома нет: C 1 392 > D 1 146 до конца.
3. **Диск → ЦП после Д5.** Каждые −14 % байт сдвигают D на ≈ 120 с; баланс при B ≈ 115–120 ГБ (−26…−29 %), дальше байты бесполезны.
4. **Хвост.** При f ≤ 0,5 единица «сутки» стоит ≈ 90 с против 30 (по [МЕТ] до 200 с): малые единицы обязательны к моменту f ≈ 0,5.

## 7. Ловушки байт-в-байт

1. **Граница 31.01/01.02.** Январь и февраль эталона считаются в отдельных домах (`e-jan`, `e-feb`) без переноса через границу; «исправление» (общий дом, перенос 01.02 на 31.01) изменит выход эталона ([КОНВ] L16). Любая раздача работы сохраняет корень переноса месяца.
2. **Сайдкары `.events`.** Ключ — длина + mtime цели (`carry.rs:189-206`); лежат рядом с симлинком в `study/root-<D>`; `rmtree` дома их стирает; копия на sda через `rsync -t` сохраняет mtime, но сайдкар после копии проверять. Сравнивать кандидатов только при одинаковом состоянии сайдкаров и записать его в отчёт.
3. **Арифметика.** `target-cpu` не меняет `+ − × ÷`, `floor`, `sqrt` (RFC 3514), но: фиксированный `x86-64-v3`, не `native`; SIMD по f64 с явным FMA запрещён; libm (`exp`, `ln`, `pow` в `sigma.rs`, `final_metrics.rs`) зависит от glibc/CPU — эталон и новый бинарник считать на одной машине. PGO/BOLT IEEE не меняют, гейт всё равно.
4. **Округление.** `round_ties_even` ≠ `round` на половинках; Ц2 заменяет деление умножением на обратное — только с проверкой `тик×tick_e9 == px_e9` и f64-fallback (112 суток со сменой шага, В-172; довесок D+1 с иной сеткой; `--events wide`).
5. **Порядок вывода при параллельности.** Строки в порядке `instruments.csv` (отсортирован), формы по порядку; склейка групп (Р2) побайтно — шапки без списка монет; `threads=` в шапке (`plan.rs:453, 487`) оставлять `1` при потоках по монетам; счётчики `HORIZON_RETRIES`, `HOLD_SKIPS`, `EXIT_GROUP_ROUNDS` на CSV не влияют, но смешиваются в stderr.
6. **Порядок внутри группы события.** Сначала все биды группы, потом все аски — не порядок файла; `PriceSet` (known_bids/asks), сортировка `stale` на снапшоте: Ц3 повторяет правила `FileReplayer` + `push_side`; гейт — равенство `Vec<CompactEvent>` целиком.
7. **Спрятанные уровни и границы** `low_bid_tick/high_ask_tick` (В-172): глубину не резать; Ц4 сохраняет поведение; `build_crate` (книга крейта на HashMap) остаётся эталоном для `--windows-check`.
8. **`ryu`.** Другая экспонента и хвост `.0` — только обёртка под `Display`; `itoa` для целых безопасен.
9. **Опрос 10 мс (Ч3, Ч4).** При `include_order_resp=true` пропускать нельзя; `entry_pending`/`fill_by_cross` читают `last_trades` по шагам; `observe_*` меняют состояние на каждом вызове (идемпотентность для Ч4); гейт `poll` ↔ `skip` на ≥ 3 суток разного веса.
10. **Довесок D+1.** Окно `max(entry_ttl) + max(deadline) + RTT` = 16 200 с + RTT (≈ 18,75 % суток); срез по `local_ts ≥ until`, как обрывает `translate_feed_until`; для Ч2 — равенство `Vec` довеска.
11. **Общий объект окон (Ч1).** t0 = объединение по всем прогонам, иначе `window_at(t0)` вернёт `None`; ключ — сутки + перенос + tick/lot; живёт не дольше монеты.
12. **Режим суток, σ, D20.** Читаются из готовых файлов по всем монетам суток (`regime.py --day D`); при единице «группа монет» режим не считать по группе.
13. **Нарезка клеток.** Файл клетки = `NR<=2 || $3==метка`; 243 клетки × 3 файла = 729 на сутки; `manifest.txt`, `.done`; при замене `awk` сравнивать побайтно.
14. **Память.** Политика точной ёмкости буфера (OOM 18.09): Ч2(б) с запасом по верхней границе проверять по пику RSS; самые тяжёлые монето-сутки (LSKUSDT 146 млн событий ≈ 4,7 ГБ) — по одной.
15. **`CountingAllocator`** (`lib.rs:18`) держит тесты «ноль аллокаций»: mimalloc — через `LD_PRELOAD` или feature, не вместо счётчика в тестовой сборке.
16. **Эталонный выход** — `b5-ref` (бинарник `alpha-tk044k1-new`, пул v171b): новый бинарник сравнивается с ним, а не с «пересчитанным правильно».

## 8. Что решать владельцу
