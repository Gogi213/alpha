## Итог
Код реализует §3.5 (контраст признака, час суток χ², п. 1–4 «кандидата»), §5.1 (бутстреп, BH q=0,10, Холм 0,05, бюджет ≤242, минимумы страты), §5.2 (MDE). Синтетика 100 активов × 14 суток, ≈3 эпизода на ячейку, 4 режима зависимости. **Два дефекта протокола найдены:**
1. **Блочный бутстреп по суткам (§5.1) занижает интервал, когда признак или исход держится по активу**: нулевой эффект, покрытие номинально 90 %, фактически 54 % (режим «актив»), 89 % (только сутки — ок), 76 % («оба»). Схема «активы и сутки независимо» (twoway) держит 90–95 % во всех режимах.
2. **Формула MDE §5.2 занижает порог в 2,45 раза** при n = число эпизодов (0,023 против точного 0,056 на DEFF 1,44).

Решение о смене схемы бутстрепа — Судье (меняет §5.1); до него код по умолчанию `day` не использовать для итогов, `twoway/t` — предлагаемая главная.

## Не проверено / ограничения
- Нет проверки контролей на реальных эпизодах (сдвиг ноги, случайные моменты) — только правило сравнения в `candidate`; генерация контролей — ядро TK-500.
- Таблица эпизодов — одна строка на θ=12,6; прочие значения сеток — справкой, вне статистики.
- Синтетика односторонняя в смысле структуры зависимости (логит-случайные эффекты); реальные кластеры могут быть иного вида.
- `n_эфф` печатается как n/DEFF (DEFF по ячейкам актив×сутки); двусторонняя зависимость им недооценивается — см. (б).

## Алгоритм
Варианты — бутстреп по эпизодам, по ячейкам актив×сутки, по суткам (§5.1), по активам, активы×сутки независимо (twoway); интервал перцентильный или e ± t_{G−1}·SE. Замер — покрытие при нуле в 4 режимах, мощность, ложные прохождения BH; время twoway на таблицу 100×14 ≈ 4 мс/400 повторов (суммы по ячейкам + einsum, без пересчёта эпизодов). Выбран — twoway/t, потому что только он держит покрытие во всех режимах; day — по протоколу, но недопустим при постоянстве по активу.
