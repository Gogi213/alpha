# TK-609: максимум Rust в счёте П-42 — опись Python и план портов (18.11.2026)

Слово владельца: «давай максимизируем раст в проекте с критиком». Повод: таблицы признаков П-42 строит Python (`tools/p42/retitr_ftab.py` → `/data/tk594/py`), до ~1 ч на таблицу, а движок — Rust.
Метки чисел: **измерено** (лог/журнал/профиль, путь указан), **модель** (измеренное × допущение, допущение названо), **догадка**. Условия замеров: srv 8 vCPU (Xeon E5-2699 v4, без AVX-512), load 16–31 из-за `tk599-run`, `tk604-*`, коллекторов — времена в таблице завышены относительно чистого хоста, но в тех же условиях будет и сравнение после порта (п. 23 приказов).

## 1. Итог

1. Узкое место Python-счёта — **не арифметика, а чтение сделок**: профиль `tk594_feat.process_coin(flow)` на srv, одна монета, `nice 19`, один процесс (**измерено**, `/tmp/prof594.py` на srv): `pandas.read_csv` + `zlib` + превращение `is_buyer_maker` в объектный массив = **≈ 80–89 %** стены (LITEUSDT 25,2 с, 60 суток: сумма четырёх верхних строк по `tottime` 82 %, `read_csv` + объектные массивы по `cumtime` 88 %; HEMIUSDT 56,5 с, 27 суток: 81 % и 89 %); `searchsorted` ≈ 5 %, остальная арифметика — единицы процентов. Тот же вывод у движка: TK-607 §1.3 — `unzip` 56,7 % + разбор CSV 21,8 % ЦП вызова.
2. Рейтинг по «часы экономии = время × запусков впереди» (п. 3): **№1 поток+деривативы (`tk594_feat`)**, №2 токсичный поток (`tk600_feat`, общее ядро с №1), №3 эпизоды TK-604, №4 ядро бутстрепа (условно, после TK-607). Всё остальное — оркестрация, разовые отчёты, библиотечные вызовы (CatBoost) — остаётся Python (п. 5).
3. Зависимость от TK-607: склад сделок `TickStore` (`src/breakout/store.rs`, по плану) **не хранит количество** (`quantity`), а потоку и токсичному потоку нужен `v = price·quantity`. Нужна колонка `qty` в формате склада (п. 6). Склада в коде ещё нет → волна 1 стартует на `ZipDaySrc` (тот же вход, что у движка) и переключается на склад отдельным малым шагом с теми же воротами.
4. Равенство: целые/строки/маска NaN — **точно**; float — побитово, порядок сложений numpy воспроизводится (`np.sum` — попарное суммирование); допуск назначается только там, где побитовое равенство доказуемо невозможно, и **после замера** (п. 4.2).

## 4. План портов

### 4.0. Общее для всех волн

- **Код**: в `src/breakout/feat/` — `mod.rs`, `trades.rs` (сутки монеты: `DayTrades { t: Vec<i64> мс, p: Vec<f64>, v: Vec<f64> (= p·q), buy: Vec<bool> }`; `trait DaySrc`; `ZipDaySrc` — `unzip -p` + разбор как `tick::parse_trades`, но цена/количество — в `f64` прямо из десятичной строки, а не через ×1e8; порядок файла, при убывании времени — устойчивая сортировка, как Python), `npcompat.rs` (п. 4.2), `flow.rs`, `deriv.rs`, `tox.rs`, `io.rs` (вход эпизодов — CSV `ep_id,sym,side,sig_ms,turn24h`; выход — CSV `ep_id,<признаки>`: float — кратчайшая круговая запись, NaN — пусто), `tests.rs`. Подкоманда `feat <flow|deriv|tox|all> --eps … --base-date … --trades … --metrics … --out … --threads N` (в `alpha-feat`).
- **Бинарь**: отдельная цель `src/bin/alpha-feat.rs` (библиотека `alpha` общая; `src/main.rs`, `breakout tick`, `cli.rs`, `tick*.rs` не правятся). Движок счёта из этой ветки не пересобираем и не выкладываем: бинарь TK-599 (md5 закреплён воротами G1) и его преемник TK-607 по §13.24.6 остаются единственным отступлением по движку; сборка библиотеки с новым модулем всё равно меняет байты движка этой ветки — поэтому её движок в счёт не идёт.
- **Python остаётся как эталон**: файлы не удаляются и не правятся (md5 закреплены логом `prod_md5` ftab); после ворот вызывающий код переключается флагом `P42_FEAT_BIN=<путь alpha-feat>` в `retitr_ftab.run_tk594`, `tk594_aug_chain.sh`, `tk600_feat.py`; без флага — прежний путь. Переключение в TK-599 — только после G-A1 (все 6 таблиц) и G-A3, датированным дополнением к §13.24 с md5 `alpha-feat` и SHA ворот; до него ftab TK-599 строит Python. Вызывающие читают CSV Rust через `pandas.read_csv(float_precision="round_trip")`.
- **Ресурсы** (приказ владельца 18.11): сборки/тесты — только `bash tools/vps-check.sh <дерево> all` и `bash tools/p42/build-srv.sh` (2 ядра, nice 19); ворота на srv — не больше 4 процессов, `nice -n 19`, пока идут `tk599-run` и `tk604-*`; ПК владельца — только чтение/правка текста. Данные эталонов — только чтение (`/data/tk594`, `/data/p42-tk599/{ftab,wa,wb,wc}`, `/data/p42-tk600`, `/data/p42-tk604`).
- **Структура и правила**: тесты — `feat/tests.rs`; `cargo fmt --check`, clippy `-D warnings`; это не горячий путь стратегии (правила «ноль аллокаций» не применяются), деньги/цены — как в эталоне `f64` (признаки — отношения), без `unsafe`.

### 4.1. Волна 0 — подложка (до портов)

1. `npcompat.rs` + золотой набор: на srv numpy 2.2.4 пишет `golden/*.bin` (случайные f64, длины 0…2·10⁶, срезы с нечётным смещением, выходы `np.sum`, `np.cumsum`, `np.mean`, `np.bincount(weights)`, `np.log`, `np.log10`, `np.searchsorted` обеих сторон, `np.clip`, `np.diff`, `argsort(kind='stable')`); тест Rust — побитовое равенство. Волна 1 не стартует, пока `np_sum` не совпал на всём наборе (в numpy `add.reduce` по непрерывному массиву — попарное суммирование блоками 128 с 8 аккумуляторами; нужно ли начальное значение отдельно от первого элемента — выясняется набором, не догадкой).
2. `tools/p42/rustfeat_gate.py` — сравнитель таблиц «эталон Python (parquet) ↔ Rust (CSV)»: ключ (`ep_id`), типы, маска NaN, для float — разбор в `int64`-биты и отчёт: число равных, число различий, max ULP, список первых 20 ключей; выход — JSON в `docs/findings/rust-max-gate-<волна>/`.
3. `DaySrc` + `ZipDaySrc` + тест круговой сверки со `pandas.read_csv` на 5 реальных суток (те же, что в микростенде TK-607: BTC/SOL/DOGE/AAVE/ALGO 2026-07-15): массивы `t`, `p`, `v`, `buy` равны побитово. Эталон — разбор pandas как есть (`float_precision=None`, по умолчанию); при расхождении на 5 сутках Rust воспроизводит `precise_xstrtod` pandas, а не наоборот. Круговая сверка — также на `metrics`, `premium`, `funding` CSV (по 5 файлов каждого вида).

### 4.2. Правила равенства (единые для волн)

- **R1** Целые, строки, число строк, маска NaN — точно, без допуска.
- **R2** float — побитово. Сумма/среднее — `np_sum` (порядок numpy), `cumsum`/`bincount` — последовательно в порядке индексов; `math.log`/`np.log` на srv (Xeon E5-2699 v4: AVX2, без AVX-512) ожидаются равными libm `log`, как `f64::ln` Rust на той же glibc — это гипотеза, её проверяет золотой набор (п. 4.1), а не допущение.
- **R3** Допуск — только для функции, где золотой набор или ворота показали расхождение, и только после замера: фиксируется max ULP на воротах, граница записывается в отчёт волны **до** принятия (назначаемое число — решение с номером, критик). Допуск не применяется к столбцу, используемому как порог движка, без ворот R4. Столбец с допуском принимается только если замороженные модели, применённые к таблице Rust, дают предсказания, побитово равные предсказаниям на таблице Python (F и август).
- **R4** Решения движка: таблица Rust и таблица Python на одном потоке дают **байт-в-байт одинаковые сделки** движка — `retitr_ftab.py gatecells/gatecheck` («пропускает всех» = база, «режет всех», + 3 клетки с порогом `fv` = реальным квантилем столбца), `cmp` выходов. Это страховка от единичного ULP на пороге.
- **R5** Эталон — выход Python, уже лежащий на диске (не пересчитывается), md5 кода эталона записан в отчёт.

### 4.3. Волна 1 — порт A (поток + деривативы, первым); порт B — условно

Порт B (токсичный поток) — условно: старт, когда набор X назначен в перетитровку; ворота G-B1 те же. Решение критика 18.11 (FIX на 08c4f4db): волна 1 = только A; общее ядро (`trades.rs`, `npcompat.rs`, `io.rs`) пишется так, чтобы B добавлялся модулем `tox.rs` без правок A.

Модули `feat/flow.rs`, `feat/deriv.rs`, `feat/tox.rs`. Перенос как есть: окна `WIN_S`, гистограммы `q99` за 7 суток (`NB`, `EDGES`), порог `n_hours ≥ 24`, `has24`, VPIN (50 корзин, `VPIN_TOL`), Kyle/Amihud на минутных барах, `SAC_MIN_N = 30`, `MK_MIN_N = 10`; чтение `metrics` (сетка 5 мин, `create_time` → мс), `funding` (месячные архивы + `funding.csv`, дубликаты — последний), `premium` (минутки). Один проход по суткам монеты считает все выбранные наборы (`--set flow,deriv,tox`). Опциональный шаг 1b (деталь реализации, значения не меняет, ворота те же): часовые гистограммы `q99` на монето-сутки в боковом файле склада — следующий поток той же монеты не перечитывает 7 суток.

Ворота равенства (все на реальных данных srv):
- **G-A1, потоки TK-599**: шесть готовых таблиц (wa/wb/wc × L/S, 290–623 строки): `tk594-flow-S.parquet`, `tk594-deriv-L.parquet` в `/data/p42-tk599/ftab/<окно>/<поток>/` против Rust на тех же `eps-*.parquet` → полное совпадение R1/R2 по каждому столбцу.

### 4.5. Условно — порт F (ядро бутстрепа)

Нужно воспроизвести `numpy.random.default_rng(seed)` (SeedSequence → PCG64) и `Generator.integers(0, n, size)` (ограниченные целые, метод Лемира для int64), `np.percentile` (линейная) и `std(ddof=1)`: побитовое равенство блока индексов — условие, иначе решения процедуры могут отличаться (`seed_of` md5 на форматированных суммах). ## 6. Контракт со складом TK-607 (кто что делает)

TK-607 (`bb/tk-607-p42-ultra-speed-v1-thr_j667egy23c`, кода склада пока нет) пишет `src/breakout/store.rs`: файл `<store>/<монета>/<монета>-<дата>.tk`, дельта-varint + zstd, ключ `(монета, дата)`. Просьбы TK-609 (без дублирования кода — склад пишет TK-607, читает TK-609):
1. Колонка `qty` (целое в масштабе НОД шагов, масштаб в заголовке) — иначе `v = p·q` не восстановить. Нужна с первой версии формата или отдельное поле версии.
2. Точный круговой путь: `price` как десятичная → `f64` (не только ×1e8): склад хранит ×1e8; если у файла есть цены с > 8 знаков или Java-запись `9.16E-4`, круговая проверка в TK-607 должна это показывать; для `f64 = p_e8 / 1e8` при ≤ 8 знаках равенство с `pandas` верно (одно деление точных чисел) — проверяется воротами.
3. API чтения суток `read_day(sym, day) -> DayTrades` без обращения к `tick::Tick` (там нет `qty`); порядок записей — как в файле, при убывании времени — устойчивая сортировка (как сейчас в `parse_trades`).
4. Место склада и его потолок 3 ГБ (план TK-607): на потоке признаков читается ≈ 9 суток на монету + весь список монет — потолок может не хватить, нужен отдельный бюджет под склад признаков (по замеру).
Конфликтов файлов нет: TK-609 — новые файлы `src/breakout/feat/*`, `src/bin/alpha-feat.rs`, `tools/p42/rustfeat_gate.py`; в `src/breakout/mod.rs` — одна строка `pub mod feat;`.
