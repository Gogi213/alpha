## Методика (на ревью Судье)
- Ранг на сутки D = по обороту суток D−1 (свеча D, полный день), без заглядывания вперёд в ранге. Допуск к ранжированию: есть свеча D−1 и D (признак «торгуется» —
  единственное знание «вперёд» на сутки D), возраст ≥ 30 сут. по `launchTime`, не BTC/ETH.
- Вселенные: `pick_rule` = исключения как в `lob pick` (BTC/ETH, 6 имён `NON_CRYPTO_BASES`, возраст) — акции/ETF/сырьё в `NON_CRYPTO_BASES` не покрыты
  (в API 199 stock, 54 ETF, 4 commodity, 3 forex); `crypto_only` = то же + выброс `symbolType` ∈ {stock, ETF, commodity, forex}. «Вырез топ-5» (cut5) = ранги 6–105.
- Правило: вход при ранге ≤ 100; выход при ранге > X (X = 100/110/120/150); минимальный срок в пуле 0/7/14/30 сут.; пересмотр daily / weekly (пн) / monthly (1-е).
  Пропавший (делист/нет свечи) уходит сразу; между пересмотрами пул не пополняется. 01.01 — пересмотр у всех.
- Метрики: смен/нед. (входы+выходы), разных монет за 01.01–02.10, средний размер, recall = доля настоящего топ-100 суток, лежащая в пуле, `have/missing` — монето-сутки
  правила против бинлогов ящика (`data/tk032/box-files.txt`, снимок 01.10).

# В-171 (владелец 03.10 05:35): правило «7 суток в топ-100 → в пуле; выход после 7 суток >110» — результат

Перебор правил выше отменён В-171 (остаётся как справка). Реализация: `tools/compute/pool-v171.py` (копия `data/tk036/v171.py`), состав — `docs/findings/pool-v171-2026-10-03.csv`
(строки `sym,day,in_pool=1`; копия на сервере `/data/tk037/pool-v171.csv`).

**Правило (толкование CEO, В-171):** ранг суток d = по обороту суток d среди допущенных на d (не BTC/ETH, не 6 имён NON_CRYPTO_BASES, возраст ≥ 30 сут., свеча d есть).
Состав на сутки D решается по рангам суток ≤ D−1 (без заглядывания): вход — ранг ≤ 100 семь суток подряд (D−7…D−1), в пуле с 8-х суток; выход — ранг > 110 семь суток подряд;
возврат в ≤ 110 сбрасывает отсчёт выхода, ранги 101–110 — держим. Пропавшая из торгов монета уходит сразу. Старт — свечи с 01.12.2025 (на 01.01 уже есть история рангов).

**Что сравнивал (В-170):** вселенная `pick_rule` (основная) против `crypto_only` (без stock/ETF/commodity/forex): 257 против 255 монет, 25 466 против 25 868 монето-суток — разница мала, берём
`pick_rule`, чтобы состав совпал с `lob pick`. Проверка правила: независимый пересчёт по рангам всех 343 входов и 253 выходов — 0 нарушений (7 суток ≤100 перед каждым входом, 7 суток >110 перед выходом);
вручную TAO/SUI/HYPE/FARTCOIN: ранги перед 01.01 ≤ 54 каждые из 7 суток → в пуле с первых суток, не выходили.

## Разогрев «по коду»
- Разметка уровней: `DEFAULT_WARMUP_MS` = 3 600 000 мс (1 ч) от начала **своих** суток; новые сутки пишутся с синтетическим снапшотом (формат бинлога) → предыдущие сутки не нужны.
- σ (`sigma-table.py`): минутные закрытия внутри суток, окно — минуты; прошлых суток не требует.
- Перенос круга через полночь (`--carry-root`, `carry_window_ns` = макс. TTL входа + дедлайн + p95 RTT): нужны **сутки D+1 последнего дня в пуле** (только начало). Это +335 монето-суток, из них нет у нас 319
  (94 — это 03.10, архив ещё не выложен), 3,3 ГБ стакана.
- Итого список докачки = пул ∪ {D+1 дня пула}: **12 256 монето-суток**, стакан **443,7 ГБ** (+ сделки ≈ 150 ГБ), ≈ **1,5 ч** при 110 МБ/с (оценка по сумме Content-Length).

## Оговорки
- Признак «монета торгуется в сутки D» берётся по наличию свечи D (знание вперёд на 1 бит); делист в середине суток — редкость.
- Гистерезис ранга считается по суточному обороту D−1…D−7, а не по обороту «24h на момент»; Судья решает, нужна ли поправка на неполные сутки при входе в 8-е сутки.
