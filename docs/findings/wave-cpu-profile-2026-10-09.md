## Кандидаты (≥5 % user)

1. **Разворот строк окна в `Event` — `windowed_with`, 15,6 % self.** Горячий цикл `buf.push(events.row(i))`
   (backtest.rs:3830): на строку — `sar/imul 1e6` (время), 2× `vcvtsi2sdq` + `vdivpd` (цена и размер целое→f64 делением),
   запись 64-байтного `Event` в буфер; 20 % цикла — на одной записи (`vmovapd` после `vdivpd`, ожидание результата деления),
   `vdivpd` 9,8 %. Идея: деление на константу → умножение на обратную только если байт в байт (не гарантировано, f64);
   лучше — не разворачивать заново окно каждого сигнала: общий разворот суток один раз (окна пересекаются) либо
   предрассчитанные f64 в компактном ряду. Оценка ≤ 10 % wall.
2. **Обновление глубины `FastMarketDepth::update_*_depth` — 17,1 %.** Горячие точки размазаны (по ≤ 7 % на ветку:
   `cmp`/`je` проверки уровней, `vcvttsd2si`, `vucomisd`) — перевод цены в тик и ветвления. Идея: целочисленный тик
   в событии (без f64→i64 на событие). Нужен код `fast_depth.rs`; оценка ≤ 8 % wall.
3. **`fast_hold` (scan 7,9 + step 6,9 + advance_to 6,0 + hold_input_sig 5,1 = 25,9 % self).** В `fast_step` 17 % одной
   проверки `testb $0x80,0x3(..)` в цикле (линейный проход по массиву флагов с шагом, промах кэша/ветвление); остальное
   — равномерно по ветвям. Идея: битовая маска пропуска/следующий установленный бит вместо линейного прохода. Оценка ≤ 6 % wall.

Не берётся: ядро/zstd/декод — < 5 %. Дальше — по решению Судьи, какой кандидат первым; код — только за флагом, гейт байт в байт.

## К-7а: потребители f64-цены/объёма и потолок (до кода)

**Потребители `Event.px/qty` на пути окна** (грепом): `windowed_with` → `expand()` (compact.rs:112) → ядро крейта
(`Local/PartialFillExchange`) и свои пути `fast_hold.rs:21–45`, `hold_index.rs:179–210`, `shared_engine.rs:149–173`,
`shared_multi.rs:845–870`, `backtest.rs:4276–4292` → `FastMarketDepth::update_{bid,ask}_depth(px, qty, ts)` и
`clear_depth(side, px)`. Внутри: `tick_q.of(px)`, `lot_q.of(qty)` и **`qty` как f64 кладётся в `Levels`** и возвращается
в кортеже (prev_qty, qty) — его читает модель очереди крейта. `px` как f64 нужен сделкам/`clear_depth`/`round(px/tick)`.

**Следствия для рычага:**
- Деление `vdivpd` в `windowed_with` — **одна упакованная инструкция на px и qty**; f64-объём остаётся обязательным
  (хранится и читается очередью), значит деление не уходит. Выигрыш в `windowed_with` только от записи/копирования — не
  от деления. (Пик 20 % у `vmovapd` после `vdivpd` — ожидание делителя, он остаётся.)
- Реально убираемое — `Quant::of` ×2 в `update_*_depth`: по annotate `update_ask_depth` строки 62fc.. `3f2c21–3f2d30` = 48,5 %
  символа (8,7 % × 0,485 ≈ **4,2 %** total self), bid симметрично ≈ 4 % ⇒ **≈ 8 % self — потолок**, если целочисленный
  тик/лот с делением на константу стоил бы 0. Реально целое деление `px_e9 / tick_e9` (64-бит `idiv` или обратное
  умножение + проверка делимости) сравнимо по задержке с цепочкой `Quant::of` ⇒ ожидаемо ≤ 3–4 % self ≈ **< 3 % стены**,
  то есть на пороге останова Судьи. Прямой путь в L2-трейт невозможен (трейт принимает f64) — нужен собственный метод
  `FastMarketDepth::update_*_e9(px_e9, qty_e9, ..)` во всех семи местах выше, f64 `qty` строить там же.
- _CHECK-ворота (целый тик == `tick_q.of(f64)`, лот == `lot_q.of(f64)`, 0 расхождений) — как задано Судьёй.

Предложение: сначала дешёвая проба-потолок — под флагом `ALPHA_E9_TICK` только `fast_hold.rs` (боевой путь d15, 25,9 % self
рядом) + _CHECK; если ABBA < 3 % — К-7а закрыт, К-7б (`fast_step`, 17 % одной проверки).

## К-7б, шаг 0: потолок «следующего события» (fast_step)

Цикл с `testb $0x80,0x3(..)` (шаг 0x40 = `Event`) — это `HoldTracker::next_event_ts` (fast_hold.rs:~413, инлайнен в `fast_step`):
`for ev in &rows[lcur..] { if ev.is(EXCH_EVENT) && ev.exch_ts > now {break} }` — линейный поиск первой биржевой строки
позже `now`. По annotate цикл (`651bc0–651bd9`) = 38,2 % `fast_step` + вход ≈ 11 % ⇒ **≈ 49 % × 6,9 % = 3,4 % всего self**.
Замена — кэш-курсор «первая биржевая строка с `exch_ts > now`» (монотонен: `lcur` и `now` только растут, ответ не уходит назад) —
убрала бы почти всё: **потолок ≈ 3 % self < 5 % ⇒ К-7б закрыт без кода.** `advance_to` (6,0 %) — это применение строк
(`apply_local` → глубина), маской не заменяется; `fast_hold_scan` 7,9 % и `hold_input_sig` 5,1 % размазаны (топ-строка ≤ 8 %,
т.е. ≤ 0,6 % self).
