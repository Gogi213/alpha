# Счётчик признаков пампа/дампа по окну (TK-422, G-017) — 2026-10-27

Инструмент: `tools/compute/tk422-features.py` (чистый Python, без numpy). Для окна (биржа, рынок, инструмент, t_start, t_peak, t_end)
печатает строку признаков. Признаки — кандидаты трека А; вердиктов нет, различающую силу мерит шаг 3 (Судья проверяет).

## Вход и выход

- **Вход** (csv, формат согласован с TK-421: `биржа,рынок,инструмент|монета,t_start,t_peak,t_end[,знак|id]`; время — ISO-минута UTC
  или мс). Нет знака → направление по цене (пик против старта). Контрольные окна (без события) подаются в том же формате —
  пик контроля = минута максимума в ориентации «памп».
- **Выход** (csv, строка на окно): `id,биржа,рынок,инструмент,t_start_ms,t_peak_ms,t_end_ms` + признаки. Пустое значение =
  данных нет (не 0). `na` — окно без признаков (нет свечи старта/пика/конца).
- **Ориентация:** для дампа цена берётся с минусом (high↔low), поэтому «вверх» = по ходу события; формулы ниже даны для пампа.
- **Единицы:** расстояния — bps от цены открытия минуты старта (`p0`); оборот — USD (`quote_v`); OI — относительное изменение, %.
- **Сетка параметров** (`GRID` в скрипте, переопределяется `--grid grid.json`): числа автора — параметры. `H` {60,240,1440} мин
  глубина пула, `K` {1,2} ширина фрактала (1 = 3 свечи), `N` {5,30} мин возврата телом, `T` {0,10,25} bps закрепления,
  `R` {60,180,360} диапазон AMD, `KM` {5,15}, `FVGMIN` {0,5,10} bps, `RET` {0,3; 0,5; 0,618; 0,786}, `IMB` {0,1;0,2;0,3},
  `SURGE` {2,3,5}, `ABS_N` {5,15}, `DISP` {0,10}. Значения — стартовая сетка шага 3, не выбор.
- **Данные:** свечи 1 м `/srv/alpha-sda/candles-1m/<биржа>-<рынок>/` (TK-411); OI/фандинг/ликвидации `/srv/alpha-sda/tk415/out/{bybit,gate}/`
  (TK-415); сделки Bybit linear `/data/tk417/bybit-linear/<SYM>/` (TK-417). Минуты без сделок (Gate) **не заполняются** (В-172):
  фракталы и ряды считаются по существующим минутам.
- Норма монеты `qmed` = медиана `quote_v` минуты за 1440 мин до старта (по существующим минутам).

## Не сделано в этой версии (следующий шаг)

- **Стакан** (ob200 Bybit, Gate): признаков в окне нет — срезы ob200 лежат по минутам в других каталогах (TK-414 `tk414-obmin`),
  подключаются отдельным модулем; в пробу не входит.
- **Поглощение по стакану** (пункт 1 «и по стакану») и сделки Gate/спот Bybit — только после согласования источника.
- **Фракталы старшего ТФ** (день/неделя) — нужна история до сентября (свечи августа, TK-420 `tk420-aug-candles.py`); пока
  скользящий максимум 1/7 суток.
- Дубль «ликвидации Gate» читаются из `oi.csv.gz` по имени колонки; в заголовке файла имён меньше, чем столбцов — используются
  только `open_interest`, `long_liq_usd_new`, `short_liq_usd_new` (они в именованной части).

## Проба (calc, alsched `--kind gate --cores 1`, окна 9–10.09.2026 из эпизодов TK-413, θ 10,48 %)

| проба | окна | job | rc | колонок признаков | время |
|---|---|---|---|---|---|
| 1: Bybit 4STOCKUSDT (25), NIULAIUSDT (8) + Gate STONKS_USDT (51) | 84 | 1027183551158 | 0 | 223 | ≈ 4 мин от подачи (1 ядро) |
| 2: Bybit PONSUSDT (5), FLOCKUSDT (4) + Gate LAPTOP_USDT (41), у всех есть спот | 50 | 1027183832761 | 0 | 241 | ≈ 3 мин от подачи (1 ядро) |

Выходы: `/data/tk0422/probe-out.csv`, `probe2-out.csv` (calc). Окна пробы — `data/tk422-probe{,2}-windows.csv` (gitignored).

Заполненность (окон с непустым значением / всего):
- Всегда: база, OI (47–98 %: нет 5-мин OI до листинга), фандинг, BTC-раскорреляция и SMT, FVG, откат.
- Фьючерс↔спот: у 4STOCKUSDT / NIULAIUSDT / STONKS_USDT спота нет (`spot_present`=0, признаки пусты — не 0). В пробе 2 спот есть
  у всех 50 окон, признаки посчитаны у 4: у остальных в тонком споте нет свечи минуты старта или меньше 5 общих минут для
  корреляции (минуты без сделок не выдумываются). Это свойство данных: раскорреляция измерима только на монетах с живым спотом.
- Поглощение по сделкам — только Bybit linear (9 окон пробы 2, 33 окна пробы 1); Gate — пусто. Ликвидации — только Gate (41/41).
- Старший ТФ 7 сут. — 24–35 % окон (истории сентября до 9.09 хватает не всем монетам); пулы `sw_*` — только там, где пик выше верхнего пула.

Оговорки для приёмки: (1) числа пробы — проверка работоспособности, не результат (3+3 монеты, 134 окна, без контролей); различающую
силу признаков не мерили. (2) Сделки читаются по окну без кэша (файл суток на окно): для боевого прогона по десяткам тысяч окон
нужен кэш «инструмент×сутки» и группировка окон по инструменту (в скрипте окна одного инструмента делят кэш свечей, но не сделок).
(3) Выгрузка стакана ob200 не подключена (см. выше). (4) Порядок/формат окон согласован с TK-421 по их постановке;
если TK-421 выдаст другие имена колонок — достаточно добавить синоним в `col(...)`.
