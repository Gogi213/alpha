# Счётчик признаков пампа/дампа по окну (TK-422, G-017) — 2026-10-27

Инструмент: `tools/compute/tk422-features.py` (чистый Python, без numpy). Для окна (биржа, рынок, инструмент, t_start, t_peak, t_end)
печатает строку признаков. Признаки — кандидаты трека А; вердиктов нет, различающую силу мерит шаг 3 (Судья проверяет).

## Вход и выход

- **Вход** (csv, формат согласован с TK-421: `биржа,рынок,инструмент|монета,t_start,t_peak,t_end[,знак|id]`; время — ISO-минута UTC
  или мс). Нет знака → направление по цене (пик против старта). Контрольные окна (без события) подаются в том же формате —
  пик контроля = минута максимума в ориентации «памп».
- **Выход** (csv, строка на окно): `id,биржа,рынок,инструмент,t_start_ms,t_peak_ms,t_end_ms` + признаки. Пустое значение =
  данных нет (не 0). `na` — окно без признаков (нет свечи старта/пика/конца).
- **Фазы** (P-TK421 v3): `pre` [t_pre, t_start), `leg` [t_start, t_peak], `post` (t_peak, t_end]; `t_pre` берётся из колонки `t_pre|t_pre_ms`, иначе
  `t_start − (t_end − t_start)`. Имя столбца = `<признак>_<pre|leg|post|ctx>`; `ctx` — контекст по лукбэку (H минут / сутки до старта, не
  фаза), его длина не равна длине события. Ничто из `leg`/`post` не называется «до пампа». Признаки, не привязанные к фазе, — служебные
  (`sign`, `leg_min`, `pull_min`, `hist_min`, `mins_<ph>`, `spot_present`, `data_age_days`, `*_hist_min`), `cov_` для них не пишется.
- **Покрытие** (правка 2): на каждый признак столбец `cov_<признак>` ∈ {`ok`, `нет_данных`, `не_применимо`}. `нет_данных` — источника нет (нет спота,
  нет сделок/срезов стакана, нет ликвидаций Bybit) или не хватает данных в фазе (меньше 5 общих минут для корреляции, нет лукбэка 7 сут);
  `не_применимо` — только у структурных признаков (`sw_*`, `fvg_*`, `swing_*`, `htf_*`, `amd_*`, `retrace_*`): источник есть, но условие признака
  не выполнено (пик ниже пула, нет разрыва). Две причины пустоты не смешиваются — «общее» не смещается к монетам с данными.
- **Таблица пар фьючерс↔спот и ряд BTC** (правка 4): рядом с выходом пишется `<выход>.pairs.csv` (биржа, рынок, инструмент, спот-инструмент, окон,
  окон со спотом, окон с рядом BTC, ряд BTC); ряд BTC той же биржи входит в инструмент (`btc_*`, `smt_btc_*`).
- **Ориентация:** для дампа цена берётся с минусом (high↔low), поэтому «вверх» = по ходу события; формулы ниже даны для пампа.
- **Единицы:** расстояния — bps от цены открытия минуты старта (`p0`); оборот — USD (`quote_v`); OI — относительное изменение, %.
- **Сетка параметров** (`GRID`, ≤ 3 значений на параметр — правка 3 Судьи; записана до счёта шага 3, переопределяется `--grid grid.json`;
  числа автора — одно из значений): `H` {60,240,1440} мин глубина пула, `K` {1,2} ширина фрактала (1 = 3 свечи), `N` {5,30} мин
  возврата телом, `T` {0,10,25} bps закрепления, `R` {60,180,360} диапазон AMD, `KM` {5,15}, `FVGMIN` {0,5,10} bps,
  `RET` {0,3; 0,5; 0,618} (0,786 снят — `retrace_depth` отдаётся непрерывно, порог любого уровня берёт шаг 3 без перечитывания),
  `ABS_N` {5,15} мин. Пороги поглощения (`IMB`, `SURGE`, `DISP`) **из сетки убраны**: отдаются непрерывные `imb`, `surge`, `disp_bps`,
  флаги-комбинации (было 36 на окно) не пишутся — порог назначает шаг 3 по назначенному правилу. Числа не из данных — стартовая сетка.
- **Данные:** свечи 1 м `/srv/alpha-sda/candles-1m/<биржа>-<рынок>/` (TK-411); OI/фандинг/ликвидации `/srv/alpha-sda/tk415/out/{bybit,gate}/`
  (TK-415); сделки Bybit linear `/data/tk417/bybit-linear/<SYM>/` (TK-417). Минуты без сделок (Gate) **не заполняются** (В-172):
  фракталы и ряды считаются по существующим минутам.
- Норма монеты `qmed` = медиана `quote_v` минуты за 1440 мин до старта (по существующим минутам).

- Ликвидации Gate читаются из `oi.csv.gz` по имени колонки (`long_liq_usd_new`, `short_liq_usd_new` в именованной части заголовка).
