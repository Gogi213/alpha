Старт и выход — не причина.
**Главная корзина «вне стадий» = 567 с из 3 440 (16,5 %): 391 зазор перед `setup` нового символа, в среднем 1,45 с** (ещё 23 зазора после `touches_load`, 23 с). Это `shared.set_pre(symbol, prescan_t0(symbol))` в цикле `--extra-runs` (`bounce_grid.rs` 270–282): перед каждым символом для каждого прогона читается и разбирается кэш касаний (`cached_touches`) только ради списка `t0`; затем `run_symbol` читает те же касания второй раз (стадия `touches_load`). То есть касания разбираются дважды на символ. Режется: брать `t0` из тех же уже загруженных касаний (одна загрузка на символ и прогон) — вычёркивает ≈ 16 % слот-с QUICK5 без изменения результата (кандидат для TK-049/TK-048; гейт «байт в байт»).
