## 0. Итог в шести строках

1. Четыре коллектора берут **4,00 ядра** (измерено `/proc`: user 1,77 + sys 2,22) на **31,3 тыс. кадров/с, 6,3 МБ/с** (1 кадр ≈ 177–237 Б, 146 соединений, 519 потоков): **75–191 мкс ЦП на кадр**.
2. **Сама работа — малая доля.** Разбор + дубли + кодировщик + zstd на записанных кадрах — **3,3–7,3 мкс на кадр** (повтор, ядро горячее, детерминированный вывод); в бою цепочка писателя стоит 33–54 мкс на кадр, т. е. в **5–12 раз** больше. Основная трата — взаимодействие с ОС на каждый кадр: **1,0–1,7 переключений контекста на кадр**, `recvfrom` ≈ 48 мкс ядра на вызов (шкала `/proc`), `futex` 1,2 вызова на кадр (≈ 17 мкс ядра каждый).
3. По perf (теневая шкала ×0,716 к `/proc`): **ядро 2,2 ядра (55 %)** = recvfrom 0,75 + futex-передача rx→писатель 0,57 + прочие системные вызовы 0,33 + softirq в потоках 0,32 + irq/таймер/планировщик 0,22; **user 1,8 ядра (45 %)** = разбор 0,26, TLS 0,25, gunzip BingX 0,24, rx-цикл 0,15, очередь/park 0,13, писатель 0,12, zstd 0,08, прочее/[unknown] 0,56.
4. **Порядок величины одним внутренним тюнингом не берётся**: пол по измеренному — вычисления ≈ 0,1–0,2 ядра, TLS/каркас ≈ 0,1, zstd ≈ 0,08, **ядро для 20,4 тыс. пакетов/с на virtio-VPS ≈ 0,4–0,7 ядра** (softirq/IRQ/ACK, там железо хостера); итог плана — **≈ 1,1 ядра (диапазон 0,9–1,4), ×3–4**; ×6 — только с опцией D (вторая линия «в запасе», решение владельца: половина кадров — дубли второй линии).
5. Ручки: busy-poll **работает, но жжёт 87 % ядра на одно соединение** (p50 ожидания 114→47 мкс) — отклонён; аппаратной модерации прерываний хост не даёт (нет `NOTF_COAL`); нативный XDP на virtio работает (проверено на Sofia), но AF_XDP — это пользовательский TCP+TLS на 146 соединений — вне плана; io_uring включён.
6. Остановки данных 13.11 (17:43, 1 стоп-минута srv-wide за сутки) — по данным тредов BingX/координатора потеря пакетов до NIC хостера, не ЦП: **оптимизация ЦП их не лечит и в отчёте этого не утверждается**; цель — запас, экономия ядер и HFT-класс.

### 2.2 Шаги (по одному; у каждого — доля, ожидание, проверка, условие отказа)

Каждый шаг: повтор (ЦП на Мкадр, 5 проходов, медиана) + гейт идентичности **G1** (разжатые файлы повтора старым и новым бинарём байт в байт; для шагов без изменения формата) → paced-повтор по loopback (**H0**, A/B) → 3-мин боевые окна старый/новый попеременно, по одному процессу на биржу, **без сборок во время окон** (сборки только Sofia) → накат на 4 боевых процесса по одному (те же аргументы, `Restart=always`, `*.prev`), подтверждение на странице здоровья. Откат — прежний бинарь. **Условие отказа шага:** < 50 % нижней оценки выигрыша на повторе, либо p99 `lag_in`/`queue_lag` хуже на 1 мс, либо любой счётчик потерь/дублей/пропусков ≠ 0 в боевом окне.

### 2.3 Не берём и почему

- **AF_XDP / обход ядра:** технически возможно (XDP на virtio работает, §1.5), но транспорт бирж — TCP+TLS: нужен пользовательский TCP (ACK, SACK, повторы, управление окном) на 146 соединений плюс TLS поверх; на virtio AF_XDP — режим копирования (без zero-copy); теряется настроенное восстановление потерь ядра на пути с 19–22 ретрансмитами/с (данные координатора). Доля, которую обход мог бы забрать, — «приём TCP + softirq» ≈ 1,1 ядра сейчас, после S2/S3 ≈ 0,4–0,6. Пересматривается, только если после S3 ядерный пол > 1 ядра.
- **Busy-poll:** измерено, жжёт 0,6–0,8 ядра на соединение (§1.5).
- **Меньше соединений / больше потоков на соединение:** кадры и пакеты те же; доля накладных на соединение (ioctl, пинги, таймеры) ≈ 1–2 %.
- **zstd другой уровень/словарь:** отклонено в прошлых замерах (уровень 3 хуже по размеру и времени, словарь 2–3 %); диск — 0,08 ядра.
- **`SCHED_FIFO`/изоляция ядер на общем боевом srv:** риск для соседей (счёт, закачка); закрепление (K3) — да, реальные приоритеты — нет.
- **Изменение формата файлов:** не допускается (В-172 «данные как на бирже»); S5 — только выбор метки `rx`, по решению.

### 2.5 Риски

1. Реактор — единая точка отказа процесса: сторож-поток, изоляция состояния по соединению, рукопожатия вне реактора; принимается только после G2 и 3 боевых окон.
2. Окно W добавляет ≤ W к метке `rx` (если не S5) — на фоне `lag_in` p50 80–130 мс и порогов 350 мс/2 с безвредно, но это изменение семантики метки — **решение до S2**.
3. Неблокирующий tungstenite/rustls: частичные кадры и частичные TLS-записи — покрываются существующими 36 тестами ядра + новыми на синтетическом источнике и H0.
4. PGO стареет при правке горячего кода — обучать на повторе в каждой сборке.
5. `target-cpu=broadwell`: бинарь не годится для CPU старше Broadwell (srv и Sofia — годятся).
6. Измерения на боевом srv шумят (PSI 27–32 %, steal 6,6 %): повтор — медиана 5 проходов, окна — попеременно старый/новый.

### 2.6 Сроки (темп Claude Code)

H0 + S0 + S0b: код ≈ 3 ч, сборка+тесты ≈ 1 ч, гейт ≈ 1 ч; S1 ≈ 2 + 0,5 + 1 ч; S2 ≈ 6 + 1 + 2 ч; S3 ≈ 0,5 + 2 ч окон; S4 ≈ 4 + 1 + 1 ч; S5–S6 ≈ 2 + 0,5 ч; накат по биржам ≈ 2 ч. **Итого ≈ 25 ч работы**; первые выигрыши (S0, S0b) — через ≈ 5 ч после вердикта критиков.
