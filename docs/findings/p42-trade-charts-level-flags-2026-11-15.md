## Сверка `src/breakout/levels.rs` с §5.1 построчно

Совпадает с §5.1: пивот-максимум ширины k, строго выше k соседей с каждой стороны, известен после закрытия бара h+k (`find_pivots`, `active = max(j, h+k)`); глубина d по минимуму часового бара; уровень = ≥ N пивотов в окне L, все в пределах τ от среднего (`group_ok`, целая арифметика, цена = среднее `sum/n`); истинный пробой — закрытие часового бара > цены уровня убивает уровень; при рождении закрытия с первого пивота проверяются (`dead`); пивоты, вошедшие в уровень, не используются повторно. Слежение D отдельно не применяется (§12 п. 4).

Расхождения и неоднозначности (проверены данными):
1. **Нет перепроверки закрытий при смене цены уровня** (присоединение пивота, выпадение члена из окна L): среднее меняется, закрытия баров с первого отскока до этого момента относительно **нового** среднего не проверяются (при рождении — проверяются). Влияние по данным (флаг G): 4 сделки, +4,08 $, перебор не больше 4,6 бп. Тот же класс — состояние запрета ложного пробоя в `tick.rs::candidates` считается по цене версии на минуте.
2. Проколы между первым пивотом и рождением уровня (флаг A без «после рождения», 423 сделки) никакой проверкой не охвачены: до рождения нет ни запрета ложного пробоя, ни минутных закрытий (проверка при рождении — только часовые закрытия). Протокол этого не запрещает; нужен ли такой фильтр — решают владелец/судья.
3. Группа строится жадно от нового пивота (ближайшие по цене, затем стоп на первом провале условия) — §12 п. 4; перебора подмножеств нет, оптимальная группа может быть найдена не всегда.
4. При присоединении пивота выбирается первый живой уровень в порядке создания, а не ближайший по цене.
5. Окно L считается по началу часового бара пивота (`bar·tf ≥ now − L`), не по минуте экстремума.
6. Глубина: если в одном баре закрытие за пиком и низ достиг d %, пивот отбрасывается (порядок внутри бара протокол не задаёт). Бары без минуток (`ok=false`) исключают пивот, если попали в окно 2k+1.
7. Запрет ложного пробоя (`candidates`): окно r считается от минуты первого пересечения серии и обновляется только если на минуте истечения снова high > уровня; то есть возврат закрытия < уровень·(1−f) позже r мин после первого пересечения, при паузе пересечений на момент истечения, запрета не даёт. Совпадает с буквой §5.1/§13.2 с оговоркой на якорь окна.
8. Проверка запрета на данных (`chk_ban_violation`, повтор логики по минуткам от рождения до сигнала по цене версии на сигнале): 3 сделки (L0704_STOUSDT, S0169_ASTSUSDT, S0424_GENIUSUSDT); у всех версия цены сменилась после рождения (`price_age_max_min` < `level_known_min`), так что пересчёт по итоговой цене подтвердить нарушение не может — ошибка движка не подтверждена.
