## (1) Порядок суток сейчас

**Планировщик `alsched` порядка суток не знает** — он ставит задания (`--cores`, класс), а сутки внутри задания раздаёт раннер. Сутки идут так:

| путь | как отдаёт сутки | источник |
|---|---|---|
| форма запуска (боевой) | единица = **сутки целиком** (`day-cells.sh`, один `bounce-grid --cells` на все символы суток); `xargs -P $NX` (12) по `days.txt`: месяцы в порядке `months.txt`, внутри месяца **«тяжёлые первыми»** (`day-order.sh`: по убыванию числа символов, ничья — по дате). Две пачки суток (std, затем tape) идут **подряд в одной оболочке** — второй проход читает те же файлы суток сразу за первым | `tools/launch/run-launch.sh:11–17`, `tools/compute/day-cells.sh:29–35`, `day-order.sh` |
| оркестровка TK-048 (Ян, G=8) | очередь `for d in days; for k<G` — **сутки-мажорная**; `HOIST_PRED`/`QTOP` выносят самые долгие единицы вперёд | `tools/compute/archive/tk048-orch-grp16q.sh:57–85` |

**Группы одних суток не делят байты.** `tk048-orch-job.sh:12–18`: группа k берёт срез `rows[k·n//G : (k+1)·n//G]` пула символов суток — непересекающиеся наборы. В волне TK-177 (p177) каждая сутко-символьная пара декодирована ровно один раз (948 различных = 948 стадий `ev_decode`). Общие у групп одних суток только `verdict.csv`/sigma/regime (стадия `setup`, ниже) — они и так из кэша.

**Разнесение по времени (p177, `units.txt`, 248 единиц, P=20, 31 сутки):**
- группы одних суток стартуют с разбросом **медиана 10,0 с, макс 29,7 с**; сутки «в работе» (от старта первой группы до финиша последней): макс 6, в среднем 3,64; интервал одних суток от первого старта до последнего финиша: медиана 49 с (мин 27, макс 140);
- максимальное расстояние по номеру суток среди **одновременно идущих** единиц — 8 суток; возврат номера суток в порядке старта — один (`QTOP` вынес 4 тяжёлые единицы суток 03 в начало).

**Укладывается ли в окно кэша** (ОЗУ 62 ГБ, кэш ~48 ГБ — условие задачи): сутки по p177 — уникально декодируется **медиана 0,67 ГБ, макс 1,23 ГБ**; 8 суток подряд ≈ 5–10 ГБ ≪ 48. Оценка TK-259 «сутки ≈ 3,7 ГБ» — это все символы суток 8 групп по размеру файлов; реально читается в 2–5 раз меньше (ниже).
Для боевого пути (12 суток в работе, по месяцу — подряд) тот же расчёт даёт ≈ 8–15 ГБ на январских сутках; **другие месяцы — не знаю** (числа символов в сутках не сверял, байтовых счётчиков боевого прохода нет — `day-cells.sh` e2e-журнал не пишет).
Оговорка по порядку «тяжёлые первыми»: единица суток D дочитывает хвост D+1 (`ev_carry`), а D+1 в этом порядке не сосед по времени; повторное использование страниц D+1 держится на соседстве (в p177 соседство было). Сколько байт это стоит в боевом проходе — **не знаю**; верхняя граница по p177: ≤ 13,7 ГБ на январь (все диск-байты `ev_carry`, оценка).

## (3) Что с TK-259

- **Оценку «до ×1,4 волны» (TK-259, «Экстраполяция») справка не подтверждает:** её п.1 даёт выигрыш только если группы читают одни и те же байты; по p177 они их не делят, а расстояние между группами суток и так ≪ окна кэша. Бюджет ожидания диска 36 % (18,7 % approaches + 14 % события) в отчёте взят «по замерам репозитория» — с p177 не сверялся (iowait p177 29,4 %; approaches/touches `.csv` в январской волне не читаются — `jan-levers` (0)).
- **п.2 прогреватель/читатель уже мерился:** PFD2/4 и PREFETCH=5 — хуже или нейтрально; читатель на диск `r2q5n1` — нейтрально (324,0 против 323,8 с); К-5 (+83 %), К-5в (+6,3 / +6,8 %, критерий был ≥ 3 % выигрыша) — закрыто; вывод К-5в: «ограничение волны — не порядок/упреждение чтения D, следующий рычаг — ЦП» (`wave-read-bytes-2026-10-09.md`, «К-5в: итог»). Проба п.2 на 15 слотах с ЦП-нагрузкой повторяла бы эту схему.
- **п.3 `.abin` вместо csv:** в боевом `day-cells.sh` `study/approaches` — пустой каталог, касания идут из журнала `--touches-from wt/sub/D20`; csv approaches на этом пути не читается — выигрыш по байтам 0 (формат `wt/sub` — не знаю).
- **Следующим (если владелец продолжает I/O) — повтор Д1 на чистом окне:** `read_ahead_kb` 64 МБ → 512 КБ, `jan-levers` (Г): байты хоста −35 % (54 → 35 ГБ), стена +6,3 % (520,2 против 489,4 с) при помехе 13,7 % времени окна — вывод о стене не получен. Цена по `jan-levers`: 0,3 ч Claude + 9 мин волны (оценка), ожидание 0…−3 % стены (оценка того же файла); он целится в найденную избыточность `ev_carry` (+8,2 ГБ), а не в порядок суток. Без нового довода I/O-линия закрывается выводом К-5в (рычаг — ЦП).
