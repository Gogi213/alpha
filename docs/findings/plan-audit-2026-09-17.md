## 3. Блокер R1 — `kind=prereg` ломает журнал испытаний

**Что произошло.** Строка предрегистрации В-58 в `docs/plan/runs.csv:10` записана с
`kind=prereg`. Такого варианта в `RunKind` нет:

- `src/lob/runs.rs:97-113` — варианты `pilot`, `confirmatory`, `rerun`, `amendment`, `debt`;
- `read_run_rows` (`:184-195`) парсит строго, и это **заявленная семантика**: тест
  `malformed_journal_is_none_not_silent_zero` (`:350-368`) утверждает «неизвестный `kind` —
  ошибка чтения», чтобы опечатка не занизила поправку DSR молча;
- `trials_from_runs_csv` (`:208-209`) — `read_run_rows(path).ok()`, то есть ошибка разбора
  превращается в `None` («журнал не читается»);
- единственный боевой потребитель — `run_shortlist`
  (`src/commands/lob/shortlist.rs:1091`), путь по умолчанию `docs/plan/runs.csv`
  (`shortlist.rs:166`): `.ok_or_else(...)` → отказ
  «журнал испытаний не читается — DSR не из чего дефлировать»,
  причём **после** тяжёлого разведочного прогона (`run_profiles_over`, `:1082-1089`).

**Следствие.** `lob shortlist` на боевом журнале не работает, а `B5` (DSR по фактическому `N`) —
ровно тот потребитель, ради которого журнал ведётся. Тесты зелёные, потому что все они работают на
временных файлах и реальный `docs/plan/runs.csv` не читает ни один тест.

**Вторая половина проблемы.** `count_trials` (`runs.rs:119-124`) считает испытаниями только
`pilot|confirmatory|rerun`; `prereg` не входит. Машиночитаемого `trials=48` нет: в CSV четыре
колонки (`ts_utc, symbol, kind, detail`), а число живёт текстом `forms=48` в `detail`. То есть
запись `(kind=prereg, trials=48)` из `SETTLED.md:339` существует как текст, но не как данные.

**Фикс (S):** вариант `RunKind::Prereg` со `counts_as_trial() = false` + тест, что журнал с
`prereg` читается и `N` не растёт от строки предрегистрации. Дополнительно решить, нужна ли
отдельная колонка/строка с числом зарегистрированных форм (иначе DSR-потребитель берёт `N` только
из фактических прогонов — что, видимо, и задумано).

**Второй слой той же находки (найден тестом при починке).** Даже с новым вариантом `RunKind`
журнал не читался: строка `prereg` записана **без экранирования**, а её `detail` содержит запятые
(`filters=AND(size_usd>=N_abs, strength>=S%)`, `from C1/C2, every extra value counts`) — вместо
четырёх полей в строке их шесть, и `deserialize::<RunRow>()` падает на несовпадении числа колонок.
То есть предрегистрация нарушила журнал дважды: неизвестным видом строки и неверной записью CSV.
**Починено** (2026-09-17): `RunKind::Prereg` в коде + строка `prereg` закавычена по RFC 4180
(содержание предрегистрации не менялось) + добавлена строка `kind=amendment` с причиной правки;
новый тест `the_repository_journal_reads` читает **боевой** `docs/plan/runs.csv` и ловит оба слоя
(он и нашёл второй).
