# G-022: подготовка Gate USDT-M фьючерсы (без боевого запуска) — лимиты, пул, каналы → формат, проба (15.11.2026)

Приказ владельца (15.11): «и начинай подключать новую биржу - гейь фьючерсы. также лесенкой тестируй» («гейь» = Gate; в документации биржа Gate — `gate.com` / `gateio.ws`, USDT-перпетуалы; расхождений нет). Ветка `bb/g-022-gate-collector-v1-thr_2r84hvf7gy` (основа — `bb/g-022-collector-perf-v1-thr_gwcp2875s8`, боевой движок `final6k`). Метод — как у BingX/OKX (`bingx-ws-prep-2026-11-12.md`, `bingx-collector-2026-11-13.md`). Пометки: **[док]** — документация Gate, **[измерено]** — замер на srv 15.11, **[вывод]**, **[догадка]**. Время в скриптах и в сырье — UTC; GMT+4 = +4 ч (замеры сняты 15.11 01:58–02:30 UTC = 05:58–06:30 GMT+4).

**Что не делалось.** Адаптер и тесты (следующий шаг); боевой запуск; суточное поведение (максимальный возраст соединения не найден: 900 с без обрыва).

**Главное в шести строках.** (1) Адрес `wss://fx-ws.gateio.ws/v4/ws/usdt`: **AWS Токио (ap-northeast-1)**, 13 адресов IPv4, IPv6 нет, **TCP RTT с srv 237–239 мс на всех** (двух путей, как у Binance, не видно); лаг прихода p50 ≈ 118–125 мс = RTT/2, смещение часов биржи по `futures.ping` +2,7 мс. (2) **Лимитов на подписки в документации нет и замером не найдено:** 1 051 контракт × 3 канала = 3 153 потока на одном соединении подписались без ошибок; 1 051 отдельных сообщений подряд без пауз — без ошибок; в документации — только **≤ 300 соединений с IP** (60 одновременных за 0 с у нас прошли). (3) **Заголовок рукопожатия `X-Gate-Size-Decimal: 1` обязателен:** без него размеры — числа, усечённые до целого (ETH: `0.8` → `0`), 30 % сделок ETH теряют дробную часть; REST — то же. (4) **Idle-закрытие без FIN-кадра:** соединение без подписок закрывается на 30,0 с, с подпиской, но без данных и без нашего ничего — на 60,0 с; наш протокольный ping (раз в 5 с) биржа отвечает pong (эхо данных) — как ядро и делает; **сервер сам не пингует** (900 с, 0 пингов, хотя документация обещает). (5) `book_ticker` склеен **по таймеру ≈ 10 мс на соединение** (не «тик за тиком»): разные соединения видят разные состояния, **значения на общих `u` совпадают в 91 251 из 91 251**, объединение двух линий даёт на 37 % больше состояний; ключ `(символ, u)` общий для соединений. (6) REST хранит историю сделок по времени (30 суток проверено) — **сверка отложенным проходом, как у OKX**; на окне ETH 110 с: REST 26 493 сделки, **в WS не хватает 0, расхождений значений 0**.

## 3. Каналы Gate → итоговый формат (`docs/collector-ws-format.md`)

Подписка: `{"time":<с>,"id":<n>,"channel":"futures.book_ticker","event":"subscribe","payload":["BTC_USDT"]}`; ответ — `{"time":…,"time_ms":…,"id":<n>,"conn_id":"…","trace_id":"…","channel":…,"event":"subscribe","payload":[…],"result":{"status":"success"}}`; кадр данных — `{"time":…,"time_ms":…,"channel":…,"event":"update","result":…}`; код символа — `BTC_USDT` как есть; числа цен/размеров — строки (с заголовком).

### `book` — `futures.book_ticker` (лучшие bid/ask с размером)

[док] «Push best bid and ask in real-time»; поля `t, u, s, b, B, a, A`; «If `a` is empty string, it means empty asks; if `b` is empty string, it means empty bids.» [измерено] ключи кадра **ровно** `t, u, s, b, B, a, A` (698 868 кадров из пяти захватов, других нет). `t` — время события, мс; `u` — номер обновления книги (монотонен по символу: 0 нарушений, шаг медиана 76–90; «глобальный» — тот же на разных соединениях); `b`/`B`/`a`/`A` — цена и размер лучшего bid / ask строками, в контрактах.

**Не «тик за тиком»: склейка по таймеру ≈ 10 мс на соединение** [измерено, BTC, одно соединение, 120 с]: интервал между `t` соседних записей p10/p50/p90 = 5 / 10 / 20 мс (макс. 4 записи в 10-мс корзину, ≥ 1 запись в 87 % корзин); `u` между записями растёт на 27 / 90 / 221. Два соединения с теми же 30 символами за 120 с: **общих состояний 91 251 из 119 354 (A) и 118 294 (B)** (на BTC: общих 6 002, только A 3 481, только B 3 465), **значения на общих `u` совпадают во всех 91 251** → ключ записи `(символ, u)` годится между линиями; **объединение линий даёт +37 % состояний на BTC** (12 948 против 9 483) — линии дополняют друг друга, как у Bybit L1 (`collector-ws-format.md`). Разница `time_ms` кадра − `t` p50 3 мс, p99 84 мс.

Скорость на пуле (285 символов, 185 с, одно соединение): **1 750 кадров/с, 339 КиБ/с, средний кадр 198 Б**; по символу p50 3,1/с, p90 14,1/с, макс 64,7/с; данные у 285 из 285.

### `trade` — `futures.trades`

[док] поля `size, id, create_time, create_time_ms, price, contract, is_internal`; «Positive size means taker is buyer, negative seller»; «Internal trade refers to the takeover of liquidation orders by the insurance fund and ADL users … the transaction price may deviate, and it will not be recorded in the K-line.» (поле опускается, если сделка не внутренняя). [измерено] кадр `result` — **массив**, в проверенных 208 089 сделках — по **1 в кадре** (форма «пачка» не встречена, разбор допускает 1–N); ключи элемента **ровно** `id, size, create_time, create_time_ms, price, contract` (`is_internal` не встречено ни разу — 0 из 208 089). `id` — целое, **подряд по контракту** (0 нарушений порядка, 0 дублей; 1 пропуск на 65 430 — id `977283578` у ETH, **нет и в REST**: биржа не публикует отдельные id, то есть непрерывность id — признак, но не точный оракул); `create_time_ms` — целое мс; размер со знаком, **дробный у ≈ 30 % сделок** (ETH: `-144.4`).

Скорость на пуле: **298 кадров/с = сделок/с, 65 КиБ/с, средний кадр 223 Б**, по символу p50 0,39/с, макс 78,9/с; данные у 282 из 285 (3 молчали в воскресенье ночью).

### `mark` — `futures.tickers`

Отдельного канала mark/index/funding у Gate нет: `futures.tickers` несёт `mark_price`, `index_price`, `funding_rate`, `funding_next_apply` (секунды), `funding_interval` и остальное (24-часовой оборот, high/low, last, …). [док] «Notify subscribed contract ticker» (частота в документации не указана), поле `funding_rate_indicative` объявлено устаревшим («use `funding_rate`»). [измерено] кадр — `result` — **массив из одного элемента**; **ровно 22 ключа** (`contract, last, change_percentage, total_size, volume_24h, volume_24h_base, volume_24h_quote, volume_24h_settle, mark_price, funding_rate, funding_rate_indicative, funding_interval, funding_offset, funding_next_apply, index_price, quanto_base_rate, low_24h, high_24h, price_type, change_from, change_price, t`) и **23** с `event_type` у первого кадра после подписки (32 992 и 876 кадров).

Частота: по контракту ≈ 1 раз в секунду, **только при изменении** — интервал между `t` p10/p50/p90/p99 = 0,6 / 1,7 / 5,3 / 15,9 с по пулу; у топ-30 p50 1,04 с; **`mark_price`/`index_price`/`funding_rate` меняется в 54 % кадров** (1 633 из 3 010 у топ-30). Пул: **112 кадров/с, 69 КиБ/с, средний кадр 632 Б**, данные у 285 из 285 за 185 с. **`t` на ≈ 456 мс старше `time_ms` кадра** (p50; p90 738, p99 993 мс) — отметка снимка, не отправки; лаг `mark` по `t` (p50 ≈ 580 мс) **не сравним с лагом `book`** (как у BingX, `E` на ≈ 185 мс старше кадра). Два соединения: общих `(контракт, t)` 2 033 из 3 040 / 3 033 (67 %), значения на общих различаются в 2 из 2 033 — личность `(символ, t)` почти идеальна, как `E` у остальных бирж.

Условия: srv 5.231.25.224 (Нидерланды), часы chrony (смещение 1 мкс); клиент — Python `websockets` (кадры пишутся на диск с приёмом в нс) и свой клиент на сырых TLS-кадрах (`rawws.py`, видит ping/pong/close); на машине идёт боевая нагрузка (4 коллектора, load average 4–9). Лаг Python-клиента завышен (нагрузка + запись): ядра нет — эти окна лагом не меряются, лаг Gate меряет Rust-ядро в лестнице.

- **Вход** (`rtt.py`): `fx-ws.gateio.ws` → 13 адресов IPv4 из диапазонов AWS Токио (3.x, 13.x, 16.x, 18.x, 43.x, 52.x, 54.x); **TCP connect 236,4–239,7 мс на всех 13 (5 замеров), редкие 245–270 мс**; рукопожатие целиком (TCP + TLS + WS) 1,0–1,15 с (TCP 0,24 + TLS 0,52 + WS 0,24). Адресов IPv6 нет (только `::ffff:` IPv4); других имён входа не найдено (`fx-ws.gate.com` — нет адреса, `fx-ws.gate.io`, `fx-ws.gateio.live` — не существуют). **Второго «медленного маршрута» (как у Binance, ≥ 347 мс против 293) в 13 адресах не наблюдалось** [измерено, одно время суток].
- **Часы биржи** (`futures.ping` ↔ `futures.pong`, `time_ms` кадра, 23 замера): RTT p50 240,1 мс (мин 238,0), смещение серверных часов относительно srv (по симметричной задержке) p50 **+2,7 мс** (−1,8…+21,4) → лаг по `t` почти чистый; REST `spot/time` для этого не годится (RTT ≈ 1 с).
- **Окно W1 — весь пул 285, по одному соединению на канал, 185 с** (`w.py`): `book` 1 750 кадров/с (339 КиБ/с), `trade` 298/с (65 КиБ/с), `mark` 112/с (69 КиБ/с) — итого **2 160 кадров/с, 473 КиБ/с**; 285 × `success` на канал, ошибок 0, обрывов 0; данные: book 285/285, trade 282/285, mark 285/285.

- **Идентичность между соединениями** (`two.py`, `an_identity.py`, 2 соединения, 30 символов × 3 канала, 120 с): `book` общих `(символ, u)` 91 251, только A 28 103, только B 27 043, расхождений значений 0; `trade` общих `(контракт, id)` 65 413, только A 17, только B 54 (границы окна), расхождений 0; `mark` общих `(контракт, t)` 2 033, только A 1 007, только B 1 000, расхождений 2.

## 5. Что нужно от ядра

1. **Заголовок рукопожатия.** Новое в `Exchange`: дополнительные заголовки запроса WebSocket (Gate: `X-Gate-Size-Decimal: 1`) — без него данные теряют дробную часть размера. Остальные биржи — без заголовков, поведение не меняется.
2. **Подписка по одному контракту на сообщение** (изоляция отказа: один неизвестный контракт проваливает всё сообщение); 285 × 3 = 855 сообщений при ≈ 1 мс паузы — меньше секунды; ответы — по одному кадру на сообщение (пишутся как `r`, ядро не ждёт).
3. **Сердцебиение — только протокольное ядра** (ping раз в 5 с → pong): биржа отвечает; сервер сам не пингует; прикладной `futures.ping` не нужен.
4. **Плановый разрыв:** `futures.system` / `update` / `type: upgrade` → `is_retire_notice` (замена без разрыва, как OKX 64008); возраст соединения 23 ч — по ядру, как у остальных (максимума у Gate не найдено).
5. **Пул и шарды:** 285 символов; лимитов подписок нет → размер шарда — назначаемое число (п. 6), лестница ищет предел; подключений с IP ≤ 300 → сторож подключений: 80 % = 240 сокетов на IP; скорость подключений — назначаемое.
6. **Снятие дублей:** `book` — `(символ, u)` общий между линиями; `trade` — `id` (подряд по контракту); `mark` — `(символ, t)`.
7. **Старт:** `mark` у контрактов без изменений молчит (до секунд), `book` у спящих акций — тоже; «символ с данными за минуту» на странице здоровья будет ниже пула в нерабочие часы акций — норма, не потеря.

## 6. Решения адаптера (назначаемое — числа назначаю я, помечены; координатор может заменить)

| каналы | book — `futures.book_ticker`; trade — `futures.trades`; mark — `futures.tickers` | п. 3; те же три вида, что у остальных |

## Отклонения и не доказано

- Документация прочитана через WebFetch (малая модель пересказывает; цитаты ≤ 125 знаков): `403` на прямой запрос с ПК и srv. Ссылки даны; числа и поведение — по замерам.
- Окна: W1 — 185 с, одно время суток (воскресенье 02:22–02:25 UTC = 06:22–06:25 GMT+4, акции закрыты: часть контрактов молчит; в рабочие часы нагрузка выше — оценка 2 160 кадров/с получена **в тихое время**); идентичность — 120 с; REST — одно окно одного символа (ETH); сутки и плановый разрыв не наблюдались.
- Не проверено: предел числа подключений с IP (300); скорость подключений в секунду выше 60 за 0 с; поведение при медленном приёмнике (сервер «закрывает, если клиент не успевает» — по ответу сопровождающего, не воспроизводилось); `futures.obu` (глубина), `…/sbe`, `futures.order_book_update`, `futures.candlesticks` — не пробовались (глубина в формат не входит, В-115).
- Ложная гипотеза, снятая замером: «боты Gate блокируют по числу подписок» — нет; «`size` — целое» — только без заголовка.
- Сырые кадры — на srv `/data/gate-probe/frames/` (в репозиторий не кладутся), скрипты — `gate-ws-prep-2026-11-15/`.
