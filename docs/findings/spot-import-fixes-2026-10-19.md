# Спот: 4 исключённые монеты и 22 пары verify-fail — разбор и рекомендация (TK-316, 19.10)

Контекст — TK-312 (PR #71): спот в `/srv/alpha-sda/binlog-spot` = 1 062 пары (месяц, монета) ok; исключены PEPE/BONK/SHIB/MOG
(i64e9, 607 нечитаемых суток + 284 прочитанных = 891 файл в `binlog-spot-excluded`) и 22 пары `far-ppm`
(`docs/findings/spot-binlog-import-2026-10-19-excluded.csv`). Код не менялся — выбор способа за Судьёй (В-206).

## 1. PEPE / BONK / SHIB / MOG

**Что именно переполняется.** Формат binlog ни при чём: файл хранит `qty_lots` (zigzag-varint i64) и шаг размера в заголовке
(`step_e9`, у v4 — расписание) — то есть масштаб на инструмент в заголовке уже есть. BONK 1,75e10 монет при шаге 1 монета =
1,75e10 лотов — в i64 влезает с запасом. Переполняет **промежуточный e9**: `qty_lots × step_e9` = 1,75e19 > 9,22e18.
Места (все i64):

| место | что |
|---|---|
| импорт `import_archive.rs` `parse_decimal_e9`/`qty_e9` | разбор CSV/ob → i64 e9, отказ `BadNumber` (607 суток) |
| `feed/replay.rs:108,162` | `qty_e9: rec.qty_lots * step_e9` при чтении в `Trade`/`Level` (`bybit::ws::Trade.qty_e9: i64`) |
| `bybit/verify.rs:100,111,831` | `q * step_e9` |
| `book/mod.rs:197` `to_lots(qty_e9: i64)` | вход книги — e9 |
| `lob/backtest/compact.rs` | `CompactEvent` ровно 32 Б = 4×i64, `qty_e9: i64`; в `f64` переводится на границе (`/1e9`, стр. 107) |
| `commands/lob/pick/measure.rs:71` | уже `i128` — образец |

Всего `qty_e9` — ≈120 вхождений в 29 файлах (большая часть — живой коллектор/REST/latency, спота не касается); на пути
«бинлог → бэктест → стратегия» — ≈6 файлов (replay, backtest/compact, backtest/feed, verify, book, bounce_grid/drive). Полный список
мест — первый шаг кода (`grep qty_e9`); оценка ниже — по этому ядру, не по полному аудиту.

**Варианты** (без потери точности и без молчаливого /1000, В-172):

| | способ | затрагивает | плюсы / минусы |
|---|---|---|---|
| A | отдельное поле «масштаб размера» в заголовке (v5) | формат, все читатели обеих версий | дублирует `step_e9` — проблема не в файле; бессмысленный бамп формата. **Не брать** |
| B | `i128` для qty в `Trade`/`Level`/`CompactEvent` | `ws.rs` (горячий путь живого коллектора), `book`, replay, compact | `CompactEvent` 32→48 Б (+50 % кэша событий), касается фьючерса и живого пути, гейт «байт в байт» на всё. Дорого и рискованно |
| **C** | **читатель держит лоты + шаг, e9 не строит**: `Trade`/`Level` на пути чтения несут `qty_lots` и `step_e9` (или f64-размер сразу из `lots × step / 1e9`); `CompactEvent.qty` = лоты (как уже сделано в `event_cache_probe.rs:114`), перевод в f64 на границе; импорт разбирает размер через `i128` и сразу в лоты (точное деление, остаток ≠ 0 — отказ, не усечение); `verify` — локально `i128` | импорт, replay, compact, backtest/feed, verify, book (приём лотов) | формат не меняется (файлы 4 монет можно писать как есть), фьючерс — байт в байт (лоты×шаг = то же e9 там, где влезало), горячий путь живого коллектора не тронут. f64 на границе = ровно то, что уже происходит сегодня (`as f64 / 1e9`) — потери относительно нынешнего нет (лоты точны в i64, до 9e15 точны и в f64) |
| D | «кило-монеты» (`--qty-shift`) | — | отклонено Судьёй: нотионал ×1000 молча неверен (В-172). Флаг уже убран из PR |

**Цена C** (темп Claude Code): код ≈ 2–3 ч (6 файлов + тесты на BONK 1,75e10 и на ту же сумму ниже границы), vps-check ≈ 0,5 ч,
гейт «байт в байт» ≈ 1 ч (1 сутки фьючерса + 1 сутки спота без 4 монет, старый против нового бинаря), переимпорт 891 суток 4 монет
(1 ядро; прежний хвост 607 суток шёл ≤3 ч) + verify 4 монет × 9 мес ≈ 0,5 ч. Итого ≈ 7–8 ч до готовых бинлогов; TK-313 идёт
параллельно без этих монет, потом — дельта-прогон только по 4 монетам (В-213), а не пересчёт всего.

**Что даст**: +891 монето-сутки к 25 594 (+3,5 %), +4 монеты — мем-монеты с крупнейшими размерами на споте, у которых «сила»/usd_min
как раз о больших плотностях. Что не даст: проверки края B1 на них (остальное — как у прочих).

**Остаточные риски C**: (1) другие места, где `qty × price` в i64 (проверить при аудите; `measure.rs:75` уже i128); (2) `usd_min`/размер ордера
= `$ / price` для BONK ≈ 5e7 монет → 5e16 e9 — влезает, но проверить в тесте; (3) в `bounce_grid` могут найтись ещё места с `qty_e9` в i64.

**Рекомендация**: C, отдельной веткой, после начала TK-313 (не блокирует). Если 4 монеты не нужны для вердикта — оставить исключёнными
(стоимость нуля, список уже в репозитории). Решение между «C» и «оставить» — Судье/владельцу: зависит от того, нужны ли мем-монеты в пуле спота.

## 2. 22 пары verify-fail

**Что не так.** Во всех 22 структура чистая (`gaps=0 invariants=0 out_of_range=0`, импорт rc=0). Единственное: доля нарушений теста 3
(«цена сделки ни разу не держалась в книге») ≥ 0,1 % сделок — порог плана §11/В-56 (`violations*1000 < trades`, `src/commands/lob/verify.rs:60`),
заданный для фьючерсного фида. Нарушения — в основном `far` (ближайший уровень ≥2 тиков, 88–99 %), 25–38 % из них «строго внутри спреда».
Для 2 пар из 22 причина проверена независимо по сырому ob200 (TK-312, `tools/compute/archive/tk312-far-check.py`: STETH 2026-05-23 493/414,
FHE 2026-01-21 1943/2506 — то же число ±20 %) — это свойство снимков биржи в быстром движении, не импорта. Остальные 20 — по тому же признаку
verify, по сырому не сверялись.

**Перекачать с Bybit / другой источник / без них**

- *Перекачка*: источник — публичный архив Bybit (ob200 zip + CSV сделок, TK-305); он статичен и осмотрен (структура чистая, нарушения воспроизведены
  независимо на 2 парах) — свежая выгрузка даст те же байты. Повода нет; сверка md5 с повторной выгрузкой не делалась (не нужна, пока
  нарушения не связаны с повреждением архива).
- *Другой источник*: исторического ob200/сделок спота вне архива нет; собственный коллектор спот не писал (остановлен, В-44).
- *Без них*: цена — 22 из 1 084 пар (2,0 %); из них STETH — 9 пар (монета целиком, структурно 0,4–2,8 % нарушений: тонкий wrapper-токен).

**Вариант «исключать сутки, а не месяц»** (не делалось, решение — методология, Судье): K1 сегодня — статус (месяц, монета). По суткам: в 13
не-STETH парах 143 суток из 203 имеют ppm < 1000 (в остальных 60 — плохие). Выигрыш 143 монето-суток из ≈25,6 тыс. (0,6 %) ценой
перехода K1 на сутки (меняет протоколы и сравнимость) — не стоит.

**Итог по парам**: 21 пара не-STETH — причина «данные биржи, `far`», перекачка не лечит, остаются исключёнными. STETH×9 —
то же, монета целиком. Исключения уже в `…-excluded.csv`; ничего чинить не нужно. **Рекомендация: оставить исключёнными.**
