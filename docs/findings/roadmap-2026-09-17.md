## 3. Фича «сила плотности» — минимальная относительная сила уровня, в процентах

### 3.1. Что уже есть и почему этого мало

Порог уровня сейчас один: `size ≥ H3`, `H3 = k × median_trade_lots` (`instruments.csv`: `h3_lots`,
`k`, `median_trade_lots`; режимы `floor`/`percentile`, `src/commands/lob/h3.rs`). Знаменатель —
**медианная сделка**, то есть «сколько типичных сделок надо, чтобы съесть уровень». `k = 1.0` —
заглушка (В-30), пилот `k` не выбрал (G1 красный). Корзины `SIZE_LABELS` `[1,2)/[2,4)/[4,∞)` ×H3
на касаниях дают монотонный рост доли отскока (35.5 → 38.4 → 40.6 %), но при `k = 1.0` уровни
живут секунды, ось возраста пуста, а медиана касания — $17.8k SOL / $2.1k DOGE / $440 ZEC против
$300k у практиков.

«Сила в процентах» = `100 × size / знаменатель`; порог `S%` — минимальная сила. Вопрос фичи —
**какой знаменатель**.

### 3.2. Три варианта знаменателя

| Вариант | Формула | Что измеряет | Чьи слова | Данные | Окно/константа (не новое число) |
|---|---|---|---|---|---|
| **A. ×H3 (есть)** | `size / (k × median_trade_lots)` | сколько типичных сделок съедят уровень | косвенно D 00:42 («крупная для стакана») — В-42 так и трактовал | лента (медиана по окну `pick`) | `window_secs = 3600` из `instruments.csv` |
| **B. ×соседи** | `size / mean(size_j)` по уровням той же стороны в окне `±W` bps от уровня, исключая сам уровень | во сколько раз уровень крупнее «средней плотности этого стакана» | **прямо** D 00:42: «объём определяется размером плотностей средних в стакане»; N 1:20:13: «настроенный стакан»; K 33:45 «разряжённость» | книга на кадре старта касания (тот же кадр, что `stack_levels`) | `W` = последняя граница расстояния 25 bps (В-45) или вся сторона `.50`; вариант — медиана вместо среднего (устойчивее к другой плотности рядом) |
| **C. ×поток** | `size / V_T`, где `V_T` — объём сделок **в сторону уровня** (агрессор против него) за `T` с до касания | сколько секунд текущего потока нужно, чтобы проесть уровень («время до проедания») | **прямо** P 06:25: «не хватит рыночной ликвидности проесть»; S 05:19 импульс «по ленте»; Z 35:29 «превышает текущую волатильность» | лента (`publicTrade`, сторона `S`, RPI исключён В-55) | `T` ∈ `HORIZONS_MS` {1, 10, 60 с}; при `V_T = 0` — сила «∞», отдельная корзина |
| D. ×глубина (из промпта) | `size / Σ size_j` в `±W` bps (доля уровня в видимой глубине) | доля стакана в одном уровне | никем прямо не названо; близко к D «$ на тик» | книга | `W` = 25 bps |

**Ближе всего к транскрипциям — B и C**: B — буквально формулировка D, C — буквально
формулировка P и того, как S читает ленту. A — наша интерпретация, подтверждённая только
монотонностью. D — измеримо, но без цитаты; регистрировать как контроль, не как кандидат.

Абсолютный фильтр «от N» (владелец, спека §12 п. 5) — отдельная ось `size_usd ≥ N_abs` (или в
лотах), комбинация с силой — И. `N_abs` назначает владелец; источники для ориентира — $300k/$200k
[D 01:20], 50–150k [S 22:03], $150k [K 40:02], а распределение наших размеров по касаниям и
смертям (`practitioner-numbers`, квантили В-46 п. 3) покажет, сколько касаний вообще останется.

### 3.3. Что нужно и есть ли в коллекторе

Всё из бинлога, без новых потоков: A — уже считается; B — книга на кадре старта касания (та же
выборка, что `stack_levels`/`frontrun_lots`, В-45, ноль аллокаций — двухслотовая выборка уже есть);
C — сделки за `T` с до `start_ms` с полем стороны и без RPI (В-55). Ограничение из аудита: у Bybit
нет ID ордеров, поэтому «одна плотность» = один ценовой уровень, и B/D считают уровни, не заявки.
Глубина для B/D — `.50` (быстрый поток); `.200` пригодится только для `W` шире 0.18 % цены — на
боевых монетах и 25 bps это не требуется.

### 3.4. Как проверить, что фича полезна

Порядок — тот же, что дал первый сигнал (`touch-size-axis`), и тот же статконтракт (BUSINESS-TASK §6):

1. **Распределения до порогов** (В-46 п. 3): квантили силы p10/p50/p90 по касаниям, отдельно
   `bounced`/`eaten`, по трём знаменателям — чтобы корзины назначались по видимой структуре, а не
   из головы. Корзины — те же три, что `SIZE_LABELS` (границы 2 и 4), пока распределение не скажет
   иначе.
2. **Маргинал «доля отскока по корзинам силы»** для A, B, C, D — по пулу и по инструменту.
   Полезность = монотонность и разрыв между крайними корзинами больше, чем у A (сегодня
   35.5 → 40.6 %, +5.1 п.п.). Это «доля отскоков выше порога против ниже» из промпта, только
   без единого порога — по корзинам.
3. **Markout `m` по корзинам** на горизонтах 10 с / 60 с и новых (S-D) — отскок, который не платит
   («Платит ли сильный сигнал», `touch-size-axis` §4), фичей не считается.
4. **`net_fill` сделки-отскока по корзинам силы** (машинерия T38, форма — по предрегистрации
   шага 1): полезность = нижняя граница интервала в верхней корзине > 0 при DSR по фактическому
   числу испытаний. Число испытаний: знаменателей × корзин × горизонтов (+ крест сила × возраст
   после выбора `k`) — заранее в `runs.csv`.
5. **Устойчивость:** wild cluster bootstrap-t по суткам (≥ 7). *(Деление на разведочную/подтверждающую
   снято владельцем 17.09 — см. §6 п. 4; остаётся одна выборка и DSR по числу испытаний.)* Порог `S%` выбирается на
   разведочной как граница верхней корзины, не подбирается по PnL.
6. **Контроль ложной силы:** корзины силы при фиксированном абсолютном размере (стратификация по
   `N_abs`) — иначе «сила» просто повторит «крупный уровень в $».

### 3.5. Где фича в плане

Звено 3 (признаки) → шаг 2 (оси и распределения) → фильтр в звене 4 → корзина в шаге 3 (повтор
T38). Она же заменяет пилот `k` по смыслу: `k` — это порог по знаменателю A; выбор знаменателя и
границы на разведочной выборке — и есть «процедура пилота» В-30, только с двумя дополнительными
кандидатами и с абсолютным полом рядом.
