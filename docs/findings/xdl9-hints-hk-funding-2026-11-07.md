## Метод H1
- `s = 1e4·ln(A/B)` по close на общих минутах (обе ноги торговались; в панелях v=0 = NaN). A = Binance (в паре Bitget-внутри — USDT-контракт). Курс HKD не вводился; базис = медиана s.
- Скользящая медиана: предыдущие 1440 мин по общим минутам (≥60 точек, без текущей). `dev = s − медиана`. Эпизод = серия подряд идущих общих минут с |dev|>θ; θ ∈ {10,20,40,80,160} bps, сетка напечатана целиком (пустые строки не печатаются).
- Сделка: вход на первой минуте эпизода против отклонения, выход при возврате s к медиане НА МОМЕНТ ВХОДА, иначе таймаут 24 ч. Вход разрешён, только если +24 ч +1 мин внутри формирования. Простая доходность двух ног равного номинала, bps на ногу. Издержки 4 ноги: тейкер 12.6, мейкер 5.04 bps (3.15 / 1.26 на ногу, как Bybit минус 10% возврата, В-88). Фандинг в H1 не входит.
- `g0` — вход и выход по close той же минуты (оптимистично, ≥θ по построению); «+L» — вход и выход на L минут позже (если минута L без сделок хотя бы на одной ноге, вход не исполнен; выход — на ближайшей общей минуте). нт/нм = чистая тейкер/мейкер. gmax = лучший момент выхода за 24 ч (знание будущего, недостижимо).
- Календарь HKEX по данным (Binance TENCENT, минут с изменением close в часах 01:30–04:00 и 05:00–08:00 UTC, сутки 1…14 окт.): 55,212,61,32,180,175,167,241,254,47,54,212,223,254 → закрыто 1 окт.
