Оценка D2b — прокси: число событий D2b задаёт Исследователь; набор 449 ячеек в замере — 12 ячеек гейта по кругу, не настоящий X.

**Что это значит для D2b:** (1) 3·10⁹ строк построчно на диск не пишутся (≈100 Б/строка ≈ 300 ГБ) — нужен режим агрегации в ядре (группы ячейка×ТФ×сторона×год: n, сумма/суммы квадратов net, доли); (2) выигрыш ядра над `trade_fast` на D2b ≈ ×5, не порядки: узкое место — проход минут на каждую (событие × ячейка); (3) следующий рычаг — один проход по минутам на событие для всех ячеек с общим входом/стопом (вариант (б) P-TK461 §10), плюс одна загрузка свечей на монету для всех ТФ (≈ −40 % стены D2a: загрузки 252 → 84).
В замере bench3 (D2a полный, 1-й прогон) у 4 пар 1440 (DOT, ETHFI, LTC, PLUME) не появились выходные файлы; повтор каждой пары по отдельности и повторный полный прогон — rc 0, 252/252. Причина не найдена (стенд делился с другими заданиями).

**Алгоритм:** варианты — (а) Python-цикл по минутам (эталон), (б) векторизация окна (`trade_fast`, потолок ×3,6 при раннем стопе), (в) компилируемое ядро с тем же циклом, 1 поток на пару + параллель по парам; замер — таблица выше; выбран — (в): единственный, дающий побитовое совпадение со всеми режимами при ×40 над эталоном на D2b; потолок (в) — загрузка свечей и запись, названы рычаги выше.
