# TK-012: дизайн кода Г-36 / Г-55 / Г-140 / Г-07 (Инженер, 28.09)

Задача — `.claude/tickets/TK-012.md`. Здесь — где живёт код и какие признаки видит протокол П-08 (TK-013);
пороги — параметрами, значения назначает протокол.

## Где код (поправка к тикету)

Фильтры входа bounce-grid — не в `lob::strategy`: стратегия создаётся на касании (`t0`) и истории до него не видит.
Все фильтры — проверка записи подхода в `TouchFilter::admits` (`src/commands/lob/bounce_grid/sets.rs`) по полям,
которые считает `LevelTracker` (`src/lob/levels.rs`) до взвода и пишет в кэш подходов (`lob touches --approach-bps D`).
Значит новая основа — в `levels.rs` (`Live` + `Approach`), признаки — новые колонки кэша подходов, фильтры — ключи
`--set` (шаблон — `usd_min`; в заголовке печатать только при `Some`, как T-35 → байт-в-байт без ключей).

**Следствие для счёта:** новые колонки = пересчёт кэша подходов (`lob touches`) на авг+сен+июль один раз новым
бинарником, затем один `--cells` на сутки. Старый кэш читается (колонки опциональны), но ключ нового фильтра на
старом кэше — отказ (образец T-35, `bounce_grid.rs:303`), не молчаливый ноль.

## Общая основа (0)

- У уровня (`Live`): минутное кольцо фиксированного размера `[LevelMin; 60]` — `add_lots`, `cancel_lots`,
  `trade_lots` на цене уровня. Разбор кадра: рост размера = add; падение = сначала сделки на этой цене с прошлого
  кадра (trade), остаток — cancel. Плюс `restored_lots` с рождения: рост размера после падения от сделок.
- У трекера монеты: такое же кольцо `[CoinMin; 60]` — add/cancel/trade по всей видимой книге своей стороны и
  агрессивные продажи/покупки ленты по монете.
- Ноль аллокаций на событие (массивы в структуре), без `f64` для размеров (лоты `i64`), без карт на пути события.

## Глубина `.200` (Г-07)

уровней (`book/mod.rs`): там глубина позади — по 200. Своя запись с 16.09 в основном бинлоге — `.50` (`.200` писался в
`deep/` и стирается). Июль — архив, т.е. тоже 200. Итог: авг и июль — 200, сентябрь — смесь (до 15.09 — 200, после —
50); протоколу — учесть либо обрезать глубину до 50 уровней везде (ключ `behind_levels=50`, по умолчанию выкл).
