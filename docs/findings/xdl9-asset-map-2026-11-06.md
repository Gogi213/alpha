## 2. Правила
### 2.1 Нормализация имени и классы
Ключ актива = базовое имя в верхнем регистре без приставки множителя (`1000000`, `10000`, `1000`, `1M`; суффикс `1000` у Bybit `SHIB1000`) и без суффиксов-псевдонимов класса «акции/ETF»: `STOCK` (Bitget, Bybit), `HKD` (Bitget), `x` (Kraken xStocks), `USD` (Lighter), приставка `rh` (Lighter); у контрактов с котировкой BTC к ключу добавляется `BTC` (Binance `ETHBTC` → ключ `ETHBTC`, не `ETH`). Для металлов, энергии, индексов и FX — встроенный словарь (`asset_cands.py`: GOLD→XAU, COPPER/XCU, CL/WTI/WTIOIL/OILWTI, BZ/BRENT/BRENTOIL/OILBRENT, NG/NATGAS, US500→SP500, US100/NDX100→NASDAQ100, JP225→NIKKEI225, KOSPI→KR200, GER→GER40; FX — пара из base+quote; кросс-котировки золота BingX XAU/AUD и т. п. получают ключ с валютой). Укрупнённые классы — P-37 §4.1 (Н3). **Ключ только предлагает кандидатов.**

### 2.2 Статистики пары (по общим валидным минутам формирования)
`n_ret` — общие минуты, где у обеих ног есть доходность (бар в t и t−1); `corr` — Пирсон минутных лог-доходностей; `med_ratio` — медиана c₁/c₂, `k` — ближайшая степень 10, `dev = |log10(med_ratio) − k|`; путь **М**, если `dev ≤ 0,02` (Н4), иначе **К**; `S = σ(lr)/σ(ln c₁)`, `lr = ln c₁ − ln c₂` на общих минутах (c₁ — нога с большим оборотом, Н20); оборот, доля нулевых минут (нет бара или v = 0) по каждой ноге и `zero_common = 1 − n_common/20160`. Реализация проверена на 200 парах случайных контрактов против матричной версии скана (макс. расхождение corr 5·10⁻¹⁶, S 7·10⁻¹⁵).

### 2.3 Основной контракт и дубли
Внутри (биржа × ключ × укрупнённый класс) контракты упорядочены по обороту за 01–14.10 (HKD-ноги — после USD-подобных), жадно: контракт — дубль уже выбранного основного, если `S < 0,09835` (наименьший S среди заведомо «разных» калибровки) при `n_ret ≥ 300`; HKD-нога — дубль по политике r2 (Н29) независимо от S (TENCENTHKD у Bitget: S = 0,184, дубль по политике). Если измерить нельзя (`n_ret < 300`) и есть один кластер — дубль «не проверен измерением» (отмечено, 26 шт.). Для C1/D2 остаются основной и HKD-ноги (самостоятельная нога, r2 §4.2). Вторых «основных» с тем же именем после измерения нет (`n_clusters_multi = 0`). Причины дублей — Т4 ниже, полный список с S/corr/отношением к основному — `docs/findings/xdl9-asset-map-2026-11-06/dups.csv`.

### 2.4 Вердикт: что по r2, что применено и почему (отступление)
r2 §4.2: путь М = степень 10 + `ratio_band` + `corr ≥ corr_threshold`; путь К = `corr ≥ corr_threshold` + `S ≤ stab_threshold`; пороги — середина зазора между худшим «одно» и лучшим «разное». **Буквально это не исполнимо:** по `corr` и `dev` зазора нет (§3.2), поэтому тесты XAU–PAXG/XAUT (ratio ≈ 1, dev до 5·10⁻⁷, corr до 0,965) на пути М проходят любые пороги, пропускающие BTC. Применена **поправка R2′**:
- **«одно»** — `n_ret ≥ 300` и `S ≤ 0,06171426` (оба пути, М и К);
- **«пограничное»** — `0,06171426 < S < 0,09835096` (в C1/D2 не идёт; список для решения);
- **«разное»** — `S ≥ 0,09835096`;
- **«класс не совпал»** — отдельный вердикт (укрупнённые классы ног разные; «связь есть/нет» по тому же S);
- `n_ret < 300` — «нет данных».
`corr`, `dev`, `path`, отношение цен выводятся в каждой строке, воротами не служат. Это отступление от r2 (назначено без Судьи, подтвердить); предложение записи в P-37 §17 — в §7.
