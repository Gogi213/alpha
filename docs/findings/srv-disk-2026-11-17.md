## 3. Выгрузка на Storage Box — состояние

- **Механизм:** `collector-day-upload.timer` (`*:17`, каждый час) → `/opt/day-upload/day_upload.py --quiet-s 300 --bwlimit 20000`: закрытые сутки (UTC) шести источников (`binance`, `okx`, `bingx`, `bybit`=`soak-bybit`, `binance-soak`, `gate`) → бокс `alpha/collect/<биржа>/<день>/` + `SHA256SUMS` + `UPLOADED.json`; sha256 каждого файла считает сам бокс. **Ничего не удаляет** (юнит `ProtectSystem=strict`, `/data` только чтение). Старые `tools/sb-*.sh` (ночной перенос Steam Deck / старого коллектора) на srv не стоят — таймеров `sb-*` нет. **Политики очистки на srv нет: всё, что выгружено, лежит на srv дублем, диск выгрузка не освобождает.**
- **Не сломана:** все шесть источников `lag_days = 0`, `last_error = null`, `СБОЙ` в журнале с 16.11 — 0. Последний успех (час проверки): Binance 16.11 (09:19 UTC 17.11), BingX 16.11 (01:19), OKX 16.11 (15:18), Bybit 16.11 (15:19), Gate 16.11 (13:21), `binance-soak` 12.11 (13.11 09:14; источник остановлен).

## 5. Нужна ли выгрузка сырья: да — готовая команда (не запускалась)

Без неё 60 ГБ свободно кончатся за ≈ 4,7 ч, диск целиком — за ≈ 3 сут. Сутки ≤ 14.11 уже на боксе и сверены; предложение — держать на srv **2 закрытых суток + текущие** (≈ 61 ГБ сырья).

`tools/srv-offload-delete.py` (копия на srv — `/root/tk586/offload-delete.py`): удаляет каталог суток `<корень>/<день>/` только если **все** условия: день < `--keep-from`; есть `.ok`, размер и mtime каждого локального файла = записи `.ok` (файл не менялся с sha256-сверки); на боксе `ls -l` суток — имена и размеры = `.ok`; в каталоге нет файла моложе 15 мин. Без `--go` — только план. Не трогает `pool-<день>*.json` в корне и всё, что не каталог суток.

```bash
# план (уже выполнен 17.11 — вывод ниже)
ssh root@5.231.25.224 'systemd-run --wait --collect -p StandardOutput=journal nice -n 19 ionice -c3 python3 /root/tk586/offload-delete.py --keep-from 2026-11-15'
# удаление (только после слова владельца)
ssh root@5.231.25.224 'systemd-run --unit=tk586-offload --collect nice -n 19 ionice -c3 python3 /root/tk586/offload-delete.py --keep-from 2026-11-15 --go'
```

Вывод плана (17.11): binance 12/13/14.11 — 0,02 + 8,02 + 7,30 · okx 13/14 — 3,62 + 2,95 · bingx 13/14 — 3,62 + 3,70 · bybit 12/13/14 — 1,51 + 3,44 + 2,92 · binance-soak 12 — 2,97 → **будет удалено 40,06 ГБ**, свободно станет ≈ 104 ГБ. Дальше по одному дню в сутки: `--keep-from <сегодня − 2 сут>` ежесуточно (таймер — отдельной задачей и тоже по слову владельца).

Альтернатива без касания сырья — `/data/aggtrades` (64,7 ГБ, скачанный датасет, копия на боксе sha256-сверена 14.11: `VERDICT OK`, 86 149 файлов; В-131/В-132 приказывали удалять скачанные датасеты). ## 7. Находки по ходу

- `du` по каталогам арбитража обманывает из-за жёстких ссылок (`cp -al`): удаление одного каталога из группы не освобождает место. Для решений — только `/root/tk586/an2.py <пути…>` (освободится ли и сколько).
- Часовая выгрузка перегоняет закрытые сутки заново, когда коллектор переписывает `pool-<день>.json` (OKX/Gate/Bybit) — лишний ≈ 1 мин ЦП и 3–8 ГБ чтения в час; безвредно.
- Правила выгрузки `day_upload.py` и политика очистки не связаны: «сверено на боксе» нигде не превращается в «удалить на srv», решение остаётся за владельцем (п. 3).
