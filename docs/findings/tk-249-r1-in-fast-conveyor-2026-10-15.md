# TK-249 — семейство R1 в быстром конвейере формы: инвентарь, дизайн, варианты, партии (15.10, план)

Статус: план (без счёта, без постановок в alsched, без вливания). Измерено только чтением записей alsched на calc (`/data/sched/jobs/*.json`:
`t_end−t_start`) и `ls` каталогов; новых запусков нет. Что оценка, а не замер, помечено «(оценка)».
Источник объёмов — `docs/findings/tk-247-off-form-hashes-2026-10-15.md` (ветка `tk247`), `tools/registry/master.py` (R1COL/R1X/R1_SIGN).

## Итог в трёх строках
1. R1 — не клетка движка, а **фильтр по готовой таблице сигналов базовой клетки B1** (`t-bid-btc4h-q1`, `--signal approach --busy-skip off --r1-cols`),
   порог которого зависит от **всех прошлых месяцев** (расширяющееся окно). Исход каждого сигнала от клетки не зависит (без «занято») — поэтому клетка R1 = выборка строк B1.
2. Рекомендация: встроить R1 в конвейер формы **новым маршрутом `r1` (и `r1x` — «клетки готовы, нужен psim»)**, а отбор — **одним параметризованным модулем
   Python** (слияние `tk064-r1cells.py` + `tk202-r1x.py`), **Rust-движок не трогать** (выкл = прежний тривиально: нулевой дифф в `src/`). Варианты (а)/(б) внутри Rust
   дороже по счёту и коду и не дают выигрыша: отбор стоит минуты, не часы (замеры ниже).
3. Объём: R1X 270 хешей × 9 мес = 2430 хеш-мес — только psim по готовым клеткам; R1COL 161 × 9 = 1449 — фильтр + psim; Г-117 (9) и nodata/noline (10) в этот конвейер не идут.
   Всё вместе ≈ 3900 хеш-мес, ≈ 20–30 мин счёта на 1 ядре по порядку величины (оценка из замеров ниже).

## 1. Инвентарь R1

### 1.1 Что делает Python-отбор (точно, по коду)
Вход: `/data/tk064/pool/m-<мес>/{signals,signals-retry}/<сутки>/t-bid-btc4h-q1/{signals.csv,rounds.csv}` + `lvl/<сутки>.csv` (`size_at_arm`). Сигнал = ключ
`(symbol, day_utc, signal_index)`; дубли снимаются, первым побеждает `signals`. Колонки признаков — 61 колонка R1 (`--r1-cols`, `src/lob/r1.rs`: все целые, пусто = не определено).
Параметры клетки: `col` (колонка), `sign` (`hi` — оставить верхние q %, `lo` — нижние; знак **задан гипотезой** в `master.R1_SIGN`/`R1EXT_SIGN`, в хеш **не входит**),
`keep_q` (5…95), для ctx-клеток (Г-78/55/140) ещё `ctx_axis` (pool1h/btc1h) и страта `ctx_q` q1…q5.
Порог месяца m (`tk064-r1cells.py thresholds/apply`, `tk202-r1x.py apply`):
- история = определённые значения колонки по **всем сигналам B1 предыдущих полных месяцев** (январь — сам по себе, `--jan-self`, TK-115);
- порог = квантиль «ближайший ранг» без интерполяции: `hi` → `1 − q/100`, `lo` → `q/100`; сигнал остаётся при `v ≥ t` (hi) / `v ≤ t` (lo);
- правило массы в нуле (П-11 §4): если по январю q33 = q67 = 0, порог берётся по ненулевым значениям (одно решение на колонку для всех месяцев);
- меры в лотах (`*_lots`, `trade_size_*`, кроме счётчиков `nz_levels15`, `frontrun_levels`) делятся на `size_at_arm` — безразмерная доля, не целые лоты;
- неопределённое значение отвергается порогом (клетки «пропуск» оставляют — только в `BIN`-клетках tk064);
- ctx: страта оси на минуте `t0` (floor), границы q20/40/60/80 из `tk202-thresholds.json`; порог keep_q — по всей истории B1, не внутри страты; нет значения оси — сигнал отвергнут.
Выход: `cells/<мес>/<хеш|клетка>.csv` — исходы по сигналам `symbol,day_utc,signal_index,t0_ns,net_bps,reason,exit_ns,qty` (из `rounds.csv` B1). **Долларов нет.**
Затем `p12-r1-psim.py <мес>` (архив): слияние деревьев → `busy-replay.py --keep <клетка>.csv` (правило «занято» ПОСЛЕ фильтра, ключ symbol,day_utc,signal_index) →
`portfolio-sim.py` (депозит 2500, позиция 500, cap 0 и 3, drop TRUMP/TRX/BCH) → `closes-cap{0,3}-<мес>.json` → `load_closes.py`.

### 1.2 Чем это отличается от строки `--cells`
| | строка `--cells` (форма) | R1-клетка |
|---|---|---|
| что задаёт | форму (вход/стоп/тейк/дедлайн/ttl/выход) + набор фильтров касаний на суточный проход движка | подмножество сигналов базовой клетки B1; формы нет |
| исход сигнала | считает движок на каждую клетку | берётся готовый из `rounds.csv` B1 (`--busy-skip off`: круг сигнала не зависит от соседей) |
| состояние между месяцами | нет (клетка по суткам) | **есть**: порог = квантиль по всем прошлым месяцам |
| единица измерения | целые/bps осей `FilterSet` | отношение `лоты/size_at_arm` (с плавающей точкой) |
| «занято» | внутри движка | после фильтра, `busy-replay.py` |
В Rust уже есть `--set … r1_<колонка>_min|_max=<целое>` (TK-025, `sets.rs::r1_key`, `ArmR1::names()`): это **фиксированная целая граница по сырой колонке** — без
расширяющегося квантиля, без деления на `size_at_arm`, без правила массы в нуле. Python-отбор этим ключом не воспроизводится (ровно поэтому в TK-064 он и написан отдельно).

## 2. Дизайн общего механизма (текущий рантайм, без новых рантаймов)

### 2.1 Схема
```
routes.json: тип "r1" (клетки не готовы: фильтр + psim), "r1x" (клетки готовы: только psim)  ← раньше "outside"/"r1col"/"r1x" «вне формы»
launch.py prepare_plan → <план>-<мес>.r1spec   (hash,hyp,col,sign,keep_q,ctx_axis,ctx_q; одна строка = одна R1-клетка запроса; та же таблица, что делает tk202-r1x.py spec)
run-launch.sh: шаг 2 (после day-cells.sh):  r1cell.py apply --spec … --pool … --out <оверлей>/r1/cells  →  psim-launch.sh с каталогом клеток r1/cells  →  closes → postload (как cells)
r1cell.py = один модуль: tk064-r1cells (thresholds/apply, FAM-колонки) + tk202-r1x (spec/apply, ctx) на общей таблице «колонка → знак/делитель/класс», тесты в tools/compute/tests/
```
- **Хеши:** маршрутизатор берёт хеш из `master.cell_hash(cfg)` (feature, q, thr[, ctx]) — к Rust-строке он не привязан → 145 готовых хешей r1ext и 19 R2-B остаются теми же ключами,
  пересчёта нет (В-213). Охрана: тест «хеш клетки в `.r1spec` = хеш в `plan_cells.jsonl`» + проверка `guard.py plan` (выписка «что есть / что новое»).
- **База B1:** для янв–окт лежит в пуле (`/data/tk064/pool`); новый месяц — один прогон движка `bounce-grid --signal approach --busy-skip off --r1-cols` по B1 (существующие флаги, умолчание старое).
  Это единственный счёт на движке для R1, и он общий для всех R1-клеток месяца.
- **Семь запретов горячего пути:** не затрагиваются — на горячем пути ничего не меняется (отбор — офлайн над CSV). Если когда-нибудь фильтр уйдёт в Rust, он обязан быть
  таблицей порогов `[i64]` (отсортированной, без `HashMap`) на кадре взвода, без аллокаций на событие; сейчас не нужен.
- **Гейт «выкл = прежний»:** `git diff -- src/` пуст; для Python-пути — «байт в байт» на готовых клетках r1ext (раздел 4). Без `.r1spec` форма ставит ровно прежний набор.
- **Что не обещаю:** ctx×keep_q (Г-78/55/140) требует `<t46>/…/study/regime/<сутки>.csv` и `tk202-thresholds.json` — это входы, их пути фиксируются в `config.json` формы, не в коде.

### 2.2 Почему не «фильтр сигнала как строка `--cells`»
1. Порог зависит от всех прошлых месяцев — суточный проход движка этого состояния не имеет; нужна внешняя таблица порогов (месяц × колонка × q), т.е. тот же Python-расчёт, только его результат кладётся в файл.
2. Деление на `size_at_arm` и правило массы в нуле в `FilterSet` нет — нужны новые ключи и отдельные ветки в горячем пути «момент касания».
3. Главное — **стоимость**: клетка R1 использует исход, уже посчитанный для B1; через `--cells` движок пересчитывал бы одни и те же круги заново в каждой из 431 клеток (R1X + R1COL) месяца (оценка: ~«число клеток × доля оставленных» от стоимости B1 за месяц).

Замер скорости/качества на малом (один месяц, свежий прогон нового модуля) **не выполнен**: требует постановки в alsched, которая в этом тикете запрещена — вынесен в Партию 1 как гейт (1 ядро, ≈ 5 мин).
