# Данные разбора плагина role-play-vibing, 16.10 12:00 – 17.10 18:00 (TK-266…TK-293)

Отчёт: [../plugin-recommendations-2026-10-17.md](../plugin-recommendations-2026-10-17.md).

Папки прошлого разбора (`2026-10-16-quality-gates-data/`) в репозитории нет — метод восстановлен по тексту прошлого
отчёта (возвраты Судьи на тикет, цитаты из логов). Прошлые числа (25 % / 0,33) здесь пересчитаны по тому же правилу
и сходятся с точностью до границы периода (30 % / 0,37: граница — 16.10 12:00, а не 16.10 вечер).

## Как пересчитать

```
python docs/findings/2026-10-17-plugin-data/recount.py      # из корня репозитория, только чтение
```

Скрипт читает `.claude/tickets/TK-*.md` **вместе с** `.claude/tickets/archive/TK-*-log.md` (старые записи длинных
тикетов вынесены в архив, без него теряются ask-owner и возвраты TK-274/278/279), `.claude/dispatcher/runs.log`,
`ceo-wake.log`, `ceo-inbox.md`. Пишет сюда: `tickets.csv`, `summary.txt`, `quotes.txt`, `askowner.txt`.

## Что внутри

- **Периоды** — по времени первой записи в логе тикета. НОВЫЙ: 16.10 12:00 – 17.10 18:00 (28 тикетов, TK-266…293).
  ПРОШЛЫЙ: 14.10 00:00 – 16.10 12:00 (27 тикетов, TK-241…265). В прошлом периоде тикетов Исследователя нет (10 тикетов
  Исследователя в новом периоде — протоколы П-14…П-19; для честного сравнения в `summary.txt` есть строки «только Инженер»).
- `tickets.csv` — по тикету: владелец-роль, статус, запуски (`runs.log`), возвраты Судьи, `ret_answer` (возврат-ответ
  на развилку), `ret_nolive` (нет выкладки/живой проверки), `ret_defect` (дефект/недостача), `repeat_signals`
  (done/accept без работы: «Повтор», «уже влит», «Дубль», «Дела нет»…), ask-owner/blocked с разметкой M/O/H,
  часы от первой записи до последнего done/accept (пусто — тикет ещё открыт), траты `resolved_cost` по запускам
  (поле `ticket_spent` в `runs.log` считается так же), записи сторожа и надзирателя.
- **Разметка ask-owner/blocked** — вручную, словарь `MANUAL` в скрипте (текст — в `askowner.txt`):
  M — методика, ресурсы, порядок счёта (по уставу решает Судья/CEO); O — решение владельца по делу (дизайн макета);
  H — блок инструментом (хук, нет пути будить роль).
- **Разметка возвратов** (`ret_*`) — по ключевым словам в первых 200–300 знаках записи Судьи (регулярки `ANS` и `LIVE`
  в скрипте); это эвристика, граница между «ответом» и «дефектом» ±2–3 записи. Для сравнения периодов годится, как
  точное число — нет.
- `quotes.txt` — записи, где роли пишут «Повтор / уже влит / ложный / сирота…», с тикетом и временем.

## Ограничения

- Траты — только запуски ролей из `runs.log`; сессия CEO и надзиратель туда не попадают.
- Тикеты TK-272, 274, 279 и ещё 4 на конец периода открыты — их траты и возвраты ещё растут.
- ceo-wake.log и ceo-inbox.md читались только на чтение (их пишет диспетчер).
- Эпизоды 4 (CEO не может `result return`) и 5 (`new --ref` требует номер реестра) в логах следов не оставляют —
  подтверждены чтением кода плагина 2.0.6 (`routes.py:17,68`; `tickets.py:93–111`).
