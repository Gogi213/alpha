#### 3. Risk:reward баз (измерено 20.11, §13.36 п. 3; повторно не считается)

#### 4. Признак (причинный)
`t = ⌊sig_ms / 60 000⌋` — минута сигнальной сделки; `cf` — закрытие BTCUSDT по минуткам кэша, пропуски заполняются последним закрытием с данными (как `sigfeat_lib.ffill_close`). **Ход BTC за W минут** `btcW = (cf[t − 1] / cf[t − 1 − W] − 1) · 10⁴ · s`, `s` = +1 лонг, −1 шорт; W ∈ {60, 240, 1 440}. Используются только минуты строго раньше минуты сигнала; та же формула, что у f12 `btc_mv5` / `btc_mv15` (сверка — ворота G-eq). `btcW > 0` — BTC шёл **в сторону сделки**, `< 0` — **против**. Нет значения (вне кэша) — **пусто проходит** (число таких строк печатается).

#### 5. Клетки (12 на сторону; назначены до P&L механизмом «рынок тянет / мешает», не выведены из результатов)
На каждое W ∈ {60, 240, 1 440}:
| клетка | исключается сигнал | смысл |
|---|---|---|
| `B<W>_with` | `btcW < 0` | торгуем только по ходу BTC |
| `B<W>_agst` | `btcW > 0` | торгуем только против хода BTC |
| `B<W>_nag20` | `btcW < q20` | не торгуем при сильном ходе BTC против сделки (нижние 20 %) |
| `B<W>_nwi80` | `btcW > q80` | не торгуем после сильного хода BTC по сделке (верхние 20 %) |
`q20`, `q80` — **общие квантили** `btcW` по сигналам базы h775 этой стороны (все монеты вместе, три окна, зачётные диапазоны, перекрытие окон один раз; `linear`; 2 значащие цифры); одно число на все монеты. Исключается сигнал базы, остальные ключи `L_base` / `S_base` не меняются; клетка — прогон движка с таблицей `--ftab` (`fa=<клетка> fo=lo fv=0.5`: 0,0 исключает, 1,0 пропускает). Портфельный режим: снятый сигнал может освободить позицию для другого сигнала — число «+ / −» сделок против базы печатается. Контроль `ALL1` (все 1,0) — ворота G-base.
**Что видели раньше на тех же сутках (контекст «найдено на этих данных»):** TK-618 шаг 1 (шорт o566, 431 сделка, ход BTC без знака стороны): верхний квартиль хода BTC за 4 ч (BTC вверх = против шорта) — −2,8 $ при Σ базы +259 $, за 24 ч и 1 ч — без явной формы. Клетки `nag20` шорта поэтому частично подсказаны этими данными; при положительном ответе — пометка «найдено на этих данных» обязательна.

#### 6. Статистика (числа назначены до счёта)
- **Портфельная Δ**: `ΔΣ = Σ$ клетки − Σ$ базы` за 136 сут., пара по суткам; бутстреп по суткам, круговые блоки 4, 20 000 повторов (зерно `st.seed_of`); 95 % интервал; p двусторонний (распределение бутстрепа, сдвинутое к 0) — функции `tk642_run.delta` без изменений.
- **Холм** по 12 клеткам **на сторону**, α = 0,05 двусторонний (z первой ступени 2,87).
- **MDE** (мощность 80 %): `(z_Холм + 0,84) · SE(ΔΣ)`; то же для $/сделку.
- Рядом: n, Σ $, $/сделку (среднее, без медиан), годовой Sharpe (136 сут. с нулями, ddof 1, × √365), Σ по месяцам и по окнам, просадка ($ и % маржи 250 $), KPI В-120, R:R, убыток стопа ($ и % маржи при плече 2), доля сделок клетки среди сделок базы.
- **Шумовой эталон над всеми 24 клетками** (обе стороны): ожидаемый максимум |z| из 12 и из 24 нулевых клеток (и 95-й перцентиль); шумовая планка Sharpe и дефлированный Sharpe (`selection_bias.py`, 24 испытания; SE для 136 независимых суток — как TK-639). Клетки перекрываются (одни сигналы) — независимых испытаний меньше 24, планка завышена.
- **Устойчивость**: знак ΔΣ сохраняется без двух суток и без монеты с наибольшим вкладом того же знака (`tk642_run.robust`).

#### 7. Правило вердикта (записано до счёта)
На клетку: (а) Холм отверг, ΔΣ > 0, ΔΣ > 0 во всех трёх окнах `wa` / `wb` / `wc`, устойчиво → «**фильтр лучше базы — найдено на этих данных**» (кандидат вперёд; заморозка — только по В-167: отдельный файл до первого чтения суток ≥ 17.11, α только из долей `L_base` / `S_mk1` (каждая ≥ 0,005), решение координатора и критика; эта задача не замораживает); (б) то же с ΔΣ < 0 → «фильтр хуже базы: ход BTC в этой форме сделкам не мешает, измерено»; (в) Холм отверг, но не устойчиво → «значимо, не устойчиво»; (г) иначе → «не различимо: |ΔΣ| < MDE не исключено» с числом MDE. **Ответ по стороне**: «работает» — хотя бы одна клетка (а); «не работает» — ни одной (а), и MDE ≤ 50 % Σ базы у большинства клеток (то есть эффект в половину прибыли базы был бы виден); иначе «не ясно».
