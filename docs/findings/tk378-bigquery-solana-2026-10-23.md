## Формат данных (проверено на частичной выгрузке)
- Колонки: block_timestamp, block_slot, tx_signature, source, destination, mint, value, decimals. Строки токенов — `mint`+`value`; **нативный SOL — строки без mint, но с value (лампорты)**, плюс служебные строки без value (не свопы).
- Квота: WSOL `So1111…`, USDC `EPjFWd…`; в маршрутах агрегатора на одну tx приходится 1–19 строк. Для восстановления свопа нужны vault-аккаунты пула: в частичных данных долю топ-аккаунта в переводах mint — 0,08…0,90 (MASK, STONK 0,87–0,90: в основном движение одного кошелька, а не пул) → vault определять по паре «вход mint ↔ выход quote в той же tx», не по частоте.
- Приоритетная комиссия/подписант (п.2) в этих 8 колонках **нет**: нужны `Transactions.fee`/`accounts` по списку tx (ещё один скан, оценка — dry_run по подписям, в Transactions кластеризации нет → без фильтра по сигнатуре нельзя; цена скана неизвестна). Не делал.
