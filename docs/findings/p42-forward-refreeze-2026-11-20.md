## Подготовка данных (п. 5) и код

- `tools/p42/tk626_prep.py` + `tk626_prep.sh`: листинг S3 (`tk621_list.py`, 01.07…D) → вселенная `U_k = B ∪ N_k` (`contracts.csv` точки: `in_base`, `tradfi`, `days_0107_1311`, `first_day`, `last_day`) → скачивание `tk621_dl.py` → REST-добор провалов минуток → деревья окон (ссылки на опубликованные файлы TK-621 / скачанные / REST) → охрана «каталог у каждого контракта, нет суток позже D, нет монет вне `all`» → `breakout convert` замороженным бинарём → `MANIFEST`, `READY`. Порядок монет в списке: база как в базовом файле, затем прирост по (первые сутки, символ) — список точки k есть префикс списка точки k + 1.
- `tools/p42/tk616_forward.py` (версия заморозки `tk626-frozen-1`): три вселенные × три клетки одним вызовом, охраны п. 6 (1)–(8) (вселенная точки с `days_0107_1311` / `first_day` / `last_day`, деревья ⊆ `all_k`, маркер, префикс и G3 швов по девяти парам, манифест файлов между точками), `L_base` — решающий член, `crypto` / `tradfi` — описательно. Тесты: `tools/p42/tests/test_tk616_forward.py` (22), `tests/test_tk626_prep.py` (7) — 29 из 29 на синтетике.
- Заморозка `docs/research/freeze/tk626-frozen.json` (сборка `tk626_freeze.py`; содержит бинарь, клетки и vid (`S_base` `c8c06a7d70b92`, `S_mk1` `cd0838447e287`, `L_base` `c3dacae86b422`), α, доли по точкам, окна, sha256 базовых списков и `contracts.csv`, исходы G-626a/c с `results_sha256`, sha256 заменяемой `tk616-frozen.json`).
