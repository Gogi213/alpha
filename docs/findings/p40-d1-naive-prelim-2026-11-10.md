- **K1 (+60 с)** — число без вывода: net ИТТ +0,72 [0,53; 0,91] (95 %, по активам), эпизодов 169 тыс., сошлись ≤60 с 36,9 %, исполнено 52,4 %. Механика: нога B сдвинута на 60 с — это запаздывающая копия, разрыв `A(t)−B(t−60)` ≈ ход B за прошлые 60 с и уходит к нулю по построению; «K1 > base» ожидаем и о реальном эффекте не говорит. Нулевой ли K1 как контроль — правка П-40 до D2 (Исследователь предлагает, Судья утверждает). **K1 (−60 с): не считалось** (в бою не заказан, run `out_d1v4` задавал только `P40_SHIFT_B_MS=60000`) — тикет на досчёт.
- **K2** (случайные моменты; d0 медиана 3,2 bps вместо 15,5): net ИТТ −3,21, исполнено 83,2 % — по d0 несопоставим; фандинг в K2 не считался. Вариант `k2` из specs идентичен base байт-в-байт (таблицы K2 лежат в `<base>.k2.k2*`, взяты они).
- **drain** — не «верхняя граница» на L1-данных, слово снято. Причина (по коду): ноги Bybit/Gate без файлов сделок; base в этом прогоне шёл в режиме `through` (оркестратор: «нога без сделок … режим проход цены сквозь уровень» в `out_d1v4/*/orch.log`; ядро `/root/p40core-tk522m/rs/src/main.rs:28,748` — `through` нижняя, `drain` верхняя, `skip` умолчание), а `drain` исполняет только по видимой убыли размера, и на L1 уход цены с уровня очередь не исполняет и не двигает (`rs/src/fills.rs:135`) — исполнение «цена прошла сквозь уровень» в `drain` теряется. Покадрово (2283 спека, `dr.py`): Bybit/Gate-пары: one→none 2372–3673 на пару бирж, none→one 484–584; без Gate/Bybit разницы нет. Итог: на L1 `drain` ≠ верхняя граница; настоящая нижняя/верхняя пара — вопрос Судье (§16.2 П-40 писался для полной книги). **`through` как отдельная нижняя граница не считался** — base и есть `through`; `skip` (off_maker) не считался — тикет.
