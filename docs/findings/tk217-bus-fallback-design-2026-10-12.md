# TK-217 — защита от падения шины: дизайн (Инженер, 12.10)

Плагин role-play-vibing 1.8.35: `bus/{bus,busclient,watcher}.py`, `dispatcher/{bus_link,dispatch,watch}.py`.

## Что есть сейчас (читано в коде)

| Слой | Что делает при лежащей шине | Дыра |
|---|---|---|
| `busclient.post` | событие → spool `%TEMP%/rpv-bus-spool.jsonl` (на Linux — `/tmp`), дошлётся **со следующим удачным post того же процесса** | сторож машины (`watcher.py`) шлёт только по факту нового события; без нового события spool не сбрасывается. `/tmp` стирается при перезагрузке. Сторож после `post→None` считает событие отправленным (`running.pop`, `files_seen.add`, `jobs[...]`) и не повторит |
| `bus_link.Listener` | long-poll, при ошибке пауза 5 с, переподключение | событие, не дошедшее до шины, слушатель не увидит никогда |
| `bus_link.Link` | `bus-down` CEO через 120 с, `bus-up` + снимок блокеров | это только уведомление, сверки по факту нет |
| `dispatch._reconcile` | раз в 300 с один ssh на машину, проверка **всех** `host:` по факту | проверяет только ключи `_WAIT_WATCH` (host:); не вызывается сразу после bus-up; формы `job:`/`ci-run:` идут через `watch.triage_waits` (тот же 5-минутный ритм, но он только чинит «мёртвые» цели, не будит на `done`) |
| `watch.triage_waits` | ssh-проба целей, DEAD_WAIT_STRIKES, idle-wait | будит по «мертво/простой», а не «выполнено вовремя» для всех форм |
| Шина сама (`rpv-bus.service`) | `Restart=always`, RestartSec=2 | нет сердцебиения снаружи, нет тревоги владельцу (CEO — только строка в inbox) |

Инцидент 12.10: шина 00:26 (132 с), rc задания 00:42, роль разбужена только CEO вручную 01:36 (≈54 мин). Сверка `host:` шла каждые 5 мин
(`ssh-calls.log`, 79+4 ключей) и не разбудила. **Причину надо подтвердить воспроизведением (п. 0) — по логам форма `wait_for` у TK-115 в ту ночь
не восстановлена**; гипотезы: (1) форма `job:`/`unit:` вне `_reconcile`; (2) событие `задание.готово` потеряно у watcher'а (spool не сброшен), а
`_event_met` без события для `unit` требует «проба после события»; (3) `_WAIT_CACHE` держит `False` до следующей сверки при `_needs_probe=False`.

## Дизайн

**(а) Запасной канал — журнал событий на диске, оба читают.**
- `busclient`: spool → постоянный append-only журнал `~/.rpv/outbox.jsonl` (не `/tmp`), строка = событие + `sent:false`. `post` пишет в журнал **всегда
  первым** (fsync), потом шлёт; успех → отметка в `outbox.sent` (id). Досыл: фоновый поток в `watcher.py` и диспетчере — раз в 15 с, пока в журнале
  есть неотправленное (не «со следующим post»). Дедуп на шине по `id` уже есть (`events.id UNIQUE`).
- Читатель без шины: диспетчер читает `outbox.jsonl` локальных машин не нужно — сторож машины пишет журнал **и** файл-маркер события в
  `~/rpv/events/<id>.json`; диспетчер при `bus down` берёт их в сверке (п. б) одним ssh-вызовом, который у него уже есть (`_recon_script`).
- Сторож машины: состояние «послано» ставить только по успешному ответу шины (сейчас — по возврату `post`).

**(б) Сверка по факту после bus-up и при старте.**
- `Link._on_state(up)`: при возврате шины (и при старте диспетчера) → `_reconcile()` немедленно (флаг `_RECON_NOW` + `_WAIT_NEW.set()`), не ждать
  300 с; плюс `watch.triage_waits` с принудительной пробой **всех** форм (`host:`, `job:`, `ci-run:`, `ticket:`) и **будить по `met`/`done`**, а не
  только по `dead`.
- Сверка при `bus down` ускоряется: пока `Link.down_since` не None — период 60 с вместо 300.
- Гарантия: завершение задания будит роль ≤ 60 с после конца простоя шины (пока шина лежит — ≤ 60 с после конца задания).

**(в) Наблюдение за самой шиной.**
- Сердцебиение: `GET /health` (новый, без токена) + поле `last_event_ts`; сторож (`watch.py`) раз в 30 с пингует, пишет `bus-heartbeat.json`.
- Автоперезапуск: `Restart=always` уже есть; добавить `WatchdogSec` + `sd_notify` нет (stdlib) — вместо этого: сторож при 3 неудачах подряд по ssh
  `systemctl restart rpv-bus` (один раз в 10 мин), журналируя.
- Тревога: простой > 5 мин (порог выбирать как `DOWN_NOTICE_S`, сейчас 120 с для CEO-строки) — `PushNotification`/ceo-wake владельцу + строка
  `служба.простой.превышен` в журнале; повтор раз в 30 мин, пока лежит.

**(г) Тест приёмки.**
1. Юнит-тест `busclient`: шина недоступна → событие в журнале, поток досыла шлёт ≤ 15 с после возврата, id не дублируется.
2. Юнит-тест `watcher`: post→None не отмечает «послано»; после возврата событие уходит.
3. Интеграционный: шина `systemctl stop` на 5 мин при коротком задании на calc (`jobrun.sh`, sleep 90 + progress `.json`); критерий — тикет с
   `wait_for host:calc:<файл хода>` проснулся ≤ 60 с после конца простоя (и ≤ 60 с после конца задания, если шина лежит дольше).
4. Регрессия: полный прогон `fastcheck.py` плагина.
