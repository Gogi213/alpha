# TK-025: пакет признаков R1 (колонки кэша подходов) — дизайн и договор (Инженер, 02.10)

Задача — `.claude/tickets/TK-025.md`; опись — `tk024-pool-inventory-2026-10-02.csv` (класс R1, 25 гипотез). Образец —
TK-012 (`ArmP08`, `--p08-cols`): признаки → поля `ApproachRecord` → колонки `approaches-*.csv` → фильтры `--set`.
Здесь то же, но пакетом и с одним общим ключом. Имена и порядок колонок — единственный источник `src/lob/r1.rs`
(`FLOW_NAMES` 40 + `LEVEL_NAMES` 22 = **62**); правки Исследователя (02:25 в логе тикета) приняты — отмечены «(П1…П5)».

## Устройство

1. **Момент — кадр касания** (причина снятия подхода `touch`, это t0 входа, причинно). У подходов, кончившихся
   `level_death`/`price_left`, колонки пусты (`r1 = None`, в CSV пустые клетки).
2. **Всё за флагом** `lob touches --r1-cols` (по умолчанию выкл): без флага состояние R1 не ведётся и колонки не
   пишутся — вывод побайтно прежний. Колонки R1 — в конце `APPROACHES_COLUMNS`, аддитивно (как TK-012).
3. **Один ключ `--set`:** `r1_<колонка>_min=<целое>` / `r1_<колонка>_max=<целое>` по таблице имён `ArmR1::names()`.
   Кэш без колонок R1 → отказ с текстом (образец `bounce_grid.rs:319`). `R1_UNDEF` порог отвергает всегда.
4. **Горячий путь:** массивы фиксированной ёмкости, `i64`-лоты, без `f64`/карт/аллокаций на событие; время — из
   кадров/сделок (`exch_ms`), не из часов. Если замер даст > +1 % user-времени при выключенном флаге — состояние
   уровня уходит в параллельную `SortedVec` под флагом.

## Общие правила

- **Окна — назад от t0, причинно.** Секундное кольцо: слот `s = exch_ms/1000`, окно `W` с = слоты `(s0−W, s0]`, `s0 = t0/1000`
  (в окно входят события с `exch_ms ≤ t0` из текущего неполного слота). Минутное: слот `m = exch_ms/60000`, окно `M` мин = `(m0−M, m0]`.
- **Прогрев (общее правило UNDEF):** окно определено, только если трекер монеты наблюдает её не меньше длины окна
  (`t0 − start_ms ≥ W·1000`; `start_ms` — первый кадр монеты в этих сутках). Первый час суток для 60-минутных окон — `R1_UNDEF`.
- **Единицы:** `_lots` — лоты; `_n` — штуки; `_bp` — доля ×10⁴ (целое, усечение к нулю); `_e2` — ×100; `_cbps` — bps×100
  (расстояния только так; 1 cbps = 1 ppm); `_ms` — миллисекунды. `R1_UNDEF = i64::MIN`, в CSV — пустая клетка.
- **Сторона.** «press» — агрессоры против стены (у бид-стены продают, у аск-стены покупают), «with» — за стену.
  Направленные величины (`obi*`, `micro_off_cbps`, `ofi_*`, `best_move_*`) ориентированы «от стены»: плюс = в пользу
  удержания (у бид-стены вверх, у аск-стены знак зеркалится) — один порог работает на обеих сторонах.
- Сделки считаются по тому же правилу, что и кольцо `flow_ring` (1 ч потока монеты); сторона агрессора — `aggressor_is_buy`.
