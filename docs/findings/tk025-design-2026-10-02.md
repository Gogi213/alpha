# TK-025: пакет признаков R1 (колонки кэша подходов) — дизайн и договор (Инженер, 02.10)

Задача — `.claude/tickets/TK-025.md`; опись — `tk024-pool-inventory-2026-10-02.md` (класс R1, 25 гипотез). Образец —
TK-012 (`ArmP08`, `--p08-cols`, `docs/findings/tk012-design-2026-09-28.md`): признаки → поля `ApproachRecord` → колонки
`approaches-*.csv` → фильтры `--set`. Здесь то же, но сразу пакетом и с одним общим ключом вместо 25 отдельных.

## Что решено по устройству

1. **Момент снятия — кадр касания.** Признаки R1 считаются на кадре снятия подхода, когда причина `touch` (это и есть t0
   входа, причинно); у подходов, кончившихся `level_death`/`price_left`, клетки пустые (входа не будет). Признак «на взводе»
   (как `ArmP08`) для ленты/книги бессмыслен: от взвода до касания проходят десятки секунд.
2. **Всё за флагом:** `lob touches --r1-cols` (по умолчанию выкл) → в трекере создаётся `R1State` (кольца, снимки сторон);
   без флага состояние не ведётся, колонки не пишутся, `APPROACHES_COLUMNS` без них — вывод побайтно прежний. Колонки R1 —
   в конце, аддитивно, как в TK-012.
3. **Один общий ключ `--set`:** `r1_<колонка>_min=<целое>` / `r1_<колонка>_max=<целое>` по таблице `R1_COLUMNS: [(имя,
   доступ)]` — вместо ~25 отдельных ключей (−2 ч кода и тестов). Кэш без колонок R1 → отказ, не молчаливый ноль (образец
   `--p08-cols`, `bounce_grid.rs:319`). Сторона: все «направленные» значения ориентированы **в пользу стены** (у бид-стены
   плюс = покупатели/бид-давление, у аск-стены знак зеркалится) — один порог работает на обеих сторонах.
4. **Память и горячий путь:** массивы фиксированной ёмкости, `i64`-лоты, без `f64`/карт/аллокаций на событие. Состояние
   монеты — `R1State` в трекере; состояние уровня — компактные кольца в `Live` (если замер даст > +1 % при выключенном флаге —
   в параллельную `SortedVec` под флагом).

## Что НЕ входит (с причинами) — решение Судьи/CEO по каждому

- **Г-72 (секундный лаг BTC→альт):** BTC нет в пуле, есть только минутные свечи (`study/regime/ref-BTCUSDT-1m.csv`);
  окно 16–118 с минутами не проверить. Нужен архив BTCUSDT ob за авг/сен — отдельное решение владельца.
- **Г-81 (резилентность после касания):** признак пост-входовый (10–20 с после t0) — как фильтр входа неприменим, как
  выход — R2 (нужна форма выхода).
- **Г-60 (калибровка дистанции по типичной сделке):** в R1 — только колонки `trade_size_p50/p90_15m` (фильтр режима);
  форма «дистанция = k × размер сделки» — R2.
- **Г-73 (композит OBI+OFI+автокорреляция):** композит = конъюнкция порогов `--set` по трём колонкам; отдельного балла нет
  (иначе изобретаем веса).
- Пересчёт кэша авг+сен(+июль), счёт `--cells` и протокол чтения — не мои (Исследователь, П-10); моя оценка пересчёта — 2 ч.

## Договор (В-156)

- **Сдам:** ветка с кодом R1 за флагом `--r1-cols`; бинарник `bin/alpha-<хеш>-v3` на Steam Deck; этот документ с таблицей
  колонок (имя → определение → гипотеза); тесты; лог гейта `docs/findings/tk025-gate-<дата>.md`.
- **Примут, если:** (1) `bash tools/vps-check.sh <дерево> all` — fmt, clippy `-D warnings`, все тесты зелёные; (2) флаг
  выкл.: кэш подходов (`touches-*`, `approaches-*`, `levels-*`) и `bounce-grid --cells` без R1-ключей за 03.08 (эпоха ob200) и
  20.09 (запись `.50`) — побайтно как у `bin/alpha-da42990-v3`; (3) флаг вкл.: старые колонки подходов побайтно прежние,
  новые — совпадают с независимым пересчётом на Python на сутках одной монеты минимум по 8 колонкам (лента 15 с/60 с, OBI5,
  OFI 60 с, отмены 60 мин, `since_far_ms`, `vpin_e2`, `sign_ac_60s_e2`), зеркальность бид/аск; (4) ключ `r1_…` на кэше
  без колонок — отказ с текстом; (5) скорость: флаг выкл. ≤ +1 % user-времени `lob touches` к `da42990-v3` на одной
  нагрузке, флаг вкл. — цифра в логе.
- **Не входит:** Г-72, Г-81, форма Г-60, композит Г-73 как балл (см. выше); пересчёт кэша, счёт, протокол чтения;
  R2; включение флага в боевой/ночной счёт.
