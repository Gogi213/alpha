# TK-402: почему спот-BBO TK-399 пуст у PEPE и обрезан у BONK (26.10)

Проба на calc (`/data/tk0402/dbg`, `/data/tk0402/dbg2`), бинарь `/data/tk0399/new/alpha-new`, сутки 16.10, `bin-spot/e-2026-10`.

- Бинлоги целы: PEPE 1 328 003 записей (12,1 МБ), BONK 605 169; `verify` ok, gaps=0; `binlog-stats` — книжные и сделочные ev есть.
- `lob seconds --bbo-events`: PEPE 0 строк, BONK 717 строк, последняя t_ms = 00:10:30,8 (дальше сутки пусты).
- `lob seconds` без флага (посекундный режим): PEPE `gap_secs=86400`, `trades=0`, mid=0 все сутки; BONK `gap_secs=85955`, trades=93 из ≈ 280 тыс. записей сделок. То есть дефект **не в `--bbo-events`**, а в чтении файла `feed_file` (`src/commands/lob/seconds.rs:440`, `:455`).
- Механизм: при `book.apply(up).is_err()` `feed_file` молча делает `break` и бросает остаток файла (`ok=false`, без счётчика и сообщения). `verify` на тех же файлах ошибок не видит (gaps=0) — расхождение путей применения; какая именно `ApplyError` (SequenceGap / PriceNotOnTick / QtyNotOnStep / Crossed) — не определена: нужна диагностика в коде (Инженер).
- Следствие: спот-BBO TK-399 неполон не только у PEPE/BONK — любая монета с ранней ошибкой применения обрезана молча. Охват спота (184 монеты) нужно сверить по числу строк/покрытию суток; FS-вердикты по таким монетам недействительны до пересборки.
- Нужно от Инженера: вывод `ApplyError` и позиции в `feed_file` (счётчик `dropped_files`/stderr), причина, исправление; затем пересборка спот-BBO по всем 184, FS + max-T.
