# TK-347: «Order id already exists» — причина, фикс, обход прошлых прогонов (22.10)

**Итог:** причина найдена и исправлена (tk347 `3fc3c831`), MYX 02-13 и 02-01 считаются, гейт «байт в байт» 02-05 identical.
Молчаливых потерь в прошлых прогонах **нет**: ошибка есть ровно в 5 единицах TK-345, все — известные MYX 02-01 / 02-13.

## Причина
Диапазон id ордеров варианта группы 12 был уже длинного выхода → id выхода залезал в соседний вариант
(«Order related to a given order id already exists», drive.rs:263). Фикс — диапазон `1<<20`.

## Обход прошлых прогонов (calc, alsched 1022112535136, rc 0, 99 каталогов `/data/*`, `/data/tk0347/scan3/`)
Шаблон `already exists` в `grid.log` / `fail*.txt` / `units.txt`; контроль (известное падение 02-13) найден — обход годен.
- **hits = 5**, все в `tk0345` (прогон валидности 1–14.02): `pass3` MYX 02-13 F1/F2/F3, `pass4` MYX 02-01 F2, `pass2` 02-01 s5 g2 F2.
- Других каталогов с этой ошибкой нет.
- Прочие fail-строки (830) — не эта ошибка: `tk064/pool/t1` 01-05/06 и `tk202/out/tol` 01-14 — CLI-ошибки (нет `--sigma-from`,
  неканоническое имя выхода), давно разобраны; `tk0345/val-cal` rc=143 — kill.
- **Отдельно: `tk0344/p24/fail-exitgroup-on.txt`** — 16 суток П-24 (2026-01-13, 02-13, 03-22, 04-16/18/21, 06-07…06-15, 06-23)
  упали при `--exit-group on` (повторный id ордера, review tk344-p24-run-fail). Текст ошибки в их `grid.log` не сохранился
  (каталоги суток пересчитаны), но симптом тот же. Они **не молчаливые**: `p24-fix.sh` (А/Б на 02-20: on == off) досчитал их с
  `EG=off`; сейчас в `run/<сутки>` — результат с `EG=off`. С фиксом 3fc3c831 их можно пересчитать с `on` — решает Судья (нужно ли).

## Что осталось
Слияние ветки tk347 (фикс + скрипт скана) в master — по гейту Судьи.
