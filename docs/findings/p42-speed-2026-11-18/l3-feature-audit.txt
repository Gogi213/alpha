3. CROSS-ROW COUPLING CHECKLIST (searched; result)
--------------------------------------------------
- rank / quantile / normalisation over the stream: none in the build. Quantiles exist only in the cut stage (retitr_ftab.py:106-113 quantile_cut; retitr_full.py:370-374 feature_cuts) - consumers, section 6.
- groupby / shift / diff / cummax / rolling over candidates: only groupby(level|sym) for iteration (retitr_ftab.py:193,219; tk594_feat.py:361); no shift/diff/cum across rows.
- first-occurrence / episode dedup: bypassed by the do_universe override (retitr_ftab.py:190-202) - candidate k never looks at candidate k-1.
- per-level state (since_born_h): row's own born (see above), not a stream structure.
- row drop / dedup / NaN filter: none. Left merges are one_to_one (retitr_ftab.py:266-270), assert len(tab)==len(sig) (:270), ep None -> NaN row (:198-200), duplicate (sym, sig_ms) in sigsx -> SystemExit
  (:263-264), write_ftab uniqueness (:68-70). NaN features pass the engine filter (ftab.rs; no_value).
- ordering: `i` (running index over (level, sig_ms)) and Pool.imap_unordered order only affect ep_id, a join key valid inside one build (retitr_ftab.py:228,266-268).
- stream-derived scalars: ONLY dmin/dmax per coin in tk594_feat.process_coin (:284). Effects: flow window start (no value effect, big1800 above) and the metrics window (loi_turn, section 4).
- randomness: none for emitted columns (controls RNG only for U1, sigfeat_run.py:303-304; U0 here).
- K. Row identity of a key. Engine rows are produced per (level, minute) candidate (tick.rs:551-611 signals_for_coin; no cross-level dedup); sigsx row = level, dist, lp, born, end, first_bar, natr, members
  (tick_cli.rs:152-183). Level list / born / members do not depend on the grid keys (levels.rs:167-169; the grid changes only sig.e_pm, natr_min_pm, t1h_u, t24_u among sig.* keys: params.rs:305-307,317).
  So a (sym, level, tick) triple yields the same row in every stream. But the key is only (sym, sig_ms): two levels (or two ticks in the same ms with different dist, changing k and hence tpm15/tpm60)
  can map to one key in different streams. The repo already records the phenomenon: retitr_ftab.py:301-305 ("у одной сделки (sym, sig_ms) бывают два уровня - ключ движка их не различает"), P-42:290 (CCUSDT).
  Inside one stream it is fail-stop (:263-264); across streams it is caught today only by merge_union value equality (retitr_full_run.py:319-321, exact: np.array_equal, equal_nan). Not measured how often it occurs.

4. loi_turn: MECHANISM AND SYNTHETIC EVIDENCE
---------------------------------------------
Gate: tk594_feat.py:242 `if first_row is not None and first_row <= Ts - DAY_MS:` guards oi_c1/oi_c4/oi_c24/loi_turn/ls_*; first_row = min create_time over the files of days d0..dmax that exist (:187,194-195), d0 = dmin - 2.
Full stream A and subset B (same key, dmin_B > dmin_A) differ only if first_B > Ts - 24h >= first_A. Ts - 24h >= (dmin_B - 1)*day - 10min, so first_B must be later than that: the metrics file of day dmin_B-2 is absent
(or starts after 23:50) AND the coin has earlier files (otherwise first_row = listing time in both). Variants: (i) file dmin_B-2 missing and the candidate in the first ~15 min of day dmin_B; (ii) files dmin_B-2 and dmin_B-1
both missing -> every candidate of day dmin_B. oi_c24 is immune (its own T*-24h row implies the gate); loi_turn needs only OIV at T* -> value in A, NaN in B.
No gap => file dmin_B-2 exists, first row <= (dmin_B-2)*day + 5min < Ts - 24h => gate true in both; coin listed inside the range => first_row = listing in both.
Synthetic run (REAL tk594_feat.deriv_features; load_metrics hand-emulated because pandas is broken on this PC; 5-min rows 00:00-23:55 on existing days; OIV const; turn24h = 5e6):
  scenario                          full stream {Y(D+2), X(D+7)}            subset {X}
  S2 no gap, X 00:20                oi_c24 1573.77 loi_turn -0.69897        identical
  S1 files D+5,D+6 missing, X 00:20 oi_c24 NaN     loi_turn -0.69897        oi_c24 NaN, loi_turn NaN   <- DIFF
  S3 file D+5 missing, X 00:05      oi_c24 NaN     loi_turn -0.69897        oi_c24 NaN, loi_turn NaN   <- DIFF
  S4 file D+5 missing, X 00:12      oi_c24 1575.49 loi_turn -0.69897        identical
  S5 files D+5,D+6 missing, X 12:00 oi_c24 NaN     loi_turn -0.69897        oi_c24 NaN, loi_turn NaN   <- DIFF
Fixes (prod code stays frozen): (P1a) data pre-scan: for each coin in the window, metrics day files contiguous from the first file to the window end (ls per coin dir under systemd-run); if no coin has a gap the
condition cannot trigger. (P1b) anchors: add to the subset sigsx, per coin with a missing key, the coin's EARLIEST stream candidate row (and optionally latest) -> subset dmin == stream dmin -> identical d0, first_row;
anchors are recomputed and compared by merge_union (retitr_full_run.py:319-321), giving the same fail-stop as today. Note the edge already exists between two FULL streams with different per-coin dmin (merge_union would stop) - L3 must not make it silent.

5. EXACT INPUTS TO COMPUTE FEATURES FOR AN ARBITRARY SUBSET OF CANDIDATES
-------------------------------------------------------------------------
(1) A sigsx CSV with the verbatim engine rows (all 10 columns: sym,level,sig_ms,dist_e8,level_px_e8,born,end,first_bar,natr_e8,members; header ignored, read by name list sigfeat_lib.py:108-114) of the MISSING keys,
    taken from THIS stream's own dump (sx/<w>/<vid>/<side>-sigsx.csv), not from another stream's dump (K). Row order, coin mix and level mix are free.
(2) L side only, if P1b is used: + the anchor rows above (their keys are already in the union; values must match).
(3) Window environment identical to the full build: --base-date = engine P42_T0 of that window (retitr_full_run.py:357); --cache = that window's cache80 incl. BTCUSDT.b42/ETHUSDT.b42 (Worker.__init__ loads them,
    sigfeat_run.py:65-72; SIGFEAT_DAYS = 80, retitr_ftab.py:49,178); --trades and TK594_TRADES = that window's aggTrades (needed days: sig-60min..sig+240min for the episode step, dmin-8..dmax for S flow);
    TK594_METRICS = metrics-all tree (L: days dmin-2..dmax); same PROD code (prod_md5 equal to the one that built the union).
(4) Fresh --work directory per subset: retitr_ftab.py:253 and :258-261 REUSE existing eps-*.parquet / tk594-*.parquet in --work; FtabStore.build_cmd points --work at ftab/<w>/<vid> (retitr_full_run.py:101,354),
    so a rerun with a different sigsx would join stale tables (misaligned ep_id numbering `i`, or silent NaN from the left merge :269). Key the dir by the subset hash or pass --force.
(5) Non-empty subset only: an empty subset or one where every row has ep None raises KeyError at retitr_ftab.py:265 (missing columns) and ValueError in tk594_feat.py:375 (pd.concat([])): skip the build, still mark ready.
(6) Cost note (inference, not measured): S `flow` reads/histograms every day in [dmin-8, dmax] per coin regardless of how many rows (tk594_feat.py:308-337; wa flow = 684 s, p42-speed-2026-11-18.md:33), so the saving
    scales with the number of coins and the span of the subset, not with the row count; the episode step scales with rows.
