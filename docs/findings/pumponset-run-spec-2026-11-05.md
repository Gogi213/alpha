# pumponset: слой `run` / `verdict` — интерфейс между кодом (TK-492) и счётом П-34 (TK-491) — 05.11.2026

Решение по форме (CEO-сессия 05.11): ядро (`cache`/`feat`/`episodes`/`control`) уже даёт куб, эпизоды, лаги, C2a/C2b. Недостающий слой —
**`run`** (проход по контрактам, потоковая агрегация в суточные ячейки, таблицы) и **`verdict`** (бутстрэп по суткам, Холм, отбор K, вердикты,
net). Связь между ними — только csv-файлы ниже: можно писать и проверять независимо. Чисел кроме параметров нет (`P-34-params.json`),
издержки — `crate::lob::costs`, расстояния в bps, зерно контролей — аргумент `--seed`, зерно бутстрэпа — `verdict.seed` файла параметров.

## Порядок (П-34 §5, §8)
1. `alpha pumponset run --stage fit …` — считает ТОЛЬКО минуты фита (2025); X_D из фита; пишет таблицы фита. Минуты 2026 не читаются в агрегаты.
2. `alpha pumponset verdict --stage fit …` — ранг правил, отбор K (≤ 10), пишет `k.json` и строку для `JOURNAL.md`. После этого 2026 открывается.
3. `alpha pumponset run --stage test --rules k.json …` — только замороженные K правил, минуты теста; X_D те же (из фита).
4. `alpha pumponset verdict --stage test --k k.json …` — вердикты подтв./оспорено/не различимо, net, «встать рано можно/не доказано», `report-tables.md`.

## Схемы csv (запятая, заголовок есть, числа с точкой, строки отсортированы по ключам — вывод детерминирован)
Ключ правила: `fam,wi,ti` — индексы `Rule` (`feat::rules`), `sign` = +1 памп / −1 дамп (знак `r_w` окна правила), `hi` — индекс в `label_forward.H_min`,
`di` — индекс в `episodes.D_min`, `day` — сутки UTC от 1970-01-01 (по `t_f`), `month` = yyyymm.

**`daycells-<stage>.csv`** — одна строка на (правило, sign, hi, day) с `n > 0 или nret > 0`:
`fam,wi,ti,sign,hi,day,month,n,hit,bn,bhit,nret,gross_bps,fund_bps`
- `n` — первые срабатывания с меткой Hit/Miss (NoData не считается), `hit` — из них Hit (`control::Label`); `bn`/`bhit` — то же по моментам C2a (пулом);
- `nret` — срабатывания, у которых определены `c[t_f+1]` и `c[t_f+H]`; `gross_bps` = Σ `sign·ln(c[t_f+H]/c[t_f+1])·1e4`;
- `fund_bps` = Σ фандинга, уплаченного позицией стороны `sign` за удержание (вход c[t_f+1], выход c[t_f+H]) по реальным ставкам файла (`Contract::funding`);
  положительное = издержка (лонг платит при rate > 0, шорт получает), в bps номинала.
- издержки входа/выхода НЕ вычитаются в таблице (они константы `lob::costs`) — их вычитает `verdict`.

**`lags-<stage>.csv`** — лаг-таблица §4 и полнота §7.3 (эпизоды и нулевая линия C2b):
`kind,stratum,fam,wi,ti,sign,di,month,n_ep,n_fired,n_lt0,n_le0,n_le30,n_le60,p10,p50,p90`
- `kind` = `ep` (эпизоды) | `c2b` (псевдо-моменты, `L_post'` = медиана длины фазы эпизодов страты); `month` — месяц `t0` (или `t'`);
- `stratum` = `all` (эпизоды без FLAG_WICK и без FLAG_OUTLIER) | `market` | `nonmarket` (разбиение `all` по FLAG_MARKET) | `outlier` (FLAG_OUTLIER, без FLAG_WICK) | `wick`;
- `n_ep` — эпизодов (моментов C2b), у которых правило НАБЛЮДАЕМО: в слотах окна лага (`[t0 − L_pre, t_end]`, для C2b `[t' − L_pre, t' + L_post']`) уровень правила определён хотя бы в одном слоте (нет `NaN` у признаков правила: не первые сутки/недели после листинга без нормы, не дыра OI) — П-34 §1, минуты без признаков в выборку не входят; ненаблюдаемые пары считаются в `run-meta.json` (`lag_observability`), в `first` и `progress` не участвуют; `n_fired` — с лагом; `n_lt0` — лаг < 0; `n_le0/30/60` — лаг ≤ δ (recall при δ = 0/30/60); `p10/p50/p90` — квантиль лага среди сработавших
  (точный, по отсортированным значениям, метод нижнего ранга `floor(q·(n−1))`); пусто, если `n_fired = 0`.

**`first-<stage>.csv`** — «какой признак первым»: для каждого эпизода и пары (wi, ti) — одиночное семейство (fam 0–8) с наименьшим лагом (ничья — меньший fam):
`kind,stratum,wi,ti,sign,di,fam,n_ep,n_first` (`n_ep` — эпизодов, у которых хоть одно из 9 семейств сработало, `n_first` — где первым был `fam`).

**`progress-<stage>.csv`** — «сколько хода уже прошло / осталось» (§7.1–7.2), по эпизодам и правилам с лагом:
`stratum,fam,wi,ti,sign,di,month,n_fired,done_bps_p10,done_bps_p50,done_bps_p90,left_share_p10,left_share_p50,left_share_p90,to_peak_bps_p10,to_peak_bps_p50,to_peak_bps_p90`
- `done_bps` = `sign·ln(c[t_f+1]/c[t0])·1e4`; `left_share` = `ln(c[t_end]/c[t_f+1])·sign / (ln(c[t_end]/c[t0])·sign)` (доля хода, оставшаяся после входа; может быть < 0 и > 1 — не обрезать);
  `to_peak_bps` = `sign·ln(c[t_end]/c[t_f+1])·1e4` (ход до пика с момента входа; это ВЕРХНЯЯ граница, пик известен задним числом — в вердикт не входит).

**`episodes-<stage>.csv`** — все эпизоды: `sym,di,sign,t0,t_end,mv,flags,x_d` (t0/t_end — минуты, `mv` — ln-ход) — для проверки по v11 и ответов «где был памп».
**`xd.csv`** — `di,sign,x_d,n_windows` (порог из фита).
**`run-meta.json`** — `stage, params_sha256, seed, oi_lag_slots, contracts, symbol_days, episodes, triggers, secs_total, secs_by_phase, peak_rss_mb, git_head`; блоки `universe` (снятые контракты, эпизоды, теряемые правилом `d − 1`), `lag_observability` (`{kind: {страта: {pairs, unobserved}}}` — пар (эпизод | момент C2b, правило) и из них ненаблюдаемых) и `funding_coverage` (`trades` — сделок в `nret`; `trades_uncovered` (всего и `trades_uncovered_by_h`) — сделок с ценами, но без покрытия фандинга окна удержания: в `nret` не входят; `contracts_with_uncovered`). Покрытие фандинга: первая ставка файла не позже `t_f + 1` и последняя не раньше `t_f + H − G`, `G` — наибольший интервал между соседними ставками этого файла; пустой файл — «нет данных». Эпизоды `ref_symbol` (BTCUSDT) помечены `FLAG_MARKET`.

**`triggers-<stage>.csv`** — только с `run --dump-triggers` (без флага прогон и остальные таблицы прежние байт в байт; код — `src/pumponset/dump.rs`).
Одна строка на ПЕРВОЕ срабатывание правила прогона (для `fit` без `--rules` — все правила, для `test` — K) и сторону `sign ≠ 0` в периоде стадии и вселенной — то же множество,
что даёт `daycells` (строк по (правило, sign) не меньше `Σ n` по `daycells` для любого `hi` и равно ему для `hi`, где метка определена; у края данных метка `NoData` в `n` не входит, строка остаётся).
Порядок: контракт по алфавиту, затем `t_f`, затем `fam,wi,ti,sign`; байты не зависят от `--threads`. Пусто/нет данных — `NaN`. Столбцы:
- ключ: `sym,fam,wi,ti,sign,t_f` (минута от `GRID0_MS`), `day` (сутки UTC от 1970-01-01), `month` (yyyymm);
- время: `hour_utc,minute_of_hour,dow` (0 = понедельник), `min_since_day`, `min_to_fund8` / `min_since_fund8` (отметки фандинга 00:00/08:00/16:00 UTC; в саму отметку: до — 480, от — 0);
- круглые числа (`p = c[t_f+1]`, расстояние до ближайшего по `|ln(L/p)|` уровня, bps, положительное — уровень выше цены, ничья — нижний): `d_dec` (уровни `10^k`), `d_half` (`{1,5}·10^k`), `d_125` (`{1,2,5}·10^k`);
  `pk_d_*` — то же для цены в точке `mfe` (у шорта это минимум цены);
- волатильность (по `close_ff`; high/low лежат в кэше с версии PMC2, в этих столбцах не используются — NATR только в `play.rs`): `rv60_bps`, `rv1440_bps` = `√Σ(ln c[j]/c[j−1])²·1e4` за последние 60 / 1440 минут по `t_f` включительно; `rng1440_bps` = `ln(max/min)` close за 1440 минут;
  `sigma_h_bps` = `cube.sigma` слота `t_f` · `√60` · 1e4 (σ 1 м за `sigma_1m_window_days`); окно не лежит целиком в данных — `NaN`;
- контекст: `ret_prev60_bps`, `ret_prev360_bps` (`ln(c[t_f]/c[t_f−w])·1e4`, без знака стороны), `drop360_bps` (`ln(c[t_f]/max close за 360 минут)·1e4 ≤ 0`), `ep_running` (`TriggerRow.in_episode_running`; концы эпизодов находятся
  задним числом — единственный столбец атрибутов, не подчинённый правилу «только данные ≤ t_f»), `age_days` (от первой свечи контракта), `qv1440_usd` (Σ quote_v за 1440 минут), `btc_prev60_bps`,
  `btc_next360_bps` (`ref_symbol`; второй — контекст исхода от `t_f+1` до `t_f+361`, не признак; нет BTC — `NaN`);
- исходы (вход `c[t_f+1]`, знаковые, bps): `gross_5…gross_1440` = `sign·ln(c[t_f+1+H]/c[t_f+1])·1e4` для H = 5, 15, 30, 60, 120, 240, 360, 720, 1440; `mfe_bps`/`mae_bps` и минуты от входа `mfe_min`/`mae_min`
  (первая из равных) за путь `e…e+1440` включительно (в `mfe` минута входа = 0), `mfe_price`; путь не лежит целиком в данных — `mfe_*`, `mae_*`, `mfe_price` = `NaN`;
- база: `b_gross_60/360/1440` — среднее `sign_m·ln(c[m+1+H]/c[m+1])·1e4` по моментам C2a этого срабатывания (`sign_m` — знак `r_w` в моменте; моменты без цен выхода не входят; моменты лежат в том же месяце и дециле σ
  и могут быть позже `t_f` — это база исхода, не признак).

## `verdict` (читает только csv + `P-34-params.json`)
- Ранг фита (§5, Р-3): для каждого правила — нижняя граница 95 % lift точности при H = 360 (бутстрэп по суткам, B = `verdict.bootstrap_B`, seed = `verdict.seed`), среднее по двум знакам;
  в семействе — лучшее правило (ничья: меньший θ, меньший w), из 11 семейств — 10 лучших → `k.json` (`[{fam,wi,ti,rank_lo,...}]`) и строка для JOURNAL. Правило замораживается на оба знака.
- Тест: на каждое (правило ∈ K, sign, H ∈ `label_forward.H_min`) — precision, база C2a, lift, интервал, p (односторонний, доля реплик lift ≤ 1), Холм по m = `trials.test_lift_m` (60);
  доля месяцев теста с lift > 1; вердикт подтв./оспорено/не различимо по §5. Net (H = 360 основной, 90 и 1440 описательно): `gross − 2·leg_fee_bps(true) − fund`, второй вариант `ROUNDTRIP_FEES_BPS`,
  нижняя граница 95 % (бутстрэп по суткам), Холм по m = `trials.test_net_m` (20), безубыточное проскальзывание = средний net при нулевом проскальзывании (в bps, число не назначается).
  Итог «встать рано можно»/«не доказано» — правило §7.6.
- Чувствительность: кластер «монета×сутки» — описательно (`verdict.cluster_sensitivity`). Описательно: recall из `lags` (δ = 0/30/60), доля `n_lt0`, «какой признак первым» как РАЗНОСТЬ долей `ep` − `c2b`.

## Выходы в прибыль (П-35, `docs/research/P-35-exits.md`) — флаг `run --exits`, стадии `verdict --stage exits-fit | exits-test`
Без `--exits` поведение и все таблицы выше прежние; с флагом основные таблицы те же байт в байт, дополнительно пишутся `exits-<stage>.csv`, `exits-grid.csv` и блок `exits` в `run-meta.json`. Код — `src/pumponset/exits.rs` (сетка и проход по минутам), `verdict/exits_stage.rs` (вердикт), тесты `exits_tests.rs`.
Порядок: `run --stage fit --exits --rules k.json …` → `verdict --stage exits-fit --k k.json …` (выбор выхода, `exits-k.json`, строка в JOURNAL.md до открытия 2026) → `run --stage test --exits --rules k.json …` → `verdict --stage exits-test --k exits-k.json …`. `--rules` — K из `k.json` фита П-34 (без него в фите считаются все правила: память на поток ≈ 5,8 КБ × правил × 2 × суток периода).

**Модель.** Вход как в П-34 (`c[t_f+1]`, сторона `sign`, тейкер). Минуты пути `j = k − (t_f+1) ≥ 1`, `pnl_j = sign·ln(c[t_f+1+j]/c[t_f+1])·1e4`. Решение по close минуты `j`, исполнение по `c[j+1]`; предел `cap` — по `c[cap−1]` (минута `t_f + cap`, как `H` в П-34: конфигурации «только cap» = `H = cap` из `daycells` до бита). Решение на минуте `cap−1` уже не принимается — предел приоритетнее. В одну минуту стоп приоритетнее тейка и трейлинга (по close тейк и стоп в одну минуту невозможны; стоп и трейлинг — возможны). Трейлинг активен с первой минуты `pnl ≥ R`; выход при `pnl ≤ pnl_max − R`.
**Набор сделок по `cap`** = те, что берёт `trade::round_trip(…, H = cap)` (цены входа и минуты предела есть, фандинг покрывает окно): `n` у всех конфигураций в bps (базовая линия, семейства A и B) с одним `cap` одинаков и равен `nret` из `daycells` для `H = cap`; у семейств C и D (единицы ATR-прокси) `n` может быть меньше — в них входят только сделки с определённой A. Фандинг — за фактическое удержание `(t_f+1, минута выхода]` (те же границы и знак, что `trade.rs`).
**Сетка** (140 конфигураций, нумерация стабильна — первые 84 не менялись, записана в `exits-grid.csv`): 0–1 «только cap» (360, 1440); 2–51 семейство A (тейк `G` ∈ {100,200,300,500,1000} × стоп `S` ∈ {100,200,300,500,нет} × cap), порядок `G → S → cap`; 52–83 семейство B (трейлинг `R` ∈ {100,200,300,500} × `S` ∈ {100,300,500,нет} × cap), порядок `R → S → cap`. Семейства в единицах ATR-прокси (A = `sigma_h_bps` на `t_f`, close-to-close прокси ATR; `src/pumponset/exits.rs`, допущения 8–10; П-35 «Семейства в единицах ATR-прокси») идут после этих 84: 84–115 семейство C «tpa» (тейк `G` ∈ {1,2,3,5}·A × стоп `S` ∈ {1,2,3,нет}·A × cap, порядок `G → S → cap`); 116–139 семейство D «tra» (трейлинг `R` ∈ {1,2,3}·A × `S` ∈ {1,2,3,нет}·A × cap, порядок `R → S → cap`). Всего 140.

**`exits-grid.csv`** — `cfg,family,G,S,R,cap,unit` (`family` = base|tp|trail|tpa|tra; `unit` = bps|atr — последняя колонка; `S = none` — стопа нет; `G`/`R` пусты там, где не применимы; у `tpa`/`tra` `G`/`S`/`R` — множители A с точкой, `2.0`).
**`exits-<stage>.csv`** — одна строка на (правило, sign, cfg, сутки) с `n > 0`, строки отсортированы по `(fam, wi, ti)`, sign (+1, −1), cfg, сутки:
`fam,wi,ti,sign,cfg,day,month,n,gross_bps_sum,fund_bps_sum,hold_min_sum,n_tp,n_sl,n_trail,n_cap,mfe_bps_sum,mfe_min_sum,mfe_cap_bps_sum,mfe_cap_min_sum`
- `gross_bps_sum` — Σ `sign·ln(c_выхода/c_входа)·1e4`; `fund_bps_sum` — Σ фандинга за удержание (положительное = издержка); `hold_min_sum` — Σ минут от входа до выхода; `n_tp + n_sl + n_trail + n_cap = n`;
- `mfe_bps_sum` — Σ максимума `pnl_j` по `j ≥ 1` в окне самого длинного cap (`j ≤ 1439`, до конца данных, если ряд короче); `mfe_min_sum` — Σ минут максимума от входа (первая при равных); `mfe_cap_*` — то же в окне собственного cap. Потолок задним числом — не стратегия.
- издержки входа/выхода НЕ вычитаются (константы `lob::costs`) — их вычитает `verdict`.
**`run-meta.json` → `exits`** — `configs, configs_bps, configs_atr, caps, rules, triggers, trades_by_cap, uncovered_by_cap, nodata_by_cap, atr_unit, atr_undefined, atr_undefined_by_cap, atr_trades_by_cap, secs` (`atr_undefined` — сделки без определённой A, исключённые из семейств C и D).

**`verdict --stage exits-fit`** (`--k` = `k.json`): net на сделку = `(Σ gross − Σ fund)/n − 2·leg_fee_bps(true)`; бутстрэп по суткам (B и seed из параметров); для каждой пары (правило ∈ K, sign) выбирается конфигурация с наибольшей нижней границей 95 %, ничья — меньший cap, затем конфигурация в bps раньше конфигурации в единицах A, затем меньший S (нет — наибольший), затем меньший номер. Выбор по всем 140 конфигурациям. Пишет `exits-k.json` (пары → cfg, `unit`, множители с точкой у семейств C и D, `best_by_group`), `exits-verdict-fit.csv` (все ячейки), `exits-verdict-fit-groups.csv` (лучшая в группах fixed/atr/tp/trail/tpa/tra по каждой паре), `exits-journal-line.txt`. Сетка `exits-grid.csv` прежней версии (84 конфигурации, без `unit`) отвергается — таблицы пересчитать. Месяц вне `split.fit` — отказ.
**`verdict --stage exits-test`** (`--k` = `exits-k.json`): по замороженным парам net, нижняя граница, односторонний p (net > 0), Холм по `trials.test_net_m` (20), доля месяцев net > 0 (знаменатель — все месяцы `split.test`), второй вариант издержек `ROUNDTRIP_FEES_BPS`, безубыточное проскальзывание, причины выхода, среднее удержание, доля mfe. Итог «выход в прибыль найден» по паре = нижняя граница > 0, p-Холм < 0,05, месяцев net > 0 не менее 2/3; пампы и дампы — отдельные итоги, иначе «не доказан» с названием, что не сошлось. Пишет `exits-verdict-test.csv`, `exits-verdict-test-grid.csv` (все 140 конфигураций по каждой паре, описательно, без Холма), `exits-verdict-test-groups.csv` (лучшие на фите в группах fixed/atr/tp/trail/tpa/tra, оценка на тесте), `report-exits-tables.md` (раздел 3 — fixed против atr, разность `atr − fixed`; без `best_by_group` в `exits-k.json` раздела нет). Строки после конца `split.test` отбрасываются (число — в отчёт), раньше начала — отказ.

## Выборка «монеты в игре» (слова владельца 05.11) — флаги `run`, код `src/pumponset/play.rs`
Владелец 05.11 (дословно): «такие лонги не должны быть в выборке. это не пампы а откупы после события какого то»; «убери мусор из монет типа crv, ldo, btc, eth, ltc и все прочее у чего не было высокой волатильности, или что является тяжем. я думаю что то что мы ищем - мы ищем не предпамп - а первую фазу монеты инплей»; «для меня нижний порог высокой волатильности это натр за 30 1м периодов >=1». Без флагов прогон и все csv прежние байт в байт; числа порога и окна задаёт запуск, в коде их нет (кроме `D = 360` для откупа — из ТЗ).
- **Кэш `.pmc` версии 2** (`PMC2`): к минутным столбцам добавлены `high`, `low` (`f32`, `NaN` в минуте без сделок/в дыре; `parse_candles` читает колонки `h`, `l` с проверкой как у цен). Файлы `PMC1` читаются с ошибкой «кэш старого формата, пересоберите», `is_stale` считает их устаревшими — `alpha pumponset cache` пересобирает.
- `--hv-natr-pct <порог, %>` и `--hv-n <свечей>` (только вместе): `hv_state[m] = NATR1_n(m) ≥ порога`. `NATR1_n` — определение проекта (`tools/compute/tk435-vol.py`): `TR_m = max(h − l, |h − c_{m−1}|, |l − c_{m−1}|) / c_m · 100` для минуты `m` со сделками (`c_{m−1}` — предыдущий `close_ff`; в `tk435-vol.py` после минуты без сделок берётся `h − l`, здесь гэп считается от последнего close); среднее `TR` по свечам окна `[m − n + 1, m]`, если свечей не меньше `max(1, n / 2)` (целочисленное деление), иначе `NaN`; окно целиком в сетке контракта. `NaN` → `hv_state` ложь.
- `--no-reversal`: откуп. `X_360` — порог хода класса `D = 360` из `xd` (в `episodes.D_min` должно быть 360, иначе ошибка до счёта), `L_pre = onset.L_pre_min`. `ok_long[m]` ложь, если `ln(max close_ff за [m − L_pre, m] / c_m) ≥ X_360` вниз (перед моментом было падение класса «дамп 360»); `ok_short[m]` ложь, если `ln(c_m / min) ≥ X_360` вверх. Окно не целиком в данных — нет свидетельства, `ok` истина. Лонг — `r_w > 0`, шорт — `r_w < 0`, знак 0 условием не режется.
- `--hv-first-phase` (требует `--hv-natr-pct`): `hv_state` не было ни в одной минуте `[m − L_pre, m − 1]`, а в `m` есть — минута перехода в игру (дословно по ТЗ). Следствие: срабатывание внутри уже идущего «игрового» отрезка первой фазой не считается, на сетке 5 мин условие держат только срабатывания точно на минуте перехода (`triggers_dropped_first_phase`).
- **Где применяется:** (а) первые срабатывания — минута `t_f` обязана иметь `hv_state`, `ok_dir(знак r_w)` и (с флагом) первую фазу (там же, где период стадии и вселенная; «первое» определяется до отбора); (б) контроли C2a (маска `cube.r`) и C2b (условие на кандидата в пуле, знак — знак эпизода) берут моменты только из «игровых» минут — тот же набор условий; (в) эпизод — член выборки, если `hv_state` есть хотя бы в одной минуте `[t0, t_end]` (по факту — конец эпизода известен задним числом) и `ok_dir(знак)` в `t0`; (г) `--exits` и `--dump-triggers` берут те же срабатывания. `X_D` считаются как прежде по вселенной фита без фильтра. Порядок учёта потерь: волатильность → откуп → первая фаза (по первому невыполненному условию).
- **`run-meta.json` → `sample_filter`** (только с флагами): `hv_natr_pct, hv_n, no_reversal, first_phase, reversal_d_min, x360_up, x360_down, contracts_eligible, contracts_with_hv, hv_minutes_share, episodes_before_filter, episodes_dropped_hv, episodes_dropped_reversal, triggers_before, triggers_dropped_hv, triggers_dropped_reversal, triggers_dropped_first_phase`. `hv_minutes_share` — доля минут с `hv_state` среди минут периода стадии во вселенной по всем подходящим контрактам; `contracts_with_hv` — контрактов хотя бы с одной такой минутой.
- **`sample-coins-<stage>.csv`** (только с флагами): `sym,minutes_in_universe,minutes_hv,triggers_kept,episodes_kept` — по каждому подходящему контракту (по алфавиту): минут периода во вселенной, из них с `hv_state` (без `--hv-natr-pct` — все), оставшихся первых срабатываний (по всем правилам прогона) и эпизодов-членов.
- **`triggers-<stage>.csv`** (с `--dump-triggers` и флагами): к строке добавлены `natr_pct` (NATR в `t_f`, `NaN` без `--hv-natr-pct`), `ok_long`, `ok_short` (1, если `--no-reversal` не задан), `first_phase` (минута перехода, 0/1; 1, если нет `--hv-natr-pct`). Без флагов схема прежняя.

## Цель `play-onset` — «первая фаза монеты инплей» (слова владельца 05.11) — флаг `run --target play-onset`, код `src/pumponset/play.rs`, `control.rs`, `run.rs`
Владелец 05.11 (дословно): «мы ищем не предпамп - а первую фазу монеты инплей»; порог высокой волатильности — «натр за 30 1м периодов >=1». **Зачем.** В прежней постановке (`--hv-natr-pct` без цели) срабатывание обязано быть в `hv_state` («монета уже в игре»), а контроли C2a берутся из игровых минут той же монеты и месяца — часто из того же самого хода. lift тогда меряет «лучше ли сигнальная минута, чем другая минута того же игрового хода», а не «предсказывает ли сигнал вход в игру»; режим `--hv-first-phase` («переход именно в этой минуте») оставляет почти ничего. `play-onset` задаёт честную постановку. Без `--target` (или `--target move`) прогон и все csv прежние байт в байт (проверено сверкой SHA-256 с коммитом до правки, `play_tests::default_target_tables_equal_the_pre_onset_golden`).
- **Флаги.** `--target play-onset` требует `--hv-natr-pct` и `--hv-n`; с `--no-reversal` и `--hv-first-phase` несовместима (отказ до счёта: монета тихая, откупа нет; «минута перехода» противоречит тишине). Числа задаёт запуск; единственные числа из ТЗ — `L_quiet = onset.L_pre_min` (из params) и окно 1440 мин для `lead_hv_min`.
- **(1) Квалификация срабатывания — тишина.** Минута `t_f` тихая, если `hv_state` ложь в каждой минуте `[t_f − L_quiet, t_f]`. «Первые» срабатывания определяются как прежде (нет срабатывания в предыдущие `L_pre`), затем отбираются тихие; счётчик — `triggers_dropped_not_quiet`. Минуты вне сетки контракта и с неопределённым NATR — не `hv_state`. Используются только данные `≤ t_f`.
- **(2) Метка вперёд** вместо «ход ≥ `X_D`»: `Hit(H)` — `hv_state` истинно хотя бы в одной минуте `[t_f + 1, t_f + H]` (`H` — каждое из `label_forward.H_min`); `Miss` — нет; `NoData` — окно не целиком в сетке контракта. Не зависит от направления; `sign` (знак `r_w` окна) остаётся для стороны сделок, выходов и разбивки `daycells`; срабатывание со знаком 0 — как раньше (без строки `daycells`, `triggers_no_sign`). `X_D` в метке не участвуют.
- **(3) Контроли C2a** — моменты той же монеты, месяца и дециля σ, тоже тихие, и окно `[m − L_quiet, m + max H]` не пересекает `[t_f − L_quiet, t_f + max H]` срабатывания, т. е. `|m − t_f| > L_quiet + max H` (при `max H = 1440` и `L_quiet = 360` — ±1800 мин). Это единственное новое правило отбора. Число кандидатов пула, попавших в зону (сумма по срабатываниям), — `controls_dropped_overlap`. Зерно потока то же, что без зоны. C2b не используется; `lags-<stage>.csv`, `first-<stage>.csv`, `progress-<stage>.csv` пишутся **только с заголовком**, `c2b_moments` = 0 (verdict читает их пустыми).
- **(4) Выгрузка** (`--dump-triggers`): после `natr_pct,ok_long,ok_short,first_phase` добавлен столбец `lead_hv_min` — минут от `t_f` до первой минуты `hv_state` в `[t_f + 1, t_f + 1440]`, `NaN`, если её там нет (в том числе у края данных). Исход, а не признак момента. Выходы (`--exits`) и выгрузка берут те же срабатывания; вход `c[t_f+1]` — до воспламенения.
- **(5) Вывод.** `daycells` и `verdict` — те же схемы: `n/hit` — срабатывания и воспламенения, `bn/bhit` — контроли; lift = precision / база C2a. `episodes-<stage>.csv` и `xd.csv` — как без флагов (эпизоды ищутся по `X_D` как прежде, фильтр выборки к ним не применяется). `sample-coins-<stage>.csv` и блок `sample_filter` пишутся (`episode_hv` = «не применяется»).
- **`run-meta.json` → `play_onset`:** `l_quiet_min, h_min, triggers_before, triggers_dropped_not_quiet, controls_dropped_overlap, hv_first_cross_share, hv_first_cross_found, hv_first_cross_known, lead_max_min` и пояснения (`label`, `controls`, `no_reversal`, `c2b`). `hv_first_cross_share` = `found / known` — доля оставленных срабатываний с направлением (строки правило × `t_f`), после которых первая минута `hv_state` наступила за 1440 мин, среди срабатываний с известным исходом (наступила либо окно `[t_f + 1, t_f + 1440]` целиком в данных); `null`, если известных нет. Название поля в ТЗ не определено — выбрано это чтение.
