# Архивация закрытых суток: сколько реально даёт сжатие (2026-09-15)

Вопрос владельца: «можем предыдущие дни архивировать или сжимать как-то ещё, чтобы в два раза
экономнее было».

## Замер

Взял боевой файл `ARBUSDT-2026-09-15.binlog` (18.44 МБ на диске, 4278 кадров, 4 026 804 записи),
распаковал тела кадров и измерил варианты (`examples/archive_probe.rs`; сильные кодеки — на сервере
через `zstd`/`xz`).

| вариант | размер | % от файла на диске | время |
|---|---|---|---|
| файл как есть (zstd-1 по кадрам) | 18.44 МБ | 100 % | — |
| **сжать файл ещё раз** (наивно) | 18.44 МБ | **100.0 %** | — |
| распакованные тела кадров (сырьё) | 24.20 МБ | 131 % | — |
| архив одним потоком, zstd-1 | 18.02 МБ | 97.7 % | 0.8 с |
| архив одним потоком, zstd-9 | 17.63 МБ | 95.6 % | 1.5 с |
| архив одним потоком, zstd-19 | 17.02 МБ | **92.3 %** | 15.1 с |
| zstd `--ultra -22 --long=27` | 17.00 МБ | 92.2 % | 13.0 с |
| **xz -9e** | 16.50 МБ | **89.5 %** | 15.5 с |
| round-trip | — | распакованное совпало байт-в-байт | |

`brotli` на сервере не установлен; xz здесь — представитель класса «сильных» кодеков, brotli обычно
между zstd и xz.

## Что это значит

1. **Повторное сжатие готового файла не даёт ничего**: внутри уже zstd-кадры, данные нежмущиеся.
2. **Архивация (распаковать + сжать одним потоком сильным кодеком) даёт 8–11 %**: zstd-19 — минус
   7.7 %, xz-9e — минус 10.5 %. Двукратной экономии тут нет и быть не может: формат уже кодирует
   цену и размер дельтами, остаточная энтропия — в самих размерах, и никакой кодек её не уберёт.
3. **Цена**: xz-9e — 15 с на 24 МБ, то есть около **1.5 часа процессора на сутки данных** (в 100
   монетах ~6.8 ГБ). Офлайн это терпимо, но это не бесплатно.
4. Сейчас zstd-1 по кадрам уже сжимает 24.2 МБ сырья в 18.44 МБ — то есть 24 % экономии даётся
   «бесплатно» на живом пути; сильный кодек добавляет ещё 8–10 процентных пунктов.

## Где реально берётся «в два раза»

Не в сжатии, а в том, **сколько суток лежит на сервере**. Сервер с 3 сутками вместо 7 — это
**в 2.3 раза меньше занято** при том же потоке. То есть «архивировать предыдущие дни» правильнее
понимать как «выгружать закрытые сутки с сервера и удалять после `verify`», а сжатие архива —
опциональная надстройка над выгрузкой (минус 8–11 %, если место или канал дороги).

Настоящие 2× по размеру самих данных достижимы только сокращением записи (замер
`docs/findings/depth-distribution-2026-09-15.md`: фильтр «ближе 25 bps» срезал бы 0.7 % у LSK,
20 % у DOGE и 64 % у тихой CYS) — это решение о данных, а не о кодеках, и оно отложено осознанно.
