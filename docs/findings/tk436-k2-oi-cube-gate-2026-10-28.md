# TK-436 — гейт K2 (OI у пика): куб против tk433-oi.py, ошибка E-007

Вход: v10 e15 сентября (`/data/tk433/e15/end-start-th15.csv`, 1350 id, 669 с K2). «Было» — `tk433-oi.py` (разбор csv.gz по инструменту),
«стало» — `tk436-vec.py oi` (срез OI-куба 5 мин). Задание calc 1028024142880 (выход `/data/tk0436/oigate/`).

| | было | стало |
|---|---|---|
| время (1350 id) | 1,64 с | 0,14 с (×11,4; открытие куба 0,00 с, срезы 0,01 с) |
| K2_pre/K2_post строки «%.6g» | — | **0 расхождений из 1350 id** (669 с K2) |

**Находка E-007.** Первая сверка дала 15 расхождений из 669 — все Gate futures_usdt (654 Bybit linear равны). Причина в старом
`tk433-oi.py`: `q = ln.split(",", 2); v = float(q[1])` — у Bybit колонка 1 = `open_interest`, у Gate колонка 1 = `lsr_taker`
(заголовок Gate: `t_ms,lsr_taker,lsr_account,…,open_interest,…`). K2 у Gate-событий в прежних выходах TK-433 (v10, e15)
считалась по отношению long/short, а не по OI (пример E60-504 AIN_USDT: старое −0,383807 post = lsr_taker; OI-значение −0,00715553).
Куб берёт канал по имени (`open_interest`) — верно. Исправление: `tk433-oi.py` читает колонку по имени `open_interest`; с ним
«было» == «стало» побайтно. Выходы TK-433 по K2 для Gate futures (15 id в e15; в других T/месяцах — сколько Gate-событий, столько)
нужно пересчитать; Bybit linear не затронут.
