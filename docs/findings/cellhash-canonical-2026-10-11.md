# Канонический хеш клетки Летописи (TK-186, В-213/В-224), 11.10

**Итог:** одна функция `tools/registry/cellhash.py::cell_hash(cfg)` = sha256[:16] нормализованного ПОЛНОГО конфига клетки
(логика, вход, стоп, тейк, дедлайн, ttl, early, форма выхода, набор фильтров, σ, исполнение: латентность/очередь/h3/hold-step/busy-skip, вариант R1/R2).
Происхождение (группа, источник, имя набора, путь σ) в хеш не входит. Данные не пересчитывались.

**442 клетки Летописи → 428 канонических** (таблица `cellhash-map-2026-10-11.csv`: старый id; хеш; источник конфига; форма; набор; прогон).
13 групп совпадений (27 клеток = 14 лишних): B1 посчитана трижды под тремя именами (`p12-r1/B1`, `p12-ext/<B1>`, `r3c/e106-pop`) → 1 хеш;
12 пар p05 (`p05-b/p05-fX-uY` = `p05-c/p05-fX-a120-uY`, TK-040 посчитал одну клетку дважды). В прежних id, построенных по «форма+набор», этого не видно.

**Откуда конфиг.** Пул TK-040 (243): имя формы + шапка группы (`hdr_*`, rtt, queue, h3); у p05 признаки набора (age мин, flow %, usd тыс.) — из имени набора
(шапка хранит только первый набор группы). Остальные 199 (TK-182/183): имя формы + набор B1 `t-bid-btc4h-q1` (P-10 §4) + вариант (`p12-cells`: family, axes; R1 — признак+квантиль из имени клетки, порог — расширяющееся окно).
**Допущения (проверить Судье):** (1) p05: `aNN` = минуты, `uNNk` = тыс. USD, `fX_Y` = flow % — вывод из совпадения a45=2700 с (B1) и `hdr`, командных файлов p05 в репо нет; (2) пул TK-040 — busy-skip `on` (умолчание команды, в шапке поля нет), 199 новых — `off` (P-12, closes portfolio-sim) ⇒ B1 пула и B1 П-12 — РАЗНЫЕ хеши; (3) исполнение 199 новых = стандарт В-68 (4,2/3,98/5,65 мс, prob:3, Notional) — как у B1 пула.
