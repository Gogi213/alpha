## 4. Что не сделано и оговорки

- **Первая половина G6** (`bench --digest` против `statarb-tk479-f27c879e` на 50 длиннейших панелях Bybit) не гонялась: `bench` и его хеш-приёмник не менялись, но сверка не выполнена.
- **PGO не применялась** (см. §1): для боевых волн по В-32 нужна PGO-сборка и гейт «байт в байт» против этого бинаря.
- **MTM — итог по клетке, а не по суткам**: `mtm_*` — суммы по заданиям; суточного разреза нет (если для блочного бутстрапа потребуется «на последние сутки окна», добавить отдельным шагом). Для корзин оценка по последнему close каждой компоненты; `check_run_ext.py` корзины не проверяет (проверено юнит-тестом).
- **Фандинг и оценка**: выплаты накапливаются до конца окна, цена для выплаты в дыре — последний известный open (правило ядра), а оценка ноги — по последнему close, поэтому у контракта, замолчавшего раньше конца окна, фандинг может начисляться дольше, чем действует цена оценки. `mtm_stale_max_min` показывает давность самого старого close.
- **Cross только с β фиксированным** (по умолчанию 1, `--beta-fixed`): OLS-β между биржами для разных активов не поддержан (pair/basket читают одну папку). План (§4.2) этого не требует: пары «один актив».
- **`fill_x` только при `--delay-x ≥ 1`**: потребителям читать столбцы по заголовку, не по номеру (как делает `check_run_ext.py`).
- **Нарезка по суткам**: дыра внутри суток режется только NaN-маской, которой в `convert` нет. На Deck в панели Binance `BTCUSDT` дыры 28–30.10 нет (50 400 минут, 0 NaN) — продемонстрировать нарезку на настоящей дыре не удалось; механика проверена тестом и разрезом реального периода на два сегмента (до 2492 и с 2495: 4965 и 977 сделок, открытых на конце 31 и 24).
- **Сборочные следы**: на VPS пересобран общий `shared-target` крейта `alpha` (следующая чужая сборка один раз перекомпилирует, ~75 с); мои каталоги `wave2-src-xdl9run1-*`, архивы и временные бинарники удалены, свободно 24 ГБ. Чужой `wave2-src-tk492b-186104` не трогал. На Deck `~/xdl9/runx/` — только скрипты и маленькие списки заданий (32 КБ); большие выходы проверок удалены, их воспроизводит перечень выше.
- **`tests.rs`**: единственное изменение — `run_panels_dir` стал `pub(super)` (общий помощник).
