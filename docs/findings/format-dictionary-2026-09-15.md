# Словарь zstd против чистого zstd-1 — замер на живых файлах (2026-09-15)

Вопрос: даёт ли обученный словарь zstd меньше байт на кадр. Это последний из «дешёвых» рычагов по
байтам после того, как колоночная раскладка дала всего 3–7 % (`format-columnar-2026-09-15.md`).

## Как измерялось

Черновой прототип `examples/dict_probe.rs` (только чтение). Кадры настоящего бинлога кодируются
штатным v3, затем сжимаются zstd-1 — сначала без словаря (базовая линия), потом со словарём,
обученным `zstd::dict::from_samples` на обучающих кадрах (размеры 8, 32 и 112 КБ).

- Один и тот же файл передаётся и как обучающий, и как тестовый: тогда словарь учится на **первой
  половине** кадров, а замер идёт по **второй** — иначе словарь «видел» бы то, на чём его проверяют.
- Второй прогон: словарь обучен на LSK, применяется к **другой монете** (CYS) — это боевой сценарий
  «один словарь отгружается со сборкой».
- Для контроля напечатан «потолок» — словарь, обученный на самих тестовых кадрах; так в бою нельзя,
  но он показывает, где предел метода.

## Результат

**Один и тот же инструмент (LSK): обучение на первой половине, замер на второй**

| вариант | байт/запись | % от базы |
|---|---|---|
| zstd-1 без словаря | 2.906 | 100 % |
| словарь 8 КБ | 2.856 | 98.3 % |
| словарь 32 КБ | 2.853 | **98.2 %** |
| словарь 112 КБ | 2.862 | 98.5 % |
| потолок: 112 КБ из самих тестовых кадров | 2.838 | 97.7 % |

**Другая монета: словарь обучен на LSK, применён к CYS**

| вариант | байт/запись | % от базы |
|---|---|---|
| zstd-1 без словаря | 8.334 | 100 % |
| словарь 8 КБ | 8.107 | **97.3 %** |
| словарь 32 КБ | 8.151 | 97.8 % |
| словарь 112 КБ | 8.163 | 98.0 % |
| потолок: 112 КБ из самих тестовых кадров | 5.834 | 70.0 % |

## Вывод: отклонить

Честная экономия — **1.8–2.7 %**, то есть существенно ниже порога 5 %, которым проект отклоняет
форматные варианты (тикеты 43/44, В-49). Словарь 112 КБ хуже восьмикилобайтного: на кадр в ~1 КБ
записей большой словарь только добавляет накладные расходы.

Цифра «70 % на CYS» — **артефакт переобучения**, а не результат: словарь, обученный на самих тестовых
кадрах, у малой монеты просто запоминает их содержимое (словарь 112 КБ против файла 190 КБ). В бою
это недостижимо, и в таблице она стоит только как граница метода.

Итог по байтам: три захода подряд — таблица `ev` и уровни zstd (В-49), колоночная раскладка
(3–7 %), словарь (2–3 %) — дают меньше порога. Формат v3 практически исчерпан: дальше байты двигает
только смена класса кодека (например brotli, где плата — процессор) либо **запись меньшего объёма
данных**, а не раскладка.

## Цена вопроса

Включена фича `zdict_builder` у зависимости `zstd` — **только** ради обучения словаря в этом
прототипе (`examples/dict_probe.rs`); на работу коллектора она не влияет. Если прототип больше не
нужен, фичу и пример можно убрать одной правкой.

```bash
cargo run --release --example dict_probe -- <обучающий.binlog> <тестовый.binlog>
```
