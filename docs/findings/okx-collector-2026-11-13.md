## 1. Что сделано

Адаптер — один файл `src/collector/okx.rs` на общем ядре (приказ 16: общее ядро + тонкий адаптер); ядро получило три общие вещи, нужные и другим биржам: (а) хвостовые столбцы `bn`/`an` у `b`, (б) сигнал биржи о плановом разрыве → замена сессии (`Exchange::is_retire_notice`), (в) метаданные пула рядом с `pool-<день>.json` (`Exchange::pool_meta`) и `--top-exclude` по умолчанию от биржи (`Exchange::default_top_exclude`: Binance/Bybit 10, OKX 0). Файлы Binance и Bybit не изменились: хвост `bn`/`an` пишется только при непустых значениях (тесты формата Binance/Bybit прежние и зелёные).

## 2. Решения адаптера

| вопрос | решение | основание |
|---|---|---|
| каналы | book — `bbo-tbt`; trade — `trades`; mark — `mark-price` + `index-tickers` + `funding-rate` | подготовка п. 3: `bbo-tbt` — полный поток изменений верха книги (156 кадров/с на 10 символов против 73 у `books5`), монотонный `seqId`; `trades` — агрегат тейкерского ордера, аналог `aggTrade` |
| пул | USDT-SWAP, `ctType=linear`, `state=live`, оборот `volCcy24h × last` ≥ 300 тыс. $, **топ-10 не исключается**, акции и сырьё входят | решения координатора (передача 13.11); приближение оборота — подготовка п. 2 |
| книга | `b`: bid/ask и размеры строками как пришли, E = T = `ts` (ET = 0), `u` = `seqId`, **число ордеров** на уровне — хвостовые столбцы `bn`, `an`; третий элемент уровня («всегда `0`», [док]) проверяется: иначе кадр пишется как пришёл | В-172; решение координатора «число ордеров, если есть» |
| сделка | `t`: `a` = `l` = `tradeId`, `f` = `tradeId − count + 1`, `m` = (`side` = sell), размер в контрактах как пришёл; **`source`=1 → `x` = `E`**, `source`=0 → пусто, другое значение → элемент пишется как пришёл (`r`) | решение координатора «вид/источник»; в документации WS `source`=1 — «Enhanced Liquidity Program», в REST — «RPI»: буква `E`, не `R` Bybit, чтобы не утверждать тождество |
| mark | запись `m` на **каждый** кадр `mark-price` (без прореживания, как шлёт биржа): p = `markPx`, i = последний `idxPx`, r = последний `fundingRate`, T = `fundingTime`; ap, P пусты. `index-tickers` и `funding-rate` — состояние символа в разборе шарда (как `tickers` у Bybit), отдельных записей не дают | решение координатора «mark как шлёт биржа»; подготовка п. 3, п. 6.9 |
| первые кадры mark | пока по символу не пришли индекс и ставка (≈ 1 с после подписки), кадр `mark-price` пишется как `r` целиком — запись `m` без индекса и ставки была бы неполной, а молча терять кадр нельзя | В-172 («ничего не теряется») |
| шард | символ целиком в одном шарде (состояние индекса и ставки живёт в разборе шарда): по умолчанию 100 символов на соединение — book 100 аргументов, trade 100, mark 300 (3 канала × 100 символов), как в пробе P1 (200 и 300 аргументов на соединение, лаг p50 123–137 мс) | в документации числа аргументов на соединение нет (подготовка п. 1); потолок ищет лестница |
| порядок и дубли | личность записи — `seqId` (`b`), `tradeId` (`t`), `ts` кадра `mark-price` (`m`): одинаковы на разных соединениях и линиях. Писатель ядра снимает дубль по личности в окне 120–240 с, а не «ключ ≤ последнего», поэтому сброс нумерации `seqId` при техобслуживании ([док]) записи не теряет | подготовка п. 6.4; устройство `Seen` в `writer.rs` |
| лимит подключений | 3 в секунду на IP ([док]); бюджет ядра для OKX — окно 1 с, **2 подключения** (запас 1), считается каждое подключение, включая отбракованные и замены | подготовка п. 6.1; число назначаемое (запас) |
| пинг | протокольный ping ядра раз в 5 с (держит соединение без данных, измерено 12.11); `g` пишется рядом с данными. Число ≈ 230–260 мс — путь до сервера OKX за Cloudflare, не TCP RTT | подготовка п. 1, 6.2 |
| плановый разрыв | кадр `notice` с кодом 64008 («за 60 с до обновления сервиса») → сессия помечается, линия открывает замену как при возрасте (`rotated`), старая закрывается после перекрытия 20 с; вход не меняется; сам `notice` пишется в `r` как пришёл. Проверено тестом на локальном источнике (одна замена, 0 пропусков `seqId`) | подготовка п. 6.3 |
| входы | единственный хост `ws.okx.com`; линия 0 — IPv4 с запасным IPv6, линия 1 — IPv6 с запасным IPv4 (разные адреса и пути, независимой точки входа у OKX нет) | подготовка п. 5 |
| REST пула | заголовок `User-Agent` обязателен (иначе Cloudflare 403, код 1010) | подготовка п. 1 |
| не в формате | `seqId` сделки (у разных сделок бывает один — [док]), `open24h`/`high24h`/`low24h`/`sod*` индекса, `nextFundingRate`, `minFundingRate`, `maxFundingRate` и прочие поля `funding-rate`, `instType` | поля вне столбцов формата; новое поле в формат — отдельным решением |
