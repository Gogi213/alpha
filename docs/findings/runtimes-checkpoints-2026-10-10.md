## 0. Сколько рантаймов нужно — **2** (потолок 3 не берём)

Рантайм = то, что поддерживается отдельно: режим запуска + машина + свод правил + путь выкладки + набор гейтов.

| граница | требование, которое один рантайм не закрывает | довод/замер | вывод |
|---|---|---|---|
| Живой ↔ Исследовательский | (а) запреты горячего пути (ноль аллокаций на событие, без `BTreeMap`/`HashMap`/`f64` на событии) против исследовательского кода: 8 путей «клетка×сутки», `Instant::now`, env-флаги, `BTreeMap` на круг (С-16…С-21); (б) жизненный цикл: демон 24/7 под systemd на боевой машине (сборка отдельно, 2 ядра, 3,8 ГБ у коллектора) против очереди `alsched` на calc (16 потоков, CPUQuota ≤ 1500 %); (в) цена исследовательских форм в живом бинарнике: R2 выкл. стоил +7,6 % ЦП (TK-065:393), правило ≤ +1 % | единственный способ «один рантайм» — cargo-feature `research`, т. е. два профиля сборки = два рантайма по определению | **граница нужна** |
| Тёплый ↔ Холодный | **нет** такого требования: оба — Rust-подкоманды одного `lob`, одна машина (calc), один запуск (`alsched submit`), одна очередь, одна выкладка; Холодный пишет под ключом, Тёплый читает. «Запуск подготовки без прогона» даёт подкоманда `cold ensure` внутри того же рантайма. Отдельная машина для подготовки сейчас не нужна (данные только на calc, коллектор остановлен) | — | **сливаем**: Холодный = стадия (модуль) Исследовательского |
| Слой разбора | читает готовые CSV, стратегию не считает; Python, не горячий | не рантайм, а потребитель выхода Исследовательского (`/data/runs` + Летопись) | модуль И, не третий рантайм |

Сравнение по цене поддержки (минимум по В-170/В-218):

| | 1 рантайм | **2 рантайма (Ж + И)** | 3 рантайма (Г/Т/Х) |
|---|---|---|---|
| профили сборки | 1, но `research` внутри живого (+7,6 % ЦП без feature) | 2 (`live`, `research`), исходник `on_event` один (А1) | 2 (Т и Х — тот же `lob`) |
| точки входа | 1 | Ж: `lob session`/живой бот; И: `warm-run`, `cold`, `analyze`, `alsched` | + отдельная служба Х |
| наборы гейтов/тестов | 1, но каждая правка исследований гоняет гейты живого | 2 + контракт «живая == Backtest» | 3 + контракт ключей Х↔Т |
| пути выкладки | 1 | 2 (боевая машина / calc) | 3 |
| риск | исследование ломает живое, невозможна изоляция | границу держит feature + гейт «выкл. = байт в байт» | лишний слой ради границы, которой нет |

## 1. Закрытие дыр (1)–(6) постановки

**(1) Язык `warm-run`: Python-обёртка vs Rust `lob run --cells --period`.** Что делает обёртка: раскладка суток по ядрам, CPUQuota, readahead, запись шагов в Летопись, вызов `cold ensure`, сверка `build-id`. Всё тяжёлое (разбор суток, клетки, касания) уже в Rust-бинарнике; параллель по суткам — процессами под `alsched` (упаковка ядер, бюджет памяти — уже в `alsched.py`).
- Rust: плюс — один бинарник, кэш и параллель в процессе; минусы — дублирует `alsched` (ядра/память/вытеснение) и `guard.py` (Летопись), каждая правка оркестровки = сборка+PGO на VPS (3–4 цикла, M3), тесты оркестровки на Rust дороже; переезд ≈ 3–4 ч сверх КТ-2.
- Python: плюс — живёт с `alsched`/`guard.py` в одном языке, правка без сборки, 154 `tk048-*` скрипта сжимаются в один; минус — накладная процесса и цена Python на горячих участках (их нет — разбор сутки в Rust).
- **Выбор (предварительный, до замера КТ-2): Python.** Правило решения, записанное до замера: если накладная `warm-run` (старт + проверка ключей + запись в Летопись) на волне 01–15.01 (241 кл., эталон 211,8 с) ≤ 1 % стены (≤ 2,1 с) и diff 0 против b14 → Python остаётся; иначе — `lob run` в Rust (КТ-2b, +3–4 ч). Замер: `benchrun wave` с обёрткой против прямого вызова, 1/10/50/241 клеток.

**(2) Слой разбора.** Сейчас: `portfolio-sim`, `p12-sharpe`, `monthly-pnl`, `tk113/114/120-*` (С-59…С-66). Решение: один пакет `tools/analyze/` (`p12lib` из П5 → `analyze`), читает `/data/runs/<run-id>/run.json` + Летопись, подкоманды `monthly`, `sharpe`, `portfolio`, `cuts` (монеты/месяцы). Стратегию не считает; новые разрезы = подкоманда, а не `tk*-` скрипт. Место: модуль И. Python (не горячий путь).

**(3) Защита от россыпи** (заводится в КТ-1, расширяется в КТ-9):
1. сборка release — только `tools/build-release.sh` на VPS из чистого `master`: пишет строку `bin/MANIFEST.tsv` (build-id = sha коммита + профиль + набор features); хук `alpha_one_build.py` отказывает прочим путям;
