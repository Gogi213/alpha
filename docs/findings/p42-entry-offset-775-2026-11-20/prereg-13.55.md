#### 4. Механика (по коду)
- **`e` — зона входа** (`signals.rs` / `tick.rs` `candidates`: `dmax = min(e, track)`, `track` = 2 %): кандидат — минутка, в которой цена подошла к уровню ближе `e` % снизу (лонг; шорт зеркально) и ещё не пересекла его; вход — рыночный по ленте (`ew = 5`, `ex = 0`, `lat = 4`). Меньше `e` — вход ближе к уровню (позже, меньше сделок); больше — раньше и дальше. База: лонг `e = 0,3` (по умолчанию), шорт `e = 0,15`. `e` — ключ сигнала: меняет поток кандидатов и, через занятость монеты, набор сделок.
- **`e2` — второй вход** (§13.19, `tick.rs` `lot2_decision`): позиция делится 50/50; лот 1 — как сейчас; лот 2 — по рынку, когда цена подошла к уровню ближе `e2` % и не пересекла; если лот 1 уже в пределах `e2` — лот 2 входит тем же событием; отказ / лот 1 закрыт / пересекли раньше — лота 2 нет (полусделка). `e2 = 0` — один вход. База: лонг `e2 = 0`, шорт `e2 = 0,05`.
- **E(k) — вход по подтверждению** (TK-617, `tools/p42/tk617_entry_replay.py` `sim_long`, без изменений): на сигнале базы — не входить сразу, а купить по рынку первой сделкой ленты с ценой ≥ `p_ref·(1 + k/10⁴)` (`p_ref` — последняя сделка покупателя ≤ сигнал + 4 мс, как у движка); приказ живёт 60 мин и снимается; если эта цена ≥ уровня — сделки нет. Дальше — выходы `L_base` (8 тейков 1…5 NATR на 50 %, безубыток после 1-го, трейл 2/2 NATR, `rt` 0,2 % / 20 с, стоп 5 %, `latx` 4 мс, проскальзывание 1 бп, комиссии мейкер 1,26 / тейкер 3,15 бп). **Это повтор по ленте, не движок:** портфель (занятость монеты, паузы) не моделируется; набор сигналов — ровно сделки `L_base` h775; сделка E(k) может только исчезнуть, не появиться. Лента — zip `aggTrades` деревьев h775 (`/data/p42-tk621/<окно>/aggtrades`), сутки — только ≤ min(конец окна, 13.11); не закрытая к концу ленты сделка — «forced» по последней сделке (как движок в конце окна). Сутки сделки E(k) — сутки входа сделки базы (пара та же).
- **E(k) только у лонга.** У шорта база с двумя лотами (`e2 = 0,05`), `bm = 1`, `tt`/`tb`: повтор `sim_long` к нему неприменим, а ключа E(k) в движке нет; шорт-E(k) — новый ключ движка с воротами «байт в байт» (отдельная задача, если понадобится). Записано здесь как ограничение; в отчёт — одной строкой.

#### 5. Клетки (записаны здесь до P&L)
Клетка = база стороны (с ` t24=12`) + патч (ключи после базы заменяют её значения); у K — повтор по ленте.
- **Блок E — зона входа:** `e` ∈ {0,05; 0,1; 0,15; 0,2; 0,3; 0,5} без значения базы ⇒ **5 на сторону** (лонг без 0,3, шорт без 0,15; у шорта `e2 = 0,05` остаётся, при `e = 0,05` лот 2 всегда входит вместе с лотом 1 — клетка законна).
- **Блок D — второй вход:** `e2` ∈ {0; 0,025; 0,05; 0,1} без значения базы ⇒ **3 на сторону** (лонг 0,025 / 0,05 / 0,1 при `e = 0,3`; шорт 0 / 0,025 / 0,1 при `e = 0,15`).
- **Блок K — вход по подтверждению (лонг):** k ∈ {5; 10; 15; 20; 25} бп ⇒ **5**; k = 0 — эталон блока (ворота G-k0), не клетка.
- **Испытаний: лонг m = 5 + 3 + 5 = 13, шорт m = 5 + 3 = 8.** Движком: (5 + 3 + 1) × 3 окна × 2 стороны = 54 прогона-варианта (порядок TK-650: 450 за ≈ 5 мин); повтор K — 428 сделок × 6 значений k.

#### 6. Что считаем на клетке
Как §13.50 п. 6 (код `tk643_run.stat_row`): сделок; Σ $; $ на сделку; годовой Sharpe; по месяцам (июль, август, сентябрь, октябрь, 01–13.11) — сделок, Σ $; 90 % интервал $ на сделку; максимальная просадка; R:R; стопов, убыток стопа; доли видов выхода. **Парная Δ $/сделку к эталону** — `tk604_stats.delta_stat` (одни блоки суток; нижняя граница — 5-й перцентиль; односторонний p; ΔΣ и SE_Σ), Δ по месяцам — `month_table`, устойчивость — `robust` (без двух суток, без двух монет). Эталон: у E и D — база стороны (движок); у K — повтор k = 0 тех же 428 сделок (по G-k0 равен движку). Дополнительно: у E и D — число сделок, отличных от базы (монета, `sig_ms`), у D — доля сделок с лотом 2 и доля «полусделок»; у K — сколько сигналов базы не исполнено (приказ снят / цена ≥ уровня) и Σ $ этих сделок в базе. Медиан нет, t по сделкам нет.

#### 7. Правило ответа (записано до счёта; единица — сторона; семейство — все клетки стороны: лонг 13, шорт 8)
Клетка — **«кандидат вперёд, найдено на этих данных»**, если выполнено **всё** (а)–(ж) (как §13.50 п. 7, без (з)):
(а) минимум сделок: ≥ 70 за окно и ≥ 20 в каждом месяце (01–13.11 — ≥ 8);
(б) **Холм** по одностороннему p парной Δ $/сделку по всем m клеткам стороны (α = 0,05) отвергает H0: Δ ≤ 0;
(в) Δ месяца > 0 в ≥ 4 из 5 месяцев;
(г) Δ > 0 без двух лучших суток и без двух лучших монет;
(д) охрана суммы: ΣS клетки > 0 и ΔΣ ≥ −1·SE_Σ;
(е) плато: упорядоченные оси — `e` (0,05 < 0,1 < 0,15 < 0,2 < 0,3 < 0,5), `e2` (0 < 0,025 < 0,05 < 0,1), k (0 < 5 < … < 25); сосед — ближайшее значение оси в каждую сторону; если сосед = база стороны (у K — k = 0; Δ ≡ 0) — берётся следующее значение в ту же сторону; нет — направление выпадает; нужна хотя бы одна сторона с соседом, и **все** найденные соседи — с Δ ≥ 0,5·Δ клетки (код как `tk650_run.neighbours` / `tk643_run.plateau_ok`);
(ж) **шум:** годовой Sharpe клетки выше шумовой планки `selection_bias.significance` при N = m + прежние клетки семьи «вход» (лонг: §13.19 2 + §13.24 6 × 2 прохода + TK-617 5 = 19; шорт: §13.19 6 + §13.24 6 × 2 = 18; округлено вверх до 20) — **лонг N = 33, шорт N = 28**, и `survives = да`; печатаются планка и дефлированный Sharpe.
Ни одна клетка не прошла ⇒ **«нет: база стороны остаётся»** (лонг `e = 0,3`, один вход, вход на сигнале; шорт `e = 0,15`, `e2 = 0,05`). Прошли несколько ⇒ ответ — **множество** (область), не «лучшая». Сильная Δ без (б) или (ж) — описательно, решений не двигает. У K: прохождение — «кандидат для ключа движка» (портфель не моделировался), не кандидат вперёд сам по себе.

#### 9. Ворота
- **G-bin:** sha256 бинаря ∈ `tk625_run.BIN_SHA_OK`.
- **G-base:** строка базы (без патча) в пакете = готовые сделки базы h775 (ключи, P&L |Δ| ≤ 1e-6) на всех окнах и сторонах; расхождение — остановка.
- **G-key:** у каждой клетки E и D набор сделок или P&L отличен от базы (хотя бы одна сделка); иначе — остановка (ключ не дошёл до движка).
- **G-k0:** повтор k = 0 против движка `L_base` h775 по каждой сделке: |Δ (gross − fees)| ≤ 0,01 $ у ≥ 99 % сделок и |Σ Δ| ≤ 1 $; иначе — остановка, блок K не читается. Печатаются несовпавшие сделки.
- **G-tape:** ни одна прочитанная сделка ленты не позже 13.11 23:59:59.999 UTC (`tk604_stats.LAST_MS`); нарушение — остановка.
- **G-dup (контекст):** клетки с одинаковым P&L — списком; в Холме остаются.
- **G-win (контекст):** зачётных сделок, закрытых концом данных окна, — число.
