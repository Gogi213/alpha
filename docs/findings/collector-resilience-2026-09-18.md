# Устойчивость коллектора: смоук сценариев A8 на сервере (2026-09-17/18)

Тикет A8.7 `docs/plan/dev-plan-2026-09-17.md` §Дополнения. Второй корень `/opt/alpha/smoke`
(владелец `ubuntu`), свой бинарник `alpha-smoke-a87` (= HEAD `29e8327`, собран на сервере из
`git archive`, сборка 1 мин 11 с), **прод не тронут**: живой юнит `alpha-collector` (`3614321`)
работал всё время смоука, корень `/opt/alpha/root` не читался на запись.

## Что прогнано и что вышло

| Сценарий | Как проверялся | Результат |
|---|---|---|
| **A8.1 add** (T34) | в пул из 6 инструментов (5 монет боевого пула + фейк) дописана 7-я строка | `session.json.instruments = 7`, файл `ENAUSDT-2026-09-17.binlog` создан, строка stderr «добавлен ENAUSDT … глубокий поток .200» |
| **A8.1 remove / replace** | атомарная замена файла (`mv`): убрана `ENAUSDT`, добавлена `SUIUSDT` | `pool_removals = [{ENAUSDT, ts}]`, файл `SUIUSDT-2026-09-17.binlog` создан, строка «снят ENAUSDT — файлы потоков сброшены и закрыты» |
| **A8.1b шов соседям** | снята `HYPEUSDT` — монета, делящая сокет с четырьмя соседями | **4 строки** `gaps.csv` класса `sequence_gap`: `шов покрытия — пересборка сокета при снятии HYPEUSDT: снапшот нового соединения ещё не пришёл` (по строке на соседа: LSK, NEAR, DOGE, AKE) |
| **A8.2 SIGTERM** | `kill -TERM` смоук-процесса | процесс завершился, `session.json closed=true`, строка stderr `session: SIGTERM — останавливаюсь (второе нажатие Ctrl+C — аварийный выход)` |
| **A8.3 отказ подписки** | в пул подложен несуществующий `ZZZFAKEUSDT` | строка `gaps.csv` `subscribe_failed` с топиком и текстом биржи, счётчик `session.json.subscribe_failed = 1` (в stderr-сводке тоже) |

Наблюдение смоука (не дефект): снятие монеты, **добавленной** на ходу, шва не даёт — `add` по
построению поднимает ей **отдельное** соединение (`plan_connections` для партии), и пересборки общего
сокета не происходит. Шов появляется ровно тогда, когда снятая монета делит сокет с другими — это и
показал второй прогон (`HYPEUSDT` → 4 строки). Порядок «старый сокет закрыт до запуска нового»
(барьер A8.1b) на смоуке отдельно не измерялся: он закреплён юнит-тестом с задержкой закрытия
транспорта.

## Что живьём НЕ проверялось и почему

- **A8.4 диск полон → свободен** — заполнение диска `/opt/alpha` (общий `sdb` с боевыми данными)
  рискованно для прода; механика закреплена юнит-тестом с двойником `ErrorKind::StorageFull`
  (тикет 51).
- **A8.5 обрыв сети на часы** — `iptables` требует root и по uid блокировал бы и мой SSH; связка
  «очередь отказов → снапшот → подписка заново» закреплена тестом с коннектором-очередью (тикет 52).
- **A8.6 скачок часов** — `timedatectl set-time` на боевом хосте сдвинул бы часы живого коллектора;
  поведение локальной метки закреплено тестом (тикет 53).

Все три — кандидаты на отдельный стенд, если владелец захочет живую проверку; на прод-хосте их
делать не стоит.
