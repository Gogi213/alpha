#### 3. Признаки: определения (все причинные; значения на сигнале из данных строго до `sig`; фиксированы здесь)
`sig_abs = T0_окна + sig_ms`. Знак стороны σ = −1 у лонга, +1 у шорта: **«перекос толпы против пробоя = топливо» ⇒ большое значение g = σ·x — благоприятно**; механизм заявлен до данных: пробой вверх (лонг) подпитывает закрытие шортов при отрицательном фандинге / отрицательной премии, пробой вниз (шорт) — закрытие лонгов при положительных.
- **F (H1).** `f8` = `last_funding_rate` последней выплаты монеты с `calc_time ≤ sig_abs`, приведённая к 8 ч: `f8 = ставка × 8 / интервал_ч`. Интервал — столбец `funding_interval_hours` строки месячного архива; у строк ноября (REST) — расстояние до предыдущей выплаты монеты, округлённое к {1; 2; 4; 8} ч. Нет выплаты до `sig_abs` (новый листинг) или последняя старше 2 интервалов (дыра) → пусто. `g_F = σ·f8`.
- **P (H2).** `prem` = `close` последней **закрытой** минутной свечи `premiumIndexKlines` (`open_time + 60 с ≤ sig_abs`; это (mark − index)/index — базис перп–спот площадки). Свеча старше 5 мин или нет файла суток → пусто. `g_P = σ·prem`.
- **C (H4).** Уровень кандидата `P60` = `level_px_e8` строки `sigsx` базы (уровень по часовым барам, `tf=60`). Дамп уровней движка при `tf=240` (`P42_LEVELS=1`, остальные ключи базы без изменений) даёт для монеты уровни со столбцами `born`, `end`, версии цены `минута:цена`. На минуте сигнала `m = ⌊sig_ms / 60000⌋` кандидат **«слит»** (`conf_τ = 1`), если у той же монеты есть 240-минутный уровень той же стороны, живой на `m` (`born ≤ m < end`), чья версия цены на `m` лежит в пределах `τ_c` от `P60`: `|P240 − P60| ≤ τ_c · P60`; иначе `conf_τ = 0`. `τ_c` — основное 0,2 % (допуск группировки пивотов `τ` движка, `tau_pm = 200`), соседи 0,1 % и 0,4 %. Уровень существует на `m` только по закрытым барам до `m` (свойство построения уровней), заглядывания нет; строки сигналов 240-минутного прогона не используются — они зависели бы от будущего хода цены.
- **R (H5).** `p = level_px_e8 / 1e8`; шаг круглого числа `s_r = 10^(⌊log10 p⌋ − 1)` (BTC 77 528 → 1 000; 0,4298 → 0,01; 5,1 → 0,1); `ρ = |p − s_r·round(p / s_r)| / (natr · p)`, `natr = natr_e8 / 1e8` строки (расстояние до ближайшего круглого числа в NATR сигнала). «Уровень у круглого числа» = `ρ ≤ δ`; основное δ = 0,5 NATR, соседи 0,25 и 1,0.
Покрытие, дыры и дубли ключей печатаются до P&L (п. 8).

#### 6. Статистика и ворота (числа назначены до счёта; как §13.32 п. 5 и §13.35 п. 6, кроме отмеченного)
Единица — сутки (136); парная Δ среднего $ на сделку «клетка − база» (`tk604_stats.delta_stat`: круговые блоки по 4, 20 000 повторов, зерно md5 как §13.24.1 п. 2): Δ ± SE, z, одностороннее p (H0: Δ ≤ 0), ΔΣ ± SE_Σ.
- **Допуск клетки:** клетка и база — ≥ 20 сделок в месяце (01–13.11 — ≥ 8), исключено ≥ 30 сделок базы. **Подмножества** (клетка оставляет < 50 % сделок базы): ≥ 70 сделок за окно и ≥ 8 в каждом месяце; метка «прирост по построению отбора сделок»; доля оставленных печатается, при доле < 70 % рядом пометка «подмножество» (критик: «≥ 70 сделок за окно — проверить долю до счёта»). Недопущенная клетка идёт в Холм с p = 1.
- **(g1)** Холм по **семейству «вход» m = 61 + m_new**: 61 прежняя пробная клетка (TK-625 — 9, TK-633 — 12, TK-634 — 8, TK-636 — 32; их p — как есть из `select.json`, `select33.json`, `select34.json`, `select36.json`, не пересчитываются; наименьшее прежнее p 0,0067, поэтому ступени ниже 0,05/62 проходят только новые клетки и точно считаются смещённым Холмом) + m_new = 8 (фактическое m_new без дублей — в п. 8 до P&L); α = 0,05 односторонне; g1 — только для новых клеток; первый шаг ≈ 0,05 / 69 = 0,00072 (z ≈ 3,2). Рядом, контекст (решение не двигает): Холм по одним новым клеткам и по стороне; Холм при m = 61 + m_new + 53 (TK-648 — 12, TK-651 — 17, TK-656 — 24 клетки того же окна признаков входа, не включённые критиком в семейство).
- **(g2)** знак Δ по информативным месяцам (≥ 5 исключённых сделок базы; `need_months`); **(g3)** охрана суммы: ΣS клетки > 0 и ΔΣ ≥ −1·SE_Σ; **(g4)** Δ > 0 без двух лучших суток и (отдельно) без двух лучших монет; **(g5)** плато: ≥ 2 допущенных соседа с Δ ≥ 0,5·Δ клетки и Jaccard исключённых ≤ 0,8 (клетка без двух таких соседей плато пройти не может и остаётся пробной; у `C` соседи по `τ_c` вероятно имеют J > 0,8 — это печатается в п. 8).

- Колонки клетки: n, Σ $, $/сделку, годовой Sharpe, сделки и Σ $ и Sharpe по месяцам (июль … 01–13.11), 90 % интервал $/сделку, макс. просадка ($ и % маржи 250 $), KPI В-120, R:R, число стопов и убыток стопа (средний и максимальный, $ и % маржи при плече 2), исключено сделок базы, Jaccard с соседями. #### 7. Правило ответа (записано до счёта)
На пробную клетку: **«добавляет $ (найдено на этих данных; кандидат только вперёд)»** — прошла (g1)–(g5); **«качество сделок выше, Σ не выше (подмножество; не добавляет $)»** — прошла (g1), (g2), (g4), но не (g3); **«не работает»** — все допущенные пробные клетки гипотезы по стороне имеют Δ < 0 (точечная оценка); иначе **«не ясно: |Δ| < MDE X $»**. Единица ответа — гипотеза × сторона (H1 = `F25`, H2 = `P25`, H4 = `C02`, H5 = `R05`); H1 и H2 — одна запись критика, но две клетки: ответ по каждой и общий по паре. Соседи, обратные клетки и `L_n24` справочно «работает» не дают. «Не работает» ≠ «признак бесполезен»: в этой форме (одно направление, q 0,25 / δ 0,5 NATR / `τ_c` 0,2 %) край на этих данных не найден.
**Если «добавляет $»:** заморозки этот тред не делает; в отчёте и карточке — «найдено на этих данных» и рекомендация координатору по В-167 (α только из долей `L_base` / `S_mk1`, каждая ≥ 0,005, сумма 0,05); файлы `docs/research/freeze/*` не трогаются. Иначе — база остаётся, клетки внутри 01.07–13.11 не правятся.
