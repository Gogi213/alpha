- Данные: ETH 17–20.10 (24 пула), Base 18–21.10 (8 пулов), BSC — нет данных (429, решение Судьи `reviews/tk374-overseer-bsc-2026-10-23.md`), Solana не качалась. Монето-единиц в счёте 31 из 32 (PROS — нет Gate); у каждой пул с ≥ 50 свопов в сутки на 4 суток; все 31 — Gate **спот**.
- Скрипты: `tools/compute/tk374-bank.py` (счёт, calc job 1023105553831, 15 ядер, <1 мин), `tk374-agg.py` (свод, Бонферрони 54 как TK-364), `tk374-fees.py` (не завершён). Сырьё calc `/data/tk0374/bank/raw.json`; клетки — `tk374-dex-gate-2026-10-23.csv`.
- fwd: событие DEX (ход цены пула ≥ X бп за T) → отклик Gate; rev: событие Gate (ход цены сделок ≥ X бп за T, X 30/100/q95 монеты) → отклик цены главного пула (последний своп ≤ t+h). Вход t+1 с, контроль — 10 случайных моментов той же монеты и часа, знак тот же.
- **rev-отклик включает «догон устаревшей цены пула»**: пул не обновляется, пока нет свопа; цена на t+h — последний своп. Торгуемый догон — по сути разрыв пул/Gate; предход для rev = 0 по построению.
- Правила кандидата не менялись (diff > 13 бп, ≥5 суток по > 13, ≥10 монет с плюсом, доля макс. монеты ≤ 0,3, нижняя граница > 0): суток всего 4–5, поэтому d13 ≥ 5 достижим только при 5 из 5 — клетки rev q95 (4/5) не проходят; это не провал сигнала, а охват.
- Монеты с разным токеном на разных сетях (NPC eth/base) считаются раздельно; общий вывод ограничен ≈ 17 EVM-монетами (ETH 11 + Base 6), BSC и Solana не покрыты.
- Нужно: fee tier пулов (GeckoTerminal/on-chain `fee()`), Gate taker из тарифа, затем net; решение Судьи — продлить окно данных до 7 суток или принять охват.
