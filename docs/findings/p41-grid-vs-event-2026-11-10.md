# П-41 §8: сетка против событийного счёта — замер на малом (TK-524, 10.11.2026)

**Итог: сетка (и 100 мс, и 1 с) не годится — теряет 60–90 % эпизодов. Счёт П-41 — только событийный** (§8: «не прошла сетка — счёт только на ядре / событийный»). Числа допуска сверки с `p40-d1-naive` (±1 % / 0,3 / 0,1 bps) этим замером не проверялись: уровень здесь упрощённый (медиана `ln(midA/midB)`, п. ниже), не премия mark/index ядра.

## Метод
Скрипт `p41-grid-vs-event-2026-11-10/gridcmp.py` (srv `/root/p40prelim/p41_gridcmp.py`): ноги Binance+Bybit из L1 бокса `/data/p40l1c/p40l1`, одни сутки; mid = (лучший bid + лучший ask)/2 по событиям L1 (флаг: бит 0 — снимок, бит 1 — bid; порядок — как в файле, время — бегущий максимум). Уровень — медиана `ln(midA/midB)` по 1-с ряду за всё прошлое окно (минимум 30 мин, до 6 ч, до `t−60 с`), пересчёт раз в минуту, **один на все варианты**; эпизод П-40 §3 (`θ`=12,6, взвод `|d|<θ/2` ≥ 60 с, конец `dir·d ≤ 0`). Варианты: событие (каждое обновление любой ноги), сетка 100 мс, сетка 1 с (последнее значение). Совпадение — `t0` события в пределах ±2 с.

## Что не показано
- 3 пара-суток, одна пара бирж (Binance+Bybit), без премии mark/index и без исполнения (E1/E2) — вывод только про обнаружение пересечения, не про доходность.
- Совпадение «±2 с» — грубое; различие в числе эпизодов (3–8×) не объясняется допуском.
- Допуск П-41 §8 к ядру (эпизоды ±1 %, |Δ net| ≤ 0,3, |Δ d0_med| ≤ 0,1 bps) — на ядре TK-522 и пара-сутки, где ядро уже посчитало `θ`=12,6.

Алгоритм: варианты — сетка 1 с, сетка 100 мс, событийный счёт по L1; замер — выше (3 пара-суток); выбран — событийный, потому что сетка теряет 60–90 % эпизодов и медленнее при плотных ногах.

## Что дальше
Счёт П-41 — событийный Python/numpy по кэшу L1 (O(событий), ~1–3 с на пара-сутки на одно `θ`; 177 клеток × пары × 14 суток — векторизовать/кэшировать по `θ`-независимой части) либо правка ядра (`θ_t` из окна) тикетом Инженеру; выбор — по замеру на 1–2 сутках × 20 активов против `p40-d1-naive` с уровнем ядра.

## Решение по счёту (Исследователь, 10.11 ~19:45 GMT+4)
Событийный счёт П-41 — **на ядре П-40** (`/root/p40core/rs/src/main.rs`), не отдельным Python: ядро уже даёт уровень `level_grid`/`d_series`, очередь, E1/E2, маски. Разбивка:
- **A0/A1 — без правки ядра:** `P40_THETAS` = `Φ/(1−q)` (Φ 15/20/29/40, q 0/¼/½ → θ 15…80; A1 — 12,6) — отдельный проход на θ (вход на первом пересечении своего θ, не фильтр `d0` по θ=12,6). Ждёт `D1NAIVE_DONE` (TK-522), CPU занят.
- **A2–A5 — нужна правка ядра (Инженер):** `episodes(.., theta: f64, ..)` (main.rs:307) → порог рядом с рядом `ds`: вектор `theta_t[i]`, посчитанный **только по прошлому** (`ds[j]`, `tu[j] ≤ t_i − 1 с`) и условия `pa < θ_t/2`, `ad ≥ θ_t` (main.rs:338); `θ_t = max(Φ_t/(1−q), S_t)`, `Φ_t = max(Φ, K_t)`, `K_t = C_fee + (spr_A+spr_B)/2` по L1 на `t`. `S_t`: A2 квантиль `|d|` (W 1/6/24 ч, p), A3 `med + k·1,4826·MAD`, A4 EWMA-квантиль, A5 A3 по классу×терцилю волатильности. Отсечка мусора (П-41 §3) — до обновления окна. `Ep.theta` и колонка `theta` в таблицах = `θ_t` на `t0` (ключ клетки — параметры правила, не θ). q ∈ {0;¼;½} в выходе (main.rs:512 `0.5·d0` → `q`). Тест: при постоянном `theta_t` — байт в байт с текущим выходом.
- Допуск сверки (§8): θ=12,6 на ядре = `p40-d1-naive` по определению; ±1 % / 0,3 / 0,1 bps проверяется на 1–2 сутках × 20 активов до счёта клеток.
