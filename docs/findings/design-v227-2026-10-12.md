Находки по описи (факты из кода, не оценки):
1. **Имя формы разбирается четырьмя независимыми парсерами** (Rust parse, Rust label, `cellhash.parse_*`, `master.r2_exit`/`R2_EXIT_RE`). Расхождение имён Rust↔Python ловится только тестами на отдельных примерах.
2. **Ветвление по номерам гипотез** уже есть: `master.rust_axes`/`r2_exit` — `if n == "87" … "92" … "93" … "106" … "119" … "114" … "65" … "95" … "129" … "110" … "104" … "117"`. Каждая новая Г — ещё ветка. Это то, что В-227 запрещает.
3. **Дыра хеша (проверить первым делом пакетом A):** `cellhash.SET_KEYS` знает `r1_born_shift_cbps_min`, но не общий `r1_<кол>_min|max`, а также `eaten`, `eaten_min`, `frontrun_min`, `behind_min`, `stack_min` из `FilterSet`. Если такая клетка идёт не через `variant`, два разных набора дадут один хеш. До добавления 56 гипотез (многие — R1-колонка + фильтр) это обязано быть закрыто, иначе В-224 «счёт по хешам» теряет смысл.
4. R1-колонки — готовый образец «одно место»: именно его распространяем на формы и фильтры.

## 2. Дизайн: механика = строка каталога

### 2.1 Каталог механик (Rust, холодный путь)
Один статический массив `MECHANICS: [MechSpec]` в `bounce_grid/mechanics.rs`:

```
MechSpec { id, kind: Entry|Stop|Take|Exit|Filter, prefix: "pyfresh",
           params: [ParamSpec { name:"n", dom: Int{2,12} | Frac{den:12,lo,hi} | Bps | Ms }],
           name_template: "pyfresh{n}", is_r2: bool,
           build: fn(&[ParamVal]) -> ExitForm }
```
- `parse(name)`: наибольший `prefix` → извлечение `params` по шаблону → проверка домена → `build`. «Имя не каноническое» — **одна** проверка `label(parse(s)) == s` для всех, вместо десяти копий.
- `label` — тот же `name_template`. `ExitForm` остаётся `Copy`-enum без кучи; каталог читается только при разборе аргументов, **не на пути события** (ни аллокаций, ни HashMap в горячем пути — правила `interfaces.md`; цены/объёмы — тики/лоты `i64`).
- Обработчик механики в горячем пути — прежний `match ExitForm` в `strategy/exit.rs`/`pyramid.rs`: новая механика = новый вариант + обработчик, но разбор/имя/домены/`is_r2`/ось — из каталога.

### 2.2 Каталог наружу: `lob mechanics --json`
Подкоманда печатает каталог (id, kind, prefix, params с доменами, шаблон имени). `cellhash.py`, `master.py`, `p14_axes_build.py` **читают его**, а не дублируют:
- `cellhash.parse_exit/parse_stop/parse_take/parse_entry` → разбор по шаблонам из каталога;
- `master.r2_exit`/`rust_axes` (ветки по Г) → **данные**: в `hyp_axes` колонки `mechanic` (id) и `param` (имя параметра механики); имя формы = шаблон(mechanic, значения оси) с проверкой домена каталогом. Ветки по номерам Г удаляются; вне домена → причина «ось вне домена `<param>` ∈ …» из каталога;
- тест-мост: для каждой механики и каждой точки домена `label_rust == name_python` (генерится из каталога, не руками).

### 2.3 Фильтры: два пути, оба общие
- **Новый признак → новая колонка R1** (append-only: `r1.rs` имя + счётчик + тест). Фильтр `r1_<кол>_min|max` уже общий. Составные признаки (Г-73: OBI+OFI+автокорр., Г-100 микроцена, Г-139) считаются в R1 целым — отдельного типа фильтра не заводим.
- **Квантильные пороги** (`keep_q`, П-14 §3): порог — число, вычисляемое Python из распределения колонки и подставляемое как целая граница `r1_*_min|max`; в хеш идёт сама граница + `variant.axes.keep_q` (воспроизводимость).
- `FilterSet`/`TouchFilter`: схлопнуть 3 копирования полей в один `FilterSpec` (одна структура, `From` на `TouchFilter`) — убирает «3 места» из таблицы. Поведение при пустом наборе не меняется.
- Хеш: добавить в `cellhash` ключ `set.r1` (отсортированный список `[кол, min, max]`) и недостающие ключи `FilterSet`; пустое значение **не** входит в канон-JSON → старые 487 хешей не меняются (проверка `test_cellhash` + пересчёт всех существующих хешей = те же).

### 2.4 Python по закрытиям (15 гипотез «вне пакета»)
Один раннер `tools/registry/closure_mech.py` (по решению Судьи М5 — П-класс П-14 §3.2: семьи в N, **без хеша** и вне хеш-счёта Летописи) + плагины `tools/registry/closures/<механика>.py` с контрактом `NAME`, `PARAMS` (домены как в каталоге), `KIND`, `SOURCES`, `run(data, ctx, **params)` (решение Судьи 12.10, В-206). `KIND='closes'` (Г-124/144/148, отчёт Г-18/19/80): data = закрытия B1, выход `[(мс,$)]`. `KIND='keep'` (P-07 ×7, Г-50, Г-26, Г-126): data = строки `signals.csv` off-дерева B1 + исход из `rounds.csv` по ключу (symbol,day_utc,form,signal_index), выход = набор keep; раннер: `keep.csv` → `busy-replay.py --keep` → expo (`p12-r2-expo.py vn`) → `portfolio-sim --drop TRUMPUSDT,TRXUSDT,BCHUSDT --deposit-usd 2500 --position-usd 500`, cap 0 и 3 → закрытия → до/после. `KIND='rounds'` (exit-sim Г-130/111/118): выход `{ключ: (exit_ns, exit_px)}`, раннер пересчитывает `net_bps` той же формулой издержек и переписывает согласованно `rounds.csv` и `exit_ns` в `signals.csv` во временной копии дерева (метка upper bound: минутные свечи, без очереди). `ctx` — ленивые загрузчики по месяцу (`signals/rounds/sigma/klines/regime`; путь в плагине не пишется, необъявленный в `SOURCES` источник — отказ): off-дерево `/data/p12r2/s-v/<мес>/<сутки>/t-bid-btc4h-q1/`, study `/data/tk046/<мес>/study/`. Гейт М5 «выкл = прежний»: keep=все и rounds без замен → закрытия байт в байт = `/data/p12r3a/closes-b1d-cap{0,3}-<мес>.json`; без тождества keep/rounds не считать. Раннер: читает B1-закрытия (уже есть), вызывает плагин, пишет в Летопись семьёй с осями (`family`, `axes`) без канон. хеша. Скрипт на гипотезу не заводится; ветвления по Г нет — плагин выбирается по `mechanic` из `hyp_axes`. Ограничение честно: плагин видит закрытые сделки, не стакан — всё, что требует событий в позиции, остаётся Rust-механикой.

### 2.5 «Выкл. = прежний байт в байт» — механизм, а не обещание
- Каждая механика по умолчанию `None`/нет ключа; новый код читается только при наличии токена в имени/ключа в наборе.
- Гейт каждого пакета: `bash tools/vps-check.sh` (golden-тесты `bounce_grid/golden/`) + `guard.py equiv` старый/новый бинарник на одних сутках (все файлы пар по md5) — до слияния. Python-часть: пересчёт хешей всех существующих клеток Летописи = прежние.
- Версия `logic` (`bounce-v1`) **не** бампается добавлением механик, только изменением семантики существующей.

### 2.6 Добавить механику — чек-лист (после рефактора)
1. Строка в `MECHANICS` (+ вариант enum и обработчик, если нужна новая динамика) или колонка R1.
2. Тест из каталога (круг имени Rust↔Python и домены) — автоматически.
3. Строка в `hyp_axes` (`mechanic`, `param`, точки F1) → клетки и хеши строятся `master.py` без правок кода.

## 4. Решения/риски для Судьи
1. **Дыра хеша (A0)** — проверить **до** любого нового счёта. Затронутые существующие клетки: те, чей `--set` содержал `eaten*`, `frontrun_min`, `behind_min`, `stack_min` или `r1_*` кроме `r1_born_shift_cbps_min`, **не** через `variant`. Выписка из БД (сколько клеток такие, нет ли пар с одним хешем) — первый шаг A0; если пары есть, они «схлопнуты» и пересчитываются отдельным решением (В-213: только дельта).
2. Каталог (A) — рефактор ≈25 форм: гейт «байт в байт» на каждую форму обязателен, перенос одним PR, не по частям.
3. **М5 без хеша** (решение Судьи в spec §1) принято в §2.4: раннер пишет семьи в N, не в хеш-счёт. Плагин видит закрытые сделки, не стакан — всё, что требует событий в позиции, остаётся Rust (М6).
4. Параметры, которых источник не задаёт (Г-111 окно, Г-118 MACD, Г-60 масштаб, Г-102 полураспад) — назначение в П-15; пакеты D/E/F их не изобретают (правило «изобретённое число запрещено»).
5. Строки спецификации помечены «опись» (не сверено кодом): перед реализацией каждого пакета Инженер сверяет по коду; расхождение — запись в лог тикета, а не молчаливая правка оценки.
6. Не делаем: новых рантаймов, Python-механик, которым нужны события в позиции, ветвлений по номерам Г.
