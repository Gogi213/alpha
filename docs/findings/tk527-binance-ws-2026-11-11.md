## Итоговый формат и состав (В-133, В-134, В-135, В-137, В-139) — 11.11 22:05

**Формат:** строки `тип 	 поля`, числа биржи строками как пришли (В-172), приём `local_ns` — разностью к предыдущей записи файла, `E`/`T`/`u`/`a`/`f` — разностями (точные целые, обратимо: `decode()` + тест на равенство), zstd уровня 1, один файл на шард и сутки UTC `<день>/<шард>-<сессия>.tsv.zst`, при закрытии `.ok` с числом записей. Что формат не разбирает точно (ответы на SUBSCRIBE, новые поля, `nq≠q`, `ps≠s`, `st≠1`) — строка `r` с кадром как пришёл. Читатель (ядро П-40) разбирает строку `split('	')` ≈ 1 млн строк/с на ядро (замер).

| вариант (60 с…17 мин живых данных, 64 символа book / 64 trade) | book, МБ zstd3 | trade, МБ zstd3 | разбор при записи |
|---|---|---|---|
| сырой кадр + приём (было) | 12,65 | 2,34 | — |
| компактный текст, числа абсолютные | 11,86 | 1,97 | 5–6 мкс/кадр |
| **дельта-текст (выбран)** | **8,3** (zstd1: 7,8) | **1,15** (zstd1: 1,07) | 7–9 мкс/кадр |

Выбран дельта-текст, zstd 1: на 34 % (book) и 51 % (trade) меньше сырого JSON и в 5 раз быстрее читается (1 млн строк/с против ≈ 0,2 млн/с у JSON); потеря точности нулевая (приём в нс). Скорость записи: уровень 1 — 146–151 МБ/с против 84–88 у уровня 3. Бинарный формат с f64 (как L1-файлы `pq2bin`) не взят: цены станут приближёнными, а размер выигрыша не мерился — не успел (открыто).
Сброс на диск — раз в 1 с (A8 требует ≤ 10 с): лаг отдачи p50 ≈ 0,6 с, размер +1 % к сбросу раз в 10 с.

**Здоровье (В-134):** каждый шард раз в 10 с пишет `frag/<шард>.json`, главный процесс сводит их в `/data/health/binance.json` (схема 1, `collector-health-format-2026-11-11.md`): символы в подписке / с данными за минуту (по книге, только из пула), пинг p50/max, таймауты (пауза без кадров > 3 с на соединении — порог ≈ 2 × максимальной паузы здорового окна 1,55 с на 984 окнах; пинг без pong > 10 с), переподключения, лаг прихода p50/p99 за 60 с, лаг отдачи (приём → сброс на диск), `last_frame_ms`, `last_write_ms`. ## Причина разрывов и отставания (В-140) — 11.11 22:30–22:50

**Лимиты Binance не причина:** потоков 64 из 1 024, входящих 5/с из 10/с, подключений 16–17 за запуск из 300 за 5 мин; при 16 потоках на соединение (32 соединения) отставание у 14 из 32 за 4,5 мин — меньше нагрузка не лечит.
**Причина — потери/переупорядочение пакетов на пути srv (NL) → AWS Токио**, замер `ss -tin` на 49 соединениях: `rcv_ooopack/segs_in` 4–5 % при RTT 294–314 мс и 15–20 % при RTT 383–421 мс; на один IP `18.179.86.100` разные порты дают RTT 309 и 387 мс — путь выбирает хеш 4-кортежа (rehash). Потеря = ожидание ≥ 1 RTT/RTO, данные догоняют пачкой, лаг p50 растёт до 5–30 с при CPU 2–7 % (не наш узкий участок). Поток bookTicker ≈ 58 КБ/с на соединение — выше пропускной способности плохого пути; aggTrade (3,5 КБ/с) и mark не страдают.
**Замер путей** (`probe_paths.py`: 8 IP × 3 соединения, 64 bookTicker, 45 с): чистые — ooo 5–8 %, лаг p50 250–265 мс, p99 640–945 мс (13 из 24); плохие — ooo 17–39 %, лаг растёт до 6–30 с (7 из 24); ещё 3 с всплесками p99 2,7–6 с. Плохой путь зависит от порта, не от IP.
**Лекарства (по порядку):**
1. Ping без pong → `transport.abort()` (мёртвый сокет при RTO до 120 с), @d0967d6c — это был наш баг, а не причина.
2. Выбор пути при подключении (@202fd052): 15 с проверки лага (p50 ≤ 500, p99 ≤ 1 500 мс — назначаемое, из замера), плохой путь закрывается и подключается заново до приёма в «живые» (`path_rejected`/`path_ok`, до 8 подряд). Окно 3 (22:35:47–22:45:47): 1 отбраковка из 18 при старте, но на book03 путь **испортился посреди жизни** (+96 с, p99 пробы был 604 мс) → `lag_reconnect`: выбор при подключении недостаточен.
3. Смена пути без разрыва (@cc3ee360): сессия с p50 лага > 2 с два окна по 10 с подряд помечается `degraded`; `run()` открывает **замену**, ждёт приёма её пути (то же окно проверки), затем перекрытие 20 с и закрытие старой — `path_switch` (не разрыв: данные идут с обеих сессий, дубли снимает писатель по `u`/`a`/`E` (В-142); `lag_reconnect` больше нет). Та же схема у ротации 23 ч.

## Устройство: ядро + адаптер (В-142, В-143) — 11.11 23:55, коммит 085e70c3

Ядро — пакет `tools/collector/wscore/` (9 модулей, 13–119 строк, зависимости только сверху вниз, карта — `wscore/__init__.py`); биржа — один файл `<биржа>_ws.py` (Binance — 123 строки); приёмка — общий `accept_ws.py --exchange <биржа>`.

| модуль | одна обязанность |
|---|---|
| `stats` | окно, период статистики, перцентиль |
| `codec` | формат записи: Encoder, decode, ключ дедупа (спецификация формата — в шапке) |
| `writer` | файл шарда за сутки UTC, `.ok`, **снятие дублей** (ключ b — u, t — a, m — E) |
| `path` | окно проверки нового пути (PathProbe), сторож лага живого соединения (PathWatch) |
| `metrics` | счётчики шарда -> строка статистики и фрагмент health |
| `health` | фрагменты шардов -> `health.json` (схема TK-529) |
| `session` | одно соединение: подключение, подписка, пинг, чтение кадров |
| `shard` | писатель + сессии: переподключение, смена пути без разрыва, ротация 23 ч |
| `runner` | процесс: пул, раскладка, запуск шардов, health раз в 10 с |

**Поток данных:** кадр биржи -> `session` (`Adapter.parse` -> записи) -> `writer` (дедуп -> `Encoder` -> zstd1) -> `<root>/<день>/<шард>-<запуск>.tsv.zst`; `session` -> `metrics` -> `health.write_fragment` (`frag/<шард>.json`) -> `runner` -> `health.json`.
Заплатки E-023…E-025 встроены: номер запуска = время старта процесса (имя файла писателя), один писатель на шард (нет файла на попытку), нет pong -> `degraded` -> замена без разрыва (нет `ping_reconnect`). Дубли на перекрытии 20 с снимает писатель; формат одинаков для всех бирж.
