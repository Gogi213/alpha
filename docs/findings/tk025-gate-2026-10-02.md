## Находки (решение — Судья/CEO)

- **Н1 (Rust, асимметрия бид/аск).** `feed_frames_multi` зовёт трекер дважды за кадр (бид, затем аск): на бид-проходе аск-сторона `BookView` — **прошлого**
  кадра, на аск-проходе бид уже новый. Затронуты `obi*`, `micro_off_cbps`, `ofi_*` у бид-стен: «последний кадр ≤ t0» для аск-половины отстаёт на кадр.
  Причинно (будущего нет), но зеркальность нарушена. Python совпал только с моделью «два прохода». Варианты: принять и записать в определение, либо
  вести книгу по полному кадру (тогда `obi*` бид-стен чуть изменятся; на гейт «старые колонки побайтно» не влияет).
- **Н2 (неоднозначность `vpin_bp`).** Совпала одна трактовка: размер бара = `max(1, flow_1h/50)` на открытии бара по обороту с учётом текущей сделки,
  RPI-сделки входят, бары — после 60 мин от первого кадра.
- **Н3 (`frontrun_levels`).** Определение «на кадре касания» вырождено (лучшая цена = стена → 0); Rust берёт наблюдение за 1–2 с до касания по слотам
  от рождения уровня. Не сверено; определение в доке надо переписать по коду.
- **Н4 (`opp_wall_dist_cbps`, `opp_wall_ratio_bp`).** «Живая» противоположная стена = уровень, отобранный трекером (H3), а не лучшая цена книги; из бинлога
  без трекера не восстановить (совпало 4–5 из ~306) — определение в доке уточнить.
- **Н5.** `cancel` с RPI / без RPI данными не различим (AAVE: RPI 0; INTC: 400, но не на ценах стен).
