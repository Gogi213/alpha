## Дефекты по важности

Важность: **неверное число** — число не то, за что выдаётся; **вводит в заблуждение** — число верное по определению, но без подписи читается как
другое; **косметика**.

### Д1. «После комиссий» — верхняя граница при нулевой задержке, не достижимый результат — *неверное число для решения*

`arb_inc.py:193,205` (круг = Sell входа − Buy выхода, обе цены в тот же миллисекундный миг, когда условие выполнилось), `core.py:210`.
Вход — в первый момент, когда исполнимая цена ушла на ≥ 12,6 bps от центра; выход — в момент, когда середина вернулась к центру. Оба события видны
по времени биржи E; робот на srv узнаёт о них через лаг (Binance p50 117 мс, Bybit 109, BingX 88 — сырые записи 15.11) и ещё столько же везёт ордер.

Проверка (`indep.py`): тот же вход и выход, но исполнение через L мс после события по ценам того момента, EVAA, медиана / доля > 0:

| L, мс | binance-bybit (7782 эп.) | binance-bingx (13 577) | bybit-bingx (6200) |
|---|---|---|---|
| 0 (как на вкладке) | −2,2 bps / 36,6 % | +0,2 / 51,9 % | −1,6 / 39,5 % |
| 50 | −22,2 / 0,7 % | 0,0 / 50,2 % | −2,1 / 41,1 % |
| 100 | −23,2 / 0,6 % | −1,9 / 42,8 % | −4,4 / 35,6 % |
| 250 (≈ лаг туда и обратно с srv) | −24,9 / 0,3 % | −13,5 / 22,2 % | −18,0 / 17,7 % |
| 500 | −25,2 / 0,4 % | −20,0 / 7,4 % | −25,6 / 4,7 % |

У binance-bybit край исчезает уже через 50 мс: вход — мерцание котировки Binance (у Binance EVAA E-шаг записей p50 1 мс). Кроме того, круг считается
на любой объём (глубина лучшего уровня есть в состоянии, `arb_inc.py:157`, на странице не показана) и без фандинга.

Исправление: подпись «верхняя граница: мгновенное исполнение по лучшей цене, время биржи, объём не ограничен»; рядом столбец «после комиссий, +250 мс»
(в `machine` — цены сторон на T_вход+L и T_выход+L: тот же carry, что уже есть) и, по желанию, объём лучшего уровня на входе.

### Д2. Пары с BingX раздуты устаревшими снимками BingX — *вводит в заблуждение (счётчики, пик, круг)*

BingX шлёт `bookTicker` снимками по таймеру: E-шаг записей EVAA p50 302 мс, p90 405 мс. Вход в эпизод почти всегда — движение другой биржи при старом
снимке BingX:

| пара | входов от другой биржи | возраст котировки BingX на входе p50 / p90 |
|---|---|---|
| binance-bingx | 13 087 из 13 577 (96 %) | 221 / 843 мс |
| bybit-bingx | 5768 из 6200 (93 %) | 232 / 781 мс |

По всему окну: из 378 889 закрытых эпизодов 309 423 (**82 %**) — пары с BingX; из 20 верхних строк по числу эпизодов — **17** с BingX; из 234 строк с
медианой круга > 0 — 101 с BingX. Как стояла настоящая книга BingX между снимками, данных нет — эпизод может быть и реальным, и артефактом.

Исправление: подпись у BingX («книга снимками ≈ 3/с»); вход считать, только если котировка второй стороны не старше Δ (например, 100 мс) или если
расхождение подтвердил следующий снимок BingX; второй вариант — отдельный счётчик «подтверждённых».

### Д3. Время — по часам биржи E, а не как видит srv; половина эпизодов короче секунды — *вводит в заблуждение*

`parse_inc.py:74` (e = приём − лаг), `arb_daemon.py:370`. Ряды двух бирж сводятся по их собственным часам; вид «приём» (`core.rx_view`) в живом счёте
не используется. Своя реализация на времени приёма (EVAA): binance-bybit **7782 → 4557 эпизодов (−41 %)**, круг среднее −0,17 → +2,10 bps;
binance-bingx 13 577 → 12 291 (−9 %); bybit-bingx 6200 → 6015 (−3 %). Схождение по всем 378 889 эпизодам: < 100 мс — 11,2 %, < 1 с — **53,9 %**,
< 5 с — 81,7 %; среди эпизодов с кругом > 0 короче секунды — 61,9 %. Точность сведения часов двух бирж — десятки мс, поэтому «схождение» < 100 мс —
ниже точности.

Исправление: подпись «время биржи»; столбец «схождение» — с нижней границей «< 0,1 с»; если вкладка отвечает на вопрос «что увидит робот на srv» — считать
по приёму.

### Д4. Gate: «за 1 сут», выбросы за сутки и оборот — за ≈ 11 ч, а не за сутки — *вводит в заблуждение (после выкладки Gate)*

Окно таблицы общее: `t0 = max(START_MS, t1 − 24 ч)` (`arb_daemon.py:238`, `arb_turnover.py:281`), `vwin` одно на всю таблицу (`arb_api.py:50`).
У Gate данные с 15.11 05:49 UTC (`common.py:182`). REST Gate за 24 ч против нашего оборота: p50 **0,33**, 137 из 141 монеты вне 0,8–1,25 (тот же
0,33 нашла репетиция выкладки, `arb-dense-deploy-2026-11-15.md:59`; против свечей Gate за то же окно — 1,001). Сортировка по «за 1 сут» и по обороту
смешивает 24-часовые пары с 11-часовыми. Самоисправится 16.11 ≈ 06:00 UTC.

Исправление: до тех пор — пометка у столбцов Gate «за N ч» (начало данных пары в строке) или серый цвет.

### Д5. Комиссия 12,6 bps — тариф владельца на Bybit на всех биржах — *нужна подпись*

`core.py:13`: 4 тейкерские ноги × 3,5 bps × 0,9 = 12,6 bps — ровно по приказу п. 12 (`.claude/preferences.md:16`), не ошибка. Но на странице этого
не видно, а базовые публичные тарифы тейкера (по памяти, не сверены сегодня): Binance 5,0, Bybit 5,5, OKX 5,0, BingX 5,0, Gate 5,0 bps → 4 ноги ≈ 20–21 bps,
то есть круг ниже на 7–9 bps на ногах без тарифа владельца.

Исправление: подпись «комиссия 4 × 3,15 bps (тариф владельца, все биржи)»; при другом тарифе на бирже — комиссия по бирже ноги.

### Д6. «Расхождение» — пик отклонения исполнимой цены от центра, а не разница цен бирж — *нужна подпись*

`arb_inc.py:259`: Es = Sell − центр, Eb = центр − Buy; столбец — медиана / p95 / макс. пика по эпизодам (`core.py:211`). Центр — скользящая медиана
за 60 мин, поэтому постоянный базис не виден: INIT binance-okx — центр +227 bps, INIT okx-bingx −221 bps, а «расхождение» считается от них.
Вход в эпизод — уже при отклонении ≥ 12,6 bps, поэтому медиана пика всегда ≥ 12,6 (по окну p50 17,4 bps).

Исправление: заголовок «пик отклонения от центра»; отдельной цифрой — сам центр (постоянный базис пары).

### Д7. Сортировка по умолчанию выводит наверх пары с 1–2 эпизодами — *вводит в заблуждение*

`page-dense.html:270` (`sort:'size'`, по убыванию медианы пика). Число эпизодов за сутки у 20 верхних строк: 2, 2, 14, 87, 2, 18, 1, 2, 9, 1, 2, 4, 1, 192,
3, 9, 7, 10, 5, 115. У 509 из 1975 строк 1–19 эпизодов, для них p95 ≈ макс. Из 234 строк с медианой круга > 0 у 115 меньше 20 эпизодов.
Отмечено ещё в `arb-tab-handoff-2026-11-15.md:34` («нужен порог числа эпизодов»), не сделано.

Исправление: порог (например, ≥ 20 эпизодов) для медианы и p95 или «—» с числом эпизодов; сортировка по умолчанию — по числу эпизодов.

### Д8. Эпизоды не знают о провале сбора одной стороны — *скрытый, сейчас 0 случаев*

`arb_inc.py:209-261`: строки пары создают записи любой стороны; если сборщик второй стороны молчит, Sell/Buy считаются против её последней
котировки. `Alive` (минуты без единой записи по бирже) влияет только на график (`arb_inc.py:274-298`); молчание одного символа или одной полосы при
живой бирже не видно вовсе. За текущее окно мёртвых минут 0, эпизодов рядом с ними 0 — сейчас чисел не портит, при первом же падении сборщика даст
ложные эпизоды с пиком до размера движения цены за время провала.

Исправление: строку пары не создавать (или эпизод не открывать), если котировка второй стороны старше порога при неживой минуте её биржи / полосы.

### Д9. Фильтр «одна монета» (0,9 < отношение < 1,1) — *скрытый, сейчас ошибок нет*

`arb_daemon.py:179-180, 207, 226-227`: отношение середин, каждая — медиана первой пачки символа, замороженная навсегда; отвергнутая пара
перепроверяется с теми же замороженными числами, то есть навсегда. Пересборка (Gate) судит по общему отрезку (`span_ratio_ok`), живой путь — нет.

На данных: отвергнуто 5 пар (BB binance-okx 0,001; BB okx-bingx 1581; ON binance-bybit 0,001; ON bybit-bingx 821; ANTHROPIC okx-bingx 0,076) — все
верно, текущее отношение тоже вне (0,9; 1,1); ложных пропусков **0**. Принятых пар с текущим отношением вне (0,9; 1,1) — **0**. Признаки чужой монеты
(центр гуляет на проценты): максимум |центр| 227 bps (INIT), максимальный размах центра p1–p99 598 bps (SOPH bybit-okx) — обе монеты на всех парах
ведут себя одинаково, это базис, не чужой актив. Ловушка остаётся: одинаковый тикер разных активов с ценами в пределах ±10 % фильтр пропустит.

Исправление: отношение по скользящей медиане на каждом проходе; для новых пар — проверка корреляции минутных изменений середины.

### Д10. Подписи направления и смысла счётчиков — *косметика*

- «Binance → BingX» (`page-dense.html:322`) читается как направление сделки; в строке сложены оба направления (Sell и Buy), стрелка — лишь порядок бирж.
- «эпизодов за 1 ч / 4 ч / 6 ч / 1 сут» — настоящие эпизоды с началом за последние N ч до t1 (`arb_inc.py:323-324`), не пересчёт; открытые входят. Верно, подпись не нужна, кроме Д4.
- «выбросов ≥ 0,3 / 0,5 / 1 %» — эпизоды порога 12,6 bps за 24 ч, у которых пик ≥ 30 / 50 / 100 bps (`core.py:194-199`); открытые — с пиком на сейчас. Верно.
- «схождение» — до возврата **середины** к центру, а не до момента, когда круг стал прибыльным; медиана и p95 — только по вышедшим (влияния нет, см. таблицу проверок).
- Круг — приближение (Sell_i − Buy_j в bps вместо точного P&L); ошибка второго порядка, B_j·(1 − bid_B,j/ask_B,i), < 0,1 bps при |центр| < 100 bps.
- График: центр слота — центр последней живой минуты, максимум Sell — любой минуты слота; поэтому 7 строк ниже таблицы на > 3 bps.

## Вердикт для владельца

Арифметика вкладки верна: все 1975 строк пересчитаны из состояния без единого расхождения, своя реализация с нуля по сырым данным дала те же
эпизоды (97–99,8 %). Оборот совпал с биржами: ±0,1 % у Binance, Bybit и BingX, −1 % у OKX.

**Можно верить без оговорок:** «монета», «пара бирж», оборот по Binance, Bybit, OKX, BingX; «эпизодов за 1 / 4 / 6 ч / 1 сут» и «выбросов ≥ 0,3 / 0,5 / 1 %»
как счёт событий по данным; график.

**Неверно для решения о торговле:** «после комиссий». Это верхняя граница: сделка в ту же миллисекунду по лучшей цене на любой объём. При задержке
исполнения 250 мс (лаг с srv до бирж и обратно) медиана на EVAA падает с −2…+0,2 до −13…−25 bps, доля прибыльных — с 37–52 % до 0,3–22 %.

**Нужна подпись или доработка:**
- пары с BingX — 82 % всех эпизодов и 17 из 20 верхних строк; почти все входы приходятся на устаревший снимок BingX (возраст p50 ≈ 0,2 с);
- время — по часам бирж; на времени приёма srv эпизодов binance-bybit на 41 % меньше; 54 % «схождений» короче секунды;
- комиссия 12,6 bps — ваш тариф Bybit на всех ногах;
- «расхождение» — пик отклонения от центра (медиана за 60 мин), а не разница цен бирж;
- сортировка по умолчанию ставит наверх пары с 1–2 эпизодами;
- Gate после выкладки: «за сутки» и оборот у его пар — примерно за 11 ч, до 16.11 ≈ 10:00 GMT+4.

Скрытые слабости, которые сейчас ничего не портят (0 случаев): провал сборщика одной стороны даст ложные эпизоды; фильтр «одна монета» замораживает цену первой пачки.
