# Сканер на К вариантов одного t0 — дизайн (TK-049, 06.10, по CEO 03:40)

**Что уже общее.** Групповой путь (Э-08, `drive_signal_group`/`run_round_group`) делит ОДИН вход (σ, qty, entry_part равны) между К вариантами выхода на одном движке: наши заявки не двигают глубину модели очереди (`queue_model.trade`), поэтому К вариантов на одном движке = К сольных прогонов. На d15: 348 групп, 6 148 членов, 29,9 с на круги групп (4,9 мс/член). Соло: 7 633 круга, 87,6 с (11,5 мс/круг), 2 517 разных окон (t0, attempt) ⇒ K = 3,03 по числу, 2,34 по строкам; d01: 849 / 742 ⇒ 1,14 / 1,09 (замер 06.10, `k-*` в `/data/tk051/stand-out`).

**Что делит сканер.** Для соло-кругов с одним (t0, attempt), но разными (σ, qty, entry): один разворот окна, одно применение строк к книге (apply/advance_to), одна лента ожидания; на вариант остаются свой StrategyState, своя заявка/очередь, своё решение. Потолок по профилю b14 d15: общее = книга 14,7 + ожидание/лента 4,3 + разворот 10,7 = 29,7 % user; снимается (1−1/K).

**Точка расхождения (правило Судьи 00:10).** Вариант ветвится от общего хода при первом отличии: ордер, цена/размер, время отправки с задержкой В-68, место в очереди prob:3, занятость (busy), перенос через полночь. У вариантов с разными entry/qty ордер отличается уже при t0 ⇒ общее у соло-К — только книга, лента и разворот окна, а не вход (вход делит групповой путь). Итог по каждому варианту — свой полный путь; гейт — rounds.csv и сводка байт в байт против b14 (729 файлов d15/d01).

**Что не делится и ломается (из истории общего движка m7, +9 % user).** (1) Позиция/`has_open_orders`/`clear_last_trades` у движка одни на актив — чужая заявка видна варианту; нужен учёт «чья заявка» на клон (Э-08 решил только для выходов). (2) Часы: окна — суффиксы с разных стартов, вариант ждёт до своего wake; лок-степ по строке проигрывает union (62 % активных строк d15), а не окна. (3) FAST_BOOK шаг 3 показал: снятие apply (−14 %) вернулось чтением ряда (+15,7 %) — выигрыш по книге съедает чтение вида.

**Ожидание.** Валовой потолок d15 −17 % (K = 2,34), d01 −2,5 % (K = 1,09). Реально снимаемое по опыту: кэш разворота дал −2…−3 % из расчётных −6 %; книга+лента — доля (1−1/K) за вычетом чтения вида на вариант ⇒ нетто −5…−9 % user d15, ≈ −1 % d01. Критерий CEO (−10 % user d15 при diff 0, иначе стоп) вероятно НЕ берётся; прототип стоит ≥ одной сессии кода + сборка + пары. Решение: см. запись в логе TK-049.
