## 3. Узкое место и выбор (предварительно)
Алгоритм: варианты — (а) эталон dict+max/min; (б) dict + ленивые кучи; (в) Rust-ядро (парсинг строк цены в целые тики, отсортированный вектор уровней/куча); замер — (а) 11 ктрок/с, (б) 798 ктрок/с, (в) не измерен; выбран — пока (б) как проверенный эталон для «байт в байт», потому что сохраняет последовательность лучшей пары при ускорении ×73.
- После ускорения книги узким местом остаётся **чтение parquet и строка→число** (1–2 Мстрок/с на ядро, один row group = нет параллели внутри файла): параллель — по файлам (контракт×час), 8 ядер.
- Rust-ядро нужно прежде всего для совмещения двух бирж по мс (слияние потоков, as-of) и модели очереди; парсинг parquet в Rust (крейт `parquet`/arrow-rs) надо измерить против pyarrow — если не быстрее, читать pyarrow и отдавать Rust массивы (Arrow IPC/numpy) — решает замер.
