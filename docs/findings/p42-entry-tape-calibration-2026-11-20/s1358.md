#### 3. Определения замера (по сырой ленте, на каждом лоте каждого входа)
- **Лоты.** Лонг — один лот (500 $). Шорт (`e2 = 0,05`) — лот 1 и, если был, лот 2 (по 250 $; из `short-detail.jsonl`: `entry_ms`, `entry_px_e8`, `legs`, `lot2`). На каждом лоте: сторона `s` (+1 лонг, −1 шорт), момент входа `T` = `entry_ms` лота (абсолютные мс), размер лота `N` (500 / 250 $).
- **Заменитель `p_x`** — пересчитан по ленте как в движке: последняя сделка с агрессором стороны (лонг — `is_buyer_maker = false`, шорт — `true`) со временем ≤ `T`, порядок файла суток, возраст `T − t ≤ 5` мс. Ворота G-px (п. 6).
- **Событие тейкера** — непрерывная серия строк `aggTrades` (порядок файла) с одним `transact_time` и одной стороной агрессора (допущение: одна заявка; две чужие заявки в одну мс не различаются).
- **Правда A (лучшая цена):** `A` = первая цена первого события стороны со временем **> `T`**; задержка `L_A` = t − T.
- **Правда V (заявка на `N`):** `V` = средневзвешенная цена прохода по сделкам стороны со временем > `T` по порядку, пока не набрано `N` $ (последняя сделка — частью); задержка `L_V` = время сделки, добравшей `N`, − T. Модель, на допущении: «книга в момент `T` ≈ то, что съели следующие тейкеры» (книга между сделками может пополняться или сниматься).
- **Объём лучшего уровня (по ленте):** первое событие стороны после `T`; если в нём ≥ 2 разных цен — объём L1 = Σ qty·price по первой цене (**точно**: уровень съеден целиком) → класс «L1 < N» или «L1 ≥ N»; если цена одна и объём события ≥ N — «L1 ≥ N» (доказано); иначе — «не известно» (цензура снизу).
- **Ошибка (бп, знак «хуже для входа» > 0):** `e_A = s·(A − p_x)/p_x·10⁴`, `e_V = s·(V − p_x)/p_x·10⁴`. Модель движка закладывает 1 бп (`slip`), поэтому **недоучёт** = `e − 1`.
- **Окно правды Δ** ∈ {50, 100, 250, 500, 1000} мс: лот «покрыт» при `L ≤ Δ`. **Главное Δ\*** — по стороне, правило до счёта: наименьшее Δ сетки, при котором покрыто ≥ 80 % лотов стороны по V; нет такого — Δ\* = 1000 мс с оговоркой. Остальные Δ — описательно.
- **Возраст заменителя** `T − t(p_x)` — распределение (доля 0…4 мс, 5 мс); правило §13.16 повторяется по ленте: **W\*_лента = наибольшее W из {5, 10, …, 5000} с средним |e_A| ≤ 1,0 бп** (на покрытых при Δ\*), иначе наименьшее W. Заметка до счёта: в `meta.json` всех 6 баз счётчик `stale` = 0 — при W ≥ 5 ни один вход не отвергался по возрасту, поэтому **любое W ≥ 5 мс даёт те же сделки по построению**; W < 5 мс в сетке §13.16 нет и здесь не считается.

По стороне × {все, крипто, TradFi} × {июль, август, сентябрь, октябрь, 01–13.11, всё}: лотов, суток с лотами, покрытие по Δ; `e_A` и `e_V` — среднее, средний |e|, p90 |e|, доля `e > 1` бп, доля `e < 0` (заменитель хуже правды); недоучёт среднего `e_V − 1` бп; классы L1 (< N / ≥ N / не известно) и доля «< N» среди известных; задержки `L_A`, `L_V` (среднее, p90). Медиан нет. Объём выборки: ворота G-n (п. 6).

#### 5. Блоки
- **Блок V — сверка метода ленты с книгой 13.11 (описательно).** 33 сигнала `b0` §13.16 с записью книги (выписка `/data/p42-t566/cal/book`, сигналы `/data/p42-t566/out/cal/b0/*-sigs.csv`, `T = T0(01.09) + sig_ms + 4`): `A` и `V` (N = 500 $) по ленте 13.11 (`/data/p42-tk621/wc/aggtrades`) против книги (лучший ask / bid последней записи ≤ T): средняя разность и |разность| (бп), совпадение класса L1 ленты с L1 книги (`qty·price` < 500 $). Решений не двигает.
- **Блок P — P&L при откалиброванном входе (на сделках баз, ноги выходов фиксированы).** Для каждого лота: gross′ = Σ по ногам `u·s·(px − p′)/p′` (ноги `legs` = [мс, цена ×1e8 с проскальзыванием выхода, $, мейкер] из `*-detail.jsonl`; ворота G-leg), fees — как в базе (разница комиссии выхода от сдвига на единицы бп < 0,001 $ на сделку — пренебрежимо). Варианты:
  - `P_A` — `p′ = A` (лучшая цена по ленте, без `slip`);
  - `P_V` — `p′ = V` (заявка на N по ленте) — **главный вариант**;
  - `P_m` — `p′ = p_x·(1 + s·ē_V/10⁴)`, ē_V — среднее `e_V` стороны (равномерный сдвиг; контроль формы);
  - у лота без правды при Δ\* — `p′ = p_x·(1 + s·ē/10⁴)` (среднее покрытых той же стороны и класса), число таких — в отчёт.
  Модель, на допущении: «ноги выхода (время, цена) при сдвиге входа на единицы бп не меняются» (тейки, стоп и трейл движка считаются от цены входа — сдвиг их уровней на те же бп). Допущение проверяется блоком E.
- **Блок E — движок со `slip` ∈ {0, 2, 3, 5}** (сдвиг и входа, и тейкерских выходов; база — 1): Σ $, сделок, Sharpe по стороне — описательная кривая «P&L против проскальзывания»; для ворот G-path тот же сдвиг считается формулой блока P на ногах базы (вход ±(k − 1) бп, тейкерские ноги ∓(k − 1) бп, мейкерские без изменений).

#### 6. Ворота (до чтения P&L; расхождение — остановка и разбор)
- **G-bin:** sha256 бинаря ∈ `tk625_run.BIN_SHA_OK`.
- **G-base:** прогон баз с `P42_DETAIL=1` — `*-trades.csv` и `*-daily.csv` всех окон и сторон байт в байт с `/data/p42-tk625/h775/base/`.
- **G-leg:** у ≥ 99,5 % лотов Σ по ногам `u·s·(px − e)/e` (e = `entry_px_e8` лота) = gross лота (лот 1 + лот 2 = gross сделки) с |Δ| ≤ 1e-6 $·(число ног); иначе формула блока P неверна — остановка.
- **G-px:** у ≥ 99 % лотов `p_x·(1 + s·slip/10⁴)` (округление как `frac` движка) = `entry_px_e8` лота с точностью 1 ед. ×1e8; несовпавшие — списком; у несовпавших `p_x` берётся из движка (`entry_px_e8 / (1 + s·1e-4)`), число — в отчёт.
- **G-tape:** ни одна прочитанная строка ленты не позже 13.11 23:59:59.999 UTC; проход V, не добравший N до конца 13.11, — «не покрыт».
- **G-n:** ≥ 30 разных суток с лотами у каждой стороны; крипто и TradFi — у каждой стороны ≥ 1 лот (число — в отчёт); иначе — оговорка первой строкой.
- **G-path:** у каждой стороны и каждого `slip` ∈ {0, 2, 3, 5}: |ΣΔ движка − ΣΔ формулы| ≤ max(2 $; 10 % |ΣΔ движка|). Не прошло ⇒ допущение блока P не держится: главным ответом становится движок со `slip` = округлённое (1 + ē_V) (целые бп; ключ `slip` — целый), блок P — описательно.
- **G-splice:** Σ (gross − fees) базы после склейки = Σ готового ряда базы (`tk643_run.load_cell` на готовых файлах) с допуском 1e-6.

#### 7. Статистика и правило ответа (записано до счёта)
На каждом варианте P и E: сделок, Σ $, $ на сделку, годовой Sharpe, по месяцам (Σ, сделок), R:R, стопов и убыток стопа ($ и % маржи при плече 2), максимальная просадка; **парная ΔΣ к базе по суткам** (`tk604_stats.delta_stat`: ΔΣ, SE_Σ, 95 % интервал ΔΣ ± 1,96·SE_Σ) и Δ $ на сделку. Шумовая планка (контекст, вариантов не выбираем): `selection_bias.significance` годового Sharpe каждого варианта при N = 7 вариантах стороны (P_A, P_V, P_m, E×4) — планка и дефлированный Sharpe печатаются.
**Ответ по стороне** (по `P_V`, или по движку при провале G-path):
- **«калибровка сдвигает базу»** — если 95 % интервал ΔΣ не накрывает 0; печатается ΔΣ, новый Σ, $ на сделку, Sharpe;
- иначе **«сдвиг в шуме»** — ΔΣ с интервалом и MDE ≈ 2,8·SE_Σ.
**По W:** W\*_лента и таблица — описательно; если W\*_лента ≠ 5 мс, это не меняет сделок баз при W ≥ 5 (п. 3) и пишется одной строкой.
**По объёму L1:** доля «L1 < N» среди известных и доля «не известно» — по стороне и классу.
