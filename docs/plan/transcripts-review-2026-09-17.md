# Разбор транскрипций, аудит коллектора, план — рабочий промпт (редакция 2026-09-17)

Исходный промпт владельца адаптирован под фактическое состояние проекта. Ниже — что поправлено
и почему, затем действующая редакция этапов.

## Что поправлено

1. **Посылка «первый готовый компонент — коллектор» устарела.** Построено: коллектор (формат v3,
   олвейс-он, сервер OVH, 100 монет), `verify` (В-56), `levels`/`markout`, касания живых уровней
   (T35, В-42/В-43/В-45), профили касаний по девяти осям (T37, В-44), сделка-отскок в бэктесте
   (T38; вердикт 2026-09-13: `net_fill` < 0 на десяти монетах), дашборд. Оба «отскок»-видео уже
   разбирались один раз — `docs/findings/practitioners-2026-09-13.md`, их признаки стали осями
   В-44. Поэтому **этап 1 — полная спецификация со сверкой**: каждый пункт помечается
   «формализовано (где)» / «нет» / «расходится с нашей формализацией». Иначе второй раз
   изобретаем то же самое.
2. **Ссылки — файл + таймкод** в нотации SETTLED В-44: `[S 12:50]` — «отскок станок»,
   `[D 01:57]` — «отскок dizzi». Для остальных семи файлов — свои буквы (таблица в этапе 2).
   Утверждение без таймкода не считается подтверждённым.
3. **Этап 2 — субагентами по файлу** (В-39: 700 КБ транскрипций ≈ 300к токенов в контексте
   не держим), единый формат отчёта на файл. «Противоречит» проверяется и против этапа 1, и
   против уже принятых решений (В-46, В-51, В-52: сетап — из ручной торговли, микроструктура —
   инструмент).
4. **Этап 3 — не аудит с нуля.** Точка отсчёта: `docs/ARCHITECTURE.md` A1–A9,
   `docs/findings/audit-2026-09-12.md`, `collector-2026-09-12.md`, семь запретов горячего пути
   (`interfaces.md`), В-56. Утверждения этих документов проверяются по коду, в отчёт идёт дельта
   и то, чего они не покрывают. Известное заранее и обязательное к разбору: сервер пишет **v2**
   до перезапуска (В-48); `verify` на сервере не гонялся; ротации/выгрузки нет (9 суток диска).
5. **Этап 4 — сверка с `docs/plan/PLAN.md`** (волны, гейты, точки В-38), не новый план: каждое
   звено цепочки «коллектор → … → реальная торговля» помечается готово / частично / нет с
   названным артефактом. Фича «сила плотности» сверяется с существующим порогом `H3`
   (`floor`/`percentile`, `k` — В-30), корзинами `SIZE_LABELS` и разбором
   `docs/findings/touch-size-axis-2026-09-13.md`.
6. **Артефакт каждого этапа — файл** (правило «шаг не закрыт без артефакта на диске»):
   этап 1 — `docs/findings/bounce-spec-2026-09-17.md`, этап 2 — `transcripts-2026-09-17.md`,
   этап 3 — `collector-audit-2026-09-17.md`, этап 4 — `roadmap-2026-09-17.md`. В чате — выводы,
   детали коротко, вопросы. Код, `SETTLED.md`, `BUSINESS-TASK.md` не трогаются: решения по
   вопросам принимает владелец, потом они попадают в SETTLED отдельным шагом.
7. **Числа:** изобретённых нет — либо цитата с таймкодом, либо константа кода с путём, либо
   `[предположение]`.

## Действующая редакция

Работа по этапам строго по порядку; после каждого — результат и ожидание подтверждения.
Код не пишется и не меняется.

**Правила.** Каждое утверждение о стратегии — с таймкодом. Не из транскрипций —
`[предположение]`. Противоречие или пробел — вопросом, не додумкой. Плотно.

**Этап 1. Спецификация «отскока».** Файлы «отскок станок», «отскок dizzi». Уровень и его
определение; вход, выход, стоп, отмена; фильтры; все числа; данные на каждый пункт. Плюс
колонка сверки с `practitioners-2026-09-13.md`, В-42…В-46, осями T37. Отдельно — расплывчатое.

**Этап 2. Остальные семь файлов** (субагент на файл): о чём; чем помогает отскоку (фильтр /
вход-выход / риск / исполнение / признак уровня / ничем); противоречит ли этапу 1 или В-##.
Сводный список идей с оценкой сильно / слабо / неясно.

**Этап 3. Аудит коллектора** по шести пунктам исходного промпта (сбор, покрытие, корректность,
надёжность, хранение, качество кода) как дельта к A1–A9 и аудиту 2026-09-12; каждая проблема —
где, чем грозит, как чинить, приоритет.

**Этап 4. План и «сила плотности»**: цепочка до торговли со статусом каждого звена и критерием
«готово»; для фичи — 2–3 формулы знаменателя, близость к транскрипциям, наличие данных,
проверка на истории (в терминах уже существующих профилей касаний и markout), место в плане.
