# План разбора убыточных сделок «на атомы» (22.09, владелец; В-84 п. 1)

**Зачем.** На 5 сутках (16–20.09) лонг от старых стен даёт +$377 / 128 сделок, но один день (19.09) —
минус, и три стопа по −2 % съедают $35. Это единственный анализ, для которого 5 дней достаточно: убытки
редкие, каждый можно рассмотреть отдельно. Цель — **не улучшить среднее, а найти контекст, при котором
ветка теряет быстро**, и фильтр против него (или честно записать, что признака нет).

**Данные.** `b5/f10fix-D20-5d/a45-bid/rounds.csv` (форма `ladder3x2..20w2-pct2-1to1-7200-ttl1800`, 128
сделок; соседние формы — для проверки устойчивости), кэши `study/touches/<сутки>/` (касания, стены, размер
по времени, `mids1m`), `study/approaches/D20/<сутки>/` (взвод, стена на взводе), `study/regime/<сутки>.csv`
(BTC/ETH/пул за 1 ч и 4 ч по минутам), бинлоги для точного хода цены вокруг сделки.

## Атомы — что снимаем по КАЖДОЙ убыточной сделке (и, для контраста, по прибыльной)

| атом | откуда | вопрос |
|---|---|---|
| A1 контекст рынка на входе | `regime` по минуте взвода | BTC/пул за 1 ч и 4 ч: минус/плюс, величина |
| A2 стена на входе | подход/касание | возраст, размер $, сила ×поток, сколько раз до этого касалась |
| A3 что стена сделала после входа | размер по времени из кэша | стояла / сняли / съели / пробили насквозь — и через сколько минут |
| A4 ход цены после входа | бинлог / `mids1m` | максимум против нас и в нашу сторону за 5 / 15 / 60 мин; дошла ли до тейка по пути |
| A5 как вошли | `rounds.csv` | ног исполнено, средняя цена, доля, время от взвода до входа |
| A6 как вышли | `rounds.csv` | причина (стоп / дедлайн / тейк), время в позиции, где стояла цена в момент дедлайна |
| A7 поток за 15 мин до входа | лента из бинлога | объём агрессивных продаж/покупок, дисбаланс |
| A8 час суток / монета | `rounds.csv` | кластеризация во времени и по монетам |

## Что сравниваем

1. **Убыточные против прибыльных** по каждому атому: где распределения расходятся — там кандидат в фильтр.
2. **19.09 против остальных дней**: те же атомы по дню целиком (все 23 сделки), плюс сам день — BTC, пул,
   волатильность — чем он отличался как режим.
3. **Стопы (3) отдельно**: каждая сделка — рассказ на пять строк: что было до, что сделала стена, куда
   пошла цена, сработал бы «съели/сняли» раньше стопа, что бы дал стоп 1 % / выход по снятию стены.
4. **Дедлайны с минусом** (≈45 сделок): цена на момент дедлайна против пути — дошла ли до тейка и вернулась
   (тейк далеко) или не дошла (держать дольше / тейк ближе / фильтр).

## Выход

- `docs/findings/loss-atoms-2026-09-22.md`: таблица атомов по убыточным сделкам, сравнение с прибыльными,
  разбор 19.09, три истории стопов, **кандидаты в фильтр с оценкой** (сколько убытка режет, сколько прибыли
  теряет — на тех же 128 сделках) и честное «признака нет», если его нет.
- Данные: `study/loss-atoms-5d.csv` (сделка × атомы) на счётной; скрипт `tools/compute/loss-atoms.py`.
- Кандидат-фильтр, если найден, идёт в предрегистрацию (строка `prereg`, страж), не в бой: проверка на
  следующих днях, не на тех же.

## Чего не делать

- Не подгонять параметры под 5 дней; не считать фильтр найденным, пока он не отработал на новых днях.
- Не смешивать с шортами и проеданием (В-76): это разбор лонга.
- Не считать «19.09 — минус» доказательством: один день; но и не игнорировать — это единственный день
  снижения, и следующий такой будет проверкой любого фильтра.

**Оценка:** скрипт атомов — 2 ч, разбор и док — 2 ч. Начало — 22.09 утром после чтения ночи.

## Шаг 1. Скрипт `tools/compute/loss-atoms.py` (2 ч)

Вход: `--grid-dir b5/f10fix-D20-5d/a45-bid --form ladder3x2..20w2-pct2-1to1-7200-ttl1800 --touches study/touches
--approaches study/approaches/D20 --regime study/regime --root root --out study/loss-atoms-5d.csv`.
Выход: CSV «одна строка = одна сделка формы» (все 128, с колонкой `pnl_usd` на $1000 — В-83), колонки-атомы:

| атом | колонки выхода | как считать (источник → поле) |
|---|---|---|
| ключ | `symbol, day, t0_ns, dir, entry_px, exit_px, net_bps, pnl_usd, reason, exit_ns, hold_min, legs_filled, fill_frac` | из `rounds.csv` (колонки те же имена; `hold_min = (exit_ns − t0_ns)/6e10`) |
| A1 рынок | `btc_1h, btc_4h, pool_1h, pool_4h, eth_4h` | `study/regime/<day>.csv`: строка по `minute_ms = floor(t0_ns/1e6 / 60000)·60000`; поля `btc_ret_1h_bps, btc_ret_4h_bps, pool_ret_1h_bps, pool_ret_4h_bps, eth_ret_4h_bps` |
| A2 стена на входе | `wall_age_min, wall_size_lots, wall_size_usd, arm_dist_bps, strength_w20, flow_1h_lots, repeat_before` | `study/approaches/D20/<day>/approaches-<SYM>.csv`: строка с `arm_ms = t0_ns/1e6` и `side=bid` (`t0` круга = взвод); `age_ms/60000`, `size_at_arm`, `size_at_arm × price_tick × tick_size` (tick_size из `root/instruments.csv`), `arm_dist_bps`, `strength_w20_pct`, `flow_1h_lots`; `repeat_before` — число касаний той же стены (`price_tick`) в `touches-<SYM>.csv` с `start_ms < arm_ms` |
| A3 судьба стены | `wall_fate, wall_fate_min, size_at_exit_ratio` | в `touches-<SYM>.csv` касания той же стены после `arm_ms`: `ended_by_death=1` → «сняли/съели» (по `traded_during / size_max_before ≥ 0.5` — «съели», иначе «сняли»), `swept_lots ≥ size_at_touch` → «пробили»; ничего до `exit_ns` → «стояла»; `wall_fate_min` — минуты от входа до события; `size_at_exit_ratio` — размер ближайшего касания до выхода / `size_at_arm` |
| A4 ход цены | `adverse_5m, adverse_15m, adverse_60m, favour_5m, favour_15m, favour_60m, reached_take, mid_at_deadline_bps` | `study/touches/<day>/mids1m-<SYM>.csv` (минутная середина `mid2x` = 2×цена в тиках): от минуты входа — минимум/максимум за 5/15/60 мин против входа в bps; `reached_take` = максимум за время сделки ≥ цена тейка (тейк = вход + (вход − стоп) для `1to1`, стоп = вход × (1 − 0.02)); `mid_at_deadline_bps` — середина в минуту выхода относительно входа (для `reason=deadline`) |
| A5 вход | `arm_to_entry_min, entry_vs_wall_bps` | `t0` (взвод) → первое исполнение: нет в `rounds.csv` — взять `hold_min` как есть и `entry_vwap`; `entry_vs_wall_bps = (entry_vwap − wall_px)/wall_px·1e4` |
| A6 выход | из ключа: `reason, hold_min, mid_at_deadline_bps` | — |
| A7 поток до входа | `sell_15m_lots, buy_15m_lots, imbalance_15m` | лента из бинлога — `bin/alpha-cab355c lob touches` не отдаёт; **первая версия — без A7** (пометить колонки пустыми); вторая — через `traded_*`/`frontrun_lots` касания-предшественника как прокси (`touches-<SYM>.csv`, колонки `traded_during, frontrun_lots, swept_lots`) |
| A8 время/монета | `hour_utc, symbol` | из `t0_ns` |

Правила: отсутствие строки в кэше — пустая ячейка + счётчик `missing_*` в stderr, не падение. Числа в bps
и минутах. Тест: `tools/compute/tests/test_loss_atoms.py` на фикстуре из трёх сделок (прибыльная, стоп,
дедлайн) с крошечными CSV — проверяет A1–A4, A8. Прогнать `python3 -m pytest tools/compute/tests -q`.

## Шаг 2. Сравнения (1 ч) — `tools/compute/loss-report.py --atoms study/loss-atoms-5d.csv`

1. Для каждого числового атома: медиана и квартили у **убыточных** (`pnl_usd < 0`) и **прибыльных**;
   разность медиан в единицах межквартильного размаха. Таблица, сортировка по разности.
2. **19.09 против остальных**: те же атомы по дню (23 сделки против 105) + режим дня (`btc_4h`, `pool_4h`
   медиана по дню).
3. **Стопы** (reason=stop, 3 сделки): каждая — пять строк по атомам A1–A6 текстом.
4. **Дедлайны с минусом**: доля `reached_take=1` (тейк был на пути — далеко) против `=0` (не дошла).
5. **Кандидаты в фильтр**: для каждого атома с расхождением — порог по квартили убыточных; на тех же 128
   сделках посчитать: сколько убытка режет, сколько прибыли теряет, P&L после фильтра. Печать таблицы.
