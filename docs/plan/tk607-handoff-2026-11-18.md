## Дизайн реализации (решено, кода нет)
- Новый модуль `src/breakout/store.rs`: (а) `TickStore` — файл `<store>/<МОНЕТА>/<МОНЕТА>-<дата>.tk`: заголовок (магия, версия, число строк, размер+mtime исходного zip, счётчики `LoadStat`), нагрузка delta-varint (цена: зигзаг от НОД шагов; время: `(off−prev)<<1 | bm`; формат — как в `docs/findings/p42-speed-2026-11-18/tkbench.rs`, round-trip проверен на 5 сутках), флаг zstd-блока; запись `tmp + rename`; потолок и `df`-страж (`df --output=avail -B1`, проверка раз в N записей). `ZipSrc::load` читает склад первым; `Vec<Tick>` после склада тождествен (в т.ч. стабильная сортировка при `unsorted`). (б) `SigCache` — на задание `(SigCfg, сторона)` файл: `Vec<TSig>` после `sort_tsigs` (поля `ms,sym,level,dist,t,day,idx,lp,far,ws`) + `TickCtr`; в `tick_cli.rs::run` фаза 1 идёт только по заданиям без попадания.
- Ключи CLI `breakout tick`: `--tick-store <dir>`, `--tick-store-cap-gb` (3), `--tick-store-min-free-gb` (5), `--sig-cache <dir>`; без ключей — прежнее поведение.
- L4: `Sym.natr`/`Sym.bars` → `OnceLock` по слотам (`natr_for`/`bars_for` инициализируют лениво; `natr_series(&Cols,…)` оставить обёрткой над срезами). L5: `first_signal` — сравнение `(lp−p)·SCALE ≥ (dmax+1)·|lp|` вместо деления (деление только для возвращаемого `dist`); `x·y/100_000` — `checked_mul` в i64 с откатом на i128 (`tick.rs` 355, 364, 424, 454, 462, 504, 605; `data.rs` 364).
- Python: `Engine.command` добавляет ключи склада/кэша из `Paths`; `OutDirEvaluator` — `bin_md5` в `npz`, проверка на загрузке; `Engine.n` с `max(bNNNN)+1`.
- Порядок: L1+L4+L5 → ворота (nice 19, ≤ 4 процессов) → отчёт критику → L2 → ворота → L3 (аудит, затем ворота). Сборка: `bash tools/p42/build-srv.sh <BIN_OUT> [test <фильтр>]`; тесты/clippy `bash tools/vps-check.sh <дерево> all`. Деплой дерева на srv — `tar` рабочего дерева (не `git archive`).
