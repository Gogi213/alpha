## 1. Правила на каждый шаг (коротко; полностью — CLAUDE.md, В-39)

- Одна переменная за раз; предрегистрация в [runs.csv](runs.csv) **до** данных; каждая сетка — строка
  журнала с контекстом; результат — `docs/findings/<тема>-<дата>.md` + компактный csv/json рядом;
  сырьё — `data/` или `study/`; «где мы» — сначала `CLAUDE.md` «Состояние», затем digest в общую
  память `.memory/` (index → alpha.md → log.md) в конце сессии.
- Числа только измеренные или назначенные владельцем (`В-##`); формы и флоры называет он.
- Разбор всегда по монетам; монета с < N касаний — шум (порог N — вопрос владельцу в H5).
- Ключи биржи — только окружение процесса; живые ордера — только с согласованным числом сделок.
- Счётная машина: ожидания — в скриптах-цепочках с логом; перед уходом — убить своих сирот.
- Контекст: файлы секциями, вывод через `tail`/`grep`, скрипты — файлом (Write), не heredoc'ом
  (оболочка агента портит `\1`/`\n`).

### H2. Ось возраста под жёстким флором 15 мин (В-71) — главный вопрос владельца
Вопрос: лучший порог возраста — один для пула, свой для нескольких пулов, или уникален по монете.
- **Шаг 1 (касания, дёшево).** По `study/touches/<сутки>/` (трекер номинал $10k — правильный, в отличие
  от `touches6`): для порогов `{15, 30, 45, 60, 90, 120}` мин по монете и по суткам — сигналов/день,
  ход за 10 мин и за час, доля отскока; расширить `floors-balance.py` флагом `--by-coin` и выводом csv.
  Помнить п. 0.7 (возраст через полночь).
- **Шаг 2 (проверка «уникален ли»).** Для каждой монеты — лучший порог на сутках A, ход на сутках B
  (все разбиения суток на A/B, как CPCV в вердикте); то же для одного порога на пул и для порогов по
  кластерам монет (кластеры — по обороту, тику, цене из `instruments.csv`, **до** взгляда на ответ).
  Критерий: по-монетный порог out-of-sample бьёт пуловый — возраст уникален; нет — один порог.
- **Шаг 3 (сетка).** База В-65 при `--min-age-secs` ∈ {900, 2700, 3600} × сила {любая, 10 %} уже в
  ночном наборе (`a15-s10`, `a30`, `a45`, `a60`); добавить `a90`/`a120` только если шаг 1 показывает
  рост хода выше часа — предрегистрация до запуска.
- Выход: `docs/findings/age-axis-<дата>.md` + csv; решение владельцу с тремя вариантами и ценой
  каждого в сигналах/день. → H1b.
