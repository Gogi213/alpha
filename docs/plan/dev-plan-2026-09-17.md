**A8.2 — сделано 18.09 (тикет 50).** SIGTERM — сигнал, которым `systemctl stop`/`restart`, перезагрузка
и `kill` по умолчанию гасят процесс, — раньше не обрабатывался вовсе: запись обрывалась на границе кадра
(данные целы), а `session.json` оставался с `closed=false`. Теперь `StopHandle::stop_on_signals` на Unix
ждёт первый из двух сигналов (`tokio::signal::unix::signal(SIGTERM)` в `tokio::select!` рядом с
`ctrl_c`) и идёт **тем же путём**, что файл `<root>/stop`: `Item::Stop` → `None` от `Feed` → сброс
писателей, `session.json closed=true`. На Windows ветка не компилируется (`cfg(unix)`) — там Ctrl+C или
файл `stop`; unix-ветка типо-проверена кросс-целью `x86_64-unknown-linux-musl` (локально она под `cfg`
не компилируется, а сервер — Linux). Тест `sigterm_reaches_the_stop_handle_like_ctrl_c` посылает сигнал
себе (после метки готовности обработчика) и требует `Item::Stop` из канала; ворота локально — **795 тестов,
0 failed, 5 ignored** (на Linux 796: тест под `cfg(unix)`), clippy `-D warnings`, fmt. Полная цепочка
«сигнал → `closed=true`» на живом процессе проверяется в A8.7 (`kill -TERM` смоук-процесса на сервере);
в проде до деплоя живёт бинарник `3614321`, где SIGTERM по-прежнему рвёт запись.
