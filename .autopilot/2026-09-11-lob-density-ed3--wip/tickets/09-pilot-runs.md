# 09 — Пилот: отладочные прогоны ≤ 5 мин, затем двухчасовой; G-DEBUG, G0, G-POWER-B

**Требования:** R40, R51, R68, R78, R81, A01
**Blocked by:** 01, 02, 08
**Зона:** `src/commands/lob/pilot.rs`
**Волна:** 3
**Status:** blocked

## Что должно заработать

Один код пилота, два режима.

**`--debug`** — ≤ 5 минут по всем десяти сразу. Результат помечен `debug` и
**данными не является**: ни для вердикта, ни для предрегистрации. Повторяется,
пока конвейер не пройдёт сквозняком `session → verify → levels → markout →
profiles → backtest` без дефекта — это гейт **G-DEBUG**.

**Боевой** — **два часа** по §11 задачи, считается второй час. Тем же кодом
`levels → классификация → markout`, что и подтверждающий прогон. Печатает по
инструменту: уровней в минуту в обоих режимах `H3`, доли исходов, `m_10s` с
интервалом, Шарп против требуемого из таска 05, перемеренные пороги GC на
десяти. И число, которого задача требует прямо: **сколько сессий нужно на
профиль**, посчитанное из ставки. И **какой режим `H3` входит в предрегистрацию**.

Разведка дала отладочный якорь: `eaten` 1.5–7%, Шарп `m_10s` от −0.40 до
+0.24 против планки ≈ 2.7. Если двухчасовой пилот подтвердит разрыв —
**G-POWER-B красный, сбор не начинается**, и это результат.

## Из брифа, дословно

> сколько сессий нужно на профиль»

> «длительность пилота — два часа, как в плане: пилот теперь ещё и назначает

> «я его отменял потому что система не собрана и надо на ранних этапах гонять
> небольшое время. чтобы дебажить результаты»

## Критерии приёмки

- [ ] `--debug`: ≤ 5 минут по всем десяти; шапка каждого артефакта несёт `debug`; такой прогон не пишет в `runs.csv` и не трогает предрегистрацию
- [ ] **G-DEBUG**: сквозной отладочный прогон проходит без дефекта; вердикт напечатан
- [ ] боевой режим: два часа по всем десяти, считается второй час; тем же кодом, что подтверждающий прогон
- [ ] ставка уровней в минуту — строка на инструмент, в обоих режимах `H3`
- [ ] доли исходов, `m_10s` с интервалом, круг в bps — строка на инструмент
- [ ] число сессий на профиль из ставки — таблица для маргиналов и тонких ячеек
- [ ] пороги GC перемерены на десяти; границы оси повторяемости и **режим `H3`** назначены по замеру и заморожены коммитом
- [ ] **G0** с числами: медианный инструмент ≥ 200 уровней за зачтённый час; `m_10s` на объединённой ≥ 7.5 bps + проскальзывание; при < 200 — продление до 6 часов один раз
- [ ] **G-POWER-B**: замеренный Шарп против требуемого; разрыв числом
- [ ] все десять — строки в `runs.csv` (боевой режим)
- [ ] **GC**
