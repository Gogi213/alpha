# 04 — `lob session`: сессия по пулу — и это `Feed` бота

**Требования:** R12, R37, R38, R41, R43, R75i, R78, R79, R80
**Blocked by:** 01
**Зона:** `src/commands/record.rs`, `src/commands/lob/session.rs`, `src/feed/`
**Волна:** 2
**Status:** ready

## Что должно заработать

Одна команда пишет **весь пул одновременно** сессией 5–15 минут. И это не
рекордер с отдельной жизнью: один поток ввода-вывода на десять подписок,
`crossbeam` в один поток решений, и рекордер и решающий цикл читают **один
и тот же `Feed`**. В фазе 2 к этому же `Feed` подключается стратегия — без
ветки `if live`.

Сегодня `RecordArgs.symbol: String` — один символ; `clock.csv` не записан ни
разу ни в одном прогоне, хотя это строка гейта GC.

## Критерии приёмки

- [ ] `lob session --minutes 5..15` подписывается на весь пул, пишет по файлу на инструмент; длина, час старта UTC, список инструментов — в записи о сессии
- [ ] `Feed { next_event }` — один трейт, две реализации: бинлог и сокет; вызывающий код не различает
- [ ] один поток решений, `crossbeam` от потока ввода-вывода; `async` в решающем потоке — нет
- [ ] ноль аллокаций на событие на пути разбор → книга; ≤ 1 на кадр в транспорте
- [ ] `Instant::now()` в горячем пути — ноль (греп); время через `Clock`
- [ ] лимит топиков проверяется; при упоре — несколько соединений, печатается
- [ ] `clock.csv` не реже раза за сессию
- [ ] тестовый прогон — **≤ 5 минут**; десять непустых файлов, `gaps.csv` пуст
- [ ] тест: оборванная сессия теряет кадр, не сессию
- [ ] **GC** на десяти сразу: CPU, RSS раз в 30 с, задержка разбора `p99 < 200 мкс`
