## Критерии приёмки

- [ ] `lob session --always-on` (взаимоисключающий с `--minutes`/`--pilot-minutes`): без дедлайна; ротация файлов по границе суток UTC через `record::claim_part` (следующая свободная часть, ничего не затирается); при старте посреди суток — часть текущих суток; `session.json.binlog_files` дописывается на каждой ротации
- [ ] `session.json` и `clock.csv` обновляются **периодически** (период — из существующего обоснования часового таймера `record.rs`, не изобретать) и на ротации, не только в конце: анализ по накопленному читает живой каталог; `session.json.always_on = true`, `duration_s` — фактическое на момент записи
- [ ] остановка Ctrl+C (`tokio::signal::ctrl_c` или эквивалент без новой зависимости): сброс всех писателей, финальный `session.json`, код выхода 0; тест на остановку по сигналу-заменителю (внутренний флаг/канал), не на реальном сигнале
- [ ] переподключение и ресинк — уже есть (`bybit::conn`); добавить в `session.json` счётчики `reconnects` и `resyncs` за прогон и строки в `gaps.csv` на каждый — без них сутки записи нечем оценить
- [ ] **из ревью таска 24, безопасность олвейс-он:** (а) `ws.rs` — быстрый путь `topic_starts_with` получает фолбэк: валидный некомпактный JSON книги/ленты разбирается как Book/Trade (или отдаёт `ParseFailed`), тест на JSON с пробелами после двоеточий и на строковое поле перед `topic`, содержащее `"topic":"orderbook.`; (б) ошибки формы при валидном JSON — `MissingField`/`BadNumber` (по `serde_json::Error::classify()`), `NotJson` только для синтаксиса, тест «валидный JSON неверной формы ≠ NotJson»; (в) неудавшийся `write_frame` считается (`session.json.frames_failed`) и пишется строкой в `gaps.csv` — квант потери теперь ~1000 записей, молчать нельзя
- [ ] **из ревью таска 24:** таймер сброса кадра сейчас — `HOURLY_REFRESH_SECS` (3600 с), то есть в сессии ≤ 6 ч не срабатывает и тихий инструмент теряет при крахе до 1000 записей; ввести окно потери как **именованную** константу с обоснованием (doc `FRAME_TARGET_RECORDS` уже называет «~10 с живого потока» — взять оттуда, не изобретать), тест: тихий инструмент даёт кадр на диске не позже окна
- [ ] **из ревью таска 24:** периодический `session.json` несёт ряд RSS/CPU-сэмплов (`samples: [{ts, rss_bytes, cpu_pct}]`), чтобы вердикт «плоский» стоял на артефакте, а не на stderr
- [ ] экономия: RSS плоский за прогон (гистограммы вместо `Vec`, таск 24), CPU < 5 % (бюджет 6.1), байт/мин не выше замера таска 24; уровень zstd — **по замеру** байт/запись × CPU на одной и той же 5-минутной записи (уровни 1/3/6/9 в офлайн-тесте на реальном бинлоге из `data/`), выбранный уровень назван в `docs/findings/collector-2026-09-12.md`
- [ ] логи: stderr не растёт бесконечно — одна строка в час со сводкой (записей, байт, gaps, reconnects, RSS, CPU), не строка на событие
- [ ] анализ по накопленному доказан на записи ≤ 5 мин: `lob verify` → `lob levels` → `lob markout` на каталоге олвейс-он сессии **пока она ещё пишет** (закрытая часть читается, открытая — до последнего полного кадра; если Reader не умеет читать незакрытый файл — сказать, что именно и как; ломать формат нельзя)
