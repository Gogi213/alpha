# 05 — `lob power`: планка до сбора

**Требования:** R47, R59, R68, A01

**Зона:** `src/lob/final_metrics.rs`, `src/commands/lob/power.rs`
**Волна:** 2
**Status:** ready

## Что должно заработать

Одна команда отвечает на вопрос, которого прежний план не задавал: какой размер
эффекта нужен, чтобы после поправки на фактическое число испытаний результат
вообще стал отличим от везения. Стоит одну команду и ноль данных.

Это гейт **G-POWER-A**. Он ничего не запрещает — он печатает число, которое
обязано быть известно до того, как потрачен календарь.

## Из брифа, дословно

> «DSR дефлирует по фактическому числу испытаний»

> «Красный итог — тоже успех, если он получен честно»

> «Число испытаний — вход DSR, и занижать его значит врать себе»

## Разделы спецификации

История 43. Решения §9.

## Критерии приёмки

- [ ] `lob power` печатает три числа: фактическое число испытаний `N` из шага отбора, планку чистого шума `SR0`, требуемый Шарп на наблюдение для DSR = 0.95 при `n = 100`
- [ ] `SR0` считается существующей `expected_sharpe_under_null`, а не новой реализацией
- [ ] тест: при `N = 1` требуемый Шарп совпадает с недефлированным
- [ ] тест на известном `N`: `SR0` совпадает с ручным расчётом по формуле
- [ ] число испытаний берётся из одного источника — вывода шага отбора; константы «178» в коде не существует
- [ ] **GC**
