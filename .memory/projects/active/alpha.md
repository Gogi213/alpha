## T45 — два потока глубины (2026-09-15, в проде)

- Причина: 50 уровней — это 0.18 % цены у ликвидных и до 3.8 % у тихих, а `.200` по замеру даёт
  больше данных при **меньших** ресурсах (−19 % байт, −44 % CPU против `.50` на тех же записях),
  но публикуется реже: BBO 10 мс / `.50` 20 мс / `.200` 100 мс.
- Решение (индустриальное): **своя книга на каждый поток**, **раздельное хранение** — основной файл
  `<SYM>-<день>.binlog` как раньше (`.50`) и `deep/<SYM>-<день>.binlog` (`.200`, тот же v3, свой
  снапшот первым кадром); склейка — на чтении по `seq`. Так сделано потому, что склеенная книга
  бывает внутренне противоречива (быстрый поток уже впереди, глубокие уровни устарели).
- Каталог `deep/` невидим для всех существующих команд (резолверы читают корень) — поведение прежних
  команд не изменилось; `session.json.streams` несёт раздельные счётчики.
- Тикет `.autopilot/2026-09-11-lob-density-ed3/tickets/45-dual-depth-streams.md` (с критериями и
  отчётом). Ревью — `needs_revision` (находки про тесты/доку), ревизия закрыта, каждая новая проверка
  проверена мутацией. Гейты: **752 passed, 0 failed**, clippy/fmt чисто (на момент T46; после T45
  было 721).
- В прод включено 2026-09-15T17:13:53Z, затем 18:36:40Z — объединённый бинарник T45-ревизия + T46.

## Дрейф `.50` против `.200` — нет (замер)

- Прототип `examples/stream_drift.rs`: две книги по одной монете, быстрая подтягивается ровно к
  метке глубокого сообщения, сравнение на границах сообщений (сравнение внутри пачки даёт ложные
  расхождения — записано как ловушка).
- LSK (самая активная, ~1.5 ч, 8 927 сравнений): верх совпал **97.63 %**, по четвертям окна
  97.25 / 97.24 / 98.15 / 97.87 % — **ровно, без накопления**; расхождения ограничены (max 41 тик,
  «крупных» 1.67 %) и разнонаправлены. DOGE (17 006 сравнений): **99.99 %**, максимум 1 тик.
- Следствие для склейки: глубокий поток отстаёт на ~100 мс (интервал публикации), поэтому верх книги
  брать из `.50`, а `deep/` — только за пределами его окна, выравнивая по `seq`.
- Артефакт: `docs/findings/stream-drift-2026-09-15.md`.

## T46 — архив закрытых суток (2026-09-15, в проде)

- Закрытые сутки сжимаются целиком: контейнер `*.binlog.zst` = один zstd-поток над заголовком v3 и
  телами кадров; команда `lob archive --path … [--level 19] [--out …] [--delete-original]` с
  **обязательной** проверкой round-trip; удаление оригинала — только с флагом и при
  `verify-<SYMBOL>.status == ok`.
- Замер: на боевом v3 `CYSUSDT` **81.3 %** от оригинала; на файле после `--rewrite-out` — 90.3 %
  (уровень 1 — 97.7 %, то есть пересжатие покадрово дало бы всего −1.6 %, а контейнер — −7…−10 %).
  Чтение архива всеми командами работает; артефакты `levels`/`markout`/`verify` на архиве совпали с
  оригиналом по SHA256.
- Ограничение: контейнер принимает **только v3**, для старых v2-суток нужен шаг
  `binlog-stats --rewrite-out`. `xz` не добавляли (новая зависимость liblzma; чтение в 20–40 раз
  медленнее при выигрыше 2.8 п.п.).
- Артефакты: `docs/findings/archive-compression-2026-09-15.md`, тикет `46-archive-container.md`.
