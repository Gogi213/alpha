# MEMORY — протокол памяти (сжатая версия)

> Полная исходная версия была на китайском и весила 4.5 КБ; она съедала бюджет boot-блока.
> Здесь только то, что нужно, чтобы вести память правильно. `raw/` — источник, не трогать.

## Каталоги

`projects/{active,archive}` — проекты · `decisions/` — решения и их причины · `user/` — о владельце ·
`skills/` — как что делать в этом окружении (грабли, команды) · `concepts/` — термины · `raw/` — сырьё (read-only).

## Страница

```yaml
---
title: ...
date: 2026-09-15
type: project | decision | skill | user | fact | concept
salience: 1        # 1 горячее (грузить всегда) / 2 тёплое / 3 холодное
last_access: 2026-09-15
tags: []
---
```

Правила: относительные markdown-ссылки между страницами; `log.md` — append-only, строка
`## [YYYY-MM-DD] <kind> | <title>`; при противоречии — править старую страницу и отметить в `log.md`.

## Четыре операции

- **remember** — из разговора/работы выделить факт → страница → обновить `index.md` → строка в `log.md`.
- **recall** — сначала `index.md`, потом конкретная страница. Не перечитывать проект заново.
- **consolidate** — `dsh-memory lint`: противоречия, осиротевшие страницы, холодные в архив.
- **forget** — по просьбе владельца сразу; автоматически — `salience: 3` + 90 дней без доступа.

## Жёсткие правила

1. Владелец эту память **не читает** — она для агента. Значит писать надо так, чтобы
   следующая сессия поняла состояние без грепа проекта: числа, коммиты, даты, пути.
2. Конец сессии = digest: обновить `projects/active/alpha.md` и блок «Состояние» в `index.md`,
   дописать `log.md`. Если изменений нет — так и написать.
3. Устаревшее не удалять молча: сначала архивировать, факт замены отметить в `log.md`.
