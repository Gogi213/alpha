## Что это по сути

TypeSafe — «единицы ИИ-суждения» как примитивы: модель **Jev** (`jev-latest`) принимает `state`
и карту типизированных `questions`, возвращает типизированные `answers` и вероятности вместо
свободного текста. Три примитива: `noul` (вероятность «да»), `choice` (одно из заданных
вариантов + распределение), `score` (взвешенная позиция на шкале уровней). Код владеет
workflow, модель даёт «программируемый здравый смысл» — маршрутизация, ранжирование, извлечение,
проверка. Применимо к alpha как источник типизированных суждений о состоянии рынка/уровня
(например, отнести касание к режиму), но это **не решено** — владелец такого решения не давал.

## API и ключ

```http
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

`model: "jev-latest"`, `questions` — карта с ключами по выбору вызывающего (ключ не уходит в
модель). Ответ: `answers` под теми же ключами + `usage`. Ошибки: `401` (ключ), `422` (валидация),
`429`/`529` — экспоненциальный backoff.
**Поля вопроса — `instructions` (текст вопроса) и `criteria` (у `choice` — карта «вариант →
описание»)**, не `question`/`options`: с последними API честно отдаёт `422` с `loc` до поля
(грабля Claude Code 21.09 вечером; после правки полей — `200`, 0.8 с, `jev-1.13.0`, из
окружения процесса Claude Code ключ читается без явного обращения к User-скоупу).

**Ключ — только в переменной окружения, значение в репозиторий и в память не пишется**
(правило проекта: секреты — только имена переменных). Это правило про **артефакты**, а не про
подозрительность к ключу: владелец 21.09 уточнил, что **у этого проекта API TypeSafe
бесплатный, и именно этот ключ предназначен для использования** — совет «отозвать и выпустить
новый» здесь неверен и снят (в других проектах/случаях так делать нельзя — это отдельная
оговорка владельца, а не вывод про TypeSafe).

Имя переменной **подтверждено доками**: JS SDK читает `TYPESAFE_API_KEY` сам
(`new TypeSafeClient()` без аргументов), Python SDK — сверить при использовании.

```powershell
[Environment]::SetEnvironmentVariable('TYPESAFE_API_KEY','<ключ>','User')   # новое окно — подхватит
```

Ключ в коде интеграции не хардкодить: клиент берёт его из окружения; в веб-приложениях держать
на сервере (`SKILL.md`: «keep API credentials server-side»).

## Как честно считать экономию против агента (21.09, замер по логу сессии)

Владелец зацепил подмену в моём сравнении «137k против 490» — она реальна: 137k/122k — цена
**моего вызова**, а не одного суждения. Замер сегодняшней сессии (`~/.dsh/tools/session-usage.py`,
`session-9f62dd2e`): 65 вызовов, вход **7 976 350** (из них cacheRead 7 843 712, свежих 132 638),
выход 73 277, reasoning 43 480, **cacheHit 98.3 %**, медиана входа на вызов **120 657**.
Цена вызова ≈ **$0.00174** (cacheRead 0.003 + свежий вход 0.15 + выход/reasoning 0.6 за 1M) —
сходится с прошлым замером $1.95/1133.

Цена одного суждения у меня зависит **только от упаковки**: 122.7k при одном суждении на вызов;
**2.5k** при пачке 50; **644** при 200; **275** при 500. То есть ×280 против TypeSafe (488 на
3 вопроса) — это режим «одно суждение = один вызов»; при жёстком батчинге по токенам почти паритет,
а на 500 в пачке я даже формально дешевле.

Что остаётся у TypeSafe как свойство (а не как артефакт сравнения): **$0** (у меня $0.0017/вызов),
моё окно и раунды не заняты, форма ответа гарантирована, 0.3 с на элемент, и она масштабируется
до 10⁵–10⁶ элементов, куда я не влезаю окном. В токенах же выигрыш не «×280», а «×280 в ленивом
режиме, ×1 при батчинге». Правило на будущее: сравнивать цену вызова против цены вызова, а не
вызов против суждения.

## Проверка одной командой (значение ключа не печатается)

PowerShell/.NET на этом хосте TLS не поднимает — проверять через Node (ключ берём из User-скоупа,
в командную строку значение не подставляем):

```powershell
$env:TYPESAFE_API_KEY = [Environment]::GetEnvironmentVariable('TYPESAFE_API_KEY','User')
node -e "const b={state:'ping',model:'jev-latest',questions:{p:{type:'noul',instructions:'Connectivity check?'}}};fetch('https://api.typesafe.ai/v1/systemone',{method:'POST',headers:{'Authorization':'Bearer '+process.env.TYPESAFE_API_KEY,'Content-Type':'application/json'},body:JSON.stringify(b)}).then(async r=>console.log(r.status,await r.text()))"
```

Старый вариант (работает там, где у PowerShell есть доступ к крипто-хранилищу):

```powershell
$k = [Environment]::GetEnvironmentVariable('TYPESAFE_API_KEY','User')
$b = @{ state="ping"; model="jev-latest"; questions=@{ p=@{ type="noul"; instructions="Connectivity check?" } } } | ConvertTo-Json -Depth 6
(Invoke-RestMethod -Uri "https://api.typesafe.ai/v1/systemone" -Method Post -Headers @{ Authorization = "Bearer $k" } -ContentType "application/json" -Body $b).model
```

## Как дать ключ DSH-агенту (2026-09-22, грабля: переменные с `KEY`/`SECRET` до shell-инструмента НЕ доходят)

**Причина найдена в коде** (`@deepseek-ai/dsh-subprocess/lib/index.js:32`):

```js
const SENSITIVE_ENV_PATTERN = /KEY|PASSWORD|SECRET|TOKEN/i;   // подстрока, без учёта регистра
function scrubbedParentEnv() { /* выкидывает имена, попавшие под шаблон, и все DSH_* (их вернёт shell-env) */ }
```

То есть **любое** имя с `KEY`/`PASSWORD`/`SECRET`/`TOKEN` вырезается из окружения каждого процесса,
который запускает shell-инструмент модели. Подтверждено данными: у владельца 22 пользовательские
переменные, процессу DSH-агента видны 13, и ровно девять невидимых — все ключевые
(`TYPESAFE_API_KEY`, `TAVILY_API_KEY`, `MOONSHOT_API_KEY`, `BYBIT_API_KEY`, `BYBIT_API_SECRET`,
`GEMINI_API_KEY`, `KIMI_API_KEY`, `DEEPSEEK_API_KEY`, `OLLAMA_API_KEY`). **Значит `TYPESAFE_API_KEY`
в User-скоупе не поможет и после перезапуска DSH** — имя подпадает под нож. (У Claude Code этой
чистки нет — ей хватает User-скоупа; отсюда «у неё работает, у него нет».)

**Рабочий путь без перезапуска DSH** — ключ в личном файле вне репозитория, а каноничное имя
выставляется внутри команды:

- файл: `C:\Users\Георгий\.dsh\typesafe.env` (одна строка, 108 байт, ACL только владельцу,
  создан разовой командой с расширением песочницы; в репозиторий не попадает);
- в каждой команде, которой нужны судьи:
  `$env:TYPESAFE_API_KEY = (Get-Content "$env:USERPROFILE\.dsh\typesafe.env" -Raw).Trim()`
  → дальше `python tools/typesafe/judge.py` или любой из шести судей; значение нигде не печатать.

Проверено 2026-09-22 ночью (DSH-агент, ключ владельца от 22.09): `judge.py` → `alive 0.79`;
`verdict-read.py` по D20 (4 запроса, 10719/531 токенов) и по D50 (4 запроса, 9406/535);
`err-classify.py` по `f10fix-D50-multi.err` — ошибок в логе нет, вызова не было. Раньше тот же
агент брал ключ по ssh со счётной (`/etc/alpha/typesafe.env`) — этот путь остаётся запасным.

**Альтернатива, если хочется «как у людей»:** завести User-переменную с именем БЕЗ запретных
подстрок (например `TYPESAFE_AI`) и перезапустить DSH — тогда файл не нужен, в команде остаётся
одна строка переименования. Плюс попытка завести User-переменную с именем `TYPESAFE_API_KEY`
бесполезна по определению (см. шаблон выше).

**Дисциплина:** в этой сессии значение ключа один раз ушло в чат (агент печатал существующую
User-переменную, проверяя, задана ли она) — правило «секреты только именами» нарушено. Отзыв ключа
для этого проекта **не нужен** (владелец: API бесплатный, ключ выдан для использования) — нужна
только осторожность: значения не печатать, в репозиторий и память не писать.
