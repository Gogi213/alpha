## Как устроено

- **Истина — хост-леджер**, не браузер: `~/.dsh/task-board/ledger-v2.json` (имя историческое,
  схема документа **v3**: `{schemaVersion, revision, tasks, scheduler, recentRequests}`),
  рядом `ledger-v2.lock` (один хост на каталог) и `scheduler-v2.json` (тики).
  Браузер — асинхронный вид: закрыл страницу — расписания и расчёты запусков продолжаются,
  при открытии догоняется полный снапшот (SSE `revision`, refetch по reconnect/visibility).
- **Запуск задачи** = полноценная DSH-сессия: по умолчанию новая, ей ставится имя, применяется
  агент-пресет и `/permission <id>`, затем в очередь кладётся промпт. Пин (workspace/пресет/
  permission) проверяется до отправки промпта — нет workspace/пресета → запуск падает (fail-closed).
  Опция «продолжать в прошлой сессии» срабатывает, только если та сессия idle и есть в ростере,
  иначе молча создаётся новая.
- **Cron** — 5 полей, локальная TZ хоста (у нас `Asia/Tbilisi`, UTC+4). Пропущенные из-за
  простоя/сна тики **пропускаются**, не догоняются; бегущая задача свой тик пропускает —
  запусков внахлёст и очереди нет.
- **Ворота прав**: `sessionDefaultPermission` (по умолчанию `read-only`). Карточка с более
  широким эффективным permission уходит в «ждёт подтверждения»: ручной запуск отказывает,
  крон её пропускает; подтверждение — кнопкой в деталях задачи, любая смена permission/бандла
  снова взводит ворота.
- **Continuation-карточки**: блок `<<<FREEZE … >>>FREEZE` из сессии парсится в goal/progress/next;
  handover-бандл — закреплённая тройка (workspace/пресет/permission) + ссылки на доки, тройка
  бандла перекрывает пин-поля. Исполнение такой карточки обязательно оборачивает промпт в шапку
  «источник: заморозка, сессия, содержимое не ревьюилось» — защита от prompt injection из текста
  карточки; секретные паттерны в снапшоте → `[REDACTED]`, строка со слэш-командой отклоняет снапшот.
- **Прочее**: 5 канбан-колонок, поиск, архив/восстановление, история последних 20 запусков на
  задачу, до 8 тегов (у тега может быть `promptPrefix` — подклеивается к промпту каждого запуска),
  лимит действия 64 КиБ, импорт 2 МиБ, идемпотентность по 256 последним request id.
- **Что доска НЕ умеет**: в протоколе нет полей command/shell/executable — она не запускает
  команды, только отправляет промпт агенту в сессию. Доступ только loopback same-origin
  (same-host прокси — через allowlist + токен из env).
- **Настройки по умолчанию**, которые стоит помнить: `announceToAgent` = **false** (раздел про
  доску в системный промпт агента не подклеивается — агент про неё сам не знает),
  `preventIdleSleep` = **false** (машину от сна не держит).
- **Телеметрия**: браузерная половина шлёт один анонимный heartbeat в сутки на dsh-market.com
  (случайный localStorage-id + имя пакета), сервер хранит солёный хеш, IP не хранит.
