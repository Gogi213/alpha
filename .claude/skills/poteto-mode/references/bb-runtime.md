# pstack в bb (alpha)

Правила проекта: `AGENTS.md` в корне. Постоянные приказы владельца: `.claude/preferences.md`. Они выше правил навыков.

## Запуск исполнителя или проверяющего

1. Бриф (шаблон в `SKILL.md`) записать в файл в `$BB_THREAD_STORAGE` (не в репо).
2. Запуск:
   ```
   bb thread spawn --parent-self --project "$BB_PROJECT_ID" \
     --new-environment worktree --base-branch <ветка>   # пишущий исполнитель: свой worktree
     # или --environment "$BB_ENVIRONMENT_ID"           # только чтение / непересекающиеся файлы
     --provider claude-code --model <модель> --reasoning-level <уровень> \
     --title "<короткое имя>" --prompt-file <бриф>
   ```
   Название треда — строго `<роль> · <тема> · <объект> · v<N>`: роль ∈ {коорд, исп, пров, чит}; тема — номер цели (`G-022`) или `none` (работа вне целей, например обслуживание master); объект — латиница kebab-case, одно имя на всю работу (`binance-ladder`, `rust-collector`); `v<N>` — номер попытки, у исполнителя и его проверяющего одинаковый. Пример: `исп · G-022 · okx-collector · v1`.
   Провайдер, модель и уровень — строка роли из `models.md`. Режим разрешений не расширять.
3. Завершение придёт уведомлением родителю. Результат: `bb thread output <id>`; сверить с файлами, diff и выводом проверки. Отчёт исполнителя сам по себе не доказательство.
4. Учесть каждый запущенный тред до отчёта владельцу. Список: `bb thread list --parent-thread "$BB_THREAD_ID"`.


## Машины

Счёт и коллекторы — на серверах по ssh (`AGENTS.md`, раздел «Машины»). Долгие процессы на сервере — только `systemd-run`, не висящая ssh-сессия. Ожидание долгого юнита — не опрос в цикле, а одна проверка по счётчику на машине.

## Расписания

Регулярные проверки (`bb automation`, `/loop`) — только по прямой просьбе владельца. Интервал — не чаще, чем реально меняется состояние.
