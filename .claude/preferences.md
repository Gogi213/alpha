# Постоянные приказы владельца (вставлять в каждый бриф)

Реестры решений — только грепом по номеру, целиком не читать. Номера в двух реестрах пересекаются: «В-NNN» — `.claude/decisions.md`, «SETTLED В-NNN» — `docs/plan/SETTLED.md`.

1. Владельцу — только деньги, направление, риск, необратимое. Методика, числа до счёта, исследовательские развилки, уборка веток и кода — решают координатор и проверяющий (В-39, В-48, В-53).
2. Прямой приказ владельца («стоп», «удаляй») исполняется сразу и дословно, без переноса и смягчения.
3. Сырые данные не удалять без слова владельца. Исключение — уже приказанное: скачанные датасеты на сервере и Storage Box (В-131, В-132).
4. Ответ владельцу — по-русски, сначала результат и число, потом смысл и следующий шаг; время GMT+4; числа — по п. 9. Без прогнозов «стоит / не стоит». Расход токенов и $ не писать, если не спросил. Статусы (владелец 12.11) — всегда короткие и плотные: числа, что сделано, что идёт, срок; без воды и лишних терминов, даже на одно слово «статус».
5. Сроки — в темпе Claude Code (код / сборка+тесты / гейт / итого), временем GMT+4, время готовности по `date`. В брифах — самые короткие реальные, не лимит «с запасом» (владелец 12.11).
6. Алгоритм — оптимальный, не первый: узкое место → лучшие известные способы → замер на малом → выбор без потери качества (SETTLED В-170). Для движка счёта: ускорение принимается только с гейтом «байт в байт» против прежнего бинаря, боевой бинарь — PGO-сборка (В-32). Для коллекторов гейт против Python снят (В-150), см. п. 13.
7. Не предлагать обходы вроде аренды или покупки серверов, найма людей — ускорять метод (SETTLED В-159).
8. ПК владельца — без тяжёлого счёта, cargo на нём запрещён (хук). Сборки — srv 5.231.25.224 и VPS София (В-103). calc и Steam Deck не использовать (В-102, В-104).
9. Числа — только измеренные; изобретённое число запрещено: измеримое меряется, назначаемое — решением с номером. Каждое число помечено: «измерено» / «модель, на допущении …» / «догадка». Модельное число решений не двигает, пока не измерено (пример: таблицы «ленивой замены» стоят на угаданной доле обнаружения).
10. Готовность — только по счётчику на машине, в процентах, не по отчёту исполнителя.
11. Данные — как на бирже, без упрощений ради удобства кода (SETTLED В-172).
12. Комиссия в исследованиях и бэктестах — по тарифу владельца на Bybit, на всех биржах и всех ногах (В-47, В-71, В-88): фьючерс мейкер 1,4 / тейкер 3,5 bps, спот мейкер 6,25 / тейкер 7,5 bps, минус 10 % возврата.
13. G-022 (коллекторы):
    - правила §2 `docs/plan/G-022-collectors-plan-2026-11-12.md` — формат сразу итоговый, лимиты WS убирать полностью, проверочные окна 3 мин, общее ядро + тонкий адаптер биржи, лестница нагрузки до обрывов, строка на дашборде здоровья, пинг пишется рядом с данными;
    - турбо (В-148): без обратного давления и подвисаний на приёме, разборе и записи;
    - копии рядом с боевым (В-156): только когда правка может изменить данные или поведение сбора (разбор, дедуп, метки, подключения, подписка). Правки только диагностики, счётчиков и логов — сразу в бой проверяемой выкладкой (`rollout.sh`: проверка аргументов, 30 с здоровья, автооткат), по одной бирже. Перед запуском копий — счёт соединений на IP (`conn_rate.py`): боевой + копии ≤ 80 % лимита биржи (BingX ≤ 60 сокетов на IP, OKX 3 подкл./с), копии стартуют не пачкой;
    - правильность — против биржи, не против Python (В-150). Полнота подтверждается только независимой сверкой с источником (REST, покрытие «символ × секунда»), а не счётчиками самого коллектора. Пример: окно w7 — счётчики чистые (0 опозданий), сверка с REST нашла 15,7 % недостающих сделок.
14. Без бесцельного ожидания (В-147): долгие замеры и редкие эпизоды — фоновым юнитом, разбор по записанным данным позже; тред ждёт только то, от чего зависит следующий шаг.
15. Без многоагентных workflow и широких фан-аутов, если владелец не просил.
16. Язык и болтовня (В-151): дочерние треды пишут всё по-английски — брифы, ход работы, сообщения, отчёты; строка хода только при смене состояния, без пересказа брифа и «сейчас сделаю». Цитаты владельца — дословно по-русски; документы в репо и ответы владельцу — по-русски.
17. Названия тредов — строго `<роль> · <тема> · <объект> · v<N>` (`.claude/skills/poteto-mode/references/bb-runtime.md`).
18. Проверяющего и исполнителей запускать только под текущую задачу владельца; нет задачи — треды не работают (владелец 13.11).
19. Контекст треда ≥ 350 тыс. токенов — передача дел и клир (сторож `.claude/hooks/context_guard.py`).
20. Перенос и переписывание: сначала проверенное поведение как было (настройки, пороги, логика), новые эксперименты — только если стало хуже по замеру (владелец 12.11).
21. Страницы и дашборды для владельца — сначала макет и его «да».
22. Звуки и баннеры уведомлений не включать.
23. Сравнение и «не работает» (владелец 13.11, вывод по Binance на Rust: «1 причина - ложноположительный вывод про факт которого на самом деле не было»):
    - сначала подтвердить сам факт: «X хуже / сломано / не заводится» — гипотеза, пока не воспроизведено в равных условиях; работа под гипотезу не ставится. Одно окно или разные минуты — не вывод;
    - условия пишутся рядом с каждым результатом (состояние рынка — сообщ./с, доля быстрых подключений, нагрузка хоста); сравниваются только результаты с равными условиями. Пример: лестница Rust шла на более тихом рынке (2,0–2,7 тыс. против 2,7–3,9 тыс. сообщ./с);
    - одно имя метрики — не одна метрика: сравниваемые числа обеих сторон считаются одним скриптом по сырым данным на диске, не счётчиками каждой стороны. Пример: «late» Python (до дедупа, каждый 64-й кадр) против Rust (после дедупа, каждая запись) дали «0 против 177 тыс.»;
    - эталонный тест повторяется один в один (та же параллельность, по одному процессу биржи за раз); на хосте во время окон — ничего постороннего (сборки — в Софии);
    - сначала исключить среду (маршрут, хост, сам тест), потом искать вину в коде.
