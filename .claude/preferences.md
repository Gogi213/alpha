# Постоянные приказы владельца (вставлять в каждый бриф)

Полный реестр решений с цитатами — `.claude/decisions.md` (грепом по `В-NNN`, целиком не читать).

1. Владельцу — только деньги, направление, риск, необратимое. Методика, числа до счёта, исследовательские развилки, уборка веток и кода — решают координатор и проверяющий (В-39, В-48, В-53).
2. Прямой приказ владельца («стоп», «удаляй») исполняется сразу и дословно, без переноса и смягчения.
3. Сырые данные не удалять без слова владельца. Исключение — уже приказанное: скачанные датасеты на сервере и Storage Box (В-131, В-132).
4. Ответ владельцу — по-русски, сначала результат и число, потом смысл и следующий шаг; время GMT+4. Числа — только измеренные и проверенные, с пометкой «измерено / вывод / догадка». Без прогнозов «стоит / не стоит». Расход токенов и $ не писать, если не спросил.
5. Сроки — в темпе Claude Code: код / сборка+тесты / гейт / итого, время готовности по `date`.
6. Алгоритм — оптимальный, не первый: узкое место → лучшие известные способы → замер на малом → выбор без потери качества (В-170). Ускорение принимается только с гейтом «байт в байт» против прежнего бинаря; боевой бинарь — PGO-сборка (В-32).
7. Не предлагать обходы вроде аренды или покупки серверов, найма людей — ускорять метод.
8. ПК владельца не грузить тяжёлым счётом; cargo на ПК запрещён (хук). Сборки — сервер 5.231.25.224 и VPS София (В-103). Steam Deck и calc не использовать (В-102, В-104).
9. Готовность — только по счётчику на машине, в процентах, не по отчёту исполнителя.
10. Изобретённое число запрещено: измеримое меряется, назначаемое — решением с номером.
11. Данные — как на бирже, без упрощений ради удобства кода (В-172).
12. Без многоагентных workflow и широких фан-аутов, если владелец не просил.
13. Страницы и дашборды для владельца — сначала макет и его «да».
14. Звуки и баннеры уведомлений не включать.
15. Комиссия в исследованиях — как на Bybit по всем биржам и ногам (В-88): фьючерс мейкер 1,4 / тейкер 3,5 bps минус 10 % возврата.
16. G-022 (коллекторы): правила §2 `docs/plan/G-022-collectors-plan-2026-11-12.md` — формат сразу итоговый, лимиты WS убирать полностью, проверочные окна 3 мин, общее ядро + тонкий адаптер биржи, лестница нагрузки до обрывов, строка на дашборде здоровья, пинг пишется рядом с данными.
17. Без бесцельного ожидания (В-147): долгие замеры и редкие эпизоды — фоновым юнитом, разбор по записанным данным позже; тред ждёт только то, от чего зависит следующий шаг.
18. Коллекторы — турбо (В-148): без обратного давления и подвисаний на приёме, разборе и записи; правильность — против биржи, не против Python (В-150).
19. Язык (В-151): дочерние треды пишут всё по-английски — ход работы, сообщения, отчёты; без болтовни: ни пересказа брифа, ни «сейчас сделаю», строка хода только при смене состояния; цитаты слов владельца — дословно по-русски; документы в репо и ответы владельцу — по-русски.
20. Статусы (владелец 12.11): всегда короткие и плотные — числа, что сделано, что идёт, срок; без воды и лишних терминов, даже на одно слово «статус».
21. Названия тредов — строго `<роль> · <тема> · <объект> · v<N>` (`.claude/skills/poteto-mode/references/bb-runtime.md`).
22. Сроки в брифах — самые короткие реальные (темп Claude Code), временем GMT+4; не лимит «с запасом» (владелец 12.11).
23. Перенос и переписывание: сначала проверенное поведение как было (настройки, пороги, логика), новые эксперименты — только если стало хуже по замеру (владелец 12.11).
24. Проверяющего и исполнителей запускать только под текущую задачу владельца; нет задачи — треды не работают (владелец 13.11). Контекст треда ≥ 350 тыс. — передача дел и клир (сторож `.claude/hooks/context_guard.py`).
25. Сравнение и «не работает» (владелец 13.11, вывод по Binance на Rust: «1 причина - ложноположительный вывод про факт которого на самом деле не было»). Сначала подтвердить сам факт: «X хуже / сломано» принимается и чинится только после воспроизведения в равных условиях; до этого это гипотеза, а не факт, и работа под неё не ставится. Вердикт «X хуже / не заводится» — только по окнам в равных условиях. Каждое окно пишет состояние среды рядом с результатом (доля быстрых подключений, нагрузка хоста); сравниваются только окна с равным состоянием. Эталонный тест повторяется один в один (та же параллельность, по одному процессу биржи за раз), на хосте во время окон — ничего постороннего (сборки — в Софии). Сначала исключить среду (маршрут, хост, сам тест), потом искать вину в коде. Одно окно или разные минуты — не вывод.
