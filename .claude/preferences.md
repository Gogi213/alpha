# Постоянные приказы владельца (вставлять в каждый бриф)

Реестры — грепом по номеру: «В-NNN» — `.claude/decisions.md`, «SETTLED В-NNN» — `docs/plan/SETTLED.md`. Слова владельца и случаи — `docs/plan/preferences-why.md`.

1. Владельцу — только деньги, направление, риск, необратимое. Методика, числа до счёта, развилки исследований, уборка веток и кода — координатор и проверяющий (В-39, В-48, В-53).
2. Прямой приказ («стоп», «удаляй», «запускай») — сразу и дословно, без переноса и смягчения.
3. Сырые данные не удалять без слова владельца; исключение — приказанное: датасеты на сервере и Storage Box (В-131, В-132).
4. Ответ владельцу — по-русски, сначала результат и число, потом смысл и следующий шаг; GMT+4; числа — по п. 9. Статус — числа, сделано, идёт, срок, без воды и терминов. Без прогнозов «стоит / не стоит». Расход токенов и $ — только если спросил (токенами). Без повторов итогов и «ещё идёт».
5. Сроки — в темпе Claude Code (код / сборка+тесты / гейт / итого), GMT+4 по `date`, «дни» не называть; самое короткое время по задаче, без запаса; срок без разбивки по шагам (шаг → минуты → время готовности) не называть.
6. Алгоритм — оптимальный, не первый: узкое место → лучшие способы → замер на малом → выбор без потери качества (SETTLED В-170); перед счётом — убрать лишние старые шаги. Движок счёта: ускорение — с гейтом «байт в байт», боевой бинарь — PGO (В-32); коллекторы — без гейта против Python (В-150).
7. Не предлагать обходы — аренду, покупку серверов, найм; ускорять метод (SETTLED В-159).
8. ПК владельца — без тяжёлого счёта, сборок, браузерных прогонов (headless Edge / Chrome); cargo запрещён хуком. Сборки и проверки — srv и VPS София (В-103); calc и Steam Deck не использовать (В-102, В-104). В каждый бриф.
9. Числа — только измеренные; изобретённое запрещено: измеримое меряется, назначаемое — решением с номером. Метка: «измерено» / «модель, на допущении …» / «догадка»; модельное решений не двигает. Найденное отбором на тех же данных (исключение «худших», подбор параметров) — «найдено на этих данных» + проверка без заглядывания вперёд.
10. Готовность — только по счётчику на машине, в процентах, не по отчёту исполнителя.
11. Данные — как на бирже, без упрощений ради кода (SETTLED В-172).
12. Комиссия в исследованиях и бэктестах — по тарифу владельца на Bybit, на всех биржах и ногах (В-47, В-71, В-88): фьючерс мейкер 1,4 / тейкер 3,5 bps, спот мейкер 6,25 / тейкер 7,5 bps, минус 10 % возврата.
13. G-022 (коллекторы): правила — §2 `docs/plan/G-022-collectors-plan-2026-11-12.md` (там же В-148 турбо, В-150 правильность и полнота против биржи, не против Python и не счётчиками коллектора, В-156 копии рядом с боевым, `rollout.sh`, ≤ 80 % лимита IP).
14. Без бесцельного ожидания (В-147): долгие замеры и редкие эпизоды — фоновым юнитом, разбор позже; тред ждёт только нужное для следующего шага. Задачи владельца не ждут: ради незаказанного замера или окна они не останавливаются; замер подстраивается под работу.
15. Без многоагентных workflow и широких фан-аутов, если владелец не просил; не оверспендить токены.
16. Язык и болтовня дочерних тредов (В-151) — правило в начале `AGENTS.md`; цитаты владельца — дословно по-русски; документы репо и ответы владельцу — по-русски.
17. Название треда — `<роль> · TK-<NNN> · <тема> · v<N>`: TK — номер самой задачи, не код цели G-022; проверяющий — с тем же TK.
18. Проверяющего и исполнителей — только под текущую задачу владельца; нет задачи — треды не работают.
19. Передача дел — при 260 тыс. токенов контекста, клир — не позже 265 тыс. (В-161; сторож `context_guard.py`). Перед передачей дел и /clear всё следующее уже запущено (счёт — юнитом, исполнители — треды).
20. Перенос и переписывание: проверенное поведение как было (настройки, пороги, логика); эксперименты — только если стало хуже по замеру.
21. Страницы для владельца: макет и «да» — только для новой страницы или перекомпоновки; вкладка, колонка, настройки, подписи на существующей — сразу в бой, в её стиле.
22. Звуки и баннеры уведомлений не включать.
23. Сравнение и «не работает»: «X хуже / сломано» — гипотеза, пока не воспроизведено в равных условиях (одно окно — не вывод); работа под гипотезу не ставится; условия (сообщ./с рынка, доля быстрых подключений, нагрузка хоста) — рядом с результатом, сравниваются равные; числа сторон — одним скриптом по сырым данным, не счётчиками сторон; эталонный тест — один в один (параллельность), без постороннего на хосте (сборки — в Софии); сперва исключить среду, потом код.
25. Перед показом владельцу — проверить самому: макет открыть, сверить с просьбой, прощёлкать каждую кнопку; утверждение о файле — по файлу, не по пересказу.
26. Бриф исполнителю — слова владельца дословно плюс нужный контекст; своих блоков, графиков, разделов не добавлять. Страница — только то, что просил: без плашек, баннеров, оговорок, один акцентный цвет.
29. Дочерний тред — `--parent-self` (иначе он не под координатором и не шлёт итог).
31. Окно счёта — все доступные данные по всем участникам; короче — только с названной причиной (дыры, смена формата), в начале отчёта и в брифе.
33. Ожидание долгой работы на srv/Софии — только `tools/srv-wait.sh` фоном (`docs/COMMANDS.md`, «Ожидание»); сообщения родителю «ещё жду / в очереди / ещё идёт» запрещены — только итог (READY / BLOCKED); опрос сервера в цикле (ssh + sleep) запрещён. В каждый бриф.
34. Расход токенов (В-158; замер `tools/token-usage.py 7`): вывод команд — через `tail`/`grep`/`head` с лимитом; логи, длинные ssh-выводы, диффы — читателю (Agent `reader`), в контекст — сводка; большой файл целиком не читать. Не пересказывать бриф, вывод, свои шаги. Отчёт исполнителя ≤ 25 строк (статус, ветка + SHA, числа, пути, отклонения). Сначала доказательство бага (тест или замер на старом коде), потом правка. Анализ, нужный второй раз, — в `tools/` тем же коммитом, разовые скрипты в ветку не класть. Простая задача — модель `simple tasks`. В каждый бриф.
