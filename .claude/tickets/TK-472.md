Владелец 31.10: «может есть конкретный пул монет который торгуется в плюс?» → «что то я не понял. у монет вообще нет пересекающихся конфигов которые дают плюс? или что?» → «окей найди кор из всех этих монет». (Реестр: секретарь пишет В-N, номер допишу комментарием.) Контекст: отчёт docs/findings/sancho-bp-exits-2026-10-31.md принят Судьёй; CEO-пробой по готовым d2b-out-bp3 (не вердикт, не принято Судьёй): bp g2.3 low D1 шорт, один выход SF2.0/TR/2.0 — плюс на 69 из 78 монет, 2551 сделка, +240 bps; в среднем по 449 вариантам выхода 74% монет в плюсе; в минусе PENDLE, AVAX, ZRO, HEMI, TRX, LDO, BICO, SKY. Сделать: определить КОР = монеты, на которых плюс устойчив — по многим сигналам (Санчо A*, bp g*, S*) и многим вариантам выхода одновременно (пересечение конфигов), не по одному лучшему выходу на монету (подгонка, в split-таблицах так). Правило отбора (порог, доля конфигов, годы/месяцы) — до счёта в протокол, методика Судьи. Отбор только на части «открытие» (чётный md5 × ≤2023, P-TK461 §8), проверка отдельно на «проверка» (нечётный md5 × 2024+) и перекрёстных xa/xb; на каждую монету сделок мало (10–50) — интервалы, не точки. Выход: простой список кора с числами (монета, сделок, net по годам, доля конфигов в плюсе), чем кор отличается от не-кора (ликвидность, возраст листинга, волатильность — описательно), docs/findings/core-coins-<дата>.md + csv. Данные готовы (calc /data/tk0461/d2b-out-{sancho,bp,bp3,s}), считать из них без пересчёта ядра (В-213); calc через alsched, N ядер по замеру. Ограничения: протокол TK-461 не менять; отчёт простыми словами сверху (владелец читает глазами); строка «Алгоритм» (В-170).
