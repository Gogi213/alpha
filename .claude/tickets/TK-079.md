СДАТЬ:
1. СОБЫТИЯ CI В ШИНУ. Программа без ИИ (часть диспетчера или отдельная служба плагина) следит за PR проекта на GitHub (gh api; шина на сервере закрыта файрволом — вебхук снаружи не достучится, значит опрос со стороны машины команды, интервал ≤ 60 с, без токенов) и публикует событие «ci.<PR>.<sha>: success|failure (+ имена красных клеток)». Тикет, чей PR это, будится по правилу: красный → владелец тикета (--next engineer) с именами красных клеток; зелёный → Судья, если вердикта на этой голове ещё нет. Новая форма wait_for: ci:<repo>#<PR> (готово, когда CI на текущей голове завершён).
2. ВЛИВАНИЕ ПО ПРАВИЛУ. Судья выносит машиночитаемый вердикт (напр. tickets.py accept <ID> --pr N --sha <голова>). Программа вливает PR, когда: вердикт «принято» именно на текущей голове + CI зелёный именно на ней + PR без конфликтов; после — ПРОВЕРКА, что state MERGED, событие в шину и запись в тикет. Конфликт → событие владельцу тикета («слить main»), не CEO. Порядок цепочек (base не main) — сам переключает base после влития родителя. Защиту main на GitHub НЕ ставить (В-193).
3. ЛОЖНЫЕ ТРЕВОГИ СТОРОЖА. watch-orphan-ticket не срабатывает на waiting с годным wait_for (условие проверяется и не наступило); watch-plan-stale — не будит CEO, а только помечает на табло (или будит владельца тикета). Каждая оставшаяся тревога CEO = действие CEO; список тревог и кому они идут — в docs/reliability.md.

ГОТОВО, КОГДА: на живом PR цикл «пуш → CI → Судья → влито» проходит без единого действия CEO и без скриптов CEO; ложных тревог из списка выше 0 за сутки (по ceo-wake.log); тесты на каждое правило (зелёный/красный/конфликт/голова сменилась после вердикта — не вливать); Судья принял.
