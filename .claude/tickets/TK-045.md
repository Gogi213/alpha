(5) Отправители: alpha-progress (старт/ход/конец/падение задания), tools/vps-check.sh (сборка готова/упала), systemd ExecStopPost/OnFailure для юнитов tk*/alpha-* на серверах (остановка с кодом выхода — автоматически), tickets.py comment/смена статуса (локально → шина). (6) Получатели: диспетчер — одно исходящее соединение long-poll с ПК (ПК без внешнего адреса), реакция за секунды, после простоя дочитывает с курсора; табло (collect.py) и CEO (Monitor может читать через curl long-poll или через ceo-wake, который пишет диспетчер). (7) Подстраховка: если шина недоступна — диспетчер работает как сейчас (wait_for host:… — делается отдельно) и пишет сигнал CEO. Готово, если: сквозной тест — задание на сервере завершилось → роль разбужена ≤ 30 с без участия CEO; упало → исполнитель + CEO; событие для заблокированного тикета держится и отпускается при снятии блокера; ПК «выключен» 5 мин → после подключения всё дочитано, без дублей; шина лежит → подстраховка работает, CEO получил сигнал.
