Сдать: (1) шина на счётном сервере 89.163.242.211 — одна программа без внешних пакетов (Python stdlib), юнит alpha-bus (CPUQuota малая), журнал событий с монотонными номерами на диске (jsonl/sqlite), HTTP с токеном: POST событие; GET long-poll по очереди получателя с курсором; подтверждение (ack) — до ack событие остаётся в очереди; повтор доставки не будит дважды (id события); порядок по номеру. (2) Маршрутизация — один файл правил (адрес события вида задача.<TK>.задание.готово / .упало, машина.<host>.юнит.остановлен, сборка.готова, задача.<TK>.сдано / .вопрос_владельцу / .статус) → получатели: диспетчер (будит исполнителя/Судью/CEO по шапке тикета), табло, CEO. (3) Блокеры: если тикет заблокирован (status blocked, depends: на незакрытый тикет, открытый вопрос владельцу) — событие для него держится в очереди, не будит; снятие блокера (тикет-зависимость done, ответ владельца, смена статуса) — само событие и отпускает удержанные. (4) Не обработано за N мин (назначить в договоре) — очередь «не обработано» + сигнал CEO (ceo-wake). (5) Отправители: alpha-progress (старт/ход/конец/падение задания), tools/vps-check.sh (сборка готова/упала), systemd ExecStopPost/OnFailure для юнитов tk*/alpha-* на серверах (остановка с кодом выхода — автоматически), tickets.py comment/смена статуса (локально → шина). (6) Получатели: диспетчер — одно исходящее соединение long-poll с ПК (ПК без внешнего адреса), реакция за секунды, после простоя дочитывает с курсора; табло (collect.py) и CEO (Monitor может читать через curl long-poll или через ceo-wake, который пишет диспетчер). (7) Подстраховка: если шина недоступна — диспетчер работает как сейчас (wait_for host:… — делается отдельно) и пишет сигнал CEO. Готово, если: сквозной тест — задание на сервере завершилось → роль разбужена ≤ 30 с без участия CEO; упало → исполнитель + CEO; событие для заблокированного тикета держится и отпускается при снятии блокера; ПК «выключен» 5 мин → после подключения всё дочитано, без дублей; шина лежит → подстраховка работает, CEO получил сигнал. Ограничения: без модели; диспетчер перезапускать только через WMI с CreateFlags=512 (защита от Ctrl+C, см. блокнот CEO); не ломать текущее табло и мост; токен шины не в коммитах. Решения (замер не нужен — поток ~десятки событий/час, узкое место — корректность ack/удержания, не скорость; В-170 так и фиксирует):
- Хранилище: sqlite3 (stdlib, WAL), не jsonl — ack, удержание и дедуп по id атомарны одной транзакцией. Таблицы: events(seq AUTOINCREMENT, id UNIQUE, addr, ts, payload), deliveries(seq, recipient, state pending|held|acked, held_for, first_sent, acked_at), blocked(tk, reason). Повторный POST с тем же id → тот же seq, без новой доставки.
- HTTP (http.server, ThreadingHTTPServer), заголовок Authorization: Bearer <токен из файла /etc/alpha-bus/token, 0600; в репо только имя>. POST /event; GET /q/<получатель>?after=<seq>&wait=25 (long-poll, отдаёт неподтверждённые с seq>after по порядку); POST /ack {recipient, seqs}; GET /health; GET /stale (очередь «не обработано»). До ack событие остаётся и пере-выдаётся при переподключении (клиент дедупит по id).
- Маршруты: routes.json (адрес-шаблон с * → получатели dispatcher|board|ceo; роль-исполнителя диспетчер берёт из шапки тикета, не шина). Адреса: задача.<TK>.задание.готово|упало|ход, машина.<host>.юнит.остановлен, сборка.готова|упала, задача.<TK>.сдано|вопрос_владельцу|статус|блокер.поставлен|блокер.снят.
- Блокеры: шина не видит тикеты (они на ПК), поэтому источник — события задача.<TK>.блокер.поставлен/снят, которые шлёт tickets.py при смене status (blocked/needs_owner/открытый вопрос/depends на незакрытый) и при done зависимости; диспетчер при каждом подключении шлёт полный снимок блокеров (лечит расхождение). Событие для TK из blocked → delivery.state=held, не будит; блокер.снят отпускает все held этого TK по порядку seq.
- «Не обработано»: N=10 мин (предлагаю; поправь, если надо) — delivery pending/выдано без ack дольше N → в /stale и событие ceo-stale для получателя ceo; диспетчер пишет его в ceo-wake.log; если диспетчер лежит, Monitor CEO читает /q/ceo напрямую.
- Доступ с ПК: ПК только исходящий. Порт шины открыт на 89.163.242.211, HTTP+токен (в событиях нет секретов — правило отправителей). TLS/ssh-туннель — не делаю, если не скажете: токен идёт открытым текстом.
- Подстраховка: ошибка соединения у клиента диспетчера → работает как сейчас (wait_for host:…) + одна строка CEO за период недоступности.
