Ссылка на задачу владельца: В-4

Решения владельца (реестр .claude/decisions.md): В-4 — простая форма запуска бэктеста (периоды, гипотезы; второй таб — выводы из Летописи; подсветка уже просчитанных; посчитанные хеши не считаем); В-5 — состав: периоды, гипотезы, титруемые гиперпараметры и фиксированный стек; В-6 — после счёта ни одной нейросети ничего не уходит (никаких автотикетов Исследователю/Судье/Telegram), форма — не единственная точка запуска (CEO запускает тем же кодом). Макет владелец видел в чате 14.10; формулировки ниже — его утверждённый вариант.

Что сделать (Python, stdlib; cargo/сборки не нужны; на этой машине сборки запрещены — только Python):
1) Ядро-CLI `tools/launch/launch.py`: подкоманды plan (сухой прогон: гипотеза/гипотезы × оси × месяцы → «в сетке / уже в Летописи / к счёту» в единицах хеш×месяц, В-224), submit (plan → `registry.py plan-grid`/master.py → файл клеток `--cells` → guard.check (rc 3 = уже посчитано, пропуск) → постановка в очередь calc: `ssh calc "python3 /data/sched/alsched.py submit … -- lob bounce-grid --cells …"`; строка в docs/registry/runs.jsonl с параметрами запуска (гипотезы, месяцы, значения осей, бинарь md5/коммит, команда) — одинаково для формы и для CLI), status (alsched ps). Один и тот же код вызывают форма и CEO.
2) Дедуп только по правилу Летописи: «хеш есть = есть строки results по месяцу» (tools/registry/master.py have_hashes, строки 475-484; plan 574; выписка «в сетке N, в Летописи M, к счёту K» 619-620). Не изобретать свой хеш: tools/registry/cellhash.py (sha256, первые 16 hex; LOGIC=bounce-v1; бинарь в хеш НЕ входит). Смена бинаря решается guard.equiv (docs/COMMANDS.md:535): форма показывает бинарь (md5/коммит) и требует явного подтверждения, если он отличается от того, на котором посчитана Летопись.
3) Локальный сервер `tools/launch/server.py` (stdlib http.server, ТОЛЬКО 127.0.0.1, порт из аргумента; не публиковать) + страница. Две вкладки:
   Вкладка «Запуск»: (а) месяцы 2026-01…2026-09 чипами (2026-10 — «частично»), пресет «янв–сен»; (б) выбор гипотезы (список из docs/registry/hypotheses.jsonl, 148 + М-04; фильтр по семейству; пресет «56 В-227» собрать из docs/research/spec-v227-2026-10-12.md таблицы «| Г-…» — там 54 строки, не 56: не выдумывать недостающие, показать расхождение); (в) титруемые оси выбранной гипотезы из docs/registry/hyp_axes.jsonl (param, lo, hi, points_f1) и сеток протоколов (П-13: стоп 2/2,5/3/4 %, дедлайн 14400/21600/28800 с, формы входа, g93 u×K, g94 n; центр B1 выделен) — значения-чипы: зелёный = уже посчитано по всем выбранным месяцам (не выбирается), синий = выбрано к счёту, серый = не выбрано; «N/9» = посчитано по части месяцев; (г) фиксированный стек — только чтение (серый блок): параметры B1 из docs/research/P-13-titration.md §2/§3 и tools/compute/hyp_stack.py (B1 = лестница 3×0…0,0409 sw2; стоп pct2; тейк tr1x1; дедлайн 14400 с; ttl 1800; набор t-bid-btc4h-q1; busy-skip off; sigma240; В-68; prob:3; пул v171c) — читать из исходного файла, не копировать числа руками; (д) три счётчика «В сетке / Уже в Летописи / К счёту» пересчитываются на каждый клик (вызов plan); кнопка «Поставить в очередь» — если К счёту = 0, сообщение «нечего считать», ничего не ставить.
   Вкладка «Летопись»: таблица по гипотезе/клетке: хеш клетки, 9 квадратов по месяцам (плюс зелёный, минус красный, пусто = не считали; клетка посчитанная полностью подсвечена), колонка «вердикт сита» из docs/registry/sieve.jsonl (eligible/plateau/edge), фильтры: гипотеза, месяц, статус. Источники: docs/registry/{cells,run_cells,results,sieve,verdicts}.jsonl (канон в git) либо data/registry.sqlite (registry.py build) — только чтение.
4) После окончания счёта (юнит завершился): СКРИПТАМИ загрузить результаты в Летопись (registry.py load-results / import-auto — как делает проход F1, см. docs/registry/README.md) и пересчитать сито (`registry.py sieve --protocol P-14 --fraction k --stats …`, TK-237). НИЧЕГО НЕ ОТПРАВЛЯТЬ нейросетям: никаких tickets.py new/comment/result, никаких запусков claude, никакого Telegram. Если загрузка упала — ошибка в файл `data/launch/<run>.log` и на вкладке «Запуск» красная строка, не больше.
5) Не трогать: идущий проход TK-231 на calc (только ставить в очередь alsched; очередь сама решает), диспетчер, `.claude/settings.json`. 6) Тесты (pytest, tools/launch/tests/): plan на фикстурах Летописи (посчитано/не посчитано/частично), submit в режиме --dry-run (ничего не ставит, печатает команду), запрет отправки при К счёту = 0, отсутствие вызовов tickets.py/claude/notify в коде (grep-тест), сервер слушает только 127.0.0.1. Клик-тест страницы (как tools/dashboard/check_page.py, Playwright): клик по месяцу и по оси меняет счётчики; кнопка при нуле даёт сообщение. Без клик-теста не «готово».
