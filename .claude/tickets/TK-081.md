Владелец 07.10 ~06:00: «коллекция ведётся исследований и конфигов? чтобы по второму разу не гонять то же самое никогда»; на три пункта CEO — «Три взрослых пункта мне понравились, внедряем». Решение В-196.

СЕЙЧАС: реестр TK-068 (tools/registry/, SQLite+JSONL, 568 прогонов, 2 430 результатов, клетки с отпечатком) есть, но перед запуском никто его не спрашивает — повтор того же счёта ничем не заблокирован.

СДАТЬ:
1. ПРОВЕРКА ПЕРЕД СЧЁТОМ: обёртка счёта (bounce-grid/touches/сетки R1/R2 — один вход, через который идут все боевые запуски, и alsched submit) до старта спрашивает реестр: клетка (отпечаток) × сутки × версия кода (бинарь/коммит) × данные (версия пула/verdict) уже посчитаны → НЕ считать, вернуть готовый результат (путь) и запись «взято из реестра»; посчитать только недостающие сутки/клетки.
2. ПЕРЕСЧЁТ ТОЛЬКО ЯВНО: флаг --recompute --why «…» (обязательная причина, напр. «изменился код») — пишется в реестр.
3. ЗАМЕРЫ СКОРОСТИ: отпечаток конфигурации замера (бинарь+флаги+P/G/порядок+окно суток+раскладка) → тот же замер без --recompute --why отказ с ссылкой на прежний результат; повтор против шума — флагом --repeat N (явно).
4. Каждый результат счёта и замера после конца — в реестр автоматически (без ручного backfill).

ГОТОВО: тест «тот же запуск второй раз → 0 с счёта, ответ из реестра», «одна новая клетка из 10 → считается только она», «--recompute без --why → отказ», «замер с тем же отпечатком → отказ»; живой прогон на одной сетке; Судья принял.
ОГРАНИЧЕНИЯ: не ломать идущие R1/R2 (подключить к следующим запускам); версия кода и данных — часть отпечатка обязательно (иначе «старое» выдаётся за новое); сборки cargo — только VPS (В-147).
