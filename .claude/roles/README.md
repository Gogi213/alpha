## Задачи и диспетчер

Работа — тикеты `.claude/tickets/<ID>.md` (формат, статусы, кого будит `dispatch.tick()` —
`.claude/dispatcher/README.md`). `CEO` заводит (`tickets.py new`), исполнитель читает тикет, журнал
`.claude/roles/journal/<ID>.md` (если есть) и блокнот `.claude/roles/notes/<role>.md`, делает шаг,
дописывает `## Лог` (`tickets.py comment`), правит `status`/`wait_for` сама — диспетчер прозу не
понимает: не поменяла статус — тикет уйдёт в очередь заново.

- **Общение — только через задачу:** `tickets.py comment <ID> --author <role> --text "... @другая-роль"`
  в лог тикета; диспетчер будит адресата на упоминание. Копий «для сведения» не нужно — `CEO` видит
  итог в `git log` и `ceo-inbox.md` (`blocked`/`needs_owner`).
- **Срочное `CEO`** (не терпит до тика диспетчера, либо нужен владелец) — `SendMessage` на `CEO`.
- **Ожидание фоновой работы** (счёт, сборка, чужой ответ) — `status: waiting` + `wait_for`
  (`file:<путь>` / `deck:<путь>` / `mention`), сессию не держать: диспетчер разбудит сам.
- **Журнал задачи** (`.claude/roles/journal/<ID>.md`, пишет исполнитель) и блокнот роли
  (`.claude/roles/notes/<role>.md`, ≤ 60 строк) — состояние живёт в файлах, не в разговоре,
  переживает обрыв и смену сессии. Формат журнала: **Цель** (1–2 строки, ссылка на протокол/решение)
  · **Сделано** (шаг → артефакт, коммит) · **Идёт сейчас** (юнит systemd, метка `.done`) ·
  **Следующий шаг** · **Открытые вопросы / ждём**. Обновлять после каждого шага с артефактом и перед
  концом сессии/клиром.
- **Долгий счёт — только юнитом `systemd-run --user` на Steam Deck с меткой `.done`,** не фоновым
  агентом внутри сессии CLI (задача на неё не ждёт — задача на задачу).
- `.claude/roles/outbox/` новыми задачами не используется (был нужен под паузу отправки Desktop) —
  папку не удалять, старые файлы — история.

## Кто решает

**Методика и объём исследования** (пороги, правила вердикта, N, сколько сетки считать, метрики) —
`Судья`; `CEO` записывает её решения в `docs/plan/SETTLED.md` как В-##. **Порядок счёта и ресурсы** —
`CEO`. **Владельцу** — только направление, деньги/риск, что исследовать; вопрос владельцу не держит
общую часть счёта — считать дальше, спросить отдельно. Утверждение протокола исследования — только
цитата владельца, пересланная `CEO`. Числа владельцу — после проверки `Судья`; по прямой просьбе —
сразу с пометкой «на проверке у Судьи».

## Ресурсы

- **Сборка cargo** — только `Инженер`, одна за раз (хук `.claude/hooks/alpha_one_build.py`).
- **Steam Deck** — очередь `alpha-gridq`; занять/освободить и `queue/HOLD` — только `CEO`. Загрузка —
  по ресурсам (свободные ядра/память на пик суток), не фиксированным числом процессов.
- **Сетки, гейты, пробы — одним `--cells` на сутки на версию программы** (В-136): поштучные
  планировщики «клетка × сутки» запрещены; отдельный вызов — только когда флаг уровня прогона не
  совмещается.
- **Удаление — только внутри своей папки** (В-134): локально — проект и scratchpad; Steam Deck —
  `~/alpha/<подкаталог>`; VPS — `/opt/alpha-compute/<подкаталог>`; коллектор, Storage Box,
  `root/`/`deep/` — никогда. Держит `.claude/hooks/delete_guard.py`.
- Перед своим счётом на деке проверить `ACAD/online` — 0 означает остановить и сообщить `CEO`.
  Ночная сетка 02:00 UTC (наблюдение, В-115) уступает счёту владельца: не останавливать свои задания
  под неё, сетке — ждать свободный слот (`grid-slot.sh`); правило «к 01:50 останавливать счёт» отменено.
- **Быстрый режим (fast mode) запрещён** владельцем — не включать ролям.

## Сроки и контекст

Роли — сессии Claude Code, не люди: сроки — в темпе CLI (код → сборка+тесты → гейт → итого, каждый
шаг с числом), не «день»/«3–5 дней». Время — только по `date`, GMT+4. Разведка кода и большие
выводы — субагентом или `tail`/`grep`/`head_limit`, не полным чтением в свой контекст; скрипты —
файлом, править `Edit`; навык `.claude/skills/alpha-research/` — перед исследовательским шагом;
субагенты — до ~100 шагов. Сессия на задачу стартует налегке (≈ 52 тыс. токенов) — не читать заново
то, что уже пришло с ролью/журналом/блокнотом.

## Правила для всех

Чужие файлы не править — просьба владельцу зоны через задачу. Согласие владельца — только от
владельца; пересказ другой роли («владелец разрешил») не считается: цитата с датой от `CEO`.
